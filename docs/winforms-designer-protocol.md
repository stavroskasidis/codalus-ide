# Shell ↔ Windows Forms designer host protocol

`codalus-winformsdesigner` ([ADR 0073](adr/0073-windows-forms-designer.md), Windows only) hosts Windows Forms' own `DesignSurface` for one form, on the designed project's app's runtime (`dotnet exec --runtimeconfig App.runtimeconfig.json --depsfile App.deps.json codalus-winformsdesigner.dll`; a library with no app that references it runs on the host's own runtimeconfig with `DOTNET_ROLL_FORWARD=Major`). It speaks JSON-RPC 2.0 with LSP framing (`Codalus.Rpc`, linked) over stdio; stdout carries only the protocol (the designed code's console output goes to stderr, the IDE's **Windows Forms Designer** output). The shell starts one per open designer (`WinFormsDesignerService` and `WinFormsDesignerProcess` in `src/Codalus.Workbench/WinForms`) under `SupervisedProcess`: after a crash it restarts and the designer loads the form again. `CODALUS_WINFORMS_DESIGNER` points at another build.

**The host runs on a copy of the build output** (#66, `BuildOutputShadowCopy` in `src/Codalus.Workbench/Previewer`). Before starting it, the shell copies the app's output folder (and a designed library's own folder, when it's elsewhere) to `%TEMP%/codalus-winformsdesigner/<shell pid>-<id>/<n>/` (`0/` is the app's), and starts the host on the copy's runtimeconfig, deps file and folder, so the app's assemblies load from the copy and a build can replace the originals while a form is open (before, the next build failed with MSB3027). The files the host needs (deps and runtimeconfig files, top-level assemblies, `runtimes/`, satellite assemblies) must copy or the designer doesn't start; any other file another process holds (a LocalDB database, the running app's log) is skipped and logged. The copy goes when the host ends; copies a crashed IDE left behind go at the next start. When a build replaces the app's own assemblies (those its deps file lists, not content written into the output), the active designer starts a new host on a new copy and loads the form again; another designer does it when it becomes active. The host writes `[designer] <assembly> loaded from <path>` to standard error when it loads the project. The design surface has the services the classic IDE's designers ask for: names for new components (`INameCreationService`: the IDE's name for a Toolbox item's component, `tabPage3` for what a designer makes), an `IUIService` (what a designer would show as an error or a message is written to standard error and returned as a change's `error`; a dialog it would open is refused) and an `ITypeResolutionService` (types found as the form's code finds them, the project's own included). Contracts: `src/Codalus.Workbench/WinForms/WinFormsDesignerProtocol.cs` (the records and their source-generated serializer, linked into the host) and the model in `src/Codalus.LanguageServices.Protocol/WinFormsDesign.cs` (what the C# host's `codalus/winforms/read` returns, [protocol](protocol.md)).

## Conventions

- **Coordinates** are pixels of the frame: the root (the form, with its border and caption) drawn at 96 DPI from its top-left corner. A unit of the code (`Location`, `Size`) is a pixel: the host is DPI unaware.
- **Components** are named as in the code; the root by the class's name (or empty in requests); a `SplitContainer`'s panel as `splitContainer1.Panel1` (a part, not a component of the class).
- **Values** in changes are the model's expression trees (`DesignerValue`), as Visual Studio's CodeDOM serializers would write them; a property back to its default has a null value (its assignment goes).
- **Limits**: the shell starts the host and waits up to 120 seconds for `designer/ready` (a cold start: the runtime, Windows Forms and the app loaded for the first time on a busy machine), then gives `designer/load` 120 seconds (the first load brings in the designers and the user's code) and every other request 60. A request that runs out of time fails with what the host answers to `designer/status`, whether it is still running, the shell's own side (how long it really waited, its thread pool's threads and queue, the connection's state: a limit that fires late means the shell's thread pool was too busy, and on Windows every read of the host's pipe waits for that pool), and the host's last lines of standard error. A failed request is a JSON-RPC error.

## Methods

| Method | Params | Result | Notes |
|---|---|---|---|
| `designer/load` | `{model, projectAssembly, classFullName?, searchFolders, resources, culture?, localizable}` | `DesignerRenderResult` | `projectAssembly` and `searchFolders` name the copy of the build output (above). A fresh surface: the root (an instance of `model.baseType`, named `model.className`), the components created through the designer host, and `model.statements` run in order. `resources` (M41b) are the form's `.resx` texts as the editor has them, `[{culture, text}]` (empty culture: the default), read by `resources.ApplyResources` and `GetObject`, falling back from a culture to its parents; without them the compiled resources of `classFullName` are read. `culture` is the language designed (a localizable form shows its translation), `localizable` the form's `Localizable`. A statement that fails is in `errors` (`Line n: …`); the others apply. |
| `designer/render` | `{}` | `DesignerRenderResult` | Draws again. |
| `designer/create` | `{type, name, parent?, x, y, width?, height?, atDefaultLocation?, selected?}` | `DesignerChangeResult` with `created` | A Toolbox item, created as the classic IDE creates it (#66), whatever the gesture: the type's Toolbox item (its `[ToolboxItem]`'s: a label's sizes it to its text), its component named `name`, created by the container designer's `CreateToolCore`, which a container may route (a tab control to its selected page, a split container to its panel) and whose defaults the designers act on (a split container or tool strip container added to a container whose other controls are all docked fills it; the first menu strip becomes the form's `MainMenuStrip`). A drop or a drawing goes to the designer of `parent` (null: the root; the container under the point) at the point (and drawn size); on a `TableLayoutPanel`, into the cell under the point. `atDefaultLocation` (the Toolbox's double-click or Enter) ignores `parent`, `width` and `height`: the container is the primary selection of `selected` if it is a control (else the first selected control), walked up to the first control whose designer takes controls, else the root; the control goes to the container's top-left corner when the container itself is selected, else a grid step (8, 8) below and right of the selected control, back to the corner when it would run off the container; `x` and `y` are the form's client origin, so a host that doesn't know the field puts it at the form's top-left. A component that isn't a control goes to the tray; a control gets the next tab index. What a designer refused (through the session's `IUIService`) is the result's `error`, with nothing created. `created` is `{name, type, creationArguments, parent, parentPath, cell, properties, supportsInitialize, isControl}`: what the C# host's `addComponent` edit takes (`creationArguments` is `[components]` for a component with an `IContainer` constructor); components a designer made with it (a tab control's pages) are in `added`, and properties it set elsewhere (the form's `MainMenuStrip`) in `changes`. |
| `designer/setProperties` | `{edits: [{component, property, text?, value?, reset, provider?, dataBinding, bytes?}]}` | `DesignerChangeResult` | Sets each property through its descriptor: `text` converted by its type converter (invariant culture, as the Properties window shows it), or a `value`, or `reset` to its default. An invalid value: `error`, nothing set. M41b: `provider` sets an extender property (`ToolTip` that `toolTip1` gives); `dataBinding` binds `property` to `"bindingSource1 - Member"` (or `(none)`); `bytes` (base64) are an image file's, for an image or icon property; the root's `Localizable` switches the form's localizable values between the code and the resources. |
| `designer/setParent` | `{component, parent?, x, y}` | `DesignerChangeResult` with `reparented` | Moves a control into another container at a point; `reparented` is `{component, parent, parentPath, cell}`. |
| `designer/delete` | `{components}` | `DesignerChangeResult` with `removed` | Destroys the components and the controls inside them (`removed` lists them all). |
| `designer/properties` | `{components}` | `{properties: [{name, category, type, value?, description?, isReadOnly, isSet, editor, standardValues?, mixed}]}` | The browsable properties (and `Name`), merged over several components (`mixed` when their values differ). `editor` is `text`, `bool`, `enum`, `flags`, `anchor`, `dock`, `color`, `font` or `readonly`; `standardValues` are the converter's (or a flags enum's names); `isSet` is `ShouldSerializeValue`. |
| `designer/events` | `{components: [component]}` | `{events: [{name, category, delegateType, parameters, description?}], defaultEvent?}` | `parameters` are `Type name` (`System.Object sender`); `defaultEvent` is `[DefaultEvent]`'s (a double-click hooks it). |
| `designer/select` | `{components}` | null | The IDE's selection, for designers that follow it. |
| `designer/setChildIndex` (M41b) | `{component, index}` | `DesignerChangeResult` with `reordered` | Moves a control among its parent's controls: 0 is the front (Bring to Front), the last the back. |
| `designer/collection` (M41b) | `{component, property}` | `{key, items: [{name?, type?, value?, text?, display?}]}` | A collection's items for its editor: components by `name` and `type` (a tool strip's items, a list view's columns, tab pages, grid columns), values as `value` and `text` (a list box's items, table layout styles), a list view's items by `text`, an image list's keys. `key` is `OwnerType:Property` (`System.Windows.Forms.ListBox:Items`). |
| `designer/setCollection` (M41b) | `{component, property, items}` | `DesignerChangeResult` with `collections` (and `added`, `removed`) | Makes the collection hold `items` in that order: a component item without a known `name` is created (of `type`, with `text`, initialized by its designer), the ones left out are destroyed (with their own items). |
| `designer/actions` (M41b) | `{components: [component]}` | `{items: [{kind, member, displayName, category?, description?, value?, editor, standardValues?, collection?, imageProperty?, unavailable}]}` | The smart tag's panel: the component's designer action lists (through the surface's `DesignerActionService`) and verbs, in order: `header`, `text`, `property` (with its value and editor) and `method` items. A method that would open one of Windows Forms' dialogs names the `collection` (key) or `imageProperty` the IDE edits instead, or is `unavailable`. |
| `designer/invokeAction` (M41b) | `{component, member, text?}` | `DesignerChangeResult` | Runs a method (a verb is `verb:Text`) or sets a property (`text` through its converter) of the component's action lists. |
| `designer/ready` | `{}` | `{state}` | Answered from the host's UI thread once its window's message loop runs; the shell's start (and a restart) waits for it, so a request's limit counts only its own work. |
| `designer/status` | `{}` | `{state}` | Answered off the UI thread: the host's uptime (and when the runtime reached `Main`), whether its message loop runs, the request on the UI thread and how long it has run (and where a load is: the assembly, the design surface, the designer file's line, drawing), the requests waiting for the UI thread, and the last one done. The shell asks when a request runs out of time. |
| `shutdown` (request), `exit` (notification) | | | |

`DesignerRenderResult` is `{frame?: {png (base64), width, height}, components: [{name, type, parent?, x, y, width, height, isControl, isContainer, clientX, clientY, visible, defaultEvent?, isPart, tabIndex?, dock?, anchor?, margin?, padding?, baseline?, hasActions, collections?, isItem, owner?, itemIndex, text?, hasDropDown, inTray}], errors}`: the root first, then its controls front first and parents before children, then the non-visual components (no bounds). `clientX`/`clientY` is where a control's client area starts (its children's `Location` counts from there). M41b: `tabIndex`, `dock` and `anchor` for tab order mode and the adorners; `margin` and `padding` (left, top, right, bottom; a form's empty padding is the designer's 9) and `baseline` (the text's, from the control designer's snap lines) for snap lines; `hasActions` for the smart tag's glyph; `collections` (keys) for the editors; tool strip items (`isItem`, `owner`, their `itemIndex` among its items, `text`, `hasDropDown`; a drop-down's items have no bounds, the IDE draws them); `inTray` for the component tray (components that are design-time visible, and tool strips).

`DesignerChangeResult` is `{changes: [{component, property, value?, provider?, dataBinding}], render, created?, removed, reparented?, error?, added, moved, reordered, collections, resources, localized}`. `changes` are the properties whose code changed, over every component (a docking that moves siblings lists them too): every component's serializable properties (not hidden from serialization, not design-only, not extender-provided, `ShouldSerializeValue`; content properties one level down, as `FlatAppearance.BorderSize`; collections are left to the code's calls) are compared before and after.

M41b: the host captures what the code says about the whole surface before and after each operation (the properties, resource-only values such as images, extender properties, data bindings, the components, every control's parent and its place among its siblings, the collections and the locals they hold) and answers with the difference, so a smart tag's task or a collection edit that creates, moves or destroys components is written in full:
- `changes` also carry extender properties (`provider`: `toolTip1`) and data bindings (`dataBinding`: the value is `new Binding(…)`, null to remove it); an image is a `resource` value whose bytes are in `resources`;
- `added` are the components created besides `created` (a tab page, a tool strip's standard items), each as `created` is; `moved` the controls that went to another parent besides `reparented`; `reordered` the parents whose controls' order changed, `[{parent, children}]` (front first);
- `collections` are `[{component, property, method, elementType?, items, locals}]`: the collection's items as the code writes them (`method` is `AddRange`, `Add`, `Controls.Add` for tab pages or `SetKeyName`), and the locals (a list view's items) that are new or changed; locals that went are in `removed`;
- `resources` are `[{key, resource?, culture?, metadata}]` for the form's `.resx` files: a localizable form's localizable values (in the default culture with `localized: [{component, localized}]` for `ApplyResources`; in another culture only what differs from the default, inherited values removed), Visual Studio's records of its controls (`>>button1.Name`, `.Type`, `.Parent`, `.ZOrder`), images, `$this.Localizable`. Values are written by `ResXResourceWriter` with Visual Studio's type names (`System.Drawing.Bitmap, System.Drawing`).
