Rounded corners: cards, tabs and controls like the classic IDE's

Task #84, the design before it is built. The user: "Add rounded corners for tabs/panels/windows etc (screenshot 4 comparison again)". In that screenshot the classic IDE's current look sits behind Codalus: its tool windows, the document well and the toolbar are cards with about 4.5 px corners on a darker window, 6 px apart; the selected tab is a rounded outline that flows into a 1 px frame around the active document; drop-downs, the search box and toggled toolbar buttons have the same corners. Codalus in front has square panels flush against each other, an accent-filled square tab and 2 px control corners (D33). This page draws the whole window now and proposed, then each part close up, on the user's BlazorSudoku solution. Most shapes are token values and styles; the frame's top edge beside the selected tab needs a small control (C). The cards also move a few Classic Light and Dark colors (the toolbar, the tab strip, the selected tab, the focused caption), listed in the colors card at the end; #83 reworks Classic's colors in parallel and may retune them. Only Classic changes shape; the other families take only the shared popup radii. {{t.name}}, {{t.p.family}} family{{familyNote}}.

Classic colors this design changes

The cards need fills that differ from the window's: today Classic Light and Dark paint the toolbar and the tab strip in the window's own color (#EEEEF2, #1F1F1F), so as cards they would show only as outlines. These are every color token the proposal touches, with the value it sets; each new value is an existing token's (Shell.Panel, the accent, the toolbar's hover), so #83 can retune it without touching the shapes (Q18). Checked on this page by render.cjs (its rules, plus the state cues it checks on this page alone): text 4.5:1 (7:1 in High contrast); icons, focus rings and check-box outlines 3:1; and, new for this design, the non-text state indicators at 3:1: the selected tab's outline or fill against the strip, the accent frame of the active document and of the focused tool window against the window, the selection pill against its row, and the open auto-hide tab's bar. Decorative, so not checked: card borders, the gaps, the toolbar card's edge and the tool tabs' outline (the selected tool tab is carried by its semibold title in the link color, checked as text). Classic Blue's and High Contrast's tabs and captions are today's fills, unchanged.

Measured in the user's screenshot (100 % scale)

Both windows show 12 px Segoe UI with 9 px capitals, so neither is scaled. Radii are fitted against anti-aliased rounded rectangles; colors are read from the pixels. One deliberate departure: the classic IDE outlines its cards differently (the document well has no border, #262626 straight on the #1C1C1C window; tool windows have a #454545 border; the toolbar card a dark #0E0E0E edge), while the proposal gives every card the same 1 px Shell.Border. Codalus's Classic Dark panels and window are 1.08:1 apart (#252526 on #1F1F1F), so without the outline the cards would disappear. If #83 adopts a darker window with lifted cards, the document card can drop its border as the classic IDE does (Q18).

Where it changes

Most of it is token values the existing setters already apply (Ember's 10 px cards have shipped since 0.3.0 and render alike on all three systems). Four parts need more: the frame's top edge beside the selected tab (a new control, required for the open tab: Dock's DocumentControl puts a 2 px separator and then a full Border under the strip, so styles can only close the frame under the tab or drop its top edge), the document well's card (a control theme), the selection pill (Solution Explorer's row template) and the feet (optional, in the same new control). The tool tabs need no drawing: Dock already interrupts their top line at the selected tab.
