.NET SDKs, redesigned

Tools → .NET SDKs… today, what is wrong with it, and three ways to lay it out. One made-up machine in every panel, so every state shows: ~/.dotnet (yours, the .NET Codalus IDE uses) with .NET 11 and .NET 10 (a security update out, an old patch left behind), and /usr/lib/dotnet from the distribution's packages with .NET 8, out of support since 10 Nov 2026. The open solution is ContosoStore.

What is wrong today

  1. No page margin: the title and the folder path are clipped at the left edge.
  2. Each table stretches across the document, so a version, its status and its support sit ~450 px apart.
  3. "Up to date" on every row is noise, and what does need attention has no color, icon or position to stand out.
  4. The buttons sit under each table and stay disabled until a row in that table is selected; with three tables and one selection, most of the buttons on screen are gray.
  5. Runtimes are a table of their own, with their own Update, though an SDK's update brings its runtimes.

 

  1. Install, the page's main action, and Refresh are below the fold.
  2. Two date formats on one page (11/27/2026, 2028-11-14); "(LTS)" in parentheses where a chip would do.
  3. The intro explains passwords and the terminal every time; that belongs in the confirmation and the folder's owner line.
  4. A raw path is the section heading, and its owner a sentence ("Managed by you.").
  5. It's built from the plugin view protocol's generic stack, table and toolbar nodes, which is why it reads as a form. Every alternative below needs a view of its own (as the package manager has) or new node kinds: card, chip, row actions.

B

List and details, as the package manager

Installed, Updates and Available tabs over a list grouped by folder (runtimes folded under it), and the selection's details on the right: its folder and owner, what it brought, who pins it, and the exact command its button runs, before the confirmation asks. The NuGet package manager's layout, so nothing new to learn; the selection always has a target, so no gray buttons.

C

One tree grid with row actions

The smallest change: one grid instead of a table per folder and kind, grouped folder → .NET version → SDKs and runtimes, with columns sized to their content and each row's buttons on the row. A toolbar holds Install, Update All and Remove Old Patches. Closest to today's code: a tree-grid node with row actions in the view protocol would do.
