# M20d checkpoint: MAUI XAML editing

Date: 2026-10-14. Builds on [M19a](m19a.md) (the XAML engine) and [M20a](m20a.md). Decision: [ADR 0047](../adr/0047-xaml-language-service.md) covers both frameworks; nothing new was decided.

**Status: XAML editing done; Hot Reload not.** .NET MAUI's `.xaml` files get the same engine as Avalonia's `.axaml`, on the project's own MAUI types. C# Hot Reload on the Mono runtime waits for a dependable Mono debug session (M20b), which it would run through.

## Built

**The engine** (`src/Codalus.LanguageServices.Host/Xaml`):
- `XamlContext.IsXaml` takes `.xaml` files as well as `.axaml`: they are additional files of their projects, like Razor's.
- `XamlTypeSystem`:
  - `IsMaui` (`Microsoft.Maui.Controls.BindableObject` is referenced) and `IsXamlFramework` (Avalonia or MAUI), which gates the analysis.
  - Attached properties as MAUI declares them: a static `XProperty` `BindableProperty` field with a static `SetX`.
  - `[ContentProperty("…")]` names the content property.
  - Controls derive from `VisualElement`; MAUI's binding and markup extensions; named colors from `Microsoft.Maui.Graphics.Colors`'s fields.
- `XamlCompletion`: MAUI's default XML namespace for a MAUI project; `Mode=` values from MAUI's `BindingMode`.
- Everything else is shared with Avalonia: elements from `[XmlnsDefinition]`, properties and events, binding paths through `x:DataType`, the diagnostics `XAML0001`–`XAML0006`, hover, go to definition, `x:Name` rename and formatting.

**The language** (shell):
- "MAUI XAML" (`mauixaml`), colored with the XML grammar, served by the C# host.
- `LanguageService.LanguageOverride` lets a file's project decide its language: a `.xaml` file in a project with an Android, iOS or Mac Catalyst framework is MAUI XAML. Other `.xaml` files stay XML.
- Completion triggers on `{`, `/`, `=` and `|` as in Avalonia XAML.

**A fix found on the way** (`ProjectEvaluator`): before its first restore, a multi-targeted project's outer evaluation has no `ProjectAssetsFile` (restore's `nuget.g.props` sets it there). Opening took that for "nothing NuGet restores", so a solution of one multi-targeted project (a new MAUI app) was never restored, and its design-time builds lacked the packages' targets (MAUI's XAML files as additional files among them). The frameworks' evaluations have the path, and it's taken from them now (`RestoreOnOpenTests`).

## Tests

- **Language host** `MauiXamlTests` (5), on a compilation with MAUI's shape (the real assemblies need the workload, which CI doesn't install):
  - elements;
  - attributes, with bindable properties, events and attached properties;
  - named colors, binding modes and compiled binding paths;
  - no diagnostics on a correct page, and the mistakes reported.
- **Shell** `MobileShellTests.Maui_xaml_completes_from_the_projects_types`: opens `samples/Maui`, checks that `MainPage.xaml` is MAUI XAML, and completes `Button` from the real MAUI assemblies. It runs with `CODALUS_TEST_MAUI=1` (and the workload).

**Validation**: Windows (the shell test with the MAUI workload, `CODALUS_TEST_MAUI=1`).
