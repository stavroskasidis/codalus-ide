# M41b checkpoint: the rest of the Windows Forms designer

Date: 2026-10-17. The second part of M41 (the Windows desktop phase; D31: Windows-only features), which completes it: M41 is done, one milestone with one stable (the maintainer's order). Decision: [ADR 0073](../adr/0073-windows-forms-designer.md), amended ([M41b: the rest of the designer](../adr/0073-windows-forms-designer.md#m41b-the-rest-of-the-designer)); no new ADR.

## Done

**Writing the new kinds of code** (C# host, `src/Codalus.LanguageServices.Host/WinForms`; [protocol](../protocol.md)):
- **`codalus/winforms/edit`** gains `setChildIndex` (a control's place in its parent's `Controls.Add`: z-order), `setExtender` (`toolTip1.SetToolTip(button1, "…")` in the extended component's section, sorted by the property's name, removed with a null value), `setCollection` (`AddRange` with a typed array, `Add` per item, `SetKeyName`, written where the old statements were; a strip's first items bring its layout calls), `addLocal` (`ListViewItem` locals after the creations), `setDataBinding` (`DataBindings.Add(new Binding(…))`), `setResource` and `setLocalized` (`resources.ApplyResources` first in a component's section). The resources variable is declared when first used (after `components`, else first) and goes with its last use.
- **The `.resx` files as text** (`ResxText`, `DesignerResourceSet`): a form's default and per-culture `.resx` files are edited with the designer file, touching only the entries that change, placed as Visual Studio orders them (by component; metadata first, properties alphabetically, the `>>Name/Type/Parent/ZOrder` records last; new components alphabetically, `$this` last), in the file's line endings, with its assembly aliases (moved before their first use when needed). A culture's file is created when a key is set in it (a new document in the workspace edit). Renames rename every culture's keys and the `ApplyResources`/`GetObject` names (refused only when a localizable form's resources can't be found); removals remove them.
- **`codalus/winforms/read`** says whether the form is localizable (`$this.Localizable`), its cultures, and the tray's order (`TrayLocation` metadata). Read and edit take the designer's unsaved `.resx` texts (`resourceFiles`), which win over the disk's: they aren't open documents in the C# host.
- The reader no longer takes `ContainerControl = this` (an `ErrorProvider`'s) for the .NET Framework style; the syntactic type resolver knows the binding, tool strip and image list types.

**The designer host** (`src/Codalus.WinForms.Designer`; [protocol](../winforms-designer-protocol.md)):
- **The surface's state difference** (`DesignerSession.State.cs`): before and after each operation, every component's serializable properties (and resource-only values such as images), extender properties, data bindings, the components, every control's parent and place among its siblings, the collections and their locals; the answer is the difference: changes (with `provider` and `dataBinding`), `added`, `moved`, `reordered`, `collections` (with new locals), removed components and locals, and resources.
- **Resources from the editor's texts** (`TextResourceManager`, a `ComponentResourceManager` over the `.resx` texts with culture fallback) instead of the compiled ones; `ResourceValues` writes values with `ResXResourceWriter` and Visual Studio's type names.
- **Localizable forms:** the root's `Localizable` (moves every localizable value between the code and the default resources, with the `>>` records), the designed culture (its translation shown; a change written to its file only when it differs from what it inherits), `Parent` and `ZOrder` records on moves and reorders, images imported from bytes.
- **New methods:** `designer/setChildIndex`, `designer/collection` and `designer/setCollection` (values, components created and destroyed through the designer host, list view locals, image lists and their `ImageStream`, a `TableLayoutPanel`'s column and row counts with its styles), `designer/actions` and `designer/invokeAction` (`DesignerActionService`'s lists and verbs; a dialog task mapped to a collection's editor or an image import, or unavailable).
- **Views** carry tab indexes, Dock, Anchor, margins, padding (a form's 9) and text baselines (the control designer's snap lines), smart tag and collection flags, tool strip items (owner, index, text, drop-down) and the tray's components. The Properties window's rows add extender properties (`Provider`), `(DataBindings)` with the binding sources' members, image and collection editors, and the root's `Localizable`.

**The IDE's side** (workbench and shell):
- **Snap lines** (`DesignerSnapping`): edges, baselines, margins and the container's padding within 8 pixels, while moving and resizing, drawn as Visual Studio's (blue edges, magenta baselines, dashed margins); `Alt` turns them off.
- **The Format menu** (top-level, shown with the designer; also the surface's context menu): Align (lefts, centers, rights, tops, middles, bottoms, to grid), Make Same Size (width, height, both, size to grid), Horizontal and Vertical Spacing (equal, increase, decrease, remove), Center in Form, Order (Bring to Front, Send to Back through `setChildIndex`). The menu bar rebuilds when the active document's kind changes.
- **Tab order mode** (View → Tab Order): labels as Visual Studio's (`5.1`), clicks number each container from 0.
- **Dock and Anchor** pickers in the Properties window (a box of five, a cross of four), and their adorners on the surface.
- **Smart tags**: the glyph at the selected component's top right (`Shift+Alt+F10`), its **Tasks** panel (headers, texts, properties with editors, methods), run in the host.
- **Menus and tool strips** edited in place: Type Here on a strip and on each open drop-down (typed text in menus, `-` for a separator, a chosen item type on tool and status strips), items named as Visual Studio names them (`editToolStripMenuItem`), text edited in place, `Ctrl`+arrows to reorder, `Delete`.
- **The component tray**: icons, selection, `F2` rename in place, `Delete`, a context menu (Rename, Delete, Line Up Icons), drag to reorder; the order written as `TrayLocation` metadata.
- **Collection editors** (an Avalonia panel over the surface): items as text, members (added of a chosen type, removed, moved, with their properties in a grid), table styles (size type and size), list view items, image keys.
- **Extender properties** ("ToolTip on toolTip1"), **(DataBindings)**, **images** (into the form's `.resx`, or the project's `Resources` folder and `Properties/Resources.resx` as a `ResXFileRef`, read as `Properties.Resources.Name`, after the ResX generator runs), and **Language** for a localizable form, in the Properties window.
- **Resources with the code:** the designer holds the form's `.resx` text models with the designer file's, saves them together, and its undo steps cover every model a change touched (falling back to the designer file's own undo when one was changed elsewhere).
- **Paste** brings collections, locals, extender properties and bindings, and event hookups within the same form (decided: in another form the handlers don't exist, so they're left out; ADR 0073).

**Docs:** the user guide's [Windows Forms designer](../user-guide/windows-desktop.md#the-windows-forms-designer) section (snap lines, the Format menu and tab order, smart tags, menus and tool strips, the component tray, collections, localizable forms and images, data binding; its limits), the website's Features page, the changelog, ADR 0073's amendment, [the designer host's protocol](../winforms-designer-protocol.md), the C# host's requests in [protocol.md](../protocol.md), the fixture's README, the roadmap. No new environment variables.

**Fixture** (`samples/WindowsDesktop/WinFormsApp`): `InventoryForm` as Visual Studio for .NET writes it (a menu strip with drop-downs and a separator, a tool strip, a status strip, a context menu strip, a list box's items, a list view's columns and `ListViewItem` locals, tab pages, a data grid view's columns, a `BindingSource` over `InventoryItem` with `DataBindings.Add`, `ToolTip` and `HelpProvider` extender calls, an `ImageList`, an `ErrorProvider` with `ContainerControl = this`, an image through `GetObject`, its `.resx` with the tray's locations), `InventoryItem`, and `AboutForm.fr.resx` (French texts).

## Gaps

- **The WPF design surface** (M41's optional part) is deferred (ADR 0073): the WPF XAML Previewer shows the window and selects both ways; a surface that writes XAML as minimal edits is a milestone of its own, to be proposed. `TODO(issue)`
- **Data binding:** Visual Studio's Data Sources window and data source wizards aren't there (set a `BindingSource`'s `DataSource` in the Properties window or the code); complex binding's designer (a grid's columns from its data source) isn't either. `TODO(issue)`
- **The component designer** (a class that is a component but not a control: its tray only) opens as code. `TODO(issue)`
- **Windows Forms dialogs without an IDE counterpart** (a data grid view's Add Column…, a column's cell style builder, a binding source's wizard) say they aren't available; their properties are set in the Properties window. `TODO(issue)`
- **Visual inheritance** (a form deriving from another of the project's forms) isn't designed as Visual Studio does it: the base form's controls aren't shown as inherited, locked or editable by their modifiers. `TODO(issue)`
- **An undo reloads the form** from the code (a few hundred milliseconds for a common form), as in M41a.
- **Linux and macOS:** the designer through a Windows machine (the remote target, decided later under D31); Windows Forms on .NET Framework (M43).
- **The website's screenshots** of the designer: `winforms-designer.png` and `winforms-designer-depth.png` come from the smoke steps on Windows (CI), not taken here.
