# M28a checkpoint: AI providers, the data boundary and the chat

Date: 2026-10-14. Decision: [ADR 0062](../adr/0062-ai-providers-and-data-boundaries.md), under D7 (opt-in, any provider, no telemetry). M28b (inline completions), M28c (AI actions on existing surfaces) and M28d (agent mode and MCP) follow.

## Built

**The provider API** (proposed: `IProposedApi.Ai`, `Proposed/Ai.cs`):
- `RegisterModelProvider(id, label, IAiModelProvider)`; a provider lists models, streams an answer (`IAsyncEnumerable<string>`) and configures itself.
- The manifest declares providers (`contributes.aiProviders`), and the plugin activates on `onAiProvider:<id>`.
- **The protocol**: `ai/register`, `ai/models`, `ai/configure`, `ai/chat` answered with a chunk count, and `ai/chunk` numbered pieces. The shell's `AiStream` orders the pieces and waits for the count, because notifications are handled concurrently. The first shell test caught exactly that race.
- **Plugin API 1.1.0**: `InputBoxOptions.Password` hides what's typed, carried through `window/showInputBox` to a password dialog.

**The built-in providers** (`src/Plugins/Codalus.Plugins.Ai`, `codalus.ai`, permissions `network` and `secrets`):
- **OpenAI-compatible**, for OpenAI or a local server through `ai.openai.baseUrl`: `/models`, and `/chat/completions` streamed. The key is optional.
- **Anthropic**: `/v1/models` and `/v1/messages` streamed. The system prompt goes on its own, with a `max_tokens` default. No request is made without a key.
- Keys live in the plugin's secrets (the OS credential store), entered through Configure…. Errors carry the API's own message.

**The data boundary** (`AiContext`, workbench `Ai/`):
- Only what the user attaches is sent: the selection or active file, open files, the active file's problems, the last build's errors.
- Never sent: secrets by name (user secrets, `.env*`, keys and certificates, Production settings), files `.gitignore` excludes (`git check-ignore`), and files `.codalusignore` lists (gitignore syntax: comments, `!`, `*`, `**`, `?`, anchors, folders).
- Each message lists what it carried, and the chat says what was left out and why. The system prompt asks for complete code blocks.

**The AI Chat** (View → AI Chat, `ShellHost.AiChat.cs`, a declarative view):
- `ai.enabled` is off by default, can be turned off per workspace, and is off when either says so.
- The provider and model pickers, Configure… and Refresh Models. The context switches; Send, Stop and New Chat. The answer streams, redrawn a few times a second.
- **Apply…** on a code block replaces the selection the question was about, or the file, through the refactoring preview.
- The status bar shows the provider and model while AI is on, and "sending" during a request.

## Tests

- **Plugins** `AiProviderTests`, in a real plugin host against a mock server streaming server-sent events:
  - the providers known before their plugin runs;
  - the OpenAI-compatible endpoint's models and streamed answer, without a key, checking the request;
  - Anthropic sending nothing without a key, then a key entered through the password prompt, its models, and its streamed answer with the system prompt apart.
- **Plugins** `PublicApiTests` and `ApiReferenceTests`: the 1.1.0 baseline and reference page.
- **Workbench** `AiContextTests`: the secrets by name, `.codalusignore` rules (negation, anchors), git-ignored files, refusals, and the message layout.
- **Headless UI** `AiChatTests`: off by default with no indicator; turned on, provider picked, model filled in; a question about a selection streamed; the request carrying the system prompt and the selection; Apply through the preview; a `.env` file refused and never sent.

**Validation**: Windows green on the affected classes; the rest with the push.

## Not done

- Token limits per request (`ai.maxTokens`) and conversation trimming aren't there yet: long chats send everything so far. `TODO(issue)`.
