# M28a checkpoint: AI assistance, the provider API and chat

Date: 2026-10-15. D7 (2026-10-10) decided AI assistance as an open, opt-in design with any provider and no telemetry. M28 is split in three parts: M28a (this one) is the provider API, the data boundary and chat; M28b adds inline completions, next-edit suggestions and the AI actions on existing surfaces; M28c adds agent mode and MCP. ADR 0062 is the decision record.

## Done

**The provider API** (proposed; `Codalus.Plugins.Proposed.LanguageModels`):
- **Declaring a provider**: `contributes.languageModelProviders` (id, label, description, `local`). The activation event `onLanguageModelProvider:<id>` is implicit, so a provider's plugin loads only once the user has chosen it.
- **What a provider implements**: `LanguageModelProvider` lists its models, streams a chat (text and complete tool calls), reports whether it is ready, and asks the user for a key with its own prompts. `LanguageModelException.NeedsConfiguration` says when a key is missing or refused.
- **What a chat carries**: messages with roles, tool calls, tool results and tools. Agent mode (M28c) needs no API change.
- **Wire** (`languageModels/*`, docs/plugin-protocol.md):
  - The host posts a chat's parts as `chatPart` notifications before its response, and the response says how many there were. The shell may handle the response first, so it waits for the rest.
  - `$/cancelRequest` stops a reply.

**Built-in providers** (thin plugins on that API, none privileged):
- **`codalus.openai`**: *OpenAI-compatible* (OpenAI, LM Studio, llama.cpp, vLLM, gateways; the key is optional) and *Ollama* (a local endpoint, no key). Both use the chat completions API, with streamed tool calls assembled from fragments, and `max_completion_tokens` for OpenAI itself.
- **`codalus.anthropic`**: the Messages API.
  - Server-sent events, with tool input assembled from JSON fragments.
  - The system message goes in `system`, and parallel tool results go in one user message.
  - `effort` is passed through `output_config`, and refusals become `refused`.
  - The models come from `/v1/models`, and Claude Opus 5.5, Sonnet 5.5 and Haiku 5.5 are the fallback list.
- **Shared code**: `Codalus.Plugins.LanguageModels` keeps the key in the plugin's secrets (the OS credential store) and reads server-sent events. It turns 401 and 403 into "configure the provider", and other errors into the service's own message.

**The data boundary** (`AiService`, workbench `Ai/`): the only code that sends workspace content.
- **When it is on**:
  - `ai.enabled` is off by default. Only the user's settings turn it on: a workspace's (a cloned repository's) can turn it off, never on.
  - Tools → AI → Turn AI Off or On for This Workspace writes the workspace's `false`.
  - With no `ai.provider`, nothing is sent.
- **Files that are never sent** (`AiExclusions`):
  - **`.gitignore`**: the repository's, nested ones and `.git/info/exclude`, with git's precedence (deeper files win, and an ignored folder hides what is in it).
  - **`.codalusignore`**: the same syntax.
  - **`ai.exclude`**: globs relative to the workspace.
  - **Secret file names**: `.env*`, `*.pfx`, keys, `secrets.json`, and the like.
  - Ignore files are read through `FileSystems`, so a remote window reads its machine's. `IgnoreRules` is a `.gitignore` matcher: the code base had none.
- **Secrets in text** (`SecretRedactor`): private keys, token shapes, and quoted values of password, secret, token and key settings, as well as unquoted ones in `.env` style, connection strings and YAML, are replaced with `[redacted]`. Code that only names a secret (`var token = GetToken();`) stays.
- **Restricted mode**: no file of an untrusted folder is sent. Only the Error List and the build output go.
- **The size budget**: `ai.chat.maxContextCharacters` (120,000), with 60,000 per item at most. What is cut says so.
- **The request log**: the *AI* Output channel gets the time, the provider and model, the size, what was sent and not sent and why, the redactions and the tokens. It never logs the content.

**AI Chat** (View → AI Chat, `Ctrl+Alt+I`; `ShellHost.Ai.cs`, `AiChatViewModel`, `AiChatView`):
- **Turning it on**: while AI is off, the window explains this and offers Turn On AI Assistance. It then picks a provider and a model in the palette, and asks for the key when the provider isn't ready.
- **What goes with a question**: context chips for the selection, the current file, the open files, the Error List's rows for the open files, the build output, and the solution's projects and frameworks. The line under them lists what would go, before sending.
- **Answers**: they stream in as Markdown, re-rendered at most every 100 ms. Each one says what went with it, what didn't and why, and the redactions. Errors offer Configure when the provider needs a key.
- **Code blocks** offer Copy, Insert at Cursor and Apply…:
  - Apply replaces the selection the question was about, found again if the text moved and indented like it.
  - When the block names a file (```` ```csharp path=… ````) or starts like it, Apply replaces the whole file. Otherwise it inserts at the caret.
  - Every Apply goes through the refactoring preview, and is one undo step.
- **Keys**: `Enter` sends, `Shift+Enter` starts a new line, Stop cancels, and New Chat clears. Conversations aren't saved.
- **The status bar**: it shows "AI: <provider>" while AI is on, "AI: working…" during a request, and "AI: no provider" when none is chosen. A click opens the chat.
- **The editor's context menu**: AI → Explain the Selection, Ask AI About the Selection.

## Results

Linux (this cloud session's container, Ubuntu, .NET SDK 10.0.401): the solution builds without warnings; the new tests pass (`LanguageModelProviderTests`, `LanguageModelPluginHostTests`, `AiBoundaryTests`, `AiChatTests`), with the catalogue, menu, icon, accessibility, public API and API reference checks. Full runs of the three affected projects:
- `Codalus.Shell.Tests`: 266 passed, 10 skipped (no display for an app's window, no debugger in the container), 0 failed.
- `Codalus.Plugins.Tests`: 150 passed.
- `Codalus.Workbench.Tests`: 445 passed, 10 skipped, 2 failed, both outside this change and specific to the container:
  - `DevContainerTests` found no podman;
  - `DiagnosticsHostTests` failed when the diagnostics host's process listing couldn't read `/proc/2/environ`. That is a real robustness gap, filed as a follow-up.

**Needs validating on Windows and on the Mac** (the Mac session had no usage left on 2026-10-15; the development machine is Windows): run `eng/validate.sh` on the Mac and the Windows test run, and the smoke step `ai.chat` on both, before M28 is released.
