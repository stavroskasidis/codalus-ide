# M60b checkpoint: the desktop app for agents, and the headless mode

Date: 2026-11-14. The roadmap's [M60](../roadmap.md#m60--the-ides-tools-for-agents-round-2), items 6 and 10, which M60 deferred; the maintainer decided on 2026-11-14 that both are built before 0.13 ([ADR 0099](../adr/0099-the-ides-tools-for-agents-round-2.md), "What M60b built"). D52: the desktop-app tools' actions follow `ai.agent.ideActions` with no approval of their own; reading the app is Read, input is Action. One pull request.

## Done

**The desktop app being built.** Three tools in a new group, `IdeDesktopAppTools`, at the end of `IdeToolsRound2.All`, served in `ShellHost.IdeTools.DesktopApp.cs` behind round 1's dispatcher. They reach the Avalonia app (or WPF app on Windows) the IDE runs or debugs through the Live Visual Tree's live session, and wait for an app that is starting.
- `desktop_app_windows` (Read): each window's id, title, class and size, with a PNG of each that the app renders itself (a covered or off-screen window has one).
- `desktop_app_controls` (Read): the logical tree, indented: type, name, text, state words (disabled, hidden, focused, pressed, checked, selected, expanded, read-only, selectedIndex, value) and bounds in the window; a filter keeps the matches and their ancestors.
- `desktop_app_input` (Action): click (the automation peer's invoke, toggle, select or expand, of the control or the nearest one around it), text (at the end, or in place with `replace`), keys (chords such as `Ctrl+A Enter`), scroll (lines, pages, top, bottom, into view), by the control's id or name. Nothing goes through the OS: the user's pointer doesn't move and their focus stays.
- Both agents (`Codalus.Previewer.Agent`'s `LiveAgent.App.cs` by reflection, `Codalus.Previewer.Wpf`'s `LiveAgent.App.cs`) gained `controls`, `picture` and `input`, and `windows` carries each window's size; `LiveSession` reads them (`ControlsAsync`, `PictureAsync`, `InputAsync`). WPF reads modifier keys from the keyboard device, so a chord with Ctrl, Shift or Alt is refused there with that reason.
- **Off-screen.** `run_project` and `debug_start` take `offScreen`: on Linux with Xvfb, the IDE's own Xvfb (`OffScreenDisplay`, `-displayfd 1`, no TCP, ended with the IDE) and the program's `DISPLAY`, given once through `RunService.ProgramPlan`. On Windows and macOS, or without Xvfb, the windows open as usual and the answer says so.

**The headless mode.** `codalus mcp --folder <path>` (`HeadlessIde`): a trusted folder only (else standard error says why and the exit code is 2); the shell on Avalonia's headless platform with Skia (the UI tests' platform, now `Avalonia.Headless` in the shell) and a 50 ms render tick; the folder opened; the same tools and dispatcher on stdio (caller `codalus mcp --folder`). Reads run; actions only under `ai.agent.ideActions: allow`, refused with the reason otherwise; plugins' tools refused; every dialog and picker cancelled; no per-folder question and no `ai.mcpServer.enabled` needed. It takes no single-instance requests, opens no MCP pipe, starts none of a window's startup work, restores no editor tabs (so the tools write files), saves any document left changed, and keeps the window's layout and session as they were. Its standard input and output are the agent's alone (duplicated on Unix, the process's own swapped for `/dev/null` and standard error; the standard handles swapped on Windows). It ends when standard input ends, with exit code 0.

**Smoke.** `ai.headless`: the shipped app runs `codalus mcp --folder` on the trusted BuildAndRun solution with a user-data folder of its own: an untrusted folder refused, the tools listed, `get_solution`, `run_command` under `allow`, and the process ending when its input closes.

**Docs.** The user guide (AI › The IDE's tools: the table row and "The desktop app"; Codalus as an MCP server › Without a window), the Features page, ADR 0099's "What M60b built", `THIRD-PARTY-NOTICES.md` (Avalonia.Headless in the shell). No new UI text, settings or `CODALUS_*` variables.
