# M51 checkpoint: 0.8, AI, feedback and OS integration

Date: 2026-10-26. The scope is the roadmap's [M51](../roadmap.md#m51--08-ai-feedback-and-os-integration), the maintainer's list of 2026-10-24, the items marked for 0.8, and M50's platform-only items carried into it (item 5). Branch `claude/version-0-8-release-cb6c17`, from `develop` at `b2d106e1`.

## Done

**External agents: the connection and the model** (item 1, [ADR 0079's amendment](../adr/0079-external-agents-over-the-agent-client-protocol.md)):
- *Across a restart:* reproduced: AI Chat's picker always started on Built-in, and with only an agent connected the built-in assistant has no provider, so the chat showed the Connect buttons as if nothing were connected (`ai.agents` was intact). The picker now writes `ai.chat.agent` (user settings) and the chat opens with the agent chosen last, also when the settings load after the window.
- *Model, mode and effort:* the agent's choices come from ACP's session config options (`configOptions` of `session/new`, selects with flat or grouped values), or, without them, its `modes` and the unstable `models`. One picker per choice after the agent picker (model, mode, effort, then the agent's own); a pick goes out with `session/set_config_option` (whose answer replaces every option), `session/set_mode` or `session/set_model`, `config_option_update` and `current_mode_update` keep them current, and the pick is kept in the agent's entry (`ai.agents.<agent>.choices`) and applied to its next sessions (a value it refuses or no longer offers is logged and left). A pick never restarts the agent; Connect keeps `choices` when it writes the entry again. The pickers show once the session exists (starting the agent only to fill them would spawn it at startup).
- Tests: `AcpAgentTests` (config options with groups and a choice that changes another, the older models and modes, saved choices applied to the next session, a refused or vanished value, the chat agent setting) against the stand-in agent's new `ACP_FAKE_CHOICES`; `AcpShellTests.After_a_restart_…` restarts the IDE on the same settings and checks the chat, its pickers and the kept model.

**More AI in the IDE** (item 2, [ADR 0062's amendment](../adr/0062-ai-provider-api-and-data-boundaries.md)). Inline completions (multi-line ghost text, Tab), commit messages, pull request descriptions, Fix with AI and Ask AI on an exception were already there (M28b); added:
- quick actions (`Ctrl+.`) end with **Fix with AI** and **Explain with AI** for the first diagnostic on the line, and **Generate Tests with AI**;
- the Error List has a row menu: **Go To**, **Copy**, **Fix with AI** (opens the file at the diagnostic, then the usual preview) and **Explain with AI**;
- a value's menu in Locals, Autos, Watch, QuickWatch and data tips has **Ask AI About the Value** (the value, its type and expression, the code around the current statement and the call stack, in AI Chat).
Each only while AI is on, through `AiService`. Tests: `AiSurfacesTests` against the mock model server.

**Report a Problem and Suggest a Feature** (item 3): two Help-menu and palette commands (`help.reportProblem`, `help.suggestFeature`, after About) open an in-window dialog with the issue's title, description and steps (or proposal) and a read-only preview of exactly what is attached: the version, OS and architecture, the .NET runtime and SDK (`dotnet --version`, 5 s), and for a problem the last 200 lines of the Codalus IDE log, redacted (`SecretRedactor`, the home folder as `~`), behind a check box that is on for problems; a feature request attaches only the version and OS. **Open in Browser** opens a new issue on `stavroskasidis/codalus-ide`, prefilled through the issue forms' query parameters (`template`, `labels`, `title` and each field's id), for the user to read and submit; the IDE sends nothing. A link is capped at 8,000 characters: logs that don't fit are saved to `<logs>/feedback/codalus-log-<time>.txt`, shown in the file manager and named in the `logs` field; text that still doesn't fit is cut with a marker, and **Copy** has the whole report as Markdown. The feature form has no version or OS fields, so one line goes under "The problem"; the issue templates are unchanged; the command sweep cancels the dialog instead of skipping the commands. `IssueReport` (`Codalus.Workbench/Feedback`), `FeedbackViewModel`, `FeedbackView`. Tests: `IssueReportTests` (10), `FeedbackDialogTests` (6, the browser faked).

**OS integration** (item 4): [ADR 0084](../adr/0084-os-integration.md). Two choices, off until chosen and removable, in **Tools → Options → Environment → System Integration** and on the first-run setup's Tools step: **Open Folders from the File Manager** and **Open Solutions and Project Files** (`.sln`, `.slnx`, `.slnf`, `.csproj`, `.vbproj`, `.fsproj`). `OsIntegration` has one class per OS, each root injectable; the registration itself is the source of truth (read back as Registered, Partial, Another copy's, Not registered or Unavailable), and only entries Codalus wrote (by name or a `codalus-os-integration` marker) are ever removed.
- *Windows:* `Directory\shell` and `Directory\Background\shell\Codalus.OpenFolder` with the app's icon, and a ProgID per type in `OpenWithProgids`, all under `HKCU\Software\Classes`; a type's default is never set (Windows may ask once, as the UI and guide say).
- *macOS:* a Finder Quick Action in `~/Library/Services`; the bundle's `Info.plist` declares the types (rank Alternate, imported UTIs), and the opt-in makes Codalus the default through LaunchServices, recording each type's previous app to give it back when turned off.
- *Linux:* a Nautilus script, a Dolphin service menu, Nemo actions and a Thunar action (when its `uca.xml` exists); for the types a MIME package, a hidden desktop entry and `xdg-mime default` (or `mimeapps.list`), turned off by taking only Codalus's entry off those lines. The packaged `codalus.desktop` declares nothing new.
`codalus <folder|solution>` (and macOS's open-document events) now go to a running window that has nothing open (`openPath` over the single-instance pipe); `--new-window` applies to folders and solutions too. Tests: `OsIntegrationTests` (11: a temporary `HKCU\Software\Codalus.Tests\<guid>` key, temporary Services, bundle and XDG folders, stand-in LaunchServices and tools) and `OsIntegrationShellTests` (4). The shell test fixture gives every headless test a Linux layout under its own user data folder, so no shell test can register anything on the machine.

**0.7.0's validation findings** (item 6, added to `develop` on 2026-10-26):
- *`GitServiceTests`' Update Branch on git 2.51:* reproduced on Windows (git 2.51.0): `fetch <remote> <ref>:refs/heads/<branch>` that git refuses as a non-fast-forward no longer moves the remote-tracking branch. A refused update now fetches the branch alone again, which moves it through the remote's refspec.
- *WSL's layout and font failures:* WSL's Ubuntu has no DejaVu fonts; fontconfig gives Noto Sans for the UI and nothing Avalonia takes for `monospace`.
  - The editor's font list (Cascadia Mono, Consolas, Menlo, DejaVu Sans Mono, then `monospace`, which Avalonia doesn't resolve as a generic) fell back to the proportional UI font: eight spaces were 27 px, so a data tip's header couldn't sit over its expression (`DataTipLayoutTests`). Every monospace list adds Noto Sans Mono, Ubuntu Mono, Liberation Mono and Noto Mono (newer Fedora has no DejaVu either).
  - Menu rows took the UI font's line box: 25 px with Noto Sans (`MenuEntryTests`). Every menu's rows are 24 px.
  - `GitShellTests`' timeout was a real bug: the mirror's files are 755 (copied from NTFS), and saving through a temporary file and a rename made the file 644, so git saw a mode change and the staged hunk left the file modified. Writes keep the replaced file's Unix mode (`LocalFileSystemTests`).
  - `IntelliSensePopupTests`: with WSL's taller monospace font the call's line sat near the view's bottom, where the list rightly opens above; the test scrolls the line up first. `PackageVerifiedBadgeTests` allows a pixel of layout rounding (a trimmed ID of 319.4 px laid out as 320).
  - `ProductNameTests` failed on WSL alone: `eng/wsl-test.sh`'s mirror had an empty git index; it now indexes the synced files.
- *`OlderSdkTests`' message on Windows:* the build host named the SDK that stands in by its `Version`, which drops a preview's suffix (11.0.100 for 11.0.100-rc.3.26522.148). The messages name the SDK's folder.
- *`eng/get-runtimes.sh` under Git Bash:* System32 goes first on `dotnet-install.ps1`'s `PATH`; the whole matrix installed on Windows, and `Codalus.TargetFrameworks.Tests` passed there (59, 12 skipped).
- *Harbor Light's Output bold green:* green and bright green both fell short of 4.5:1 on a light background and were raised to the same edge. Bold and bright ANSI colors need 1.4 times the theme's contrast (High Contrast's palette has one green for both).
- *SDK 2.1 in the build host on WSL* (not in item 6, found in this validation): `DesignTimeBuilder` called `ProjectInstance.FromFile(string, ProjectOptions)`, MSBuild 16's, in the method every design-time build runs, so with the 2.1 SDKs' MSBuild 15.9 the build failed with `MissingMethodException`. The two ways of loading a project without its missing imports are methods of their own, MSBuild 15's through `Project`.
- *Not reproduced* (passed on a second run, as in 0.7.0's validation): `DataHostTests`, `BuildDepthIntegrationTests`, `DotNetTestRunControlTests`, `XamlPreviewerTests`, and `PackageIntegrationTests` leaving out three Roslyn 5.9.0 packages of WSL's NuGet cache (it fails the same on `develop`: that machine's cache).
