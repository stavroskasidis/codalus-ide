# M30b checkpoint: Codalus on .NET 11

Date: 2026-10-16, on the .NET 11 SDK's second release candidate (11.0.100-rc.2.26504.105, runtime 11.0.0-rc.2.26504.105). The maintainer moved M30b forward the same day: Codalus moves to .NET 11 on the release candidate rather than at GA, and nightlies and stables ship on it. It is finished on the GA SDK in November 2026 (see Gaps). Decisions: [ADR 0025](../adr/0025-hosts-and-the-users-sdk.md) (amended), D22. The checklist it followed and corrected: [Moving to a new .NET release](../release/dotnet-upgrade.md).

## Done

**Codalus on .NET 11**
- **The SDK:** `global.json` takes 11.0.100-rc.2.26504.105 with `allowPrerelease` (RC2 was on the feeds; it replaces RC1 everywhere M30a pinned it). `Directory.Build.props` targets `net11.0`: the shell, the workbench, every host, the built-in plugins, the tests, the benchmarks, the website and `eng/Codalus.Release`.
- **What stays on .NET 10:** the plugin API (`Codalus.Plugins.Abstractions`, `Codalus.Plugins.Testing`), the `codalus-plugin` template and the sample plugins target `net10.0`. Plugins built with the .NET 10 SDK keep building and load into the .NET 11 plugin host (the plugin tests load the `net10.0` sample plugins). The startup hook and previewer agent stay `netstandard2.0`, the EF agent `net8.0`.
- **Native AOT:** the shell publishes with the same 26 trim and AOT warnings as on .NET 10 (Dock's templates and two compiled XAML closures of the third-party themes), and no new ones.
  - **Found:** the .NET 11 SDK publishes Native AOT without a full Build by default ("optimized publish", `_PublishOptimizedBuildAlternative`). It runs `PrepareResources` before `ResolveReferences`, where Avalonia adds its resources, so they weren't embedded: no compiled XAML, a binary 20 MB smaller with no warnings at all, and a shell that failed at start ("No precompiled XAML found for Codalus.Shell.App"). The shell sets `UseOptimizedPublish=false`. Caught by starting the published shell (the cold-start benchmark), not by the publish, which succeeded.
- **The new SDK's analyzers** (`latest-recommended`, warnings as errors): CA2027 (17 places: `Task.WhenAny` with `Task.Delay`, now `WaitAsync` with `ConfigureAwaitOptions.SuppressThrowing`), CA2026 (`JsonElement.Parse`), and CA2016, CA1830, CA1860 and CA2263 for new overloads.
- **Paths with a framework:** the shell copies the hosts and plugins from `bin/<configuration>/$(TargetFramework)`, and the tests find built hosts, plugins and servers through `Codalus.Tests.RepoBuild.TargetFramework` (assembly metadata, `tests/Shared/RepoBuild.cs`) instead of a hard-coded `net10.0`.

**Dependencies on .NET 11**
- **Roslyn 5.12.0-1.26504.105**, the RC2 SDK's compiler (RC1's was 5.11), in the language host, C# Interactive and the T4 host, with the Visual Basic packages. Before GA it is only on the .NET team's public `dotnet-tools` feed: `NuGet.config` (new) maps `Microsoft.CodeAnalysis.*` to nuget.org and that feed, everything else to nuget.org.
  - **C# 15** shows no false errors: unions, collection expression arguments and labeled `break`/`continue`.
  - **The .NET 11 SDK's Razor generator** loads in the language host as it is; the stand-in from an older SDK (M30a) stays for the next .NET's previews.
  - **Found:** that generator writes a component's class and `@code` blocks to `<File>_razor.decl.g.cs`, and the render tree to `<File>_razor.g.cs`. The Razor mapping knew one generated document per file, so Go to Definition landed in generated code (two `RazorTests` failed). A mapping now holds both documents (`RazorPart`); requests run on the one that has the position, and ranges, diagnostics and references map back from either.
- **Moved to their .NET 11 RC2 versions** (they ship with the runtime): `System.Security.Cryptography.Pkcs` (the data host's pin) and `System.Drawing.Common` (the benchmark harness), 11.0.0-rc.2.26504.105. Roslyn's own `System.Composition` and friends come in at 10.0.10, and `System.Data.DataSetExtensions` is no longer a dependency.
- **Checked, unchanged:** Avalonia 12.1.3, Dock 12.1.0.7, AvaloniaEdit and TextMate 12.0.0 / 2.0.3 (the published shell starts, the headless UI suite passes), MSBuild 17.11.48 and NuGet 6.11.2 (compile-time only; the build host uses the SDK's), Microsoft.Build.Locator 1.11.2, xunit.v3 3.2.2 with Microsoft.Testing.Platform, the HangDump extension, Coverlet 10.1.0 (its console tool rolls forward onto .NET 11), Velopack 1.2.161, ClrMD 4.1 (dumps of .NET 11 programs open), TraceEvent 3.2.8. Newer patch releases exist for Avalonia (12.1.4) and Dock (12.1.0.9); nothing on .NET 11 needed them.
- **Tools:** `vpk` is a `net10.0` tool without a roll-forward policy; `eng/package.sh` runs it with `DOTNET_ROLL_FORWARD=Major`, since the packaging jobs install only the .NET 11 SDK.

**The hosts and the user's SDK** (ADR 0025, amended)
- **Option 2 stands:** every host keeps `RollForward=Major`. A private runtime would let a machine with only .NET 10 start the hosts, but couldn't run a newer SDK's MSBuild, and would add tens of MB to every package.
- On the release candidate the hosts' `runtimeconfig.json` asks for 11.0.0-rc.2.26504.105: that, a later release candidate, or GA starts them.
- **Older SDKs:** the build host on .NET 11 loads the MSBuild of an older SDK that `global.json` pins (`DotnetVersionsTests` pins 10.0.401 here); the newer-SDK roll-forward now only acts for a .NET 12 preview.
- **Help → Check Environment** (`EnvironmentCheck`): with SDKs whose runtimes are all older than the hosts' (`dotnet --list-runtimes`, ordered as the host rolls forward), the .NET SDK is a mismatch, and the plan installs the .NET 11 SDK (`dotnet-install --channel 11.0`; winget's `Microsoft.DotNet.SDK.Preview` while on a release candidate).
- **FsAutoComplete** (the F# language server, the user's tool) loads the SDK's MSBuild too. Its `net10.0` build rolls forward to release runtimes only, so the .NET 11 RC SDK's MSBuild failed to load in it (the F# shell test). With an SDK newer than its build installed, it starts with `DOTNET_ROLL_FORWARD=LatestMajor` and `DOTNET_ROLL_FORWARD_TO_PRERELEASE=1`.
- **Packages:** the `.deb` and `.rpm` recommend `dotnet-sdk-11.0` and say the hosts need .NET 11; the winget manifest depends on `Microsoft.DotNet.SDK.Preview`; the AUR package's optional dependency says .NET 11 runs the hosts. The remote server stays self-contained (its own trimmed runtime), so remote machines need nothing new.

**Fixtures**
- `samples/BuildAndRun` (Hello, Greetings) and `samples/Debugging` (Debuggee, Partner, GeneratorTarget) target `net11.0`.
- `samples/Testing`: Calculator and MultiTargetTests multi-target `net10.0;net11.0` (they were `net9.0;net10.0`).
- `samples/LanguageFeatures`: App targets `net11.0` and has `CSharp15.cs` (a union with an exhaustive switch, collection expression arguments, labeled `break` and `continue`); `CSharp_15_features_show_no_false_errors` checks it through a full pass and a hover.
- `samples/Net11` pins RC2 and stays, as the roadmap allows (its tests still cover the newer-SDK path).
- **The target framework matrix** (M33): the `Net100` row gets C# 15's collection expression arguments as the feature its C# 14 rejects (`error CS9327` checked with the RC2 compiler), and `eng/get-runtimes.sh` installs .NET 10's runtime (10.0.13), which no longer comes with the SDK.

**Markup host schemas and SDK status:** the RC2 host (`hostfxr`) reads the same `global.json` keys as .NET 10's (`version`, `rollForward`, `allowPrerelease`, `paths`, `errorMessage`), which the schema has; no new `runtimeconfig.json` or MSBuild properties were found. `net11.0` and C# 15 were already in the lists (M30a). The .NET SDKs panel shows .NET 11 (STS) as a preview; Microsoft hasn't announced its end of support.

**CI and validation:** the setup action installs the RC2 SDK by version (setup-dotnet reads `global.json`'s `latestFeature` as the channel's newest release, which .NET 11 doesn't have before GA) and, for test jobs, the .NET 10 SDK in place of .NET 9 and the separate .NET 11 SDK. `eng/validate.sh` checks for `global.json`'s SDK with `dotnet --version` (its version-band check broke on a prerelease version) and installs .NET 10's SDK for its runtimes.

**Docs and website:** ADR 0025's amendment; the upgrade checklist corrected from this run; the user guide (prerequisites, the SDKs section and its gaps, Older .NET versions, the debugger's .NET 11 gap, troubleshooting); README, CHANGELOG, `docs/plugins.md` (its changelog: no API change); THIRD-PARTY-NOTICES; the website's Download page, Home and Features.

## Gaps

- **GA:** at .NET 11's release (November 2026): the GA SDK in `global.json` without `allowPrerelease`, `samples/Net11/global.json`, the setup action back to `global-json-file`, Roslyn from nuget.org (and `dotnet-tools` out of `NuGet.config`), `System.Security.Cryptography.Pkcs` and `System.Drawing.Common` at 11.0.0, `Microsoft.DotNet.SDK.11` in the winget manifest and the Check Environment plan, .NET 11's end of support in `DotnetSupport`, the "release candidate" wording in the user guide, README and website. `TODO(issue)`
- **Debugging .NET 11 programs:** netcoredbg 3.2.0 debugs them (breakpoints, stepping, locals, exceptions, dumps), but gives their stack frames an empty `moduleId`, so exception module conditions can't apply. `Module_conditions_skip_exceptions_thrown_in_other_modules` skips with that reason while the adapter reports no module, and the user guide lists it. GitHub wasn't reachable from here to look for a newer release. `TODO(issue)`: a netcoredbg release that supports .NET 11.
- **The target framework matrix wasn't run** on .NET 11: `eng/get-runtimes.sh` ran out of disk in this container. The support tables in `docs/user-guide/dotnet-versions.md` are still M33's, measured with the .NET 10 SDK; the manual `compat.yml` run on three OSes updates them. `TODO(issue)`
- **Windows and macOS** weren't validated here (the maintainer's choice: CI's runners validate them). The Windows-only paths (winget's preview SDK, the Velopack Setup.exe with the RC runtime) and the Mac's `eng/validate.sh` install of RC2 need CI's results.
- **The benchmark fixtures** (`FixtureGen`'s Solution50 and Tests5k) still target `net10.0`, like the budgets measured on them; moving them would change what ADR 0002's numbers measure. `TODO(issue)`: decide with the next reference-hardware run.
