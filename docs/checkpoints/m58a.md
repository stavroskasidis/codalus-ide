# M58a checkpoint: the Codalus debugger's gaps closed

Date: 2026-11-11. The first part of the roadmap's [M58](../roadmap.md#m58--the-codalus-debugger-by-default), D49 ([ADR 0094](../adr/0094-the-codalus-debugger-by-default.md)): the adapter's features, with `debug.adapter` still `netcoredbg` by default. M58b follows with remote targets, the adapter bundle and the default. One pull request.

Everything here is the Codalus debugger's (`codalus-debughost --clr-dap`), and the .NET Framework adapter's where the session is shared. Under netcoredbg nothing changes: each feature is offered by a capability of the stopped thread's adapter.

## Done

**Breakpoints applied by the debugger.** Hit counts, filters, dependent breakpoints and logpoints are sent with `setBreakpoints` and applied in the adapter: a hit that doesn't count never becomes a stop. The filter's parser and the hit condition's test moved to `Codalus.Debugging`, shared with the IDE's handling for the other adapters.

**Stepping.**
- **Set Next Statement** (`Ctrl+Shift+F10`, the editor's context menu, as in the classic IDE; the Debug menu is at its length limit): DAP's `gotoTargets` and `goto` on `ICorDebugILFrame::SetIP`, with the runtime's reason when a line can't be chosen.
- **Step Into Specific** (`Shift+Alt+F11`, the editor's context menu): the current line's calls, read from the method's IL (`IlCalls`), picked in the palette.
- **Returned values**: back in the caller after a step out, the call's value is Locals' first row and `$ReturnValue`.
- **Freeze and Thaw** in the Threads window.

**Expressions.**
- The adapter's evaluator reads `new`, generic methods, `$exception`, `$ReturnValue` and object IDs (`$1`; Make Object ID and Delete Object ID in the variable windows).
- `[DebuggerTypeProxy]`, Results View and Raw View are built by the adapter. The five collections the shell shows through its own views keep them.
- What the evaluator doesn't read is compiled: the adapter asks the client (`codalus/compileExpression`), the C# language host compiles the expression where the frame is stopped (`ExpressionCompilerFeature`: lambdas, LINQ, extension methods, the rest of C#; private members; `VisualBasicExpressionCompiler` for Visual Basic documents), and the adapter loads the assembly into the program and calls it.
- Three defects of the evaluator found on the way are fixed: an empty string couldn't be read, a primitive passed as `object` ended the program, and a PDB still at its build location was taken for a Windows PDB.

**The machine's side.** The Disassembly, Registers and Memory windows (Debug → Windows), on DAP's `disassemble`, `readMemory` and `writeMemory` and our `codalus/registers`, with steps of one instruction. x64 is decoded by Iced, arm64 by a decoder of our own (`Arm64Disassembler`, 1,531 rows checked against what llvm-mc prints).

**Symbols.** Options › Debugging has the symbol settings (`debug.symbols.*`): symbol paths, Microsoft's and NuGet.org's servers and the user's own, a cache, and the modules to look up. Every server is off until it is turned on. **Load Symbols** in the Modules window asks for one module. `Codalus.Debugging.Symbols` finds PDBs by their SSQP keys; the tests use a mock HTTP server.

**Edit and Continue.** An edit applied while the program is stopped is made with the frames' active statements (`codalus/activeStatements`):
- the frame stopped in an edited method goes on in its new version at the statement Roslyn mapped, with its locals; a step from it starts again there, and the stopped frame is shown at its statement's new place at once;
- a calling frame goes on in the new version at the statement after its call, when that follows straight (no branch between, in the old code and the new); otherwise it runs on in its old version until it reaches a mapped statement;
- an edit of the statement a calling frame waits in is Roslyn's rude edit.

**Several startup projects.** A stop in one program pauses the others whose debugger says it can, which is the Codalus debugger (`CompoundDebugAdapter.BreakAllOnStop`, `supportsBreakWithOtherPrograms`, the setting `debug.breakAllProcesses`, on by default): they go on with it, during a step too.

**Windows PDBs.** `WindowsPdbSymbols` reads them through Mono.Cecil's managed reader, on every OS: next to the module, where it was built, or from a symbol path or server. The fixture is a real one, the Windows PDB a package of the test platform ships.

**The smoke test.** `debug.codalus`, after the Codalus debugger's other steps: a hit count the debugger counted, Set Next Statement, a lambda in an expression, the Memory, Registers and Disassembly windows (`smoke-test-debug-disassembly-codalus.png`), then on `HotReload.slnx` an edit that moves the stopped frame into its new code. The command sweep's reasons for the two new commands name it.

**Docs.** The user guide's Debugging page (the Codalus debugger's sections on expressions, the machine's side, symbols and Edit and Continue; the limits list split into the Codalus debugger's and netcoredbg's) and .NET Framework page; the Features page; `docs/protocol.md`; ADR 0094's "What M58a built" and the amended ADRs' headers; `THIRD-PARTY-NOTICES.md` (Iced, Mono.Cecil); the roadmap.

## Moved to M58b

- **32-bit .NET Framework processes.** ICorDebug debugs processes of its own bitness, so they need a 32-bit adapter process, and a 32-bit .NET runtime to run it is rarely installed. The self-contained adapter bundle M58b builds for remote targets is the same thing for `win-x86`, as an on-demand component beside the `osx-x64` one.
