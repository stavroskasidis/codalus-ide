# M35 checkpoint: Visual Basic

Date: 2026-10-15. Visual Basic projects get rich editing, at the same level as C#. Since the MVP they only loaded, built and ran. ADR 0066 records the decisions.

## Done

**The language service** (the C# host, `codalus-lshost`):
- **Packages:** Roslyn's VB Workspaces and Features (`Microsoft.CodeAnalysis.VisualBasic.Workspaces`, `.Features`) at the C# packages' version (5.9.0).
- **Projects:**
  - The workbench's C# descriptor serves the `vb` language and takes the build host's `VB` projects (`LanguageServiceDescriptor.MoreProjectLanguages`, `TakesProjects`), so C# and VB projects share one workspace.
  - `ProjectLoader` parses `vbc` arguments with `VisualBasicCommandLineParser`. `VisualBasicArguments` repairs MSBuild's `/"` in the quoted `/define:` on Unix (`CONFIG=/"Debug/"`). Without it, the compilation didn't load and emitting it threw.
- **Analyzers, code fixes and refactorings:** kept per language (`ProviderCatalog`), and loaded from the VB Features assembly for VB projects.
- **Features:**
  - **Fenced as `vb`:** completion and Quick Info descriptions.
  - **Across C# and VB:** definitions. A metadata symbol from the other language's project maps back to source (`SymbolFinder.FindSourceDefinitionAsync`). References and rename are Roslyn's.
  - **Syntax-based features in VB** (`VisualBasicStructure`): document symbols, folding and test candidates. Test names include the project's root namespace, as the compiler writes them.
  - **Signature help** for VB invocations, `New` and attributes, in VB's syntax (`Sub List(Of T).Insert(index As Integer, item As T)`).
- **Pretty listing** (`VisualBasicPrettyListing`, on-type formatting on `\n` and `>`):
  - Enter after a block's first line adds the missing end (`End If`, `Next`, `End While`, `Loop`, `End Select`, `End Try`, `End With`, `End Using`, `End SyncLock`, `End Sub`/`Function`/`Operator`/`Property`/`Get`/`Set`/`Event`, `End Class`/`Module`/`Structure`/`Interface`/`Enum`/`Namespace`, multi-line lambdas), indented like the block.
  - Enter fixes the casing of the keywords on the line it ends.
  - `>` closing an XML literal's start tag adds its end tag.

**The shell:**
- **Editor:** the editor sends Enter to on-type formatting as `\n` (it was `\r\n` on Windows), and keeps the caret before text an edit inserts at it.
- **Snippets:** `Editor/Snippets/vb.json` has 28 snippets (types, members, every block, `#Region`, `Sub Main`, an xUnit `<Fact>`).
- **Item templates:** Class, Module, Interface, Structure, Enum and Code File for VB projects (`ItemTemplates`, `Languages = ["VB"]`).
- **Property pages:** a `.vbproj` gets `ProjectPropertyPages.VisualBasic`. That's C#'s pages, with VB's options (Option Explicit, Strict, Infer, Compare, the VB language version) instead of C#'s language settings, "Remove integer overflow checks", comma-separated constants, and no unsafe code or warning level.
- **New Project** (the templates plugin): lists every language's templates (`dotnet new list --type project`). It asks the language when a template has several, with C# first, and passes `--language` to `dotnet new` and to the framework question.

**Fixture:** `samples/VisualBasic`, with `VbConsole` (uses both libraries), `VbLibrary` (XML literals, documentation comments), `CsLibrary` (C#) and `VbTests` (xUnit).

**Tests:**
- **`VisualBasicLanguageTests`** (LanguageServices.Host, 8), on the real build and language hosts:
  - completion of VB keywords and a C# library's members;
  - Quick Info in VB syntax;
  - definitions VB→C# and VB→VB, and references from the tests project;
  - live `BC30456`, then fixed;
  - classification with XML literals;
  - rename across projects, formatting, outline, folding and signature help;
  - `IDE0005` with its fix;
  - pretty listing: `End Sub` with keyword casing, `End If`, nothing for a closed block, `</note>`;
  - test candidates in the root namespace.
- **`VisualBasicShellTests`** (Shell, 1): `Program.vb` is `vb` and gets the C# host's live errors; VB snippets; VB property pages; VB item templates only in VB projects.
- **`VisualBasicDebuggingTests`** (Debugging, 1), on the real netcoredbg: a breakpoint in a `.vb` file binds and stops, locals and a VB object's properties show, member paths and C# operators evaluate, and stepping goes into the C# library.
- **`TemplatesPluginTests`** (Plugins): the language question, and a new VB console project (`.vbproj`, `Program.vb`).
- **Smoke step `vb.editing`:** `Program.vb` in the real app completes the C# library's members, and Enter after `If … Then` adds `End If` (screenshot `visual-basic.png`).

## Gaps

- **VB expressions in Watch, Immediate and breakpoint conditions:** netcoredbg reads C#. The user guide gives the C# equivalents. Translating simple VB expressions is a candidate. `TODO(issue)`
- **Automatic line continuation:** removing `_` isn't offered. VB's implicit continuation makes it rarely needed. `TODO(issue)`
- **Project-level imports:** `Import` items have no page. They're edited in the project file. `TODO(issue)`
- **`My`:** only what the compiler generates for `MyType`. The WinForms application framework is a non-goal.
- **VB-specific semantic token types:** not added. Roslyn's VB classifications map onto the existing legend (keywords, types, XML literal parts).
