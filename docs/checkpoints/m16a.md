# M16a checkpoint: Razor and Blazor

Date: 2026-10-10. Decision: [ADR 0023](../adr/0023-razor-through-the-source-generator.md). M16b (HTML, CSS and JavaScript services on Node, D3) and M16c (Blazor WebAssembly, browser debugging) follow.

## Built

**C# language host** (`Razor/RazorMapping.cs`, `Razor/RazorFeatures.cs`)
- **Documents:** open `.razor` and `.cshtml` files update their additional documents, so the Razor source generator runs on unsaved text. They never go to Miscellaneous Files.
- **Mapping:**
  - the generated document of a Razor file is found by its `#pragma checksum`;
  - `#line` mappings become pairs of spans, as long as the two texts agree;
  - positions map into the generated C#, and ranges back to the Razor file;
  - locations in Razor-generated code, anywhere, move to the Razor file (`RazorLocations`), including references.
- **Features in C#:** completion (edit ranges mapped, the resolved edit mapped, additional edits dropped), hover, signature help, Go to Definition, highlights and references.
- **Diagnostics:** for an open Razor file, from its generated document. In the solution-wide pass, every Razor-generated document's diagnostics go to its Razor file.
- **Markup:**
  - completion of components (the project's and the referenced component libraries'), HTML elements, a component's `[Parameter]` properties (minus those already set), Blazor directive attributes, and directives at a line start, merged with C# where the generator sees an implicit expression;
  - hover and Go to Definition on component tags and parameters.

**Shell:** the C# language service also serves `razor` (`ShellHost.RazorLanguageId`).

**Fixture:** `samples/Blazor`: a Blazor Web App with interactive server rendering (`dotnet new blazor --empty`), with:
- `Counter.razor`, which has a `@code` block and an event handler;
- `Greeting.razor`, a component with parameters and documentation, used by `Home.razor`;
- `launchBrowser` off, so tests don't open browsers.

**Tests**
- **Language host:** `RazorTests` (3):
  - C# in Razor: hover with its range, definition from an event handler, mapped completion and resolve, references;
  - markup completion of components, parameters and directives;
  - component and parameter hover and definition, and a C# error reported at its Razor line, then cleared.
- **Headless UI:** `BlazorTests`:
  - a Razor file served by the C# host: hover, and an error at the right line, then cleared;
  - the Blazor app run with Hot Reload: a markup edit of `Counter.razor`, saved, changes the rendered `/counter` page.
- **Smoke test:** step `blazor.razor` (M16): Razor hover and component completion; the app runs and renders `/counter`.

**Docs:** ADR 0023, the protocol (Razor documents), [User guide: Web development](../user-guide/web.md) (Razor and Blazor), the roadmap (M16 split into M16a, M16b and M16c; M15c deferred).

## Found along the way

- **The window title overlapped the menu on Windows.** Avalonia 12 draws its own title text when the client area extends into the title bar; it landed on File and Edit. A style hides it (`WindowDrawnDecorations … PART_TitleTextPanel`). Screenshots now render the visual root, decorations included.
- **The View menu ran off the screen**, with every tool window and two duplicates. Menus gained submenus (`MenuItemRule.ForSubmenu`, the in-window and the macOS menu bar). View keeps the main windows, View → Other Windows has the rest alphabetically, and Debug → Windows has the debugger's.
- **A race in the M15a web test:** it read the response window before the posted update.
