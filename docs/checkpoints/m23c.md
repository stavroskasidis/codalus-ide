# M23c checkpoint: the UI's strings in the catalogues

Date: 2026-10-13. M23's third part, after the localization foundation ([m23b](m23b.md)). No new ADR.

## Done

**Every view's text** is in `Localization/en.json` (`{l:T key}`): 1,207 strings in 79 views were moved by `eng/localize-xaml.py`, including the three new views from M19b and M21a. The literal check now holds every view at no hard-coded strings, and it decodes XML entities first, so `&gt;` doesn't count as text.

**Messages built in code**: 360 calls in the shell and the workbench, converted by `eng/localize-cs.py`, which rewrites a call's string arguments only when they're plain or interpolated literals:
- the message of `Notifications.Info`, `Warning` and `Error` (not their buttons, whose text the code compares);
- `StatusBar.ShowMessage`;
- `Dialogs.ConfirmAsync` (title, message and button) and `Dialogs.InputAsync` (title and prompt).

Interpolated strings become `Localizer.Format` patterns that keep their format specifiers (`{0:N0}`). The catalogue test reads each call's English into `en.json` and fails on a key used with two different texts. The catalogue holds about 2,400 strings.

**Plugins' own text** (API 0.2.9, additive): `context.Localize(key, english[, args])` reads the same `daedalus-plugin.nls.<locale>.json` files as the manifest's placeholders. The shell gives its hosts the display language in `DAEDALUS_DISPLAY_LOCALE`; a pseudo-language accents the text there too. The Welcome plugin's Start page, tips and keyboard-scheme picker use it (its manifest asks for `^0.2.9`).

**Checked** with `--locale qps-ploc`: the menus, the toolbar, tool windows and their titles, the Start page and the Error List's controls are translatable. What stays English is text built by view models.

**Tests**:
- `LocalizationCatalogTests` covers the views, the code's messages and the generated keys.
- `PluginLocalizationTests` covers a plugin's text in English, German with a regional fallback, and the pseudo-language.
