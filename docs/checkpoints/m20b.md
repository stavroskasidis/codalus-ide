# M20b checkpoint: the Mono debugger adapter

Date: 2026-10-15. The second and last part of M20. With it, M20 is done. F5 on a .NET MAUI project debugs the app on an Android device or emulator, an iOS simulator or Mac Catalyst, through a Mono soft-debugger adapter of our own. ADR 0065 records the decisions.

## Done

**Research** (before writing code; the full report is in the session's notes):
- **The runtimes:** Mono is the default on mobile in .NET 8 to 10. .NET 11 makes CoreCLR the default, without an open debugger for it on mobile, so the release notes say to opt back into Mono for debugging.
- **The client library:** debugger-libs is MIT and maintained, and dotnet/android, vscode-mono-debug and DotRush build it from source. Its NuGet packages are `net40` only and unlisted.
- **Licenses:** the DAP library others use is proprietary, and mlaunch is closed.
- **How each platform connects:** the Android SDK's own debugger properties, confirmed in the installed pack; and the iOS and Mac Catalyst environment variables.

**The protocol client:** `Mono.Debugger.Soft`, vendored in `src/ThirdParty/Mono.Debugger.Soft` from debugger-libs at commit e7fbb713, with its LICENSE and a README of where it comes from and what changed. It's built without Mono.Cecil, and `PdbChecksum` replaces its one Microsoft.FileFormats type, so it adds no packages. It's built without our analyzers.

**The adapter** (`codalus-debughost --mono-dap`; `Codalus.Debugging.Host/Mono`):
- **`DapServer`:** DAP's server side, with `Content-Length` framing, requests answered in order, events from any thread, and our source-generated contracts.
- **`MonoDebugSession`:**
  - **Connecting:** `connect` retries the handshake until it succeeds or the timeout passes (adb's forward accepts before the app listens); `listen` waits for the runtime to connect.
  - **Breakpoints:** bound in the loaded types of the file (`GetTypesForSourceFile` by file name, then matched by full path), and in types loaded later (a type-load request filtered by the files). A line without code moves to the next line with code in the same method. `breakpoint` events report a binding.
  - **Exceptions:** all, or unhandled.
  - **Running:** resuming after `configurationDone` when the runtime started suspended; continue; pause; step over, into and out (line steps without static constructors, `[DebuggerHidden]` or `[DebuggerStepThrough]`). With Just My Code, a step into code without source steps out.
  - **Threads and stacks:** frames without source are shown dimmed.
  - **Variables:** locals and arguments with `this`; fields (auto-properties' backing fields under the property's name, other compiler fields hidden); other properties through their getters (with breakpoints off, single-threaded); arrays (the first 100); structs.
  - **Evaluation:** names, `this`, members, static fields, member paths and array indexes.
  - **Exception info:** the type and its `_message`.
  - **Ending:** disconnect ends the program (or detaches), and the program's end sends `exited` and `terminated`.
  - **Refused, with a message:** function breakpoints, changing values, other expressions.
- **`MonoDebugArguments`** (in `Codalus.Debugging`): mode, address, port, timeout, Just My Code.

**F5 on a mobile project** (`ShellHost.Mobile.DebugOnDeviceAsync`):
- **The port:** a free local one.
- **The run:** the platform's debugger properties are added (`MobileTargets.DebugArguments`, `MobileService.DebugPlan`):
  - Android: `AndroidAttachDebugger=true`, `AndroidSdbTargetPort`/`AndroidSdbHostPort`;
  - iOS simulators: `MtouchDebug` and `MlaunchAdditionalArguments` with `__XAMARIN_DEBUG_PORT__`/`_HOSTS__`;
  - Mac Catalyst: `_BundlerDebug` and `OpenArguments` with the same variables.
- **The session:** `DebugService.LaunchAdapterAsync` with the adapter and its arguments. A run that fails before the app is up cancels the session and says why.
- **iPhones and iPads** say debugging isn't available yet.

**Fixture:** `samples/Debugging/MonoDebuggee`, a .NET 8 console app on the desktop Mono runtime pack, self-contained for this machine: a loop, a method call, auto-properties, a list, a record, a caught exception. .NET 9 and later ship no desktop Mono, and .NET 8's agent is the mobile one.

**Tests:**
- **`MonoDebuggerTests`** (Debugging, 3), the real adapter process against the real Mono runtime:
  - **The protocol:** the capabilities; a launch sent before the app starts (retrying); a breakpoint in a type not loaded yet that binds and stops; the stack, locals, `this`, auto-properties, a record's properties; evaluation of member paths and an unknown name; a step over; an exception stop with its type and message; the end.
  - **Through `DebugService`,** the path F5 takes: a breakpoint from the store, verified, stopping; evaluation; Stop ending the program.
  - **No runtime:** the launch fails after its timeout with what happened.
- **`MobileTests`** (Workbench): the debug arguments for Android, a simulator and Mac Catalyst, none for an iPhone; the debug plan with the device and the port.

## Results

Linux (this container): the solution builds without warnings.
- **Tests:** `MonoDebuggerTests` 3/3 and `MobileTests` 7/7.
- **Other suites:** the whole Debugging project 108 passed, 5 skipped. `MobileShellTests`, `UxPassTests` and `LocalizationCatalogTests` pass 43/43. The website tests pass 11/11, and the export is clean.
- **By hand:** a .NET 8 app on the desktop Mono runtime answered the soft debugger's handshake through `MONO_ENV_OPTIONS`. The Android pack's `_Run` target has the debugger properties.

**Needs validating:**
- **The Mac:** iOS simulator and Mac Catalyst sessions (the `MlaunchAdditionalArguments` and `OpenArguments` properties), and `MonoDebuggerTests` on macOS.
- **Windows and Linux with KVM:** an Android emulator session from F5.
- **Windows:** `MonoDebuggerTests`.
