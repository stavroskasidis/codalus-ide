# M19b checkpoint: the Live Visual Tree and Live Property Explorer

Date: 2026-10-13. Decision: [ADR 0052](../adr/0052-live-visual-tree.md) (the live tools for running Avalonia apps). M19a ([m19a](m19a.md)) built XAML editing and the previewer.

## Built

**The live agent** (`src/DaedalusStudio.Previewer.Agent/LiveAgent.cs`).
- The previewer's startup hook has a second mode, `DAEDALUS_LIVE_AGENT_PORT`/`_TOKEN`, for a running app. Like the previewer's mode, it uses reflection only.
- Commands: `windows`; `tree` (logical or visual, with ids that stay while the elements live); `props`; `set`; `highlight`; `pick`; `path`.
  - `props` gives each property's value, type and source through Avalonia's `GetDiagnostic`.
  - `set` parses the value as XAML would for the property's type (enums, numbers, `Parse` methods, brushes) and sets it as a local value.
  - `highlight` draws an adorner over the element.
  - `pick` turns on pick mode: the next click is taken, not passed to the app, and sent as an event.
  - `path` gives the logical path the IDE resolves in the XAML.
- It touches nothing of Avalonia until the app has an `Application`. It connects before `Main`, and the first touch of `Dispatcher.UIThread` from its thread bound Avalonia's UI thread to it, so the app failed to start (found by the end-to-end test).

**The IDE's side.**
- `LiveSession` (workbench `Previewer/`) listens on loopback with a token, gives the app its environment, and turns requests and events into typed calls.
- `RunService.ProgramPlan` adds the agent to an Avalonia app's plan for Run and Debug alike. A project counts as an Avalonia app when it references an Avalonia package. The setting `debug.liveVisualTree` is on by default.
- **Debug → Windows → Live Visual Tree** (`LiveTreeViewModel`, `ShellHost.LiveTree.cs`):
  - the logical tree by default, the visual tree on request;
  - the selection highlighted in the app;
  - Select Element in the App;
  - Go to XAML: the file whose `x:Class` is the window's class, then the element's tag through the C# host's `daedalus/xaml/logicalTree` and `PreviewSelection`;
  - it refreshes until the app's first window is up.
- **Debug → Windows → Live Property Explorer** (`LivePropertiesViewModel`): the selected element's properties with values and sources (local ones in bold), a filter, and editing.

**Templates**: New Project offers **Install the Avalonia templates…** (`dotnet new install Avalonia.Templates`) when none is installed, then shows the list again.

**Docs**: the user guide's new [Avalonia page](../user-guide/avalonia.md) covers XAML editing, the previewer, the live tools and templates (M19a had none). CLAUDE.md and ADR 0052 are updated too.

## Tests

- `LiveAgentTests` (headless, in-process):
  - windows, and the logical against the visual tree;
  - properties and their sources;
  - set values: a thickness, a brush, an enum; read-only properties refused;
  - the highlight's adorner in and out, the path;
  - pick mode: a click selects without clicking the button;
  - parsing.
- `LiveSessionTests`, against a stand-in agent on a real socket:
  - the environment, startup hooks chained;
  - a stranger refused;
  - typed replies, errors and the picked event;
  - the app's exit.
- `LiveTreeShellTests` runs `samples/Avalonia` from the IDE (Ctrl+F5):
  - the agent joins and the tree shows `MainWindow` with `IncrementButton`;
  - the visual tree adds templates' parts and the logical tree has none;
  - the button's properties show; a margin set in the explorer comes back local;
  - Go to XAML selects the button's tag in `MainWindow.axaml`.
