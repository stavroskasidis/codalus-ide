# M47 checkpoint: Code Search

Date: 2026-10-17. Phase 11's last feature milestone before M34g, on top of M46 (its branch, not merged yet). The scope: the roadmap's [M47](../roadmap.md#m47--code-search), from the maintainer's comparison of Go To All with Visual Studio's Code Search window; there is no design in `docs/design/` for it, so the window follows Visual Studio's and the theme tokens of [ui-guidelines.md](../ui-guidelines.md) and [ADR 0077](../adr/0077-theme-families.md). Decisions: [ADR 0078](../adr/0078-code-search-and-its-persistent-index.md) (the window, the sources and ranking, the persistent index, incomplete results, the preview, plugins).

## Done

**The window** (`CodeSearchViewModel`, `CodeSearchView`, `ShellHost.CodeSearch.cs`):
- One floating, resizable window over the documents, centered under the title row (the main window's `CodeSearchLayer`), opened by `Ctrl+T` and `Ctrl+,` (Go To All, `workbench.action.gotoAll`) on **Code Search** and by `Ctrl+Q` and the title row's search box (`workbench.action.featureSearch`) on **Feature Search**. New: Go To File, Type, Member and Text (`workbench.action.gotoFile`, `gotoType`, `gotoMember`, `gotoText`; `Ctrl+1` then `F`, `T`, `M` or `X`; Edit → Go To) open it on that chip. The editor's single-line selection is the query.
- Two tabs; above them, buttons to show the preview, pin (keep open after a result opens), dock and close. Dragged by its tabs' row (kept inside the main window), resized from its corner; its size, offset, pin, preview and docked state are in the shell's `state.json` (`ShellState.CodeSearch`). A click outside closes it unless it's pinned (then clicks go through).
- **Docked**, the same view fills the **Code Search** tool window (View → Other Windows, bottom by default), and the dock button floats it again; `Esc` there gives the focus back to the document. Only the view that shows hosts the preview's editor.

**Code Search:**
- **Sources**, in batches so the fast ones show at once: the persistent index and the solution's files (by name, or by the relative path when the query has a `/`); then `workspace/symbol` of every running language service that offers it (`LanguageService.RunningClients`, new: the C# host, which adds source-generated declarations, F#, the LSP bridge's servers), de-duplicated with the index; then, with **External items**, the referenced assemblies' types (`codalus/externalSymbols`, new); then text through Find in Files' engine (its file filter and `MatchLine`, plain text, any case, open documents as edited), for three characters or more (any length after `x:`), up to **Code Search → Text Results** lines (100; 0 turns them off).
- **Chips and prefixes**: all, files (f:), types (t:), members (m:), text (x:), as pills under the box (`Alt` and the letter, `Alt+A` for all); the prefixes typed first do the same and show as their chip; choosing a chip removes a typed prefix. `:42` and `:42:7` (or `:42,7`) give "Go to line 42" of the active document.
- **Matching and ranking** (`Codalus.Workbench.Search`): `CodeSearchQuery` parses; names match with the palette's `FuzzyMatcher` (camel-case humps and word starts, then any characters in order), whose new `TryScore` scores without allocating; `CodeSearchRanker` adds a weight per kind (types, files, members; external items lower; text last), up to 15 for the eight most recently opened files, 6 for the active document's project and 4 for the active document; ties go to the shorter name. Results are interleaved by score (Visual Studio's default) or grouped by kind under headers (**Code Search → Result Grouping**).
- **Two-line results**: the icon (the symbol's kind, the file's type) and the name with the matched characters bold, then where it is ("in Circle (project Lib)", "in Lib (project Lib)" for a type's namespace, a file's folder, "in Program.cs (project App)" for a text line, the namespace and assembly for an external type), and the file name on the right (`Shapes.cs:24` for a text line). Screen readers hear the name, the kind, where it is and the file.
- **The preview**: below the results, behind a splitter, a `CodeEditorView` on the result's file, on the model an editor tab of the file shares (held like the Windows Forms designer holds one, `AcquireModelAsync`), so it has the language services' colors, completion and diagnostics. It scrolls to the result and selects the match without taking the focus from the box; the same result again (a refresh, a later batch) leaves the caret where the user moved it. Edits are the document's: undo, `Ctrl+S` saves (the main window's key bindings don't act on the active document from there), the status line shows "Ln 12, Col 5" (and "Sel 6") and the title says "(modified, Ctrl+S saves)". When the preview moves on or the window closes, an unsaved edit opens the document in a tab before the model is let go. Images and binary files show no preview; external items open decompiled on Enter but aren't previewed.
- **Opening**: `Enter` or a double-click opens the result (a text match selected, as Find Results does) and closes the window unless it's pinned; `Ctrl+Enter` keeps it open; Navigate Back returns.
- **Scope**: entire solution, current project or current document, a filter of files for every source; it and External items are settings (**Code Search → Scope**, **Include External Items**), changed from the window too.
- **Incomplete results**: a notice while a solution opens (its saved index answers meanwhile) or while a trusted solution with C# or Visual Basic projects loads or hasn't been indexed in this session; when that ends, the open window runs its query again (and when the index or the projects change).

**The persistent index** (Go To All's, deferred since M12):
- Roslyn's persistent storage first, as M12 planned: it is internal to Roslyn's workspaces (no public API) and lives in the host's process, which a search before the host loads can't use (ADR 0078).
- **`codalus/symbolIndex`** (new, `SymbolIndexFeature`): every type and member declared in each document (or in the given ones), from syntax through `SyntaxGenerator` (C# and Visual Basic), with the container, the project's name and the name's position (after attributes and doc comments). No compilation, so it answers as soon as the projects are in the workspace.
- **`CodeSearchIndex`** (Workbench): an immutable snapshot whose distinct names are scored once each, in parallel chunks, before their declarations take their kind's weight and their file's boost (once per file) and a queue keeps the best; kept in `.codalus/state/<solution>/code-search-index.json` through `SolutionStateStore` (ADR 0070), with each document's file length and time written, and the solution's file list. Reading it leaves out documents whose files changed or are gone; another format version is ignored.
- **Freshness**: read in the background as a solution opens (before its projects evaluate; the saved file list stands in until they do); the whole solution asked for once the C# host has its projects and whenever it reports ready; an edit to a C# or Visual Basic document re-indexes it 800 ms after typing stops. Saved after each full refresh and, when edits changed it, as the solution closes and the window state is saved. Logged as `[code search] Indexed … symbols in … documents in … ms.`
- **External items** (`codalus/externalSymbols`, new): public types of the referenced assemblies matching the query (substring or camel-case humps), the exact name first, read once per assembly per session, in `codalus-metadata:` documents.

**Feature Search**: the title row search's list moved here and lost files and symbols (they're Code Search's): commands (palette-visible and enabled, with their key bindings and icons), settings (title or key; opens Options filtered to it) and **Options pages** (new: a category opens Options on it). `Enter` runs or opens; the window closes unless pinned.

**Keyboard and accessibility**: everything from the keyboard (the box keeps the focus while `Up`, `Down`, `PageUp`, `PageDown` move; `Tab` cycles the box, the tabs, the chips, the scope, External items, the results and the preview; `Enter`, `Ctrl+Enter`, `Esc`, `Alt`+letter); accessible names on every control, chips announced with their state, live regions for the status and the preview's line; tokens only (`Shell.Overlay`, `Shell.Selection`, `Shell.Accent`, `Shell.Border`, `Shell.Info`, `Shell.Match`), so it follows every family and High contrast; every text trims with a tooltip or wraps at the tool window's 280 px.

**Plugins**: no API change (none existed for search providers, as the roadmap's scope assumed): a plugin's LSP language appears through `workspace/symbol`, its commands and settings in Feature Search ([plugins.md](../plugins.md#m47-no-api-version-change)).

**Smoke test:** step `navigation.codeSearch` (M47, after `editor.findInFiles`): the index built and saved next to BuildAndRun; `Greet` finds the Greeter type ("in Greetings (project Greetings)", `Greeter.cs`), its Greet member and files; the preview shows Greeter.cs with "Greeter" selected (`smoke-test-code-search.png`, the website's `code-search.png`); `f:` lists only files and `m:` only members; Enter opens Greeter.cs and closes the window; Feature Search lists Build Solution with its key (`smoke-test-feature-search.png`).

**Docs and site:** the user guide's [Code Search](../user-guide/editing.md#code-search) section and its navigation table, the shortcuts in the [user guide's index](../user-guide/README.md), the search box in [settings](../user-guide/settings.md); [protocol.md](../protocol.md#extensions) (the two methods, and who asks `workspace/symbol`); [plugins.md](../plugins.md); ADR 0078; the website's Features page (a "Code Search" screenshot in the tour, the navigation list) and Home's C# card; the README; `CHANGELOG.md`; the roadmap's status row, M47's status, the parity row, the deferred-work table (the index left it) and the change log.

## Gaps

- **The other platforms:** the window, the preview's keys (`Cmd+S`, `Cmd+Enter` on macOS) and the smoke step need their runs on Windows and macOS. The exit criterion (Code Search finds files, types, members and text in a large solution with a live preview, on Windows, Linux and macOS) is met on Linux, on samples and the generated 96-project index, not on the maintainer's solution. `TODO(issue)`
- **External items** are types only, opened at their file's start (members of external types, and positions before decompiling). `TODO(issue)`
- **The budget in the running app:** the harness has no `code-search` scenario; the 100 ms budget is checked on a generated index of the 96-project shape in a unit test. `TODO(issue)`
- **A search-provider API** for plugins (results of a plugin's own kind) waits for a plugin that needs it; it would start as a proposed API. `TODO(issue)`
- **XAML names** reach Code Search through the C# host's source-generated fields (Avalonia's name generator) while it runs, not from the index (which is syntax only, without generated sources).
- **Closed files changed outside the IDE** (a checkout) are re-indexed at the next full refresh (the C# host's next ready), not as they change.
- **The preview's editor** takes the main window's editor key bindings only for `Esc` and `Ctrl+S`; commands that act on the active editor (Find, Go to Definition) act on the active document's, not the preview's. Visual Studio's preview has the same split.
