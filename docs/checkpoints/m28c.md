# M28c checkpoint: AI actions on existing surfaces

Date: 2026-10-14. Builds on M28a and M28b ([m28a](m28a.md), [m28b](m28b.md), [ADR 0062](../adr/0062-ai-providers-and-data-boundaries.md)).

## Built

Each action is a command the user runs, so each use is opted into. They are enabled by the `aiReady` context key (AI on, with a provider and a model) and live in `ShellHost.AiActions.cs`. Each gathers its own context through `AiContext`; the first four ask in the AI Chat (`SendInChatAsync`, shared with the chat's own question) and open it.

| Command | Where | Sends |
|---|---|---|
| Ask AI About This Problem | editor context menu | the diagnostic at the caret (or the nearest), and 15 numbered lines around it |
| Write Tests with AI | editor context menu, with a selection | the selection; the solution's test platform when it has test projects |
| Explain the Exception with AI | Debug menu, stopped on an exception | type, message, stack, inner exceptions; the code around the selected frame |
| Explain the Test Failure with AI | Test menu | the selected failed test's messages, expected/actual, stack; its source |
| Draft Commit Message with AI | Git menu | the staged diffs (up to 24,000 characters), streamed into Git Changes' message; secret or ignored files by name only |

Also fixed: the chat's **Problems** attachment asked the diagnostics store by URI, which keys by path, so it never attached anything.

## Tests
