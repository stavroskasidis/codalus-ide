# M34h (part 2): colored output, toolbar icon colors, Toolbox icons, real theme previews

Date: 2026-10-18. Four findings from the maintainer's review of the M34 gallery (D25), on every theme and OS. The other M34h findings (AI Chat, Add New Item, NuGet, Keyboard Shortcuts, the preview dialog, the Windows Forms designer, the gallery's themes) and the shared button and input style are separate work. No new ADR: the choices follow ADR 0019 (look and feel) and [ADR 0077](../adr/0077-theme-families.md) (the families' tokens); the rules are in [`ui-guidelines.md`](../ui-guidelines.md).

### Colored output

- **What a line says** (`Workbench/Output/OutputClassifier`, source-generated regexes, no allocation): errors are MSBuild's and the compilers' `error XX1234:` and `file: error:`, `error:`/`fatal:`, the console logger's `fail:` and `crit:`, *Build failed* / *Build FAILED*, `1 Error(s)`, *N failed*, an exception's line, its stack frames and `---` markers, the test runners' *Failed!*, `Failed Name`, `[FAIL]`, *Test Run Failed*; warnings are `warning XX1234:`, `warning:`, `warn:`, `N Warning(s)`, `[SKIP]`; successes are *Build succeeded* (with warnings too), `0 Error(s)`, *Passed!*, *Test Run Successful*, *N succeeded, 0 failed*. The whole line takes the color; lines are classified only as the editor draws them (the visible ones), the first 1,024 characters of a long one.
- **Standard error:** `OutputChannel.AppendError`/`AppendErrorLine` record the ranges that came from it (through trims and clears, merged when adjacent) and a `TextAppended` event says so; the run service's program output, External Tools and the debugger's `stderr` output use them. A line that says it's a warning or a success keeps that color over standard error's red.
- **ANSI** (`Workbench/Output/AnsiDecoder`): SGR's 16 colors, 256 colors and 24-bit colors, bold, italic, underline; every other sequence (cursor moves, erasing, OSC titles, links and the terminal logger's progress, private modes, character sets) is dropped; a sequence split across appends is joined. A process's color is the terminal's palette for the theme's kind, raised to 4.5:1 (7:1 in High Contrast) against the editor's background, keeping its hue (VS Code's minimum contrast).
- **Cost:** appends are decoded on the thread that appends them (escapes stripped, runs found) and applied in one batch per dispatcher pass, as before; plain text keeps no runs. A trim's re-read is decoded off the UI thread too.

### Toolbar icon colors

Solution Explorer's icons were all blue. Each now takes its family's color through an `accent-*` class where its kind's color would be the wrong family. The other tool windows' toolbars were walked (every `Button.toolbar` icon and its color, per view):

| Toolbar | Before | Now |
|---|---|---|
| Solution Explorer | 6 icons, 1 color | 4 colors: blue, green, purple, tan, blue (Switch Views, purple, shows only in a folder) |
| Live Visual Tree | 4 icons, 1 color | 3: Show Visual Tree purple, refresh green |
| XAML Previewer | 4 icons, 1 color | 2: refresh green, zoom and fit blue |
| Work Items | 3 icons, 1 color | 3: mention in the commit message the Git family's, refresh green |
| Git Changes | fetch, pull, push and sync blue | the Git family's orange, as the same commands in the menus |
| NuGet (Package Manager) | 2 icons, 1 color | 2: refresh green (its view is another fix's: only the kind's color changed) |
| Find Results, Terminal, Coverage Results, Dotnet Tools, Worktrees, Entity Framework, Database Explorer, Pull Requests | 2–3 colors, or one button | unchanged, apart from refresh |

**Refresh is green everywhere** (it was blue): the refresh family, as Visual Studio colors it, so a toolbar's refresh stands apart from its blue navigation and window commands.

### Toolbox icons

`ToolboxViewModel.IconFor` maps each framework type to its icon: Fluent icons (42 added to `fluent-icons.txt`: button, check box, multiselect, calendar with a clock, text and text-box glyphs, list and tree lists, the gallery view, a password box, the sliders, tabs, layout cells, menus, a status bar, a toolbar, the data link, a timer, print and preview, the folder list…) and three 16 × 16 stroke drawings in `IconSet` where Fluent has no picture: the combo box, the progress bar and the group box. Colors: inputs, lists and menus blue, containers purple, pictures and progress green, data and notifications yellow, the error provider red, folders tan. A derived or vendor's control takes the icon of the known control its name ends with (`RadButton`, `OrderRichTextBox`), else `control-generic` (a window) or `control-component` (a gear); the Pointer is the cursor. Fluent's icons are MIT and already in `THIRD-PARTY-NOTICES.md`.

### Real theme previews

`ThemePictureView` is now a 356 × 200 sample of the shell's chrome shown at half size: the title row (the menu, the search box, the solution's name on its chip), the toolbar with Start, a document tab with the family's indicator and corners, the editor with line numbers, the current line and C# in the variant's syntax colors (`EditorTheme.For`), the gutter, Solution Explorer with its caption (Graphite's marker, the bold title), classic file icons and the selection, the status bar (Ember's dot). It sits in a `ThemeVariantScope`, so every `{DynamicResource}` is that variant's token. A scope whose variant is the one it inherits looked nothing up again once in a window (the chosen card drew no fills, M45's note); the view passes through another variant when it's attached, so it resolves. The preview is decorative (`AccessibilityView="Raw"`); the polish checks' text measurements don't apply to its scaled text, so they skip it, and its colors are the themes' own token pairs.
