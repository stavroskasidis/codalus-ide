# M21b checkpoint: containers, Dev Containers, reconnecting, test environments and plugin placement

Date: 2026-10-13. Decisions:
- [ADR 0053](../adr/0053-dev-containers.md): containers as remote targets, and a C# subset of Dev Containers;
- [ADR 0054](../adr/0054-reconnect-and-resync.md): a server that outlives its link, and reconnecting;
- [ADR 0055](../adr/0055-remote-test-environments.md): `testenvironments.json`;
- [ADR 0057](../adr/0057-plugin-placement.md): `runsOn`, where plugins run.

With M21a ([m21a](m21a.md)) this completes M21.

## Built

**Containers as remote windows** (ADR 0053):
- **Attaching.** `container:<name>` is a remote target through `docker exec` or Podman's, with the container tool of the settings (`containers.tool`, including one inside WSL). The server bundle is copied in and started there as over SSH.
- **Opening.** The remote picker lists the running containers, `codalus --remote container:<name>` opens one, and the Containers window has **Open in Remote Window**.
- **Dev Containers.** `DevContainers` (workbench `Containers/`) reads `.devcontainer/devcontainer.json`: `image`, `build`, `workspaceFolder`, `containerEnv`, `runArgs`, `mounts`, `remoteUser` and `postCreateCommand`, with the `${localWorkspaceFolder}`-style variables.
  - **Reopen in Container** (offered when such a folder opens, and `remote.reopenInContainer`) builds or pulls the image and runs the container, labelled and named after the folder, with the folder mounted at the workspace.
  - It runs `postCreateCommand` once, then opens a remote window there. Opening the folder again reuses the container.
  - Features, Docker Compose and the other lifecycle commands are listed as not done yet.

**Reconnecting** (ADR 0054):
- **The stream.** `ResumableStream` (`Codalus.Rpc/Multiplexing`) is under the multiplexer on both sides. Bytes have offsets, are kept until acknowledged, and are resent from the peer's offset when a new link attaches.
- **The server.** Remote targets start `codalus-server --relay <session> --grace <s>`:
  - the relay connects to the session's daemon over a Unix socket (`$XDG_RUNTIME_DIR/codalus/`, else `/tmp/codalus-<user>/`, mode 0700), starting it detached when there's none, and copies bytes;
  - the daemon runs the server on a `ResumableStream`, ignores SIGHUP, and ends after its grace period without a link.
- **The client.** `RemoteConnection` notices a dropped link: the transport exits, a read fails, or a ping goes unanswered for 20 s. It starts the transport again, checks the daemon's instance, and resumes. It backs off for up to 15 minutes.
- **The window.** The status bar shows *reconnecting…*, and the Remote log says how long the link was down. Transports are killed without their process tree, because the relay's child is the daemon.

**Remote test environments** (ADR 0055):
- **The file.** `testenvironments.json` lists `wsl`, `docker` and `ssh` environments, found next to the solution or above it, up to the repository.
- **Picking one.** The Test Explorer's toolbar gets a target environment list.
- **Running.** Tests are built here and run there with `dotnet test <assembly>`, filtered by name and run from `/tmp`. Their TRX results come back onto the tree (`TestService.ApplyImported`, `BeginExternalRun` for running and cancel).
  - WSL goes through `/mnt/<drive>`.
  - Docker uses a kept container of the image (or Dockerfile) with the solution mounted.
  - SSH copies each project's output to `~/.codalus-tests/`.

**Plugin placement** (ADR 0057):
- **The field.** `"runsOn": "ui" | "workspace"` in the manifest (plugin API 0.3.0). Workspace plugins get host groups of their own (`workspace:…`).
- **In a remote window**, their host runs on the server through the session's launcher. The bundle carries the plugin host and each workspace plugin's folder, and `RemoteSession.ToBundlePath` maps the plugins' folders.
- **The .NET test plugin** is a workspace plugin: the Test Explorer works in remote windows, its runners on the server.

## Tests

- **Rpc** `ResumableStreamTests` (3): resend after a drop with nothing twice; 3 MB across two drops; closing ends the reader.
- **Workbench**:
  - `RemoteServerTests`:
    - a running container is a remote target the server is copied into (Podman with the local Ubuntu image, in WSL on Windows);
    - a dropped link reconnects in under 5 s, with a process's channel and waiting requests intact;
    - a killed daemon ends the session;
    - the relay on the WSL (Windows) or fake-ssh (Linux) stand-in reconnects to the same daemon;
    - plugin folders map into the bundle.
  - `DevContainerTests`: the parser and variables, and a real dev container brought up and reused.
  - `TestEnvironmentTests`: parsing and problems, the filter's escaping, container paths, finding the file, and samples/Testing's xUnit project built here and run in the stand-in (WSL, fake ssh) with passed, failed and skipped results back.
- **Plugins** `ManifestValidationTests`: `runsOn` values and host groups.
- **Headless UI**:
  - `RemoteShellTests`: the remote window reconnects after a dropped link and its terminal goes on; the Test Explorer in a remote window runs tests in a plugin host started through the server, retired on disconnect.
  - `TestEnvironmentShellTests`: the Test Explorer's environment list runs tests in WSL.
- **Smoke** `remote.session`: the resumable stand-in reconnects within the 5 s budget, a save goes through after the reconnect, and the C# host goes on.

**Validation**: Windows and Linux (WSL) green, including a full suite of each on the renamed tree. The Mac was asked to validate the snapshot with the smoke test (pending at the time of writing).
