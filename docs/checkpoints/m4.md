# M4 checkpoint: build and run

Date: 2026-10-09. Plan and decisions: [ADR 0006](../adr/0006-build-and-run.md).

## Built
- **Build host** ([project-protocol.md](../project-protocol.md)): `build/run` builds, rebuilds or cleans the solution file or one project with the active configuration, restoring first the way `msbuild -restore` does. All work runs in MSBuild's out-of-process worker nodes (one per core, no node reuse), with a fresh project collection per build. A logger streams `build/output` lines in MSBuild's format and structured `build/diagnostic` notifications. `build/cancel` stops a build. Design-time builds in flight pause for a build and resume after it. `project/runInfo` evaluates the SDK's `RunCommand`/`RunArguments`/`RunWorkingDirectory` for the active configuration and target framework.
- **Workbench**: `BuildService` (one build at a time, the Build output channel, the last build's diagnostics) and `RunService` (startup project, launch profiles from `launchSettings.json`, programs with their own "Run: name" output channel, Stop). `LaunchSettings`/`LaunchPlanner` handle `Project` and `Executable` profiles: arguments, working directory, environment, `applicationUrl` as `ASPNETCORE_URLS`, `launchBrowser`.
- **Shell**:
  - Build and Debug menus, and Build/Rebuild/Clean in the Solution Explorer's context menu.
  - Ctrl+Shift+B, Ctrl+Break, Ctrl+F5 and Shift+F5.
  - Save All before a build (`build.saveAllBeforeBuild`).
  - Build progress and result in the status bar; the Error List opens on a failed build.
  - The Error List merges build and IntelliSense diagnostics, with a Source column and filter; a diagnostic both report is shown once.
  - Set as Startup Project: the startup project is bold in the explorer and remembered per solution. The status bar's startup item picks the launch profile, or stops the running program.
  - `run.externalConsole` (Windows) runs console apps in a console window of their own.
- **Fixes on the way**:
  - Evaluation progress could arrive out of order (a "1/2" after "2/2 done"), leaving a solution "loading" forever. Progress is now counted and queued together.
  - Three shell UI tests raced asynchronous focus and a project-file update. They failed on the M3b CI run (Windows and Linux) and now wait for the state they check.
- **Tests**: host integration tests cover build, a compile error, clean, cancellation, one build at a time, run info, launch profiles, exit codes and untrusted solutions. There are unit tests for launch settings and planning, and a headless UI test drives the Error List flow and Ctrl+F5. Fixture: `samples/BuildAndRun`.

## Deviations and gaps
- No fast up-to-date check: every build runs MSBuild's own incremental targets (a no-op build of a small solution takes a few seconds, mostly node startup and restore). `TODO(issue)`.
- Programs run with output in the Output window and no standard input (input ends immediately), except Windows console apps with `run.externalConsole`. `TODO(issue)`: integrated terminal (post-MVP).
- Launch profiles: only `Project` and `Executable`. `IISExpress`, `Docker` and `WSL` are refused with a message, and `$(MSBuild)` property substitution in profiles is not supported (only `%ENV%` expansion). `TODO(issue)`.
- Build diagnostics are not drawn as squiggles. The language service's squiggles already cover compiler errors; build-only errors (MSBuild, analyzers that run only in builds) appear in the Error List only.
- Programs keep running when the shell exits; there is no "stop on exit" setting yet.
