# M17c checkpoint: publishing

Date: 2026-10-11. Decisions: [ADR 0042](../adr/0042-container-tooling-and-publishing.md). This completes M17, after [m17a](m17a.md) and [m17b](m17b.md).

## Built

**Publish profiles** (`Workbench/Publishing/PublishProfiles.cs`): `Properties/PublishProfiles/*.pubxml` read and written as plain XML (unknown properties kept, as other IDEs write them): folder or container image; configuration, target framework, runtime identifier, self-contained, single-file, trimmed, ReadyToRun, Native AOT; the folder; the container registry, repository and tag. A profile says what it lacks (a RID for self-contained, single-file, trimmed, R2R and AOT; no single-file with AOT; a repository for an image).

**Publishing in the build host**: `BuildTargets.Publish` (`Publish`) and `PublishContainer` (`Publish;PublishContainer`), run as builds with `PublishProfile`, `_IsPublishing=true` and the profile's configuration (`BuildService.BuildAsync` with properties), so restore sees the profile's RID and trim and AOT warnings arrive in the Error List. A container image goes to the local engine (`LocalRegistry` Docker or Podman, from the container engine setting) or the registry named.

**The Publish page** (`ShellHost.Publishing.cs`, Build → Publish…, a project's context menu): the profiles, New Profile, the fields above, Save and Publish; a folder profile is made when there is none; the result says where the app went, and a notification offers to open the folder.

## Tests

- **Workbench** `PublishProfilesTests`: a Visual Studio-style folder profile read, edited and written with its unknown properties kept; a container profile; what a profile lacks; a publish's properties.
- **Projects** `PublishTests`: a folder profile publishes a single-file app for this machine's runtime; a container profile publishes an image to the local engine (with an engine; the image is removed).
- **Headless UI** `PublishShellTests`: the page makes a folder profile, says what single-file lacks, and publishes.
- **Smoke** `publish.folder`: the page (`smoke-test-publish.png`) publishes a single-file app.

## Deviations and gaps

- Self-contained, trimmed, ReadyToRun and Native AOT publishing are offered and passed to the SDK, but the tests publish framework-dependent single-file only (the others download runtime packs or need the platform's native toolchain); trim and AOT warnings reach the Error List as build warnings. `TODO(issue)`: a Native AOT publish in the release pipeline's tests.
- Cloud targets (Azure, AWS, Google Cloud) are plugins, not core (roadmap); none is built in.
- Registry sign-in is the user's (`docker login`); the page doesn't manage credentials.
