# M63 checkpoint: services under the debugger, compose and Aspire

Date: 2026-11-13. The roadmap's [M63](../roadmap.md#m63--services-under-the-debugger-compose-and-aspire), D55 ([ADR 0102](../adr/0102-services-under-the-debugger.md)): D55's four questions settled at plan time as recommended. One pull request.

## Done

**Compose in fast mode** (`Workbench/Containers/ComposeApp.cs`, `ComposeYaml.cs`, `Shell/ShellHost.Compose.cs`), on by default (`containers.fastMode`, D55):
- The compose app is read as compose runs it (`compose config --format json`), else from its files (podman-compose has no JSON), with a reader of compose's block YAML of our own (no reflection: the Native AOT shell takes it).
- Each .NET service is found by its label `dev.codalus.project`, else the one project of the solution (or on disk) in its Dockerfile's folder; a `.dcproj`'s `DockerServiceName` is the startup service. A Dockerfile without a `base` stage, and every service that isn't .NET, runs as the compose file says.
- The IDE's override, `.codalus/state/<solution>/compose.override.yml` (D55: never committed, rewritten on each run), builds only the `base` stage as `<app>-<service>:dev`, mounts the project's Debug build at `/app` (static web assets too) and starts `dotnet /app/App.dll`, or idles for the debugger. **Show the IDE's Override** (the Containers window's toolbar, the compose file's menu, Debug → Other Debug Targets) opens it read-only.
- **Rerun:** Compose Up again restarts only the services whose build changed, and so does any build while the app runs. No image build for a code change.

**Debug every service.** Debug Compose (the command id `containers.composeDebug`, "Debug Compose Service…" before) starts every service and launches each .NET service's program under the debugger in its container (M58b's bundle copied in), as programs of one independent session (M14c), so start-up breakpoints hit; paths map back to the solution. One service alone, the others left running: **Restart / Stop / Debug / Detach Compose Service…** (Debug → Other Debug Targets). `DebugService.EndProgramAsync` and `RestartProgramAsync`, `CompoundDebugAdapter.EndPartAsync` end or restart one program of a session.

**Hot Reload in containers.** A fast-mode service runs this machine's build: its remote adapter is marked `LocalBuild`, so Apply Code Changes (a save, Continue) reaches every debugged service under the Codalus debugger, in its container (M55).

**Aspire.** A session holds 64 programs (`CompoundDebugAdapter.MaxParts`, 8 before): every project of an AppHost runs under the debugger. The Aspire window's new **Debug** debugs one project resource alone under Ctrl+F5 (the debugger attaches to the program the IDE started for it); Restart was there already, and a project restarted under F5 joins the session again.

**Fixture:** `samples/Containers/Compose` (`Compose.slnx`): `front` calls `back` by its service name, each with a Dockerfile with a `base` stage; `idle` (`mcr.microsoft.com/dotnet/runtime-deps:10.0`) isn't .NET.

**Docs.** [ADR 0102](../adr/0102-services-under-the-debugger.md) (with D55's table) and amendments to ADR 0042 and 0043; the user guide's [Containers](../user-guide/containers.md) (Compose rewritten: fast mode, the override, every service debugged, one service alone; Aspire's Debug; limits); the Features and Home pages; the fixture's README. No new `CODALUS_*` variable; new UI text in `en.json`; the four per-service commands have the command sweep's skip reasons (they run the user's engine).
