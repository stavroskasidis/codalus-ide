# M22a checkpoint: plugin API 1.0 and its contribution points

Date: 2026-10-13. Decision: [ADR 0058](../adr/0058-plugin-api-1-0.md), plugin API 1.0 and its contribution points.

M22 is split in three:
- **M22a** (this one): the frozen API and the contribution points that were missing.
- **M22b**: the development experience: the `dotnet new` template, `Codalus.Plugins.Testing`, a development instance with a debugger attached, the API reference, and SVG icons for icon themes.
- **M22c**: distribution: the NuGet marketplace and plugin browser, auto-update, per-workspace enablement, bisect, signatures and declared permissions, the Components page with an offline layout, and plugin performance attribution.

## Built

**API 1.0** (`PluginApi.Version = "1.0.0"`):
- The proved proposed APIs are members of `IPluginContext`: `Tests`, `Workspace`, `Build`, `Debug` with visualizers, `Terminals`, `Hosting` and `Secrets`. Every built-in plugin and sample moved to them and to `^1.0.0`. `IProposedApi` is empty, kept for new proposals.
- The policy after 1.0 is ADR 0003's: minor releases add only, and deprecations use `[Obsolete(DiagnosticId = "CODALUS0001")]`.
- The public surface is `src/Codalus.Plugins.Abstractions/PublicAPI.txt`. `PublicApiTests` compares it with the assembly; `CODALUS_UPDATE_PUBLIC_API=1` rewrites it.

**Progress, and tasks in the status bar** (also the maintainer's request for a progress bar like the classic IDE's):
- `ProgressService` (workbench `Notifications/`) holds the running tasks.
- The status bar shows the newest task's text where "Ready" is, with a green bar (indeterminate when the work can't say how far it is), ✕ to cancel and … to list them all.
- Loading projects says *Loading project 29 of 96: <path>* (the build host now sends the project), and restores and builds are tasks.
- Plugins get `IWindow.WithProgressAsync`. The smoke step `build.solution` takes the screenshot `smoke-test-progress.png`.

**Appearance**:
- **Color themes** (`contributes.themes`): VS Code's theme files. `ThemeFiles` maps `colors` onto the shell's tokens and editor elements, and `tokenColors`/`semanticTokenColors` (scopes and selectors) onto token types. A theme applies over its `uiTheme` base, offered by `workbench.colorTheme`, with the user's color customizations on top (`[Label]`). Sample: `samples/plugins/MidnightTheme`.
- **File icon themes** (`contributes.iconThemes`): VS Code's icon theme files (`IconTheme` in `Theming/IconThemes.cs`), chosen by `workbench.iconTheme` (`default` is ours). Raster icons draw as `img:<path>` in the `Icon` control. SVG icons fall back to ours and are named in the log, because the shell never parses SVG at run time. Sample: `samples/plugins/BlockIcons`.

**Debuggers** (`contributes.debuggers`): a DAP adapter over stdio per launch configuration `type`. `.codalus/launch.json` configurations of that type (`FolderConfiguration` keeps each one's JSON, with variables expanded) start the adapter through `DebugService.LaunchAdapterAsync`, so the session uses the usual debugger windows.

**Declarative views (D2) and custom editors**:
- `ViewNode` trees (stack, text, button, text box, check box, dropdown, table, toolbar, separator) cross the protocol as `ViewNodeDto` and render with the shell's controls (`Controls/DeclarativeView.cs`). They fill tool windows of kind `view`.
- Events (`click`, `change`, `select`, `activate`) go back to the plugin. Input survives updates by element id.
- **Custom editors** (`contributes.customEditors`, `RegisterCustomEditor`) open matching files in such a view. `SetCustomEditorText` makes the document dirty and Save writes it. **Reopen With Text Editor** switches to text.
- Sample: `samples/plugins/TodoBoard`, a board for `*.todos.json` and a summary tool window.

**Platform providers**:
- **File systems** (`IFileSystems`): a plugin's scheme is mounted under `\\codalus-plugin.invalid\<scheme>` (Windows) or `/codalus-plugin/<scheme>` in the workbench's `FileSystems` (`PluginFileSystem`), like a remote's root. Errors map to not found, denied and failed. **Browse a Plugin's Files…** opens one in the editor.
- **Authentication** (`IAuthentication`, `contributes.authentication`): providers offer sessions and any plugin asks for one. The provider's plugin activates on `onAuthenticationRequest:<id>`. Another plugin's request asks the user's consent, once per plugin and provider in a session. The Accounts page lists each provider's sessions under Other sign-ins, with Sign Out.
- **Source control** (`ISourceControl`): a provider's groups of files, its commit box and its originals, in the Source Control Providers window (View → Other Windows), drawn as a declarative view. Opening a file compares it with the original. Git stays built in.
- HelloWorld has one of each: `MemoryFiles`, `MemoryAccounts`, `FolderScm`.

## Tests

- **Plugins**:
  - `PublicApiTests`: the baseline, and the deprecation diagnostic's id.
  - `PluginHostIntegrationTests`, through a real plugin host:
    - a task reports progress and is cancelled;
    - a plugin's file system is mounted, read, listed and written;
    - an authentication provider signs in, lists sessions, asks consent and signs out;
    - a source control provider shows its state, commits and gives originals.
  - `ManifestValidationTests`: `runsOn` and host groups.
- **Headless UI**:
  - `ProgressStatusTests`: a task's text, bar and cancel; loading projects and building as tasks.
  - `ThemeContributionTests`: the VS Code mapping, and Midnight offered, applied over its base and customized.
  - `IconThemeTests`: the icon theme mapping (names, extensions longest first, folders, SVG skipped), and the setting switching the file icons.
  - `ContributedDebuggerTests`: a launch configuration of a plugin's type runs under its adapter (the scripted DAP server, `codalus-lsp-conformance --dap`), which gets the configuration with its variables expanded and prints it to the Debug Console.
  - `DeclarativeViewTests`: TodoBoard's custom editor shows the view, its edits dirty the document, Save writes them, and the summary tool window follows.
  - `SourceControlProviderTests`: the window shows the provider's files, the commit box commits, and opening a file shows a diff.
- **Smoke**: `build.solution` shows the build as a task in the status bar (screenshot).

**Validation**: Windows green (the full suite). Linux (WSL): the file system and placement classes green (36 of 37, the WSL-only test skipped). The full Linux and Mac runs come with the push (CI runs all three).

## Not done

- **F1** (URIs for document identity) wasn't done before 1.0. Plugin file systems use mounted roots of this machine's path form, as remote windows do (ADR 0050). `TODO(issue)`: revisit if a provider needs URIs that don't map to paths.
- **Icon themes**: only raster icons draw; SVG conversion at install time comes in M22b.
- **Contributed debuggers**: launch only, no attach requests.
- **Webviews**: after 1.0, as a proposed API.
