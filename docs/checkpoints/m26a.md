# M26a checkpoint: project items, templates, folder mode and External Tools

Date: 2026-10-11. Decision: [ADR 0033](../adr/0033-project-items-templates-and-folder-mode.md). M26 is split (roadmap rule 5): M26a is the project system, M26b build depth (Batch Build, build settings, the fast up-to-date check, timings, binary logs, build events, custom tools and T4).

## Built

**Build host** (`items/*`, `fs/listTree`, `fs/changed`, `folder/*`, `templates/instantiate`; [project-protocol.md](../project-protocol.md#project-items-show-all-files-folder-mode-and-item-templates))
- **Item edits** (`ProjectManagement/ProjectItems.cs`): each edit is applied to the construction model, the project is evaluated again in memory, and the edit is adjusted until the evaluated items are what was asked:
  - metadata of a globbed file: an `Update` item, metadata as child elements, next to other updates of its type; existing metadata changed in place (attribute or element as written);
  - a new Build Action under a glob: `<Old Remove>` plus `<New Include>`, the metadata carried over; back to the glob's type, both go and the metadata becomes an `Update` again;
  - the minimal change: a value equal to what the project would evaluate to without its own definition removes the definition (an empty `CopyToOutputDirectory` counts as `Never`);
  - Exclude From Project: explicit `Include`/`Update` items go, then a `Remove` per type a glob still includes; a folder gets `Remove="Folder\**"` for `Compile`, `EmbeddedResource`, `None` (and `Content` with web SDK globs), as Visual Studio writes it; Include In Project removes them, or adds an `Include` when a wider `Remove` still excludes the file;
  - links (`<Compile Include="..\Shared\X.cs" Link="Folder\X.cs" />`) and Add Existing Item (copy, then include).
- **Moves between projects:** `fs/move` carries the source project's explicit items for a file (an `EmbeddedResource Include`, a `None Update` with `CopyToOutputDirectory`…) into the target project with the same edit, and drops them from the source (a copy keeps them).
- **Folder mode:** `solution/open` on a folder answers format `folder`, the folder as `path`, and the loaded projects (`.daedalus/folder.json`); `folder/discover`, `folder/setProjects`; builds of several projects go through a generated `.daedalus/folder.slnx`; the folder is watched even untrusted.
- **`templates/instantiate`:** `dotnet new <template> --project`, restoring the project first when a project-capability constraint needs its assets; the created files by a before/after comparison.

**Workbench**
- `ProjectItemService`; `SolutionInfo.Directory` (the workspace folder for every format; the shell's features that used the solution file's folder use it).
- `ItemTemplates` (the built-in set: class, interface, record, struct, enum, code file, global usings, text, JSON, app settings, XML, Markdown, resources with `ResXFileCodeGenerator`, text template with `TextTemplatingFileGenerator`, HTML, CSS, JavaScript, TypeScript; the filter by language and project kind; namespaces from the folder).
- `TemplateService`: `dotnet new list --type item --ignore-constraints` parsed by its dashed rule; installed packages (`dotnet new uninstall`) and updates (`update --check-only`); install, uninstall, Update All; Export Template (a project without `bin`, `obj`, `.vs`, `.daedalus` and `*.user`, or items with a `namespace` symbol bound to `msbuild:RootNamespace`), installed with `dotnet new install <folder>`.
- `FolderConfiguration`: `.daedalus/tasks.json` and `launch.json` (VS Code's shapes, JSONC), `${…}` variables, running a task (`process` or `shell`).
- `ExternalToolStore` and `ExternalToolRunner`: `externalTools.json`, `$(…)` macros.
- `SolutionTree`: Show All Files' excluded nodes and the folder view.

**Shell**
- **The Properties window** (`F4`, View → Properties): a property grid for the Solution Explorer's selection, with descriptions, bold project values, Add Metadata, and links (Project Properties, Configuration Manager, Include In Project).
- **The Solution Explorer:** Show All Files (toolbar; excluded files dimmed), Include and Exclude From Project, Add New Item (`Ctrl+Shift+A`), Add Existing Item (`Shift+Alt+A`) and As Link, drag and drop of linked files (moves the link; Ctrl copies) and between projects, files dropped from the file manager copied in; in folder mode the folder view and the solution view (Switch Views), Load Project, Load All Projects, Unload Project, Open Project.
- **Add New Item** (a document): search, categories, the templates for the project's language and kind ("Show templates for every kind of project"), a preview, the name.
- **Export Template** and **Tools → Templates** (the template manager).
- **Folder mode:** File → Open Folder (`Ctrl+Shift+Alt+O`); `daedalus <folder>` opens its only solution, or the folder; recent folders; Build runs the default build task (else builds the loaded projects); Build → Run Task and Configure Tasks; Debug → Select Launch Configuration and Configure Launch, the configurations in the toolbar's startup list, F5 and Ctrl+F5 run them (`project` or `program`, with `preLaunchTask`, `args`, `cwd`, `env`).
- **External Tools** (Tools → External Tools): add, order, edit and run tools; each is a command `externalTools.run.<id>` in the Tools menu and the palette (key bindings work).
- **Plugin API 0.2.8** (additive): `contributes.propertyProviders` (Properties window rows from a command) and `contributes.externalToolMacros`.
