# M20c checkpoint: iOS simulators and Mac Catalyst

Date: 2026-10-14. Builds on [M20a](m20a.md). Decision: [ADR 0064](../adr/0064-mobile-devices-and-android-runs.md), which this extends to Apple's tools.

**Status: built; on-device validation pending.** On a Mac, the device list offers this Mac (Mac Catalyst) and the iOS simulators, and Start Without Debugging runs a MAUI app on them. The end-to-end test needs the MAUI workloads on the Mac, which the validation Mac doesn't have yet. Debugging on Apple platforms waits for the Mono adapter (M20b).

## Built

**Workbench** (`Mobile/AppleDevices.cs`, `Mobile/AppleRun.cs`):
- `AppleDevices` lists:
  - this Mac (`mac:local`, platform `maccatalyst`);
  - the available iOS simulators from `xcrun simctl list devices available --json`, booted first, then the newest runtime.

  It boots a simulator (`simctl boot`, the Simulator app, `simctl bootstatus`), installs a bundle, terminates an app, and gives the launch command (`simctl launch --console-pty`). It is macOS only: elsewhere it lists nothing.
- `AppleRunner`:
  - **Mac Catalyst:** the build host builds the `maccatalyst` framework, and the bundle's `Contents/MacOS` executable runs as the program, its output in the Run output.
  - **iOS simulator:** the simulator boots if needed. The build host builds the `ios` framework for `iossimulator-arm64` (or `-x64`), `simctl` installs the bundle and launches it attached to its console, and Stop terminates it.

**Shell** (`ShellHost.Mobile.cs`):
- The device list joins the Android and Apple devices; the toolbar shows only the platforms the startup project targets.
- The Devices window names each kind and boots a simulator on double-click.
- Start routes by the device's platform. F5 on an Apple target says debugging isn't available yet.
