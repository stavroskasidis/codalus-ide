# M55b checkpoint: Apply Code Changes while debugging, the other programs and the rest

Date: 2026-10-29. The second part of the roadmap's [M55](../roadmap.md#m55--a-managed-coreclr-debugger-phase-2-apply-code-changes-while-debugging), D48's phase 2 ([ADR 0086](../adr/0086-a-managed-coreclr-debugger.md)), after [M55a](m55a.md) (the deltas, `codalus/applyChanges`, the triggers and rude edits). The plan's PRs 3 and 4 went in as one (`feat/m55b-programs`), which saves a CI cycle; each part was validated before the next.

## Done

**The other programs** (the plan's PR 3).
- **The integrated terminal and a console window:** the launcher starts both under the debugger, so their modules get Edit and Continue's JIT flags as they load, as a launch's do. `HotReloadConsolesTests` edits each through `DebugHotReload` and stops on a line only the new version has. The console window runs on Windows, on CI.
- **Test debugging:** VSTest's test host and the testing platform's start under the debugger (`DebugService.LaunchAsync`), so a test being debugged takes edits. `DotNetTestRunControlTests.A_test_being_debugged_under_the_Codalus_debugger_takes_an_edit` edits `Arithmetic.Add` while stopped in `Adds`, for xUnit v2 and v3, and the test then fails. The plugin tests' debugger now uses the Codalus debugger built with them; it was found only through `CODALUS_DEBUGHOST`, which the `debug-codalus` shard alone sets.
- **Attach to Process:** a process started without `DOTNET_MODIFIABLE_ASSEMBLIES=debug` loaded its code before the debugger came. Apply Code Changes then says it wasn't started to take edits, and how to start it, instead of the runtime's `CORDBG_E_ENC_MODULE_NOT_ENC_ENABLED`.
- **A library the program hasn't loaded yet:** an edit to it came back "not loaded" and was lost, because the module that loads later is the build's. The adapter keeps such deltas (`pending`) and applies them in order as the module loads, while the program is stopped in its load event. `dotnet watch`'s agent does the same for assemblies that load later. `An_edit_to_a_library_the_program_hasnt_loaded_yet_applies_as_it_loads` loads `samples/Debugging/HotReloadLib` on a first call after the edit.

**A Blazor Web App's server** (the plan's PR 4; ADR 0086's open question).
- Under the Codalus debugger, the server that `dotnet watch` runs takes its edits in place through the debugger.
- `dotnet watch` also sends the server its own copy of each update. The runtime refuses it (a debugger is attached), and `dotnet watch` then stops sending that process updates: it neither restarts it nor stops updating the browser. The browser keeps getting `dotnet watch`'s updates.
- An edit that needs a restart keeps `dotnet watch`'s own restart, which debugging follows, with no question from Codalus IDE. The new server's debug session starts a new Hot Reload session from the new build.
- An updated file's breakpoints stay in the server, since it runs the new code. The Debug Console says the server takes edits, and the status bar says when it last took them and that the browser got its own.
- `samples/BlazorHosted` gets `/api/greeting` (`Greeting.cs`). `BlazorWebAppHotReloadDebugTests.Under_the_Codalus_debugger_an_edit_applies_to_the_server_in_place` edits it while the server runs: it answers with the edit, without a restart, in the same process. The test's other two cases pass under both debuggers.

**The offer under netcoredbg.** The first C#, Visual Basic or Razor edit saved while netcoredbg debugs a program shows, once per session, an info bar: edits apply under the Codalus debugger (a preview). Its buttons:
- **Use It** sets `debug.adapter`; the next start takes it.
- **Don't Show Again** sets `debug.codalusOffer`, a new setting in Options › Debugging.

The `debug.hotReload` setting's description now says what it does under each debugger.

**The smoke test.** `debug.applyChanges.codalus`, after the Codalus debugger's other debug steps, opens `HotReload.slnx`:
- stopped before `Greeter.Message` runs, an edit applies on Continue;
- while the program runs, another applies with Apply Code Changes;
- the status bar says so, with a screenshot (`smoke-test-debug-apply-changes-codalus.png`).
