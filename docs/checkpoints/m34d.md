# M34d checkpoint: UI polish, round 2

Date: 2026-10-13. On 2026-10-12 the maintainer asked to focus on performance, UX and UI before other milestones; M34a did the icons and menus, M34b the solution-load performance, and M34d the rest of M34's checklist that can be done now. Decisions: D24 (icons) and D25 (the checklist and the gallery). No new ADR: the choices follow ADR 0019 (look and feel). The guide is [`docs/ui-guidelines.md`](../ui-guidelines.md).

## What changed

**The open items (M29, M34a, M19a).**
- **High Contrast's menus are black**, with the theme's cyan border and a blue hover, and so are its drop-downs, flyouts and tooltips. Fluent's resources take their colors by `StaticResource`, so overriding its colors had no effect there; `Tokens.axaml` now overrides the keys the controls use (`MenuFlyoutPresenterBackground`, `ComboBoxDropDownBackground`, `FlyoutPresenterBackground`, `ToolTipBackground` and their borders).
- **The active document's title in a pane without the focus** was white on light gray in Light and black on black in High Contrast: Dock gives that state `DockDocumentTabSelectedForegroundBrush`, which our tokens had set to the active tab's white. Document tabs now take our colors in every state from `ShellStyles.axaml` (styles outrank Dock's control theme): `Shell.Tab.Inactive` for other tabs (Blue's dark tabs with white titles at last), `Shell.Tab.Selected` for the selected tab of a pane without the focus, `Shell.Tab.Active`, `Shell.Tab.Hover` and `Shell.Tab.Preview`.
- **The preview tab** opens at the right end of its group; other documents open to its left; while active it has its own color (purple, as a classic IDE's), and its title stays italic.
- **Pinned tabs:** Window → Pin or Unpin Tab (`workbench.pinEditor`) keeps a tab at the left of its group with a pin; Close All But Pinned (`workbench.closeUnpinnedDocuments`). Pinning keeps a preview tab.
- **Tabs colored by project:** the setting `workbench.editor.colorTabsByProject` (Appearance, off by default) gives each project one of eight `Shell.TabColor.N` tokens, drawn as a 3 px stripe along the tab's bottom edge (`ShellHost.Tabs.cs`).
- **Inactive captions:** tool window captions without the focus take `Shell.Caption.Inactive` (Blue's slate caption with a white title), their buttons too; the selected tool window tab's title is the link color (it was a light blue below AA).
- **The Solution Explorer's root label** (and every row's name) trims with an ellipsis, the path in its tooltip; the detail text follows the name in the same line.
- **The Test Explorer's filter row** no longer wraps: the toolbar is one row that overflows, and the search box has its own row the pane's width. Test names trim with an ellipsis.
- **Light's muted text** is `#646464` (5.1:1 on the background; it was 4.2:1).
- **The XAML Previewer's toolbar:** the render scales are multipliers (1×, 1.25×…), so the zoom button is the only "100%"; icon buttons (refresh, zoom out, zoom in, fit) in one row that overflows in a narrow pane. The frame already fitted the pane with scroll bars since M19a's follow-up (`c5a2ca4`).
- **A cross-thread refresh in `TestExplorerViewModel`:** the test service raises `Changed` on its own threads; the refresh flag is now atomic, `Refresh` and `SetPlaylists` marshal to the UI thread when called off it, and the queued refresh always posts.

**Tokens** (`Theming/Tokens.axaml`, the same in every theme): spacing on a 4 px grid (`Shell.Space.XS`–`XL`, `Shell.Padding.*`), sizes (`Shell.Size.Toolbar`, `ToolbarButton`, `Input`, `Icon`, `IconSmall`, `Row`, `ToolWindowMinWidth`), type (`Shell.FontSize.Body` 12, `Small` 11, `Heading` 14, `Title` 18) and corner radii. Applied through `ShellStyles.axaml`:
- the window's 9 pt body text, `TextBlock.small`, `TextBlock.heading` and the new `TextBlock.subheading` (the 15, 16 and 14 px headings became one of the two sizes), `TextBlock.emptyState` (muted, wrapped, 12 px around) on 24 empty and status messages;
- toolbars: 24 px buttons with 16 px icons (`Button.toolbar`, `ToggleButton.toolbar`), 24 px inputs and combo boxes in toolbars;
- 94 literal 11 px font sizes now use `Shell.FontSize.Small`.

**Toolbars that never wrap.** `Controls/ToolbarPanel` is a tool window's toolbar row: items keep their order, a text box takes the rest of the width, and when the pane is too narrow the items that don't fit move into an overflow menu (») at the right end: buttons as entries with their names and icons, toggle buttons as checkable entries, combo boxes as submenus of their choices. It replaced the wrapping and clipping toolbars of the Test Explorer, Solution Explorer, Error List, Breakpoints, Exception Settings, Find Results, Processes, Code Metrics, Coverage Results, Pull Requests, Worktrees, Database Explorer, Entity Framework, Aspire, Containers, Benchmarks and the XAML Previewer.

**Tables in narrow panes:** the Error List, Processes, Code Metrics and Benchmarks keep their column widths and scroll sideways, header and rows together, instead of cutting the headers off.

**Contrast fixes** found by the new test: the status bar's hover (`#005A9E`) and debugging color (`#BC4B00`) under white text, Dark's muted text on the search box, Dark's text on its accent (now black), Light's inlay hints, folding glyphs and warning color, Blue's links and modified mark on its lavender surfaces.

## Tests

- **`PolishTests`** (headless, 4 tests):
  - **Contrast:** every pair in `TestData/contrast-pairs.txt` (76 pairs: text 4.5:1, icons and focus 3:1) in Blue, Light, Dark and High Contrast, read from the resources the app resolves; and every `Shell.*Foreground` token must be in the list.
  - **Clipped text:** opens the ProjectSystem fixture, then hosts every registered tool window at 280 px and walks its text: anything wider than what its clipping ancestors show, where the content doesn't scroll sideways, fails unless it is trimmed with an ellipsis that is itself visible and has a tooltip. It found 30 cut-off texts in 15 tool windows before the fixes.
  - **Toolbars:** a `ToolbarPanel` stays one row at 200 px, moves buttons and the combo box into the overflow menu, keeps the search box, and the menu's entries run the button and choose in the combo box.
  - **Tabs:** the preview tab stays on the right, pinning moves a tab left and Close All But Pinned keeps it, tabs get project colors once the setting is on, and the selected-without-focus colors meet AA in every theme.
- **The gallery** (`eng/smoke-test.sh`): `shell.galleryEmpty` (before a solution opens) and `shell.gallery` (the Testing solution after its runs).

## The gallery

`eng/smoke-test.sh` copies it to `artifacts/smoke-test/gallery/` (CI uploads it with the smoke test's artifact on each OS): `index.md` and a picture per surface, state and theme, `{surface}-{state}-{theme}.png` (Windows run: 420 pictures, 7 MB).
- **Empty** (`shell.galleryEmpty`, before a solution opens): all 48 registered tool windows, built-in and the built-in plugins' (Start page, Pull Requests, Work Items…), each photographed as its docked pane with its caption.
- **With data** (`shell.gallery`, the Testing solution after its runs, with the BuildAndRun steps' debugging, Git and build behind it): the same 48 tool windows; the documents Options, Keyboard Shortcuts, Project Properties, NuGet and Configuration Manager; the whole window (`window-data-*`) with a pinned tab, a preview tab and tabs colored by project while the Solution Explorer has the focus, and again with the editor focused (`window-editor-focused-data-*`).
- **Error states:** the Error List with a compile error, the Output window after the failing build, and the Test Explorer with a failed test's details (`*-error-*`).

Reviewed (Windows, 2026-10-13) against the checklist, which led to the second round of fixes: disabled toolbar buttons drew gray boxes; High Contrast's buttons were dark gray and its combo boxes filled with the accent; the Error List's description column pushed the others off the pane once it scrolled sideways (the tables now fill the pane above their minimum width); the Options page's settings path was cut off; Project Properties was photographed while loading; Git Changes had no next step outside a repository (Create Git Repository); the Test Explorer's placeholder was cut off (the syntax moved to the tooltip). Seen and left: the Error List's Project column is empty in the error-state picture (the test project's files aren't matched to it; `TODO(issue)`); the Start page's toolbar (a plugin view's items) still wraps in a narrow pane.

## Budgets

- **Startup and idle memory** (`daedalus-bench run --targets shell --scenarios cold-start`, 15 runs of each build alternated, the published `origin/develop` at `2c435d9` against M34d): ready median 352 ms before and 349 ms after, interactive 649 ms and 652 ms (within the noise; ADR 0002's budget is 800 ms); idle private memory 146 MB and 148 MB.
- **Typing** (`self-driven`, 3 runs each): p99 39–45 ms before and 39–43 ms after.
- **Icon assets:** M34d adds no SVGs; four 16 px stroke glyphs (zoom in, zoom out, fit, the overflow chevron) are path strings in `IconSet`. The assets stay 125 Fluent SVGs (49 KB) and 123 Material SVGs (70 KB) in the source, compiled into `CompiledIcons`. The Native AOT `daedalus.exe` is 77.87 MB, 164 KB more than `origin/develop`'s 77.71 MB (the toolbar panel, the tab and gallery code, the styles).
