# M34a checkpoint: the UX pass

Date: 2026-10-12. The maintainer pulled part of M34 (UI polish) forward, ahead of the remaining milestones, from their report on the Windows app (five items, below). Decisions: D24 (Fluent UI System Icons for commands, compiled to geometries at build time) and D25 (the checklist; the items it covers cheaply: tooltips with shortcuts, no clipped text). No new ADR: the choices follow ADR 0019 (look and feel) and D24. The rest of M34 stays the last milestone before Visual Basic and F# ([roadmap](../roadmap.md#m34--ui-polish)).

## The report and what changed

**1. Icons, colored as in a classic IDE.**
- **Fluent UI System Icons** 1.1.344 (Microsoft, MIT; the licence checked again and recorded in `THIRD-PARTY-NOTICES.md`): the 125 SVGs listed in `src/DaedalusStudio.Shell/Icons/fluent-icons.txt` are copied unchanged into `Icons/Fluent/` by `eng/get-fluent-icons.sh` (the npm package `@fluentui/svg-icons`, SHA-256 pinned) and committed.
- **Compiled at build time:** `eng/icons/CompileFluentIcons.cs`, an MSBuild inline task (`RoslynCodeTaskFactory`, so no tool and no extra project, on every OS), parses each SVG's path data (all commands, relative and absolute, implicit repeats, compact arc flags; anything but `<path d>` fails the build) into drawing operations and constant numbers, `obj/FluentIcons/FluentIcons.g.cs`. At runtime `FluentIcons.Create` replays them into a `StreamGeometry`: no SVG or path-data parsing, Native AOT clean.
- **Size:** 17 KB of IL plus the numbers' data (about 60 KB) for 125 icons; the first version (one method of calls per icon) was 185 KB of IL. The AOT `daedalus.exe` is 78.1 MB.
- **`controls:Icon`:** a name in `IconSet`'s Fluent map is filled from its compiled geometry at its design size (16 or 20); the other names keep their stroke drawings (the test outcomes, the solution and project glyphs, plugins' names). 59 existing names moved to Fluent (save, play, stop, step into…), and 67 new names cover the commands.
- **Color by command family:** `Controls/CommandIcons.cs` maps 184 built-in commands to an icon and a family: run (green), stop (red), save and navigation (blue), open (amber), build (purple), Git (orange), tests (teal). The `accent-*` icon classes take `Shell.Icon.*` tokens from `Theming/Tokens.axaml` (Light and Blue share one set, Dark has its own, each at least 3:1 against its menus); in High Contrast every family is white, so shape carries the meaning. Disabled entries dim their icons.
- **Where:** every menu-bar entry and context-menu entry with a command icon, the standard toolbar (back and forward, open, save, save all, steps and restart colored), tool windows' View entries with their window's icon.

**2. Menus as trees.** The menu bar and the editor's context menu are declared in one place, `BuiltIns.Menus.cs`; the feature files keep only their context menus' entries and their tool windows' View entries.
- **Edit:** Go To ▸, Find and Replace ▸ | Undo, Redo | Cut, Copy, Paste, Show Clipboard History, Paste Special ▸, Select All | Advanced ▸ (format document and selection, comments, duplicate, move lines, expand and shrink selection, line endings), Bookmarks ▸, IntelliSense ▸ (List Members, Parameter Info, Quick Info, Complete Word, snippets), Multiple Carets ▸, Outlining ▸, Refactor ▸. Undo, Redo, Cut, Copy, Paste and Select All are new commands (`edit.*`) on the focused text box or editor; their keys stay with the controls and the menu shows them (`MenuItemRule.Keys`).
- **File:** New ▸ (the templates plugin), Open ▸, Clone, Open Recent… **Git:** Branches ▸, Stash ▸, Current File ▸, Hosting ▸, Repository ▸. **Project:** Packages and Tools ▸, Entity Framework ▸, Solution ▸. **Build:** Build Diagnostics ▸, Tasks ▸. **Debug:** Windows ▸, Other Debug Targets ▸, Breakpoints ▸, Startup and Launch ▸, ASP.NET Core and Aspire ▸, Dumps ▸, Profiler ▸; Continue, Break All, Stop, Detach and Restart only while debugging, as a classic IDE does. **Test:** Playlists ▸, Test Results ▸, Code Coverage ▸. **Analyze:** Calculate Code Metrics ▸. **Tools:** Database ▸.
- **Context menus:** the editor's (refactoring, navigation, tests, Breakpoint ▸, Snippet ▸, Git ▸, Outlining ▸, clipboard) and the Solution Explorer's (Add ▸ with New Item, Existing Item, Project Reference, Service References, Docker Support, Existing Project…, Git ▸, Entity Framework ▸) nest; `MenuBuilder.Context` builds every context menu, submenus included (they used to drop them). Fixed on the way: the editor's context menu listed Go to Definition, Find All References, Rename, Quick Actions and Format Document twice.
- **Density:** menu rows are about 24 px (`MenuFlyoutItemThemePadding`), so the longest menu (Debug while debugging, 31 entries) is about 820 px.
- **D25:** every entry's tooltip is its full name and shortcut after a pause (`Edit: Go to Definition (F12)`); the standard toolbar's tooltips take the shortcut from this OS's bindings (they were hard-coded `Ctrl+…`, wrong on macOS); long titles trim with an ellipsis.
- **macOS:** the global menu bar gets the same tree as native submenus; native menus carry no command icons (Apple keeps them for a few system items), shortcuts only.
- **Plugins:** may contribute to `menuBar/analyze` and to the submenus (`menuBar/<menu>/<submenu>`, `editor/context/<submenu>`, `solutionExplorer/context/<submenu>`); the manifest check accepts them. The Templates plugin's entries moved to File → New ▸ and the Solution Explorer's Add ▸. `docs/plugins.md` (no API version change).
- No "Visual Studio" in any title (the test checks it).

**3. Output that follows.** `Controls/FollowTail` keeps a log view at its end while the user is there: it scrolls when the extent grows (after layout, when the new end is known; scrolling right after appending reached the old end), stops when the user scrolls up, and resumes when they reach the end again. Used by Output (Scroll Lock pauses it), the Debug Console, C# Interactive's transcript, and the container and Aspire logs. Two causes of "the user has to scroll": the editor allowed scrolling below the document, so the old `ScrollToEnd` showed an empty page (log editors now stop at the last line), and `ScrollToEnd` also scrolled sideways, which hid the first characters of every line once a long line arrived (following keeps the horizontal offset). The Output text keeps its 6 px padding.

**4. The minimap docked.** The code view's popups were the last children of its dock panel, so the last popup took the fill and the editors were docked left at their content's width: the minimap followed the longest line. The popups now sit beside the dock panel in a plain panel; the minimap stays at the editor's right edge.

**5. Ctrl+Space.** It was listed in the menu but did nothing in the real app: the window learns which view has the keyboard focus from the bubbling `GotFocus` event, and the editor's text area marks that event handled, so `editorTextFocus` was never set and **none of the editor's key bindings matched** (Ctrl+Space, Ctrl+Shift+Space, F12, F2, Ctrl+.…; the menus and the palette, which don't need it, worked). The window now listens with `handledEventsToo`. Per OS (`docs/user-guide/keyboard.md`):
- **Completion:** Ctrl+Space everywhere, the physical Control key on macOS (⌘Space is Spotlight); Ctrl+J too (the classic List Members, and the way round IBus's or a CJK IME's Ctrl+Space); ⌥⎋ on macOS for when ⌃Space switches input sources. Parameter Info stays Ctrl+Shift+Space. The menus show Ctrl+Space.
- **The audit** of the default keymap against each OS's reserved shortcuts moved: Complete Word to ⌃. on macOS (⌘⌥Space is Finder search); the outlining chords to ⌘⌥[, ⌘K ⌘0 and ⌘K ⌘J on macOS (⌘M minimizes); Add Caret Above/Below to Shift+Alt+↑/↓ on Linux (GNOME and KDE workspaces); Performance Profiler, Diagnostic Tools and Apply Code Changes off Alt+F2, Ctrl+Alt+F2 and Alt+F10 on Linux (run dialog, virtual terminals, maximize); Task Runner Explorer off Ctrl+Alt+Backspace on Linux (X zap). F11 on macOS and Ctrl+Alt with AltGr on European Windows layouts are documented, not changed.

## Tests

- **Headless UI, `UxPassTests`** (12 tests, 37 cases):
  - every command the menus offered before the restructuring (`TestData/menu-commands.txt`, 384 lines: the menu bar, the editor's and the Solution Explorer's context menus) is reachable through the trees, and no submenu is orphaned;
  - no menu location has more than 32 entries, idle or in the busiest context (debugging a C# file in a Git repository, every Solution Explorer item kind), and the Edit menu is the classic tree with the shortcuts shown per OS;
  - every top-level menu and submenu, opened in a 1920×1040 window, is at most 950 px tall; File → Save shows its colored icon and its tooltip;
  - context menus nest (Add ▸, Git ▸);
  - every Fluent name compiles to a geometry inside its design box, and every command icon exists; the icon accents are colored in Light, Dark and Blue and white in High Contrast;
  - Output follows 300 lines, shows the last lines (not a page below the document), never scrolls sideways, has its padding, stops following when scrolled up and resumes at the end; a log text box follows its end;
  - the minimap ends at the editor's right edge with short, 400-character and medium lines, at the same x each time;
  - completion keys per OS (Windows, Linux, macOS) and no default binding on 24 OS-reserved shortcuts;
  - **Ctrl+Space pressed in a focused C# editor** opens completion with the language service's items and types nothing; Ctrl+Shift+Space runs Parameter Info.
- **Smoke test** (`eng/smoke-test.sh`, the real app): `shell.menus` opens every top-level menu and each Edit submenu, checks each fits the screen and photographs it with its popups composited (macOS checks the native menu's IntelliSense submenu); `editor.completionKey` sends Ctrl+Space through the window's key handling and waits for completion; `shell.outputFollows` writes 200 lines to the Output window, waits until it shows the last one, and photographs Edit ▸ IntelliSense and Debug over the editor and Output in Blue, Light, Dark and High Contrast.

## Deviations and open items

- **Icons in the Windows and Linux menus only:** macOS's native menus show titles and shortcuts (Apple's convention); `NativeMenuItem.Icon` would need bitmaps rendered per scale and theme. `TODO(issue)` if the maintainer wants them.
- **The checked-in SVGs, not a download at build time:** builds stay offline and reproducible; `eng/get-fluent-icons.sh` refreshes them from the pinned package.
- **File-type icons** (Material Icon Theme, D24's second half), the inventory and checklist on every surface, the gallery mode, the clipped-text and contrast tests and the UI guide stay in M34.
- **Ctrl+Space and the OS:** the smoke test sends the key through the window's handling, not through the OS: an input method or macOS's input-source shortcut that takes Ctrl+Space first is outside the app; the alternatives (Ctrl+J, ⌥⎋) and the settings to change are in `docs/user-guide/keyboard.md`.
