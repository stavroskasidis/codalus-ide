# M28b checkpoint: AI inline suggestions, next edit suggestions and AI actions

Date: 2026-10-15. The second part of M28 (D7, ADR 0062): suggestions in the editor, and AI where the IDE already shows something. Everything goes through M28a's `AiService` boundary. Nothing new is sent while a feature's own switch is off.

## Done

**Inline suggestions** (`AiCompletions` in workbench `Ai/`, `InlineSuggestions` in the editor):
- **Its own switch**: `ai.completions.enabled` is off by default, because it sends code as you type. There's also `ai.completions.model` (a faster model) and `ai.completions.delayMilliseconds` (400).
- **When it asks**: after typing pauses, with the caret at the end of a line (or before closing characters), without a selection or an open completion list. It sends up to 6,000 characters before the caret and 2,000 after, redacted. An excluded file or an untrusted folder sends nothing.
- **How it asks**: through the chat API, with a completion prompt (any provider works). `AiCompletions.Clean` takes off code fences, the current line's start when the model writes it again, and the text after the caret, and caps the suggestion at 16 lines.
- **Rendering**: gray italic ghost text at the caret, drawn by a `DrawableTextRun`. Its first line sits at the caret, and the other lines sit below from the line's start, so the visual line grows and the code below moves down.
- **Keys**: `Tab` accepts as one undo step, `Ctrl+Right` (`Alt+Right` on macOS) accepts a word, and `Esc` or moving away dismisses. Typing what it shows keeps the rest.
- **Never blocking typing**: a new keystroke cancels the request (budget 2). Requests are "quiet": they don't flip the status bar to "working".

**Next edit suggestions** (`AiNextEdit`, `NextEditSuggestions`):
- **Its own switch**: `ai.nextEdit.enabled`, off by default.
- **What it tracks**: the editor keeps the last five edits, merging the keystrokes on one line into one edit.
- **When it asks**: 1.2 s after an edit, with those edits and the 40 lines around the caret.
- **What comes back**: the model answers with JSON (`startLine`, `endLine`, `newText`, or `none`). `AiNextEdit.Parse` checks it against the shown lines, and drops a suggestion that undoes the last edit or changes nothing.
- **Showing it**: the lines are highlighted, with `⇥` and the new text at their end. `Tab` applies it (and can lead to the next suggestion), and `Esc` or another edit dismisses it.

**AI actions** (`AiActions` in the workbench, `ShellHost.AiActions.cs`), each only on the user's request and shown only while AI is on (`AiUi.Current.IsEnabled`, bound by the views):
- **Git Changes**: ✦ beside the message box writes the commit message for the staged diff, in the style of the last 10 subjects. `FilterDiffAsync` drops excluded files' sections and names them instead.
- **Create Pull Request**: Write with AI writes the title and description from `remote/target..source`'s commits and diff.
- **The exception helper**: Ask AI sends the exception, its stack, the call stack and the code around the current frame to AI Chat.
- **Test Explorer**: Ask AI Why It Fails (on a failed test's context menu, and Tools → AI) sends the result's messages, expected and actual values, stack, output and test file.
- **The editor's AI menu**:
  - Fix with AI fixes the diagnostic at the caret: the 25 lines around it, numbered, go to the model, and its corrected block comes back through the refactoring preview.
  - Generate Tests with AI uses the solution's test framework (`TestFrameworks.Detect`: MSTest, NUnit, TUnit, xUnit).
- **A CPU profiling report**: Summarize with AI sends the report's summary and top 40 functions.
- **The boundary**: `AiService.AskAsync` is the one-shot form of a request, through the boundary. New context kinds (debugger, test result, changes, profile) are named in the request log.

**Docs and site**: the user guide's AI page (inline suggestions, next edit suggestions, AI actions, settings) and the Features page.

**Tests**:
- **`AiActionsTests`** (4): completion cleaning, next-edit parsing and validation, diff splitting and unfencing, test framework detection.
- **`LanguageModelPluginHostTests`**: a new test, through the real plugin host. It covers completions behind their switch, an excluded file sending nothing, a commit message without the excluded file's diff, a pull request description, and a fix.
- **`AiSuggestionsTests`** (2 shell tests): inline suggestions (off sends nothing; on, the ghost shows, typing through it, Esc, Tab) and a next-edit suggestion after a rename, applied with Tab.
- **Rendering**: a frame of a multi-line suggestion, captured once in the headless renderer, showed the layout above.
