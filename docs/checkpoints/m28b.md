# M28b checkpoint: inline suggestions

Date: 2026-10-14. Builds on M28a ([m28a](m28a.md), [ADR 0062](../adr/0062-ai-providers-and-data-boundaries.md)): the same providers and data boundary.

## Built

- **The setting** `ai.inlineSuggestions` (off by default, per workspace, and only while `ai.enabled` is on).
- **`InlineSuggestions`** (`Editor/InlineSuggestions.cs`, one per editor):
  - After a 600 ms pause in typing, with no selection and no completion list open, it asks for a suggestion at the caret (`IEditorServices.SuggestInlineAsync`).
  - The next keystroke or caret move cancels the request, so typing never waits.
  - A suggestion shows as ghost text: a zero-width element of the view, italic and faded, that the caret can't stop in. A suggestion of several lines shows its first line and the count of the others.
  - **Tab** inserts it, **Esc** dismisses it, and typing or moving the caret dismisses it.
- **The request** (`ShellHost.AiChat.cs`):
  - It is refused for files the data boundary refuses (secrets, git- or `.codalusignore`-ignored).
  - It carries a system prompt asking for only the text to insert, and the file around the caret (4,000 characters before, 1,500 after) with `<CURSOR>`. It asks for at most 256 tokens.
  - `CleanSuggestion` strips code fences, a repeated line start and an overlap with what follows the caret.

## Tests

- **Headless UI** `InlineSuggestionTests`, against a mock OpenAI-compatible server:
  - the reply cleanup in five cases;
  - nothing asked while the setting is off;
  - the suggestion shown at the caret after a pause, the request carrying the file with `<CURSOR>`;
  - Tab inserting it and moving the caret on, and moving away dismissing one.

**Validation**: Windows green on the affected classes; the rest with the push.

## Not done
