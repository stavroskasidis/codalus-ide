# M62 checkpoint: inline values while debugging

Date: 2026-11-13. The roadmap's [M62](../roadmap.md#m62--inline-values-while-debugging), D50 and D54 ([ADR 0101](../adr/0101-inline-values-while-debugging.md)). One pull request.

## Done

**The language host** answers LSP 3.17's `textDocument/inlineValue` for C# and Visual Basic: for each line of the stopped method up to the stop (at most 100 lines), the locals and parameters it reads or writes as variable lookups, and the fields and auto-properties it reads (on `this`, or static) as expressions. Other properties, calls and other objects' members are left out, so drawing values never runs the user's code. It works through Roslyn's operations, so declarations, `foreach` variables, pattern and `out` variables, deconstructed tuples, lambda parameters and top-level `args` all count.

**The editor** draws them after each line's end at every stop in the document, for the frame selected in the Call Stack: `name = value, …` in gray italics, a value changed since the previous stop in orange, each value cut at 60 characters and the line at the editor's width. Lookups come from the frame's scopes, as Locals reads them; expressions are evaluated in the frame, at most 40, each with a 1-second timeout. The values arrive after the stop is drawn, a newer stop cancels them, and they clear when the program goes on.

**The switch:** `debug.inlineValues` (Options › Debugging › Inline values), on by default, and per language through language settings.

**Tests and the smoke test.** The language host's answer on a fixture (`samples/LanguageFeatures/src/App/Values.cs`: locals, parameters, fields, an auto-property and a property with a body, pattern and `out` variables, a lambda, a static field, nothing after the stop). In the shell under the real debugger: values at a breakpoint in a loop, `total` marked changed on the next iteration while `numbers` isn't, nothing drawn when the setting is off, and nothing once the program goes on; a long value cut with an ellipsis. The smoke test's `debug.depth` step (and its netcoredbg pass) checks that `args` shows after its line.

**Docs.** The user guide (Debugging › While stopped › Inline values, and Settings), the Features page, ADR 0101, the changelog and the roadmap (D54).
