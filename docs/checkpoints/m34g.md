# M34g checkpoint: the polish pass over the Windows desktop UI

Date: 2026-10-17. M34's pass over the UI added since M34f: M40–M44 (the Windows desktop phase, D31) and, as the roadmap's status says, M45's theme families, M46's first-run setup and M47's Code Search. It applies M34d–f's checklist ([`docs/ui-guidelines.md`](../ui-guidelines.md)) to every view they added, in all sixteen themes, and puts the views in the gallery. No new ADR: the choices follow ADR 0019 (look and feel) and [ADR 0077](../adr/0077-theme-families.md) (the families' tokens).

The first pass was built on M47's stack, which didn't have M43 (.NET Framework: M43a's projects on `claude/m43a`, M43b's desktop-CLR debugger on `claude/m43b`). M43 was merged in afterwards (`claude/m43b`, which has M43a) and walked the same way: its rows are below, marked M43.

**Found by PR #34's Windows CI, from develop's code:** `DotNetTestCoverageTests` (MSTest on Microsoft.Testing.Platform) got no report: `coverlet.console` had printed "Generating report" and was stopped before it wrote the file. A run's session stopped the process tree 5 s after asking the app to exit, and for coverage that process is `coverlet.console`, which still reads the hits, restores the assemblies and writes the report after the app has exited. Reproduced on Linux with the window cut to 70 to 100 ms (the same output, one or two of the four cases failed on each run). The session now waits for the console once it has said the app exited ("Calculating coverage result..."), until the run is cancelled; with the same short windows the four cases pass. The test's message shows only its own run's output (it showed every earlier case's too).
