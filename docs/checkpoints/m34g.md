# M34g checkpoint: the polish pass over the Windows desktop UI

Date: 2026-10-17. M34's pass over the UI added since M34f: M40–M44 (the Windows desktop phase, D31) and, as the roadmap's status says, M45's theme families, M46's first-run setup and M47's Code Search. It applies M34d–f's checklist ([`docs/ui-guidelines.md`](../ui-guidelines.md)) to every view they added, in all sixteen themes, and puts the views in the gallery. No new ADR: the choices follow ADR 0019 (look and feel) and [ADR 0077](../adr/0077-theme-families.md) (the families' tokens).

## What was walked

| Milestone | Views |
|---|---|
| M40 | The XAML Previewer's WPF states (Windows only, the loader's error), the Live Visual Tree and the Live Property Explorer |
| M41 | The Windows Forms designer document, the Toolbox, the Properties window over the designer's selection (properties and events) |
| M42 | The WCF Test Client, the Service References document's WCF page |
| M43 | Nothing: M43 is scheduled after M44 and hasn't been built; its views get the checklist in its own definition of done |
| M44 | No view of its own: "Windows Machine" in the device picker (a quick pick) and Check Environment's Developer Mode and Windows App SDK rows are existing surfaces (M34f walked Check Environment) |
| M45 | Options' color theme cards and mode, the theme picture |
| M46 | The setup window's four steps (with a missing SDK's plan shown) |
| M47 | Code Search floating and docked: empty, nothing found, incomplete, results with the preview, Feature Search |

Each in its states (empty, loading, error, disabled where a view has it, with data), at its minimum size (280 px for tool windows, 640 px for documents, 420 px for Code Search's floating window, the setup window's 760 × 560), in Classic's four themes and the families' twelve. The Windows-only views are checked through their view models and views with fakes, as M34f did: the designer document, the Toolbox and the Properties window through `FakeWinFormsDesignerHost` (M41a's) over the real build and C# hosts.

## Tests

- **`PolishWindowsDesktopTests`** (part of `PolishTests`, 3 tests, headless):
  - **The new views in every state:** the XAML Previewer (empty, WPF off Windows, an error), the Live Visual Tree (empty, data, a template part selected), the Live Property Explorer (empty, data with an error), the Toolbox (no designer, data, an item armed, no matches), the WCF Test Client (empty, a missing address, loading against a gated mock, a WSDL's form, a response, a fault), the setup window's four steps, Options' color theme cards, and Code Search floating (empty, nothing found, Feature Search).
  - **With a solution** (samples/LanguageFeatures, the real build and C# hosts): Code Search incomplete while it loads, with results and the preview, docked at 280 px; the Service References document's WCF page and its error.
  - **The Windows Forms designer** (samples/WindowsDesktop's WinFormsApp, the fake designer host on any OS): the designer document with a selection, the Toolbox and the Properties window (properties and events) with the designer's data, and a designer that can't start, whose reason shows where the form would be.
  - Each surface is hosted at its minimum size in all sixteen themes and walked with M34d–f's checks (cut-off text, accessible names) and three new ones: **contrast as rendered** (every text against the background under it, blended, 4.5:1, 3:1 large, 7:1 in the families' High contrast), **icons in the palette** (a kind a view shows without a color of its own), and **squeezed inputs** (a text box or combo box under 48 px). The squeezed check was proven against the WCF form's old columns (a 32 px combo box).
- **`UxPassTests.The_new_views_reach_every_control_with_Tab_in_reading_order`**: Tab pressed through the WCF Test Client's form, the Toolbox, the Live Property Explorer, the setup's settings step and Code Search's Feature Search; every visible, enabled control is reached.
- **Contrast pairs** (`TestData/contrast-pairs.txt`, 111 → 123): the error and warning text on the panel, the window, popups and the editor; `Shell.Foreground` on `Shell.Editor.Background` (the setup's cards and sections); the accent's outlines on popups and the editor; checked toggle buttons.
