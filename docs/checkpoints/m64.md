# M64 checkpoint: XAML depth

Date: 2026-11-13. The roadmap's [M64](../roadmap.md#m64--xaml-depth-hot-reload-refactorings-and-xaml-debugging), D50 and D56 ([ADR 0103](../adr/0103-xaml-depth.md)). One pull request.

## Done

**Rename across C# and XAML, both ways** (the C# host, `XamlRename`).
- A C# rename of a type, property, field, method or event also renames its uses in the solution's XAML, wherever Go to Definition would reach it from: compiled binding paths under `x:DataType` and WPF's from `d:DataContext`, `{x:Static}`, `x:Class`, `x:DataType`, `DataType`, `TargetType`, `{x:Type}`, `d:DesignInstance`, element and property-element names, attributes (`<vm:TodoItemViewModel Title="…">` in `Design.DataContext`), style selectors' types and event handlers.
- In XAML, a binding path, a type, an `x:Class`, a `{x:Static}` member, a command method or an event handler that the solution declares in source is renamed through Roslyn, with its C# and XAML uses. An element name renames as before (M19a).
- A resource key (its `x:Key`, now a target of hover, definition and rename, or a lookup) renames in the XAML of its project, the projects it references and those referencing it, and in their C#'s `FindResource("…")`, `TryFindResource`, `TryGetResource` and `Resources["…"]`.
- WPF's `obj/*.g.cs` and `*.g.i.cs` are never edited.

**Code actions in XAML** (`XamlCodeActions`, with their edits, through the lightbulb's preview): **Extract Resource** to the file's resources, to `App.axaml`/`App.xaml`, or replacing every equal value; **Extract Style** (an Avalonia class style in the root's `Styles` and the class on the element; a WPF keyed `Style` with `TargetType` and `Style="{StaticResource …}"`); **generate from use**: a property for an unknown binding path on the `x:DataType`'s (or `d:DataContext`'s) class, a `[RelayCommand]` method with CommunityToolkit.Mvvm or an `ICommand` property for a command, a converter class (`Converters/`, Avalonia's or WPF's `IValueConverter`) and its resource for a missing converter.

**Failed bindings in the Error List.**
- The Avalonia agent hooks Avalonia's logger before the app's first binding (the app's own `StringLogSink` from `LogToTrace`/`LogToTextWriter`/`LogToDelegate` keeps its lines; without one, a sink of the agent's for `Binding` warnings), keeps each failure once per element, property and path, says `event bindings`, and answers `bindings` with the element's type, name and the classes it sits in.
- The WPF agent listens on `PresentationTraceSources.DataBindingSource` (refreshed, so WPF traces without a debugger).
- `XamlBindingLocator` puts each at its XAML line: the file of the nearest class first, the element of the failed type and name preferred. Error List warning `XAML0100`, source **Binding**.

**XAML Hot Reload** (`debug.xamlHotReload`, on by default; on save).
- Avalonia: the shell resolves the file's app as the previewer does and sends the saved text with the app's own designer host, which holds Avalonia's runtime XAML compiler; the agent loads it into the app once and populates each live instance of the `x:Class` (styles, data templates and resources emptied first, a new name scope, named fields set to the new elements, handlers connected by the compiler to the running class's methods). A failure is put back and answered with its line.
- WPF (Windows only): WPF's schema context and System.Xaml's object writer populate each instance, handlers kept.
- The shell refuses a changed `x:Class` before sending; a failure is an Error List error `XAML0101` (source **XAML Hot Reload**) at its line with **Restart** offered (the debug session, or the program run without debugging); success says how many instances changed. A save under the Codalus debugger no longer says XAML needs a restart when the agent takes it.

**Docs.** ADR 0103 (D56), the user guide (Avalonia: rename, code actions, XAML Hot Reload, failed bindings; WPF: the same, Windows only), the website's Features page, `CODALUS_UPDATE_GOLDEN_FILES` in [environment variables](../environment-variables.md), the setting's text in `en.json`.
