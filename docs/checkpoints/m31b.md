# M31b checkpoint: the first published releases

Date: 2026-10-13. Decisions: [ADR 0028](../adr/0028-release-cycle-and-installers.md) and [ADR 0029](../adr/0029-self-update.md), unchanged. The maintainer moved this ahead of the remaining milestones on 2026-10-13 ("I want to release the first 0.1 version") and decided:

- enable GitHub Pages for the apt and dnf repositories;
- release 0.1.0 without code signing (certificates later), with the prompts explained;
- merge `develop` into `master` once CI and the nightly are green on every platform, without asking again;
- add openSUSE and Arch Linux (asked the same day).

M31 built the release cycle and waited for the public repository; this finishes it.

## Done

**Pages** (source: GitHub Actions). The owner's account serves Pages from a custom domain, so the site is `https://stavroskasidis.com/daedalus-studio/`, and `<owner>.github.io` redirects there over HTTP, which apt refuses. `linux-repos.yml` takes the address from `actions/configure-pages` and serves it over HTTPS; the getting-started guide links it.

**Linux arm64** packages build on GitHub's `ubuntu-24.04-arm` runners. They have no Chrome, and none exists for Linux arm64; Ubuntu's chromium is a snap. The package job installs Playwright's Chromium (pinned, 1.56.1) as `chromium` for the browser-debugging smoke steps; it needs unprivileged user namespaces, which Ubuntu 24.04 restricts (090fae9, from the session that took the arm64 browser debugging). The smoke test now reports a missing browser at once (failed in CI, skipped elsewhere) instead of waiting out two 600 s steps into its watchdog.

**openSUSE**: zypper installs from the signed rpm repository as it is (its `.repo` file); the package's `libicu`, `git` and `fontconfig` resolve on Tumbleweed and Leap 15.6. `eng/test-linux-repos.sh` installs, runs and removes it in openSUSE Tumbleweed after Ubuntu and Fedora; the packages page shows the commands.

**Arch Linux**: the AUR package `daedalus-studio-bin` of each stable release (`eng/aur.sh` fills `eng/packaging/arch/PKGBUILD` and writes its `.SRCINFO`; no Arch machine needed), from the release's Linux `.tar.gz` files with the desktop entry, icon and license from the tag. `publish-release.sh` attaches it (`aur-daedalus-studio-bin-<version>.zip`), and `release.yml` pushes it to the AUR once the maintainer's `AUR_SSH_PRIVATE_KEY` secret is set. `eng/test-aur.sh` builds it with `makepkg` in an Arch container, checks the `.SRCINFO` against `makepkg --printsrcinfo`, installs it with `pacman`, runs it and removes it.

**Release notes**: `CHANGELOG.md` starts with the 0.1.0 section, the release page's introduction (nightlies before 0.1.0 show it too): what the preview covers, the requirements, each OS's prompt for unsigned installers, the signed Linux packages, platforms and gaps. The commits follow, grouped by milestone with links to the checkpoints.

**Found by the first nightly runs**:
- `eng/package.sh`: `sha256sum` starts its line with a backslash when the file name has backslashes (the update test's Windows path), which put `\1…` into the winget manifests' `sed` expression. Only the hex digits are kept now.
- macOS packaging (`sign_args[@]: unbound variable` under `set -u` without signing parameters), fixed on 2026-10-12.
- **Publishing a release's tag** got HTTP 403 with `contents: write`: the workflow token may create a tag only on a commit whose workflow files match the default branch's (otherwise GitHub asks for `workflows`, which a workflow token can't have), and `develop` moved on with a workflow change during the hour the first nightly built. `nightly.yml` and `release.yml` tag in their plan job, while the commit is the branch's head; `publish-release.sh` releases on that tag (`--verify-tag`), and a failed run removes it.

**CI on `develop`**: tests that read a loaded runner's timing as a failure, fixed:
- an unloaded project's `bin/` (a design-time build creates the folder);
- `git add` racing the build host's `obj/`;
- the profiler's hottest line;
- plugin activation's 10 s limit, now 30 s.
