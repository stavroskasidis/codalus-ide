# M23b checkpoint: profiles, sync, customization and the localization foundation

Date: 2026-10-13. M23's second part (the split is in [m23a](m23a.md)). Moving the rest of the UI's strings into the catalogues is M23c: about 1,200 view strings and the messages built in code. No new ADR: settings stay VS Code-shaped, sync has no Daedalus-hosted service (as M23 planned), and D11 (hosted Weblate) stands.

## Done

**Profiles** (File → Profiles; `ProfileStore` in workbench `Settings/`, `ShellHost.Profiles.cs`):
- **What a profile holds**: settings (the keyboard scheme, theme, turned-off plugins and menu customizations among them), keyboard shortcuts, user snippets, saved window layouts and the window's layout.
- **Where they're kept**: the active profile's files stay where they always are, so nothing that reads them changes. Switching saves them into `<config>/profiles/<active>/`, copies the other profile's in, and reloads settings, shortcuts, snippets and the layout at once. When the profiles turn different plugins off, it offers a restart.
- **New Profile**: a copy of the current profile, or empty.
- **Delete Profile**: any but Default and the active one.
- **Export and import**: Export Settings' file, which now carries the profile's name and window layout.
- **Status bar**: names a profile other than Default; the context key `profile` holds it.

**Settings Sync** (`SettingsSync`, `ShellHost.Sync.cs`): the active profile's settings, shortcuts, snippets and saved layouts, kept in a folder (one a cloud drive syncs) or a Git repository the user chooses.
- **Git**: a gist's clone URL works. The clone is ours alone in the cache folder; pushes use the user's git and credentials, and a neutral identity only when git has none.
- **When**: at startup, five seconds after a change, and on demand.
- **How a change is detected**: against the hash of the last synced document. One side's change goes to the other; a change on both sides asks Use Synced or Keep Mine. A first sync with settings on both sides asks too.
- **What stays on the machine**: the sync settings themselves and `settingsSync.ignoredSettings`. The target is a setting, so each profile syncs to its own.

**Customizing menus and toolbars** (Tools → Customize; `MenuCustomizations` and `MenuRegistry` in the workbench, `ShellHost.Customize.cs`, `CustomizeViewModel`):
- **The setting**: `workbench.commandBarCustomizations` holds per location the commands added, the items removed and the order, plus the user's own toolbars.
- **Menus**: the registry applies it to every menu, submenu and context menu, plugins' items included.
- **The standard toolbar**: rebuilds from it. Built-in buttons can be removed and restored, added commands are ordered, and user toolbars follow.
- **The page**: lists the toolbars, every menu bar menu with its submenus, and the editor's and Solution Explorer's context menus.

**Turning plugins off and restarting**:
- `plugins.disabled`: a turned-off plugin is discovered but isn't applied or activated (`PluginState.Disabled`). The Plugins window's Turn Off and Turn On say what changes at the next start.
- File → Restart starts the IDE again on the same solution, user-data folder and plugin folders, after the single-instance lock is released.

**Localization foundation** (`Localizer` and `LocalizationCatalog` in workbench `Localization/`, `ShellHost.Localization.cs`, `TExtension`):
- **Catalogues**: flat JSON (`Localization/<locale>.json`, embedded), with English as the source; Weblate reads that format.
- **Translated as they register**, by id: commands and categories, settings (titles, descriptions, categories, enum names), menu and submenu titles, and tool windows. That is about 900 strings with no change to the code that declares them.
- **Views**: `{l:T key}`. The standard toolbar, Plugins, Fonts and Colors and Customize are moved; `eng/localize-xaml.py` moves the rest view by view.
- **Display language**: `workbench.locale`, `--locale`, `DAEDALUS_LOCALE`, else the OS's language when there is a catalogue for it, else English. Regional catalogues fall back to their language.
- **Pseudo-languages**: `qps-ploc` and `qps-plocm`. The second mirrors the window (`FlowDirection`), which is also how Arabic, Hebrew, Persian and Urdu lay out.
- **Plugin manifests**: `%key%` with `daedalus-plugin.nls(.<locale>).json`, applied as the manifest loads. The Welcome plugin's manifest uses it, and built-in plugins ship their `nls` files.
- **Tests**: `LocalizationCatalogTests` keeps `en.json` equal to the code and the views (`DAEDALUS_UPDATE_LOCALIZATION=1` regenerates it), and a per-view baseline of hard-coded strings may only go down. It starts at 1,207 strings in 79 views. Contributors' guide: `docs/translating.md`.

**RTL review** (the pseudo right-to-left run, `--locale qps-plocm --screenshot`):
- **What works**: the window mirrors as it should. Tool windows swap sides, the title row and toolbar run right to left, and the caption buttons move left.
- **What to fix** (M23c): text that isn't translatable yet stays English; it's what the baseline lists. A long tip on the Start page clips.

**Tests**:
- `ProfileTests` covers switching, copies, validation, deleting, export and import, and a turned-off plugin.
- `SettingsSyncTests` covers a folder with pull, push, up to date and both conflict answers, and a bare Git repository with another clone pushing.
- `CustomizeTests` covers menus, the standard toolbar's buttons, a user toolbar and the page.
- `LocalizationTests` (workbench) covers fallbacks, pseudo-languages, right to left and manifest placeholders, and `LocalizationCatalogTests` covers the catalogue and the baseline.
