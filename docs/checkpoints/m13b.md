# M13b checkpoint: Git hosting integration and the rest of Git depth (M13 complete)

Date: 2026-10-11. Decision: [ADR 0031](../adr/0031-git-hosting-and-repository-features.md). With M13a (ADR 0020) this completes M13. Everything in M13a's "Not done" list is built; nothing was split into an M13c.

## Built

**The credential store** (`DaedalusStudio.Platform/Credentials`)
- `ICredentialStore`, chosen by `CredentialStore.Create()`:
  - **Windows Credential Manager** (`CredReadW`/`CredWriteW`/`CredDeleteW`): generic credentials `Daedalus Studio:<service>:<account>`, persisted for the user on this machine; secrets over 2,560 bytes are split into parts.
  - **macOS Keychain** (`SecItemAdd`/`CopyMatching`/`Update`/`Delete` with Core Foundation dictionaries; the constants read from the frameworks' exports).
  - **libsecret** (`secret_password_storev_sync` and friends, the schema `org.daedalusstudio.Credential`, cancellable through a `GCancellable`).
  - **In memory**: `DAEDALUS_CREDENTIAL_STORE=memory` (tests, the smoke test on Linux), and the fallback when the OS store fails (the shell says so once).
- `SecretStorage` (workbench): plugins' secrets under the account `<plugin id>/<key>`; a `--user-data-dir` profile gets a service of its own, so tests and the smoke run never touch the default profile's tokens.

**Hosting** (ADR 0031)
- **Plugin API 0.2.6** (proposed): `IHosting` with the abstract `HostingProvider` (repository resolution, account, device-flow and token sign-in, sign-out, repository info, pull requests, details with review threads, checkout instructions, create, branch status, work items, owners, publish), `IDeviceCodePrompt`, `HostingAuthenticationException`; `ISecrets`. The manifest's `contributes.hostingProviders` (`id`, `label`, `hosts`, `serverSetting`, `icon`) and the implicit activation event `onHostingProvider:<id>`.
- **Wire:** `hosting/*`, `secrets/*` and the error codes `-33010`–`-33013` (`HostingMessages.cs`, docs/plugin-protocol.md).
- **Workbench `HostingService`:** the declared providers (with their configured server's host), the non-secret account list (`hosting-accounts.json` in the state folder), matching the repository's remotes (`origin` first) to a signed-in provider, and the requests, with activation on demand. Errors become `HostingSignInRequiredException` (the account is forgotten and the user asked to sign in again) or `HostingRequestException`.
- **Built-in plugins** on a shared `DaedalusStudio.Plugins.Hosting` (RFC 8628 device flow, sessions with refresh, HTTP and JSON helpers, remote URL parsing):
  - **GitHub** (`daedalus.github`): REST, GraphQL for review threads (resolved, outdated), check runs and commit statuses, issues, organizations; github.com and GitHub Enterprise Server (`github.serverUrl`).
  - **Azure DevOps** (`daedalus.azuredevops`): Entra ID's device flow for the Azure DevOps resource with refresh tokens, or a personal access token as Basic credentials; pull requests and threads, builds, WIQL work items, projects; `dev.azure.com`, `*.visualstudio.com`, SSH and Azure DevOps Server remotes.
  - **GitLab** (`daedalus.gitlab`): the device flow (GitLab 17.2+) with two-hour tokens refreshed, merge requests and discussions, pipelines and jobs, issues, namespaces; nested groups.
- **Inactive until sign-in:** no plugin loads, and nothing is sent, until the user signs in to a host; then only for repositories on a host with an account. `hosting.enabled` turns everything off.

**Shell** (`ShellHost.Hosting.cs`, `HostingViewModels.cs`, views)
- **Git Hosting Accounts** (a document): per provider, Sign In (the device code, Copy Code and Open Browser, Waiting…, Cancel), sign in with a personal access token, Sign Out, where tokens are kept, the server setting.
- **Pull Requests** window: all, mine or review requested; details (description in Markdown, reviewers, review threads with their file and line, conversation); Check Out (`GitService.FetchAndSwitchAsync`: a branch of the remote with its upstream, or a fork's `refs/pull/N/head`/`refs/merge-requests/N/head` onto `pr/N`/`mr/N`); Open in Browser; Create.
- **Review comments in the editor:** the current branch's pull request's unresolved threads at the end of their lines (`EditorInsights`, segments that follow edits), with a flyout showing the thread. `hosting.reviewComments`, `hosting.showResolvedComments`.
- **Create Pull Request** (a document): title from the branch, Markdown description, the target (the default branch first), draft; pushes the branch first.
- **CI status:** the status bar (`daedalus.hosting.ci`) and Git Changes, with Show Checks; refreshed on branch or HEAD changes and every `hosting.statusRefreshSeconds` (120); `hosting.ciStatus`.
- **Work Items** window (assigned to me, or search; Mention in Commit Message) and **`#` completion** in the commit message (a popup; Up, Down, Enter, Tab, Escape).
- **Publish to a Git Host:** provider, owner, name, visibility, description; creates the repository (and a repository with a first commit when the solution has none), adds the remote and pushes with `-u`.
- **Askpass:** `GIT_ASKPASS`/`SSH_ASKPASS` (`SSH_ASKPASS_REQUIRE=force`) are the `daedalus` executable, which forwards the prompt over a per-process pipe with a token (`AskpassServer`, `AskpassClient`) and prints the answer; the shell asks in a dialog, masking passwords and passphrases, and answers yes/no for ssh's host keys. Nothing is stored; the user's credential helper still comes first.
- **Worktrees** window: list (current, main, locked, prunable), Add (new or existing branch, a folder next to the repository), Open, Open in New Window, Lock/Unlock, Remove (forced only after a second confirmation), Prune.
- **Git LFS:** badges in Git Changes (LFS, LFS pointer, locked by …), Git LFS Locks (unlock, force), Lock/Unlock File, Download Files. Patterns come from `git check-attr`, so it works without git-lfs.
- **Several repositories:** the repositories of the solution's and projects' folders (`GitService.FindRepositoriesAsync`; nested repositories found); a picker in Git Changes and Switch Repository; gutter markers and blame use each file's own repository.
- **Commands and menus:** the Git menu's hosting and repository groups; context keys `hostingRepository`, `hostingProvider`, `gitRepositories`, `gitLfs`; icons `cloud`, `pull-request`, `comment`, `issue`, `worktree`, `account`, `sync`.

**Tests**

- **Plugins:**
  - `GitHubProviderTests` (9), `AzureDevOpsProviderTests` (6), `GitLabProviderTests` (5): each provider against a mock of its host's APIs and device flow (`tests/Shared/MockGitHub.cs`; the Azure DevOps and GitLab mocks in the tests): remote URLs, the device flow, token sign-in, refresh, pull requests, threads, checkout, creation, checks, work items, owners, publishing.
  - `HostingPluginHostTests` (3): the GitHub plugin in a real plugin host through `HostingService`: inactive until sign-in, the device flow and every request over the wire, a revoked session.
- **Headless UI** (`HostingShellTests`, 7): device sign-in on the Accounts page, the Pull Requests window and checkout over HTTP from the mock, review comments in the editor, CI status, Create Pull Request (pushing the branch), Work Items and `#` completion, the Worktrees window, LFS badges and the repository picker, and askpass end to end (git asking the `daedalus` apphost for a user name and a masked password).
- **Smoke test:** step `git.hosting` (M13b) drives the shipped app against the mock GitHub: device sign-in, the pull request listed, checked out over HTTP, its review comment in the editor and its checks, screenshots in the Blue, Light and Dark themes, `#` completion, askpass with the Native AOT executable, a worktree, sign-out.

**Docs:** ADR 0031; the user guide (Git: hosting, credentials and SSH passphrases, worktrees, Git LFS, several repositories); docs/plugins.md (proposed APIs, the contribution point, the changelog for 0.2.6); docs/plugin-protocol.md; the manifest's JSON schema; the roadmap; CLAUDE.md; README.

It was seen on the Mac too (develop at 03e3f79). The client now retries a refused connection within its 5-second budget and reports why a request fails (on stderr, which git shows); the test prints that reason.
- `TODO(issue)`: browsing the user's repositories in Clone.
