# M37 checkpoint: environment setup

Date: 2026-10-13. The maintainer asked the same day for the IDE to notice what's missing (the .NET SDK, git) and offer to install it, "same later for MAUI". No ADR: the policy is the one the roadmap's M37 section states (nothing installs without consent; user-local where possible).

## Done

**What's found** (`EnvironmentCheck`, workbench `Setup/`):
- **The .NET SDK**: `dotnet` from `DOTNET_ROOT`, then `PATH`, then where the installers put it (`%ProgramFiles%\dotnet`, `/usr/local/share/dotnet`, `~/.dotnet`, `/usr/share/dotnet`, `/usr/lib/dotnet`). Its SDKs come from `dotnet --list-sdks`. Runtimes without an SDK count as missing.
- **A solution's `global.json`**: checked by running `dotnet --version` in its folder, so the muxer's own roll-forward rules decide. A failure is a mismatch, with the version `global.json` asks for.
- **git** (`DAEDALUS_GIT` or `PATH`) and, with git, Git LFS. Docker, Podman, and WSL on Windows, with their versions.
- The process runner and the file checks are injectable: the tests use stand-ins.

**How it installs** (`InstallPlans`, one plan per tool and OS, shown in full before anything runs):
- **Windows**: winget (`Microsoft.DotNet.SDK.<major>`, `Git.Git`, `GitHub.GitLFS`, `RedHat.Podman`); the download page without winget; `wsl --install` in the terminal.
- **macOS**: the SDK through `dotnet-install.sh` into `~/.dotnet` (no password); git through `xcode-select --install`.
- **Linux**: the SDK the same way. git and Git LFS through the distribution's package manager, picked from `/etc/os-release` (apt, dnf, zypper, pacman, apk), in the integrated terminal, where `sudo` asks itself.
- **A pinned SDK** installs at its exact version (`dotnet-install --version`); winget installs its channel's newest patch.

**In the IDE** (`ShellHost.Setup.cs`, `EnvironmentViewModel`):
- **At startup**: a missing SDK or git is offered (Install… or Check Environment), except in the smoke test and benchmarks.
- **When a solution opens**: its `global.json` SDK is offered if it isn't installed.
- **Help → Check Environment**: lists each tool's state, version, path and what needs it, with Install…, Install in Terminal… or Open Download Page… The command shows as the button's tooltip.
- **After an install**: the environment is checked again, and a restart is offered. That offer doesn't hold up the install (a test found an install waiting for the notification's answer).
- **An SDK only in `~/.dotnet`**: becomes `DOTNET_ROOT` and goes first on `PATH` for the IDE and every process it starts, from startup on.

**Tests**:
- `EnvironmentCheckTests`: nothing found, versions, the `global.json` mismatch, the plans on each OS, the distributions' package managers, `os-release`.
- `EnvironmentShellTests`: the page on this machine, and an install declined, then agreed with a stand-in runner.

Nothing installs for real in any test.
