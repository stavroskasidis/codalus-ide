# M14c checkpoint: debugger sessions

Date: 2026-10-11. Decisions: [ADR 0039](../adr/0039-debugger-sessions.md) (sessions) and [ADR 0040](../adr/0040-hot-reload-while-debugging.md) (the Hot Reload research). This completes M14, after M14a ([ADR 0021](../adr/0021-debugger-depth.md)) and M14b ([m14b](m14b.md), [ADR 0032](../adr/0032-debug-companion-host.md)).

## Built

**Multiple startup projects**
- **The Startup Projects page** (`run.configureStartupProjects`: the Debug menu, and the solution's context menu). It chooses a single startup project or multiple ones. With multiple, each project gets an action (None, Start, Start without debugging), a launch profile and an order. The choice is saved with the solution's session.
- **F5** builds the solution once and starts the projects in order. Those set to Start debug in **one compound session**: `CompoundDebugAdapter` in its new independent mode, one netcoredbg per program, until the last one ends.
  - Threads are named after their program, and each program's exit is reported.
  - The Processes window lists every program.
  - Ctrl+F5 runs them all without the debugger.

**Debugging in the integrated terminal**
- `debug.console` = `integratedTerminal` starts a console app in a new terminal tab. netcoredbg has no `runInTerminal`, so `HeldLaunch` starts the program with a startup hook (`DaedalusStudio.Debugging.StartupHook`, netstandard2.0, shipped in `debughost/`). The hook holds it before `Main` until netcoredbg has attached and its module (and so its breakpoints) are loaded.
- The program reads input from the terminal. Stop ends it. **Detach All leaves it running**, which closes the M14b gap.
- DAP `runInTerminal` itself is implemented (`DapConnection.Handle`, `ITerminalLauncher`) for adapters that send it.
- **Found by the shell test, and fixed:** netcoredbg 3.2.0 on Windows ends an **apphost** (`App.exe`) that it detaches from while it is stopped at a breakpoint (0xC0000409), unless a function evaluation ran since the stop. This affected M14b's Detach All too. `DebugService` now prepares every detach from a stopped program: it removes the breakpoints and exception filters, and evaluates `System.Environment.ProcessId`.

**Remote targets** (`Workbench/Debugging/Remote`)
- `SshTarget`, `ContainerTarget` and `WslTarget` run `sh -c` scripts through `ssh -T`, `docker exec -i` (the `debug.containerTool` setting: docker, podman, or one inside WSL) and `wsl.exe --exec`.
- netcoredbg runs there as a **pipe transport** (`DebugAdapterStartInfo`).
- **Processes** are listed from `/proc`, with .NET ones recognized by `libcoreclr`; `ps` is the fallback.
- **netcoredbg is copied on first use** with consent, streamed into `tar -xzf -`: the pinned build of the target's platform, from `DAEDALUS_NETCOREDBG_<PLATFORM>`, the local build, `.work/netcoredbg-<platform>` (`eng/get-netcoredbg.sh --platform`) or a verified download.
- **Source maps**: `PathMappingDebugAdapter` and `SourceMap`, given (`debug.sourceFileMap`) or inferred from the solution's files.
- **Commands**: Debug → Attach to Process on a Remote Machine (`debug.attachRemote`), and Reattach. SSH passwords go through the shell's askpass.

**The WSL launch profile** (`"commandName": "WSL2"`, `"distributionName"`): Ctrl+F5 runs the Windows build output on the distribution's `dotnet` through `/mnt`, and F5 launches it under netcoredbg in the distribution.

**Roslyn components** (`"commandName": "DebugRoslynComponent"`, `"targetProject"`): `RoslynComponents` runs the SDK's `csc.dll` on the target's design-time command line, from a response file. The outputs go to a temporary folder. Breakpoints in the generator stop.

**Just-In-Time debugging** (Debug → Just-In-Time Debugging, off by default, consent per OS)
- It sets the runtime's crash-dump variables per user, with no administrator rights: Windows user environment, `environment.d` and `~/.profile` on Linux, `launchctl` and a LaunchAgent on macOS.
- `CrashDumpWatcher` notices each new dump, and the shell offers to open it in the dump view.
- Turning it off removes the variables.

**Hot Reload while debugging (research, ADR 0040)**: not possible today. With netcoredbg attached, the runtime refuses `dotnet watch`'s `ApplyUpdate` ("Assembly updates cannot be applied while a debugger is attached"). netcoredbg can apply Edit and Continue deltas (`ApplyChanges`) only through its MI interpreter (`-apply-deltas`), only for launched processes, and not over DAP.

**Fixtures**
- `samples/Debugging/Sessions.slnx` adds `Partner` (the second program of a compound launch), `Generator` (with its `DebugRoslynComponent` profile) and `GeneratorTarget`.
- The Debuggee gets `--read` (console input) and `--crash` (an unhandled exception, which also closes M14b's "app that crashes on purpose" gap).

**Diagnostics**: `DAEDALUS_NETCOREDBG_LOG=<folder>` logs netcoredbg's DAP traffic.

## Tests

**Unit and integration**
- **Workbench** (`LaunchSettingsTests`): the `WSL2` and `DebugRoslynComponent` profiles, the WSL plan (Linux paths, the `sh -lc` script with its quoting) and the compiler's response file.
- **Debugging, on netcoredbg:**
  - `CompoundDebugAdapterTests`: independent programs ending one by one, and a stop waiting for the one shown.
  - `RunInTerminalTests`: the reverse request answered with a process id or the failure.
  - `TerminalLaunchTests` (a real pseudo-terminal): input, a breakpoint and Detach All; Stop; Detach All from an apphost stopped at a breakpoint.
  - `DebugServiceTests`: Detach All from an attached apphost stopped at a breakpoint.
  - `SessionsTests` (`Sessions.slnx`): two startup projects in one session, one ending before the other; a source generator stopping while the compiler runs on its target.
  - `RemoteTests` (`RemoteFixture`'s local stand-ins): attach in WSL and launch through the WSL profile (Windows); attach over SSH through a stand-in `ssh` (Linux, macOS); attach in a Podman container with a local Ubuntu image (Linux, and WSL's Podman from Windows); SSH destinations, listings, source maps and WSL paths.
  - `JitDebuggingTests`: registration in stand-in environments (never the real one), the Linux files, and a crash writing a dump that the watcher reports and ClrMD opens.
  - `HotReloadResearchTests`: opt-in (`DAEDALUS_RESEARCH=1`), the ADR 0040 experiment.
- **Headless UI** (`DebugSessionsTests`):
  - the Startup Projects page and a compound launch, with the Processes window and persistence;
  - a console app in the terminal with input and Detach All;
  - F5 on the generator;
  - Just-In-Time debugging offering a crashed program's dump.

**End to end**: the smoke steps `debug.compound`, `debug.terminal`, `debug.roslyn` and `debug.remote`, on the published Native AOT app. `debug.remote` attaches in WSL on Windows, and over a stand-in `ssh` elsewhere. Screenshots: `smoke-test-startup-projects.png`, `smoke-test-debug-compound.png`, `smoke-test-debug-terminal.png`, `smoke-test-debug-roslyn.png` and `smoke-test-debug-remote.png`.

**Found by validation and fixed**
- **The netcoredbg apphost detach crash** (above), found by the headless UI test.
- **Detaching while running** races with the program's own debug events (0xC0000354), so a stopped program is prepared and stays stopped for the detach.
- **Paths:** the compiler's response file and the entry module took file names with `/` only, which failed on Linux for Windows-style paths.
- **Container .NET:** a distribution's own .NET package can't run in a bare container (it needs the system `libunwind`), so the container tests mount a Microsoft build of .NET.
- **Context keys:** the Debug menu's `debugStopped` enablement trails the debugger state, so the tests wait for it before running `debug.continue`.

## Deviations and gaps

- **Multiple startup projects:**
  - a stop in one program doesn't pause the others (no "break all processes"). `TODO(issue)`
  - a web project's page isn't debugged in a multi-project session (its browser opens). `TODO(issue)`
  - the toolbar's startup project box shows one project. `TODO(issue)`
- **runInTerminal** is emulated for netcoredbg (attach after a startup hook). Programs that disable startup hooks can't be debugged in the terminal. DAP's own `runInTerminal` is supported for adapters that send it.
- **netcoredbg's detach of a stopped apphost** is worked around with a function evaluation. `TODO(issue)`: report it to Samsung/netcoredbg.
- **Remote:**
  - Windows targets (over SSH, or Windows containers) aren't supported: the scripts are `sh`. `TODO(issue)`
  - targets need `tar`, `gzip` and `libstdc++`.
  - there are no SSH jump hosts beyond `~/.ssh/config`.
  - real SSH servers and remote machines aren't tested (local stand-ins only, as required).
- **The WSL profile:**
  - a custom `automount.root` isn't read;
  - a web project's browser isn't opened from WSL. `TODO(issue)`
- **Roslyn components:** F# isn't supported, and design-time-only generators aren't covered.
- **Just-In-Time:**
  - live attach as the system JIT debugger (`AeDebug`, administrator rights) isn't offered. `TODO(issue)`
  - registration was tested against stand-in environments only (by design). The real Windows, Linux and macOS writers run only when a user turns it on.
- **Hot Reload while debugging:** not possible with netcoredbg's DAP today (ADR 0040). `TODO(issue)`: propose a DAP request upstream.
