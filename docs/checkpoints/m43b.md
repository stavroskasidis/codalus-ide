# M43b checkpoint: the desktop-CLR debugger and tests on .NET Framework

Date: 2026-10-17. The second and last part of M43, the last milestone of the Windows desktop phase (D31: Windows-only features; "M43 includes its debugger"). With it, M43 is done. Decisions: [ADR 0076](../adr/0076-debugging-the-desktop-clr.md) (it amends ADR 0007, 0032 and 0075).

## The spike

The roadmap planned a desktop-CLR port of netcoredbg (MIT), after a spike. The spike compared it with a managed DAP adapter of our own in the debug companion, M20b's precedent (ADR 0065), and chose the adapter:
- **The desktop CLR's debugging API comes with every install:** `mscoree.dll`'s `CLRCreateInstance` → `ICLRMetaHost::GetRuntime("v4.0.30319")` → `ICLRRuntimeInfo::GetInterface(CLSID_CLRDebuggingLegacy)` gives that runtime's `mscordbi` `ICorDebug`, the same interface CoreCLR's debuggers use. Nothing to ship; CLR 2 the same way with `v2.0.50727`.
- **The port** means replacing netcoredbg's dbgshim start path in C++, keeping its managed part (symbols, evaluation) hosted on CoreCLR inside a process debugging the desktop CLR, and a Windows-only native build in CI, packaged and signed under `debugger/netfx/`, none of it buildable or testable on Linux.
- **The adapter** drives ICorDebug from C# through **ClrDebug** (lordmilko, NuGet 0.4.2, MIT, maintained, no dependencies; source-generated COM interop, compiles on every OS), reads metadata and portable PDBs with System.Reflection.Metadata, and evaluates C# itself. Everything above the ICorDebug calls runs on every OS against a fake. MDbg's CorApi (unclear licence) and dnSpy's `dndbg` (GPL) weren't used; vsdbg is proprietary.

## Done

**The adapter** (`codalus-debughost --netfx-dap`, `src/Codalus.Debugging.Host/NetFx`):
- **`CorDebugTarget`/`CorDebugger`** (Windows, ClrDebug): the runtime version from the program's `.config` `supportedRuntime` (first installed) or `GetVersionFromFile`, or for an attach from `clr.dll`/`mscorwks.dll` in the process; `CreateProcess` with a Unicode environment block and pipes for stdout and stderr (the Debug Console) or a console window of its own (`NewConsole`), `DebugActiveProcess` to attach; the adapter's own standard handles kept out of the debuggee. Callbacks become `ClrEvent`s in a channel, the process stopped until the session continues; during a func-eval the other callbacks continue at once (modules and threads still reported). 32-bit programs and processes are refused with what to change. COM errors become messages with the HRESULT's name.
- **`ClrModuleInfo`:** a module's metadata and portable PDB (next to it, from the debug directory, or embedded): type, method, field and property names, signatures as C# names, enums and attributes, sequence points both ways, local scopes; Windows PDBs reported in the symbol status, not read.
- **`NetFxDebugSession`** (the DAP layer, every OS): breakpoints bound as modules load (each method's first offset on the line, or the next line with code; set while the program runs, it's stopped for the change and goes on), conditions evaluated, function breakpoints; line stepping (`StepRange` over the sequence point, hidden lines and mid-line stops step on), Just My Code (user code is what has symbols and isn't optimized; `SetJMCStatus`, JMC steppers, stepping out of code without symbols or marked non-user), step filtering of accessors and operators; threads (names from `Thread.m_Name`), stacks (internal frames as labels, frames without source dimmed); locals and arguments by the PDB, `this`, an async method's or iterator's hoisted variables; members by fields and getters (5 s func-eval limit, the rest skipped after a timeout); enums (flags), `decimal`, `DateTime`, `TimeSpan`, `Nullable<T>`, boxed primitives, arrays (100 elements, several dimensions); setting primitives; exceptions (`all` with netcoredbg's type-name condition, `user-unhandled`; with Just My Code, once per exception where it's thrown in user code) with message, stack trace and inner exceptions; pause; output and `Debugger.Log`; detach and terminate.
- **`ExpressionParser` and `ClrEvaluator`:** a C# subset (literals with C#'s types, names, `this`, members, `?.`, indexers, calls, unary and binary operators with C#'s precedence and numeric promotion, `?:`, `??`, casts); names resolve to locals, arguments, `this`'s members, static members of the method's types, types (keywords, the method's namespace, `System`, a unique name) and namespaces; overloads picked by argument types; calls through `ICorDebugEval` with the generic class's type arguments.
- Off Windows the mode answers DAP and refuses launch and attach: ".NET Framework programs run and debug only on Windows."

**Wiring** (`DebugService`, `DesktopClr`, `ProcessList`, the shell):
- The debug service sends a launch whose program is a managed `.exe` (`DesktopClr.IsManagedExecutable`: a PE with a CLI header; .NET Core's apphosts are native) and an attach to a process with `clr.dll` or `mscorwks.dll` and no `coreclr.dll` to the desktop-CLR adapter (`DesktopClrAdapter`, `IsDesktopClrProgram`, `IsDesktopClrProcess`, settable for tests). F5, multiple startup projects, test hosts and plugins' launches take it without knowing. A terminal launch uses the Debug Console and says why.
- M43a's "debugging comes later" offer and its multiple-startup exclusion are gone. Attach to Process shows ".NET Framework" for desktop-CLR processes (`ProcessEntry.IsDesktopClr`).
- **Old-style projects build portable PDBs:** the build host's targets file sets `DebugType` `portable` where a non-SDK-style .NET Framework project asks for `full` or `pdbonly` (`CodalusKeepDebugType=true` keeps it).

**Tests on .NET Framework:**
- Old-style test projects are test projects by Visual Studio's test project type GUID in `ProjectTypeGuids` (or `IsTestProject`), on VSTest. An import of Visual Studio's targets conditioned on `Exists(...)` no longer makes a project unbuildable (the TeamTest targets of MSTest's old template).
- A debugged .NET Framework test host runs as the IDE's architecture (`TargetPlatform` x64 or ARM64) unless `testing.architecture` chose one.
- Fixtures: `samples/NetFramework` gains **NUnitTests** (NUnit 3.14 on `net48`) and **LegacyTests** (old-style MSTest v2 2.2.10 with `packages.config`, as Visual Studio's Unit Test Project (.NET Framework) template writes it); `samples/Debugging/NetFxDebuggee` is the debugger's `net48` console app (a list loop, auto-properties and a getter, a `[Flags]` enum, an array, a method to call, an async method, `Debug.WriteLine`, a caught exception, exit code 3, and `wait` for attach tests).

**Smoke:** `netfx.projects` on Windows now also debugs the console app with F5 to a breakpoint in `Main`, evaluates `greeter.Greet()` and saves `netfx-debugging.png`.

## Tests

- **Every OS:** `NetFxExpressionTests` (Debugging, 94): precedence and literals, errors, numeric promotion, casts, exception conditions, hoisted and backing field names, Windows command-line quoting. `NetFxSessionTests` (7): the net48 debuggee's metadata and portable PDB (locations, lines, locals, ranges, members, enums, attributes); a PDB that isn't portable; a whole session through DAP against a fake ICorDebug and the real PDB (pending, conditional and function breakpoints bound on module load, stacks, locals, members, getters, enums, arrays, evaluation with calls and static fields and boxed primitives, setVariable, a hidden line and Just My Code while stepping, an async method's variables, exceptions filtered by type and stage, pause, output, the exit code); attach and detach; terminate; the adapter process off Windows; the debug service's routing (and netcoredbg for the rest). Build host `NetFrameworkTests` (+6): project type GUIDs, the portable PDB targets, `Exists` conditions, and in the fixture test the NUnit project, the old-style MSTest project (a test project, its packages, its adapter copied) and LegacyApp's portable PDB. Plugins `OlderFrameworksTests` (+1): the test host's architecture when debugging .NET Framework tests.
- **Windows only** (skipped elsewhere; CI's `windows-latest` has .NET Framework 4.8): `NetFxDebuggerTests` (3): the real adapter on the desktop CLR (breakpoint before load, stack, locals, members, getters, evaluation with calls and `Math.Max`, a step, an async method, the filtered exception's info and stack trace, output, `Debug.WriteLine`, exit code 3); F5's launch plan through the debug service; Attach to Process on a running process found by `ProcessList`, then detach. `NetFrameworkTestingTests` (Plugins, 2): xUnit, NUnit and old-style MSTest tests discovered and run on VSTest's .NET Framework hosts; a net48 test debugged to its breakpoint, with a static getter evaluated. `NetFrameworkShellTests.Windows_starts_and_debugs_the_net48_console_app` (headless UI): Start Without Debugging, then F5 to a breakpoint and an evaluation.

## Gaps

- **32-bit processes** (x86, `Prefer32Bit`): refused with what to change; an x86 debug companion would debug them. `TODO(issue)`
- **Windows PDBs** (assemblies built outside Codalus with `DebugType` `full`): reported, not read. `TODO(issue)`
- **CLR 2** (.NET 2.0 to 3.5): wired (the runtime version from the program), untested: no CI runner has .NET 3.5 turned on. `TODO(issue)`
- **Not in the .NET Framework debugger:** mixed-mode debugging, Edit and Continue, Set Next Statement, data breakpoints, the integrated terminal (the Debug Console or a console window), `DebuggerTypeProxy`; expressions beyond the subset (`new`, lambdas, `typeof`, generic methods, assignments, boxing a number for an `object` parameter); getters of generic base types reached through a non-generic derived type. `TODO(issue)`
- **Code coverage on .NET Framework test hosts:** Coverlet's collector is unvalidated there. `TODO(issue)`
- **Running and debugging on Mono** (Linux and macOS): a later decision (D31), as in M43a.
