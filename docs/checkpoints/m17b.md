# M17b checkpoint: .NET Aspire

Date: 2026-10-11. Decisions: [ADR 0043](../adr/0043-aspire-integration.md). Part of M17 with [m17a](m17a.md) and [m17c](m17c.md).

## Built

**Run and debug an AppHost** (`ShellHost.Aspire.cs`): F5 or Ctrl+F5 on a project whose `IsAspireHost` is true (the build host reports it, `ProjectInfo.IsAspireHost`) starts it with its launch profile and:
- `DEBUG_SESSION_PORT`, `DEBUG_SESSION_TOKEN`, `DEBUG_SESSION_RUN_MODE` and `DEBUG_SESSION_INFO`, pointing its orchestrator at our IDE execution server;
- `DOTNET_RESOURCE_SERVICE_ENDPOINT_URL` (a free loopback port, plain HTTP/2) and `ASPIRE_DASHBOARD_RESOURCESERVICE_APIKEY` (our key), so we can read its resource service.

**The IDE execution protocol** (`Workbench/Aspire/IdeExecutionServer.cs`): `HttpListener` on localhost with the bearer token; `GET /info`, `PUT /run_session` (a project: path, mode, launch profile, environment, arguments), `DELETE /run_session/{id}`, and the `/run_session/notify` WebSocket (`processRestarted`, `sessionTerminated`, `serviceLogs`). Each project starts with its launch profile (or the one named, or none), the AppHost's environment over it and its arguments:
- Ctrl+F5: a program of `RunService` with its Run channel; its output also goes to the dashboard's console logs;
- F5: a program of the AppHost's compound debug session (`DebugService.LaunchAsync(…, compound: true)`, new `AddLaunchAsync`), so the AppHost and its projects debug as one session.

**The resource service client** (`AspireResourceClient`, `Protobuf.cs`): gRPC framing over `HttpClient` (HTTP/2 prior knowledge, trailers) and a protocol buffers reader of our own, with the field numbers of Aspire's `dashboard_service.proto` (read from Aspire.Hosting 13.1's descriptors): `WatchResources`, `WatchResourceConsoleLogs`, `ExecuteResourceCommand`. Nothing new in the Native AOT shell.

**The Aspire window**: the resources (projects, containers, executables; hidden ones and parameters left out) with state glyphs and endpoints; the selected one's console output, environment, endpoints and properties; Start, Stop and Restart (the resource's commands), Open Endpoint, Open Dashboard (the login URL the AppHost prints; opened at start with `launchBrowser`). Debug → Open the Aspire Dashboard.

**D12**: the orchestration package declares MIT with licence acceptance and carries Microsoft's EULA for DCP's binaries; we never ship, download or start DCP (ADR 0043).

**Fixture**: `samples/Containers/Aspire` and `Aspire.slnx`: an AppHost (Aspire 13.1, `Aspire.AppHost.Sdk`) with an api, a frontend that waits for it and calls it, and a Redis container with `WithExplicitStart()` (listed, never pulled by tests).

## Tests

- **Workbench** `AspireTests` (the real AppHost and orchestrator): the AppHost asks our server for its two projects, the resource service lists them running and the cache not started, the frontend answers through the api, the api's console logs arrive, and its stop command reaches us as a `DELETE`.
- **Headless UI** `AspireShellTests`: Ctrl+F5 (resources, dashboard URL, Run channels, the frontend's answer, logs and environment in the window, Stop through the command ends the program); F5 (three programs in one session, a breakpoint in the api stops a request coming through the frontend, stop ends everything).
- **Smoke** `aspire.run`: Ctrl+F5 on the AppHost, the resources running, the frontend answering, the api's output, the window (`smoke-test-aspire.png`), cleanup.
