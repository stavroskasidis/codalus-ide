# M42 checkpoint: WCF

Date: 2026-10-14. Decision: [ADR 0066](../adr/0066-wcf-through-dotnet-svcutil-and-our-own-test-client.md). Builds on M15c's service references (ADR 0041).

**Status: done.** WCF clients are generated, updated and removed through the user's own `dotnet-svcutil`. The WCF Test Client calls a service's operations from its metadata. New Project offers the CoreWCF templates, and `.config` files know `<system.serviceModel>`. All of it works on every OS.

## Built

**Build host** (`SolutionSession.Wcf.cs`, `ProjectManagement/WcfReferences.cs`, protocol `wcf/*` in `docs/project-protocol.md`):
- `wcf/tool` finds `dotnet-svcutil` (local or global). With `install`, it restores the manifest or installs the tool as a local tool.
- `wcf/add` runs `dotnet svcutil` in the project's folder (trusted solutions only, one at a time with scaffolding) into `Connected Services/<name>`, with Visual Studio's dialog's options.
- `wcf/update` uses the tool's `--update`, or generates again with new options.
- `wcf/remove` sends the folder to the trash.
- `ConnectedService.json` is written next to the tool's params file, so Visual Studio's provider reads the reference too.
- `serviceReferences/list` includes WCF references (kind `wcf`, with their input and options) and the `System.ServiceModel` packages.

**Workbench:**
- `ServiceReferenceService` gains the WCF operations and a Service References output channel.
- `Wcf/WsdlDocument` (WSDL 1.1 with its XML Schema, imports, policies) and `Wcf/WcfTestClient`:
  - load from a file, a `?wsdl` address or the service's address;
  - sample requests;
  - SOAP 1.1 and 1.2 over HTTP, with WS-Addressing headers where needed;
  - faults.

**Shell:**
- The Service References page has a WCF kind:
  - name, namespace, operations, collection type, internal types and type reuse;
  - the selected reference's namespace, operations and internal types are editable, and Save generates it again;
  - Refresh, Open (its `Reference.cs`), Test… and Remove.
  - Adding offers to install `dotnet-svcutil` when it's missing.
- Tools → **WCF Test Client** (`wcf.testClient`, `ShellHost.Wcf.cs`, `WcfTestClientViewModel`): an address box, the operations by endpoint (with the reason when one can't be tested), the request to edit, Invoke, and the response.
- New Project offers **Install the CoreWCF service templates…** while none is installed (the Templates plugin's offers generalized from Avalonia's).

**Markup host:** `ServiceModelKnowledge` and `XmlLanguage.ServiceModel.cs` give `.config` files:
- completion of `system.serviceModel`'s elements, attributes and values, with the file's own binding and behavior configuration names;
- hover;
- warnings for unknown elements and for values outside a choice.

**Fixture:** `samples/Wcf`:
- `Calculator.Service`: CoreWCF 1.9.1, BasicHttpBinding at `/CalculatorService.svc`, metadata on;
- `Client`;
- `contracts/Calculator.wsdl`, the service's `?singleWsdl`;
- `dotnet-svcutil` 8.0.0 in `.config/dotnet-tools.json`.
