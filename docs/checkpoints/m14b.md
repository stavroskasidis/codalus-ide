# M14b checkpoint: the debug companion host

Date: 2026-10-11. Decision: [ADR 0032](../adr/0032-debug-companion-host.md). Builds on M14a ([ADR 0021](../adr/0021-debugger-depth.md)).

## Built

**The debug companion host** (`daedalus-debughost`, `src/DaedalusStudio.Debugging.Host`, shipped in `debughost/`)
- Started on first use and supervised (`DebugCompanion` in the workbench, `DAEDALUS_DEBUGHOST`); JSON-RPC methods `daedalus/debug/*` (`docs/protocol.md`).
- `TypeAttributes`: `[DebuggerDisplay]`, `[DebuggerTypeProxy]` and `[DebuggerBrowsable]` from the modules' metadata, base types included.
- `Dumps`: ClrMD 4.1 opens a dump: threads, managed stacks, exceptions, the heap by type, instances and fields. Frames map to source lines through the portable PDBs (`SourceLines`), from the JIT's IL map at the return address; frames without a map get no line. Create Dump writes a dump through the diagnostics IPC (DiagnosticsClient).

**Display**
- `DebuggerDisplays` applies `[DebuggerDisplay]` in Locals, Autos, Watch, QuickWatch, data tips and evaluations. Each `{expression}` is evaluated on the object (`,nq` drops the quotes) within 3 seconds, and `[DebuggerBrowsable(Never)]` hides members, fields included.
- **Visualizers** (`CollectionVisualizers`): Grid for arrays and the common collections (`.ToArray()` when needed, 500 rows, an object's members as columns, a padded text table) and Image for byte arrays (Base64 through `System.Convert`, PNG/JPEG/GIF/BMP/WebP/ICO, opened in the image viewer). The View submenu offers them by type.
- **Pinned data tips**: the data tip's pin button. `PinnedDataTipStore` (workbench) evaluates every tip at each pause and frame change, marking changed values and errors. `PinnedDataTipLayer` floats them over the editor right of their lines, with comments in a flyout, Copy, Add Watch, Unpin, QuickWatch on double-click, and edits followed through text anchors. They are saved with the session; Clear All DataTips removes them.

**Plugins** (API 0.2.7; M13b took 0.2.6)
- Proposed `IDebug.RegisterVisualizer(options, visualize)`: types by name or prefix; `IDebugVisualizerContext.EvaluateAsync` in the paused frame; a text or table `VisualizerView`. Protocol: `debug/registerVisualizer`, `debug/unregisterVisualizer`, `debug/visualize`, `debug/evaluate`. The new activation event is `onDebug`.
- `DebugVisualizerRegistry` (workbench), whose entries are dropped with their plugin host.
- `samples/plugins/DictionaryVisualizer` reads a `Dictionary<TKey, TValue>`'s `_entries`, skipping removed ones.

**Windows and toolbars**
- **Parallel Stacks** (`ParallelStacks` in the workbench: stacks merged from the outermost frame), **Parallel Watch** (an expression in each thread's topmost frame with source).
- **Processes** (state, Attach, Detach All for attached sessions, Terminate All) and the **Debug Location** toolbar (process, thread and frame pickers in the standard toolbar while paused).

**Breakpoints and exceptions** (client-side, like M14a's hit counts)
- **Breakpoint filters** (`BreakpointFilter`): Visual Studio's syntax over thread id and name, process id and name, and machine name; a step in the Conditions and Actions dialog; saved and exported with the breakpoint.
- **Exception module conditions**: a box per type in Exception Settings (wildcards, `!` excludes), matched against the module of the throwing frame (`moduleId` on DAP stack frames); saved with the session.
- **`debug.stepOverPropertiesAndOperators`**: netcoredbg's `enableStepFiltering`, separate from Just My Code.
- **Detach All** (`DebugService.DetachAsync`).

**Commands**
- `debug.openDump`, `debug.createDump`, `debug.detachAll`, `debug.clearDataTips`;
- the tool windows `debug.parallelStacks`, `debug.parallelWatch`, `debug.processes`.

  - `BreakpointFilterSessionTests`: of two named threads through one line, only the filtered one breaks;
  - `DebuggerDepthTests`: module conditions, matched by the throwing frame's module;

  - `PluginVisualizerTests`: the real plugin host runs the DictionaryVisualizer sample and reads a dictionary with a removed entry;
  - `CompanionTests`: the attributes from metadata, full dumps of a running program and of one paused at a breakpoint (the paused frame on its own line, its caller on the call's line), and runtime versions from the framework folder.

  - grid and image visualizers;
  - a pinned data tip over the editor with its comment;
  - the Processes window;
  - the Debug Location toolbar picking a frame;

**End to end:** the smoke step `debug.companion`, on the published Native AOT app:
- Parallel Stacks with the active thread;

Screenshots: `smoke-test-debug-companion.png` and `smoke-test-dump.png`.

**Found by validation and fixed**
- The dump view crashed while loading (its tab control raised `SelectionChanged` before the named fields were set), only in the windowed app. There is now a headless test for it.
- The leaf frame of a paused thread was mapped from "return address minus one", so it showed the previous line. ClrMD's IL map ranges end exclusively, so an address on a boundary matched the range before it.
- On Linux, the runtime version read as 0.0, because ELF modules have no version resource. It now comes from the framework folder.
- A test assumed that the compiler always marks backing fields `Never`. It does that in Debug builds only.

## Deviations and gaps

- **Type proxies:** `[DebuggerTypeProxy]` is read, but showing one means evaluating `new Proxy(value)`, which netcoredbg can't. Collections have the Grid Visualizer instead. `TODO(issue)`
- **Make Object ID**, **return values after Step Out**, **freezing threads**, the **Memory window**: netcoredbg has no handles, return values, thread suspension or `readMemory`. The companion can't hold handles: it never attaches to the live process. `TODO(issue)`: upstream netcoredbg.
- **Symbol settings:** no symbol servers or paths. netcoredbg and ClrMD read the PDBs next to the modules; library sources still come from embedded sources and Source Link (ADR 0017). `TODO(issue)`
- **Grid:** `IEnumerable` in general and `DataTable` aren't covered (extension methods and `new` can't be evaluated); the roadmap asked for both.
- **The visualizer plugin API is declarative** (text or a table), not F3's rich surface.
- **Detach All only for attached programs:** a launched program's console is netcoredbg's (no `runInTerminal`), so it dies at its next console write once netcoredbg exits; found by a test. `TODO(issue)`: `runInTerminal` (M14c).
- **macOS:** createdump can stall on a program that netcoredbg holds paused. The Mac's smoke run hung there for 12 minutes, with createdump orphaned afterwards. A dump request now times out after 3 minutes and ends the createdump it started, and on macOS the smoke step dumps the build host instead. macOS core dumps don't record the process id. `TODO(issue)`: find out why createdump stalls under netcoredbg on macOS (the test that dumps a paused `dotnet exec` debuggee passes there).
- **Dumps from another OS** don't open (the runtime's DAC must load on the reading machine). Cross-OS DACs from the symbol server are a possible follow-up. `TODO(issue)`
- **Step filtering** is passed to netcoredbg and not separately tested.
- **Parallel Stacks' task view** (async state machines as tasks) isn't built: the thread view only. `TODO(issue)`
- **The budgets** (F10 to locals ≤ 150 ms p95, data tip ≤ 100 ms, a 10k-element collection paged without frames over 50 ms) aren't measured yet, and the variable trees don't page large collections (the grid caps at 500 rows). `TODO(issue)`: benchmark scenarios.
- **Fixtures:** the async deadlock and the app that crashes on purpose aren't in `samples/Debugging`; dumps are tested on live processes (running, and paused at a breakpoint). `TODO(issue)`
