# M59 checkpoint: no telemetry from the tools the IDE runs

Date: 2026-11-13. The roadmap's [M59](../roadmap.md#m59--no-telemetry-from-the-tools-the-ide-runs), D50 and D51 ([ADR 0098](../adr/0098-no-telemetry-from-the-tools-the-ide-runs.md)). One pull request.

## Done

**One helper.** `ToolTelemetry` (`Codalus.Platform`, compiled into `Codalus.Rpc`, the build and REPL hosts and the test plugin as an internal copy) adds `DOTNET_CLI_TELEMETRY_OPTOUT`, `AVALONIA_TELEMETRY_OPTOUT`, `TESTINGPLATFORM_TELEMETRY_OPTOUT` and `DOTNET_SVCUTIL_TELEMETRY_OPTOUT` to a process's environment, each only when the environment doesn't already have it: a user who opted in stays opted in. It replaces the eight call sites that set the SDK's variable themselves.

**Hosts.** `ProcessLaunchInfo.Host` (and `ToolTelemetryOptOut`) asks the launcher to add the opt-outs where the process starts: the build host (so MSBuild's nodes, `dotnet ef`, restore, `dotnet tool` and `svcutil` it starts have them too), the language, markup, debug companion, diagnostics, data, plugin, T4 and REPL hosts, the WinForms designer, FsAutoComplete, and plugins' language servers. The previewer and the icon compiler add them to their own start. On a remote machine, `process/spawn` carries `toolTelemetryOptOut` and the server adds them there, keeping a value that machine has; the server's own environment, which its terminals inherit, is unchanged.

**Tools.** `dotnet watch` (the plan's environment: the program it starts inherits them from it), `dotnet new` and the template commands, the build host's `dotnet --version`, `dotnet nuget verify`, Check Environment, benchmarks, the web development tools, installs the IDE runs, Microsoft.Testing.Platform's test programs, and the script of a remote test environment (`export NAME="${NAME-1}"`).

**Left alone, and why.** The integrated terminal, the programs the user runs and debugs (a debug adapter's program inherits the adapter's environment, so the adapters get nothing), tasks from `tasks.json`, external tools, agent mode's commands, external agents and MCP servers: their telemetry is the user's choice. Git, docker, podman, ssh, Node and npm have none of these switches.

**Avalonia Accelerate.** The package's task refuses the opt-out on the Community and Trial tiers, with "Avalonia Accelerate Community requires telemetry. To opt out, please upgrade to a paid tier." (found in `Avalonia.BuildServices` 11.3.2). The build output adds a line after it: the IDE set the variable, and the build passes with `AVALONIA_TELEMETRY_OPTOUT=0` in the environment Codalus starts with, or on a tier that allows the opt-out.

**The source scan.** `ToolTelemetryTests` fails when a file in `src/` starts a process without the helper and isn't listed with why, and when a listed file no longer needs its line.

**The repository's own builds.** `eng/telemetry-optout.sh`, sourced by `validate.sh`, `smoke-test.sh`, `wsl-test.sh`, `ci-test.sh`, `compat-containers.sh` (and passed into its containers) and `package.sh`. `pipeline.yml`, `compat.yml` and `pages.yml` set the four variables in their top-level `env`, and `.github/actions/setup`'s first step fails a job that runs without one. `CONTRIBUTING.md` says how to set them for a build outside the scripts.

**Docs.** The user guide (Settings › Updates and network access: the variables, what's left alone, Avalonia's tiers), ADR 0098, `docs/remote-protocol.md`, `CONTRIBUTING.md`, the Home page, `CHANGELOG.md` and the roadmap (status, the Security track, D51).
