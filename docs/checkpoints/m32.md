# M32 checkpoint: self-update

Date: 2026-10-11. Decision: [ADR 0029](../adr/0029-self-update.md). Builds on M31's installers and update channels ([M31](m31.md)).

## Built

**The policy** (workbench `Updates/`, no Velopack types)
- **`UpdateService`:**
  - the schedule: once the window is interactive, then every four hours, off the UI thread, with Help → Check for Updates on demand;
  - `update.mode`: `auto` downloads in the background, `notify` offers the release, `off` checks only when asked;
  - `update.channel`: switching nightly → stable confirms, then installs an older version;
  - the states: Disabled, Checking, UpToDate, Available, Downloading with its percentage, Ready, Failed.
- **`InstallInfo`**, the kind of install:
  - development builds never check;
  - Velopack installs update themselves;
  - `.deb` and `.rpm` installs are told to use the package manager;
  - the zip, `.app` zip and tar.gz get a link.
  
  An install's default channel is its own.
- **`ReleaseVersions`:** SemVer 2 precedence.
- **The release stores:**
  - `GitHubReleaseStore`: the newest release of the channel's kind that carries its feed; "(pulled)" releases are skipped; packages are found in older releases; a token for a private repository (`DAEDALUS_UPDATE_TOKEN` or `gh auth token`);
  - `FolderReleaseStore`: tests and the update test.
- **`FeedSignature`:** ECDSA P-256 / SHA-256 over each `releases.<channel>.json`. It refuses a feed that is unsigned, doesn't verify, or lists a package without SHA-256. The public key is built in.

**The shell**
- **`Infrastructure/Updates.cs`:** the stores as Velopack's `IUpdateSource`; `UpdateManager` for installs; a feed-only backend for the others; the notes of every skipped version; `daedalus --update-now`, which checks, downloads and applies after exit without a window.
- **`ShellHost.Updates.cs`:**
  - status bar items: "Downloading 0.3.0… 42%" and "Restart to update (0.3.0)", the latter hidden while debugging or building;
  - the restart closes the window the usual way and restarts with the open solution; quitting applies the update without a restart;
  - notifications for notify mode and other installs;
  - the channel switch;
  - What's New: once after an update, and on Help → What's New.
- **Settings:** `update.mode` and `update.channel` under Options → Environment → Updates. The Help menu has Check for Updates and What's New.
- **`eng/package.sh` signs the feeds** with `DAEDALUS_FEED_KEY` (the `FEED_SIGNING_KEY` secret, generated 2026-10-11), and makes delta packages when `zstd` is there.

**Tests**
- **Workbench** (`UpdateServiceTests`, `ReleaseFeedTests`):
  - the modes, kinds, schedule, downgrade confirmation and failures;
  - SemVer precedence;
  - the signature (tampered, foreign key, not base64, missing hashes) and the built-in key;
  - the folder store, and the GitHub store against an in-memory GitHub (kinds, pulled releases, a package from an older release, the token, the public URLs).
- **Headless UI** (`UpdateUiTests`):
  - the Restart to update item, and how it hides while debugging;
  - What's New;
  - a portable build's notification, and a development build;
  - the settings group and the Help menu.
- **Smoke test** `update.restart`: the published app's status bar item and What's New, on a stand-in backend, with a screenshot.
- **`eng/test-update.sh`**, the end-to-end test:
  1. builds the real installer at N and N+1 with a delta, the feed signed with a throwaway key;
  2. installs N;
  3. checks that a tampered feed is refused;
  4. updates to N+1 and checks that it runs;
  5. uninstalls.
  
  `packages.yml` runs it on every platform after uploading the release packages.

## Deviations and gaps

- **Ed25519 → ECDSA P-256:** .NET 10 has no Ed25519, and ML-DSA isn't on every platform yet (ADR 0029).
- **Exit criteria not met yet:** "an installed nightly updates itself to the next nightly through the published feed, and a stable install to the next stable release". That needs published releases, which wait for the hosted runs at the end (the maintainer's call). The same flow passed against a local signed feed on every platform run so far (below).

## Validation

- **Windows 11** (2026-10-11):
  - **`dotnet test` (Release):** 607 tests, 605 passed, 2 skipped (the symbolic-link tests).
  - **The Native AOT smoke test:** 43/43 steps, `update.restart` included.
    - The screenshot review fixed two things: the status bar icons (`$(sync)` isn't one of ours; now `$(refresh)` and `$(arrow-down)`), and What's New showing its version marker, which is now in a file of its own.
    - One run had `blazor.wasmDebug` time out after 600 s: its build failed with a NuGet restore race ("Cannot create a file when that file already exists") while two other milestone builds restored into the same package folder. The step now fails as soon as its build fails.
  - **`eng/test-update.sh`:** passed.
    - 0.1.0-test.1 installed through its Setup.exe;
    - the tampered feed refused ("signature doesn't verify");
    - updated to 0.1.0-test.2 through a 124 KB delta (the full package is 84.5 MB);
    - the uninstall left no PATH entry, uninstall entry or Start menu entry.
- **Linux** (WSL 2, Ubuntu 24.04):
  - `eng/wsl-test.sh --smoke`: 607/607 tests, and the smoke test 43/43 steps.
    - The first run found two `InstallationTests` failing on Linux: `Path.TrimEndingDirectorySeparator` only trims the platform's separator. Fixed in c92c526, which also hardens `DiffCommandTests`' waiting request against a connect timeout seen once in CI.
  - `eng/test-update.sh`: passed.
    - The AppImage of 0.1.0-test.1 refused the tampered feed.
    - It then updated to 0.1.0-test.2: Velopack replaced the AppImage file in place.
    - The delta package was 1.1 MB; the full package is 105 MB.
    - Delta packages need `zstd` on Linux and macOS; without it, `package.sh` builds full packages only. CI installs it; WSL got a copy unpacked without root.
- **macOS:** queued with `daedalus-mac`, after its batch.
