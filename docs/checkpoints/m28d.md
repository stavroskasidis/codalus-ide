# M28d checkpoint: agent mode and MCP

Date: 2026-10-14. Completes M28 (AI assistance) with [m28a](m28a.md), [m28b](m28b.md) and [m28c](m28c.md). Decision: [ADR 0063](../adr/0063-ai-agent-mode-and-mcp.md).

## Built

**Tool calls in the provider API** (proposed).
- `AiChatRequest.Tools`, `IAiModelProvider.ChatEventsAsync` streaming `AiEvent`s (text or an `AiToolCall`), and `AiMessage.ToolCalls`/`ToolCallId`. The default implementation wraps `ChatAsync`.
- Over the plugin protocol, `ai/chat` with `events: true` sends numbered `ai/event` notifications, ordered and counted like `ai/chunk`s (`PluginManager.ChatEventsAsync`).
- The OpenAI-compatible provider maps them to `tools`/`tool_calls` and gathers streamed arguments by index. Anthropic's maps them to `tool_use`/`tool_result`, with `input_json_delta` gathered per block and tool results as one user turn.

**The agent** (`AiAgent`, `AiAgentTools`, workbench `Ai/`, behind `IAiAgentHost`).
- A loop of at most 25 steps.
- `list_files`, `read_file` (numbered lines, ranges), `search_text`, `get_problems`, plus, in a trusted workspace only, `edit_file` (exact replacement once, or a whole file), `run_command` (two minutes, output cut to 8,000 characters keeping its start and end) and `build`.
- Paths stay under the solution's folder; bin/obj/.git are skipped, and the data boundary refuses secrets and ignored files.

**The shell** (`ShellHost.AiAgent.cs`): the chat's **Agent mode** checkbox.
- The steps stream into the conversation.
- Edits go through the refactoring preview (`PreviewAndApplyAsync` now says whether it applied; new files get their folders).
- Commands use a dialog whose default is Don't Run. MCP calls offer Allow Once, Allow for This Session and Don't Allow.

**MCP client** (`McpClient`, `McpServers`): `ai.mcpServers` in Claude Desktop's and VS Code's shape.
- Stdio, newline-delimited JSON-RPC: `initialize`, `tools/list` with pages, `tools/call` with text content; `ping` is answered, other server requests declined.
- Started on first use and stopped with the window. Tools are named `server__tool`.

**MCP server**: `codalus mcp [--user-data-dir <dir>]`.
- An `McpServer` on stdio whose tools (`get_solution`, `get_problems`, `get_test_results`, `build`) ask the running IDE.
- They ask through a new kind of single-instance request, a query answered with text (`SingleInstance.AskAsync`, `InstanceRequest.Query`).

Also, from the Mac's validation of the 0.2.0 candidate: when the build host stops for want of an SDK, opening the solution no longer adds a second "the connection was lost" error.

## Tests

- **Workbench** `AiAgentTests` (9):
  - the loop with tool results going back, and its step limit;
  - reading, listing and searching kept to the workspace, with secrets left out; read-only tools when untrusted;
  - exact-text edits and the user's choice as the result; approved and refused commands; output cutting;
  - the setting's parsing;
  - `McpClient` against `McpServer` in process (list, call, an error result, an unknown tool);
  - the IDE tools' answer when no IDE runs.
- **Plugins** `AiProviderTests` (+2): both providers send tools and conversations with tool calls in their APIs' shapes, and stream tool calls back (arguments in pieces), against mock servers.
- **Headless UI** `AiAgentShellTests` (2):
  - In the ProjectSystem fixture, the agent edits `Program.cs` through the preview, then runs `echo` once approved. The results reach the model, and the file changes.
  - The real `codalus mcp` process, driven by `McpServers`, answers `get_solution` and `get_problems` from the test's shell over its pipe, asking for approval once per session.

**Validation**: Windows green on the affected classes; the rest with the push.
