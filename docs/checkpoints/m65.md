# M65 checkpoint: 1.0, hardening and the release candidate

Date: 2026-11-20. [M65](../roadmap.md#m65--10-hardening-and-the-100-release) (D57): from the 0.14.0 cut, `develop` held 1.0.0 under a feature freeze until every open flake and bug was fixed or closed, M34 was closed, the 1.x promise was written down and one validation pass ran on every platform. What's left after this checkpoint is the release gate: five dispatched dry-run nightlies of `develop` in a row, then `release/1.0.0` from the head of one of them (`docs/release/releasing.md`).

## Done

**Every open flake fixed or closed** (`docs/ci-flakes.md`; item 1). About 44 rows were open on 2026-11-15, and the hardening added more. Each was fixed at its root cause, reasoned to it, or, for a row neither reproduced nor reasoned, closed under the maintainer's rule for 1.0 (2026-11-19): 50 passes or more under heavy load with its diagnostic in place, and it reopens if it fails again.
- Fixes in the product that users could hit, among them: the Codalus debugger in a container or on another machine named no frame's source (a remote launch now says `sourcesOnClient`); a superseded inline-values refresh wiped the newer one's values; a Step Out that found no awaiting caller; a timed-out func-eval with no dump; a DAP request that left before its response faulted unobserved; the adapter ended before the program's exit was written; an agent that crashed lost its last words; a lost setting under a locked file; a dead T4 host restarted twice; the previewer held a frame after an update; IntelliSense closed on a horizontal scroll; deferred content measured before its ancestors. The validation pass itself found four: a C# project's first design-time results dropped when they came before the solution's evaluation ended (the smoke's CS1061), the Codalus debugger's expression compiler caching a failed compilation (#489), a file's breakpoints moving to line 1 when its line endings changed on disk, as a checkout under `core.autocrlf` does (#491), and a profiling report without counters on a busy machine, its session's last values dropped at the stop (#493).
- Stress (`docs/ci-flakes.md`, "M65's stress"): the CI stress run 44465663261 ran each open row's tests on the runners they failed on (Windows, Linux x64 and arm64, macOS), half of each runner's cores kept busy, 30 jobs and no failure; WSL (20 cores, Release, load average 40 to 78) and a Windows PC (CPU at 100%) ran the Linux, web, build-host and debugger rows 50 to 1,050 times; the Mac session ran its rows 82 to 3,352 times.
- CI's own limits: the macOS smoke step has 55 minutes (the job 105), as its test shards have 60, after a nightly ran out of 40 with every step passing (#477).

**Every open bug fixed** (item 2): #391 (Rename in a `.razor` `@code` block, #411), #392 (the WPF previewer ran `StartupUri`, #409), #393 (the Properties selector after a drop, #414), #394 (a bottom tool window tab's single click, #415), #454 (the Windows Forms designer with a package's base form and controls, #456), #460 (the Toolbox with a control library, #462), the Start button's launch profile drop-down (#479), and #483 and #484 (Solution Explorer's search box kept Delete, Ctrl+C, Ctrl+V for the tree; #486, a new `inputFocus` context key). The one open issue is #461, an enhancement (control vendors' own designers, a 1.x study).

**M34 closed for 1.0** (item 3): the maintainer approved the gallery on Windows, Linux and macOS (2026-11-18; text beside an icon centered on it, #464), checked the display scales (2026-11-18), and M34h's open items are fixed (#453; AI Chat in the Native AOT app, #412).

**The 1.x promise** (item 4; #410): [ADR 0105](../adr/0105-what-1x-keeps-stable.md) and the user guide's [compatibility](../user-guide/compatibility.md) page: settings, the `codalus` command line and user data stay stable within 1.x, beside the plugin API (ADR 0058).

**netcoredbg in 1.0** (item 5; #410, #452): `debug.adapter: netcoredbg` stays a supported fallback, the promise's one named exception; its upstream limits are known limits.

Windows signing follows in 1.0.x; the Download page and the install guide show the way past SmartScreen.

**1.0's release text** (item 9; #466): `CHANGELOG.md`'s 1.0.0 notes, the website's Home and Download pages, and the user guide's [What's new in 1.0](../user-guide/whats-new.md).
