# M10 checkpoint: integrated terminal and C# Interactive

Date: 2026-10-10. Decisions: [ADR 0014](../adr/0014-terminal-emulator.md) (terminal emulator: engine, renderer and PTY placement) and [ADR 0015](../adr/0015-interactive-host.md) (the C# Interactive host).

## Built

**Terminal engine** (`src/DaedalusStudio.Terminal`, UI-agnostic, no dependencies)
- VT parser after Paul Williams' state machine (C0/C1, CSI, OSC, DCS, ESC).
- Screen model:
  - primary and alternate screens, scroll regions, origin mode, tab stops, DEC line drawing, insert/delete;
  - true colour, 256 colours and SGR attributes;
  - wide characters and emoji (two cells), combining marks;
  - OSC 8 hyperlinks;
  - a ring buffer of scrollback that reuses the rows it drops.
- Input encoding: keys with modifiers, application cursor and keypad modes, mouse reporting (X10, normal, button and any-event, SGR), bracketed paste and focus events.
- Replies to queries: cursor position and device attributes.
- Link scanning (URLs and `path(line,col)`/`path:line:col`) and OSC 133 command marks.

**Pseudo-terminals** (`DaedalusStudio.Platform/Pty`)
- ConPTY on Windows 10 1809+.
- `openpty` + `posix_spawn` on Linux and macOS: a new session, the pty as controlling terminal, default signals. No managed code runs in the child (see Deviations).

**Terminal tool window** (`TerminalService`, `TerminalControl`)
- Several terminals and side-by-side splits.
- Profiles detected per OS (pwsh, Windows PowerShell, cmd, bash, zsh, fish, sh) and a ".NET Developer" profile with the solution's SDK first on `PATH`.
- Starts in the solution folder.
- Shell integration scripts for bash, zsh and PowerShell: OSC 7 working directory, OSC 133 marks with exit codes in the gutter.
- Ctrl+click links (files open at the line, URLs in the browser).
- Find, copy, paste, copy-on-select.
- Theme colours including High Contrast; font settings.
- Configurable key passthrough (`terminal.commandsToSkipShell`).
- A UI Automation/AX peer exposing the screen as text.
- **Run in terminal**: `run.console: integratedTerminal` runs console apps (Ctrl+F5) in a terminal.

**C# Interactive**
- `daedalus-replhost`: a supervised process on Roslyn scripting.
  - State carries across submissions; values are formatted as C#.
  - Captured `Console` output, exceptions that keep the state.
  - `#r` (paths and `nuget:` through `dotnet restore` with the folder's `nuget.config`), `#load`.
  - Completion, signature help and semantic tokens on the pending submission.
  - A crash or `Environment.Exit` restarts it with an empty state; Reset starts a new process (also stops runaway code).
- The window: a transcript and a highlighted multi-line input with completion and parameter info.
  - Enter runs complete submissions; Ctrl/Shift+Enter; Alt+Up/Down history; Escape clears.
  - Reset and Clear.
- **Send Selection to Interactive** (Ctrl+E Ctrl+E) and **Initialize Interactive with Project**: builds, then references the output and its references.

**Plugin API 0.2.3** (proposed, additive)
- `ITerminals`: create a shell or run a command in a terminal, send text, read output, exit code, kill.
- Protocol `terminal/*` (docs/plugin-protocol.md).

**Benchmarks**
- The `terminal` scenario:
  - `terminal_frame_ms`: frames while printing a 1M-line file;
  - `terminal_cat_ms` and `terminal_cat_lines_per_s`;
  - `terminal_memory_mb`;
  - `terminal_echo_ms`: keystroke → echo rendered.

## Measurements (Windows, Native AOT, `terminal` scenario, 2 runs)

| Metric | p50 | p99 | max | Proposed budget |
|---|---|---|---|---|
| `terminal_frame_ms` (while printing 1M lines) | 6.1 | 10.0 | 988 | max ≤ 50 |
| `terminal_echo_ms` (pwsh) | 25.1 | 28.2 | 29.4 | p99 ≤ 40 (Windows) |
| `terminal_memory_mb` (10k lines of scrollback) | 22.6 | | 22.9 | ≤ 30 |
| `terminal_cat_ms` (1M lines, 62 MB) | 31,739 | | 32,367 | informational |

- **The frame maximum is not the terminal's.**
  - On this machine on 2026-10-10, every run had a stall of 0.4–1 s about every 9.3 s: an idle window with no terminal, the editor's scroll scenario (which met its budget on 2026-10-09), and the terminal.
  - A profile shows Avalonia's composition thread waiting on the GPU commit, while the UI thread waits for the dispatcher.
  - Without those stalls, frames stay under 50 ms (p99 10 ms).
  - Re-measure on a quiet machine before the budget becomes a gate. `TODO(issue)`: track the composition stall.
- **Throughput is bounded by the inbox ConPTY on Windows.** `type` of the file through ConPTY without the IDE takes about 25 s.
  - The engine alone parses it in 0.6 s, about 100 MB/s; reusing dropped scrollback rows doubled that and removed all gen2 collections.
  - VS Code ships the newer `conpty.dll` from Windows Terminal for this reason. `TODO(issue)`: optionally use `Microsoft.Windows.Console.ConPTY` (MIT).
- **Echo:** the 16 ms in-app editor budget doesn't fit a shell round trip through ConPTY and PSReadLine. Proposed: p99 ≤ 40 ms on Windows. To be compared with Windows Terminal and VS Code by hand.
- **Tried and reverted:** handing the terminal lock to the renderer between output slices. It didn't change the stalls (they weren't lock waits) and quartered the throughput.

## Not done, and deviations

- **`forkpty` → `posix_spawn`.** ADR 0014 first chose `forkpty`. It hung on Linux because the child JIT-compiles and binds P/Invoke stubs in a forked copy of a multi-threaded runtime. The ADR records the change.
- **Screen-reader announcements.** The terminal exposes its screen to screen readers, but doesn't yet announce new output in batches (ADR 0014). `TODO(issue)`.
- **Recorded streams.** Instead of real `vim`/`htop`/`dotnet build` captures, the recorded VT streams are synthetic sequences covering the same features.
  - Real captures need those programs on every CI OS.
  - `TODO(issue)`: record and add them.
- **Debugging in the terminal.** The netcoredbg console redirect isn't done: debugging still shows program output in the Debug Console. `TODO(issue)`.
- **Found during validation, fixed:**
  - A program that exits right after writing could lose its output on Linux. The reader thread delivered output before anyone subscribed; pseudo-terminals now keep early output for the first subscriber, and terminal sessions take their listener at creation.
  - On Linux the package manager could show an updated package as not installed. It read the installed packages mid re-evaluation; it now also reloads when a project is re-evaluated (M9).
- **Incremental publish.** Publishing over an existing `artifacts/shell` once left a language host that loaded projects but answered no requests; a clean publish fixed it. CI always publishes clean. `TODO(issue)`: find the stale file.
- **C# Interactive editor services** come from the REPL host, not the language host (ADR 0015):
  - no hover, documentation, quick fixes or import completion;
  - no `#r` of a project.

  - Failures found and fixed on the way: the pseudo-terminal child hung with `forkpty` (now `posix_spawn`); a program that exits right after writing lost its output; a deadlock between the REPL host's output and .NET's console stream lock on Unix.
