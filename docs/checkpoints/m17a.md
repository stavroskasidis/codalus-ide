# M17a checkpoint: containers

Date: 2026-10-11. Decisions: [ADR 0042](../adr/0042-container-tooling-and-publishing.md). M17 is split (roadmap rule 5) into M17a (containers), M17b (Aspire, [m17b](m17b.md)) and M17c (publishing, [m17c](m17c.md)).

## Built

**The engine** (`Workbench/Containers/ContainerEngine.cs`): the user's `docker` or `podman` CLI (the `containers.tool` setting, else `debug.containerTool`, else whichever is on the PATH), one process per operation, cancellable; `ps`, `images` (Go templates), `inspect` (Docker's JSON shape, which Podman writes too), `logs`, `exec ls`, `cp`, start, stop, restart, remove, `build`, `run -d`, `port`, `compose`. Podman's `docker` shim note is ignored. Containers we create carry the label `dev.daedalus.project`.

**Run and debug in a container** (`ContainerLaunch`, `ShellHost.Containers.cs`): the "Container (Dockerfile)" launch profile (`commandName: Docker`, with `httpPort`, `sslPort`, `publishAllPorts`, `launchUrl` placeholders and `containerRunArguments`).
- **Fast mode** (default): `build --target base`, a container of it idling with the build output mounted at `/app`, ports on `127.0.0.1`; Ctrl+F5 starts `dotnet /app/App.dll` through `exec -i` (its Run channel), F5 copies the Linux netcoredbg in (M14c's `RemoteDebuggers`, without asking) and launches the app under it as a pipe transport. The container is removed when the program or session ends.
- **Regular mode** (`containers.fastMode` off): the whole Dockerfile, its entry point; F5 attaches to its .NET process.
- F5 and Ctrl+F5 (single and multiple startup projects) dispatch to it for that profile.

**Add Docker Support** (`DockerSupport`): the .NET templates' multi-stage Dockerfile (aspnet or runtime image by framework and SDK), `.dockerignore` in the solution folder, the container launch profile. The fixture's Dockerfile is what it writes (a test compares them).

**Compose**: Compose Up (`compose -f file [-f override] -p name up -d --build`), Compose Down, Debug Compose Service (up, then attach to the service's .NET process; a `.dcproj`'s `DockerServiceName` picks it). On compose files and `.dcproj` in Solution Explorer, and the Debug menu.

**`.dcproj`** (build host `ComposeProject`): read from its XML, loaded with its compose files (nested as the file says), no frameworks, no design-time build; solution builds and restores use a filter without it (`BuildEntryPoint`), as for unloaded projects.

**Editing**: the Compose Specification's JSON schema (Apache-2.0) bundled in the markup host for `compose*.y?ml` and `docker-compose*.y?ml` (validation, hover); Dockerfiles keep TextMate's grammar.

**The Containers window**: containers (ours first) and images; for the selected container its logs, environment, ports and mounts, labels, and files (`exec ls -1Ap`; a file opens as a local copy); start, stop, restart, remove, open in browser, a terminal in the container (`exec -it`, the integrated terminal), attach the debugger; remove image.

**Fixture**: `samples/Containers` (`Containers.slnx`: `Web` with its Dockerfile and container profile, `docker-compose.yml` with its override, `docker-compose.dcproj`).

## Tests

- **Workbench** `ContainerToolsTests` (no engine): `ps`, `images`, `inspect` and `ls` output; the engine setting; Dockerfile stages and `EXPOSE`; Add Docker Support's files (equal to the fixture's); the fast and regular plans. `ContainerRuntimeTests` (engine): the base stage built, the fast container run, `inspect`, `port`, files, the app answering through `exec`, cleanup. `MarkupHostTests`: a compose file checked against the bundled schema, with hover.
- **Projects** `ComposeProjectTests`: the `.dcproj` loads with its files, gets no design-time build, and the solution builds.
- **Headless UI** `ContainerShellTests`: Add Docker Support and the `.dcproj`; Ctrl+F5 through the container profile (the app answers, the Containers window lists it with its environment, ports and files, stopping removes it) and F5 (a breakpoint in a request stops, locals, continue, stop removes the container).
- **Smoke** `containers.run` (where an engine runs Linux containers; CI's Linux runner): Ctrl+F5 in a container, the app answers, the Containers window (`smoke-test-containers.png`), cleanup.

Container tests skip with the reason where no engine runs Linux containers, and fail on CI's Linux runner only. They pull only `mcr.microsoft.com/dotnet/aspnet:10.0` and remove every container and image they make.
