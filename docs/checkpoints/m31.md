# M31 checkpoint: release cycle and installers

Date: 2026-10-11. Decision: [ADR 0028](../adr/0028-release-cycle-and-installers.md). Built on the maintainer's go-ahead to complete every milestone (2026-10-11), including the GitHub-side steps: `develop` as the default branch, private releases, and the signing keys as repository secrets.

## Built

**Branches and versions** (D21)
- `develop` is the default branch (since 35b391f), and CI runs on `develop` and `master`. CLAUDE.md and CONTRIBUTING.md moved to it. Parallel milestones may use branches in worktrees.
- `VERSION` (0.1.0) holds the next release's version; `Directory.Build.props` reads it into the shell's `VersionPrefix`. Local builds stay `-dev`.
- **`eng/DaedalusStudio.Release`** (`daedalus-release`, tested in `tests/DaedalusStudio.Release.Tests`, also against a throwaway repository):
  - `version stable|nightly|dev`: `0.1.0`, `0.1.0-nightly.YYYYMMDD.N`, `0.1.0-dev`;
  - `check-tag`: refuses a released version;
  - `bump [--after X.Y.Z]`: the next minor version, unless `develop` is further already (a hotfix);
  - `notes`: grouped by milestone, with links to the checkpoints and a `CHANGELOG.md` section first.

**Installers** (D17, D18): `eng/package.sh [version] [kind]` with Velopack's `vpk` 1.2.161 (MIT; the `Velopack` library at the same version).

| Platform | Packages |
|---|---|
| Windows x64 | `…-win-x64-setup.exe` (per user, `%LocalAppData%\DaedalusStudio`, Start menu and uninstall entries), `…-win-x64.zip`, winget manifests for the Setup.exe |
| macOS arm64 | `…-osx-arm64.pkg` (in `~/Applications` or `/Applications`), `…-osx-arm64.app.zip`; the `.dmg` is gone |
| Linux x64 (arm64 once public) | `….AppImage` (vpk; appimagetool is gone), `.deb`, `.rpm` (new; `rpmbuild`), `.tar.gz` |

- Every build has its update channel `<rid>-<kind>` (`velopack/`: feed, full and delta packages) and `SHA256SUMS-<rid>.txt`.
- **The shell's hook** (`Infrastructure/Installation.cs`): `VelopackApp…Run()` first thing in `Main`. On Windows the install and update hooks write `bin\daedalus.cmd` (it runs `current\daedalus.exe` and waits, for `--wait` and `merge`) and put `bin` on the user's PATH, keeping the PATH's registry value kind; uninstalling removes it.
- `.deb` and `.rpm` versions use a tilde for the prerelease (`0.1.0~nightly.20261011.1`).

**The installer smoke test** (`eng/smoke-test.sh --packages`): installs every package as a user would, runs the smoke test, uninstalls and checks that nothing is left.
- **Windows:** the silent Setup.exe into a temporary folder; its uninstall entry, PATH entry and `daedalus` command; the full smoke test; `Update.exe --uninstall` leaves no `current\`, registry entry, PATH entry or Start menu entry. The zip: `--version`.
- **macOS:** `installer -pkg … -target CurrentUserHomeDirectory`, the full smoke test, then the app and the package receipt removed. The `.app` zip: `--version`.
- **Linux:** the AppImage gets the full smoke test; the `.deb` and `.rpm` are installed and removed with apt and dnf, on the host when sudo needs no password (CI), otherwise in Ubuntu and Fedora containers (rootless podman); the tar.gz: `--version`.

**Workflows** (D20): `packages.yml` (reusable, every platform), `nightly.yml` (from `develop`, keeps 14), `release.yml` (from `master`; merges a hotfix back and moves `develop` past the release), both publishing through `eng/publish-release.sh`, with a dry run by default on dispatch. While the repository is private the schedule and the push trigger do nothing.

**apt and dnf repositories**: `eng/linux-repos.sh` builds a signed site (suites `stable` and `nightly`; signed `InRelease`/`Release.gpg`, signed rpms and `repomd.xml`, `.repo` files, the public key, an index page); `eng/test-linux-repos.sh` installs from it in Ubuntu and Fedora containers with the signatures checked; `linux-repos.yml` deploys it to Pages once the repository is public.

**Keys** (generated 2026-10-11, private halves only in repository secrets): the package key `PACKAGES_GPG_PRIVATE_KEY` (RSA 4096, fingerprint `765B8B725B3FD42A8EAA508F59C7590683C2B9B3`, public half `eng/packaging/linux/daedalus-studio-packages.asc`); the update feed key `FEED_SIGNING_KEY` (M32).

## Deviations and gaps

- **Exit criteria not met yet**: "one nightly and one stable release published by the workflows, installed and smoke-tested on three OSes". The maintainer asked for the hosted runs at the end of all the milestones (CI minutes), so the first `nightly.yml` and `release.yml` dispatches without the dry run wait for that batch. Locally, the same scripts were run end to end (below).
- **Linux ARM64** waits for the public repository (GitHub's ARM64 runners are free there).
- **apt and dnf on Pages** wait for the public repository (Pages needs a public repository on the free plan); the site and its signatures were tested locally.
- **The `daedalus` command on Windows** is a `.cmd`: `cmd` gives a GUI program no output handles to capture, so `--version` prints to the console window rather than a pipe. Waiting and the exit code work.
