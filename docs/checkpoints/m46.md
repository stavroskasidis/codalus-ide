# M46 checkpoint: the first-run setup

Date: 2026-10-17. Phase 11's setup, on top of M45 (its branch, not merged yet). The scope: the roadmap's [M46](../roadmap.md#m46--first-run-setup); the design: [`design/shell-themes.md`](../design/shell-themes.md#the-first-run-setup-appearance) and `design/shell-themes/Setup.dc.html`. Decision: D32 (Harbor with Match system preselected). No ADR: the setup's state is a setting, `workbench.setupCompleted`, in the settings file every other setting is in, so there's no new store.

## Done

**When it runs** (`ShellHost.FirstRun.cs`, `SetupDecision`):
- The first time the IDE starts for a user data folder, the setup opens instead of the start window, once the main window is interactive; closing it goes on to what `workbench.startup` says (the start window by default).
- **Done** and **Skip setup** (and closing the window, `Esc`, or closing the IDE with it open) set `workbench.setupCompleted`, a user setting (Environment → First-Run Setup Completed), so it shows once. Turning the setting off shows it at the next start.
- **It doesn't run**, in this order (`ShellHost.Decide`, logged as `[setup] First-run setup: <decision>`):
  - `--skip-setup` (new, in `codalus --help`) or `CODALUS_SKIP_SETUP=1` (new, in [environment-variables.md](../environment-variables.md)), for automation; neither is recorded;
  - the smoke test, benchmarks (`--bench`, `--exit-on`) and `--screenshot`;
  - a command line that opens something: a path, a file, `--remote`, `codalus diff`, `codalus merge`, `--wait`;
  - `workbench.setupCompleted`;
  - a synced profile: the settings name a sync target (`settingsSync.target`), so the profile comes from sync; a synced settings file that carries `workbench.setupCompleted` counts as completed too;
  - **a user data folder used before the setup existed**: its `settings.json` holds a setting, or `state/state.json` (a saved window) exists, read before anything writes to the folder. Decided here: the roadmap says "the first time the IDE starts for a user data folder", so an existing install isn't asked after an upgrade, and nothing is written for it (as M45 didn't rewrite the theme). An empty settings file (`{}`, comments only) is a new folder.
- **Help → Set Up Codalus IDE** (`help.setUp`, new) and **Help → Get Started** (the Welcome plugin's `welcome.showOnboarding`, which now runs `help.setUp`) open it over the running IDE; from there, closing it doesn't open the start window.
- At a first start, M37's offer of a missing .NET SDK or git waits for the setup: its Tools step checks; when the setup ends without showing the Tools step, the offer follows as before.

**The window** (`SetupWindow`, `SetupViewModel`), after the design: the steps on the left (Appearance, Keyboard, Your settings, Tools, the current one highlighted), the step on the right, Skip setup, Back and Next below. Every color is a token, so the window repaints in the theme being chosen.
- **Appearance:** the four families as cards, each with a picture of its layout in the chosen mode (`ThemePictureView`, now shared with M45's Options cards, which drew the same picture inline), its name and a line from the design; the mode: Light, Dark, High contrast or **Match system** (the default, with its note). Harbor with Match system is preselected (D32), or what the settings say when it runs again. Choosing previews through `ThemeService.Preview`: the setup window and the IDE behind it repaint, nothing is saved. A theme that isn't one of the four (Classic's, a plugin's) shows no card chosen and is kept unless a card is picked.
- **Keyboard:** Default (the name the code and catalogue give Visual Studio's scheme: "the classic IDE's keys"), VS Code, ReSharper, Emacs, each with a line on what it does.
- **Your settings:** import from VS Code (its user folder found as Tools → Import Settings from VS Code finds it), from a `.vssettings` file, or from a file exported with Tools → Export Settings (all of it); or turn on settings sync with a folder or a Git repository's URL. The importers don't ask again (clicking is the consent) and say what they did in the window; the pickers open over the setup window. Sync from the setup (`TurnOnSettingsSyncFromSetupAsync`) takes what the target has without asking on a first sync with settings on both sides, as the step says, so the profile arrives whole.
- **Tools:** M37's check of the .NET SDK and git, each found (with its version) or missing, and Help → Check Environment for the rest. **Install…** shows the plan and its exact command in the row ("… This runs: curl -sSL https://dot.net/v1/dotnet-install.sh | bash …") with **Install** (or Run in Terminal, Open Page) and Cancel: nothing runs before that yes.
- **Saving:** leaving a step with Next or Back saves its choice (when it differs from what's saved; the theme's preview ends). Skip setup doesn't save the step it's on, so at a first start it keeps the defaults: Harbor following the system, the Default keys. Done (Next on the last step) records the setup and opens the start window.
- **Keyboard:** `Tab` through a step, the arrow keys between the cards, modes and schemes of a group (each one chosen as it's reached), `Space` or `Enter` on the focused one, `Alt+Right` Next, `Alt+Left` Back, `Esc` Skip setup; the focus starts on the chosen card of each step.
- **Accessible names:** the cards (with their line as help text), the modes, the steps ("Step 1 of 4: Appearance, current step"), the buttons and the URL box.
- **Translations:** the window's text is in the catalogue (`setupWindow.*`), and what the model builds is `msg.firstRun.*` (and `msg.sync.setup*`).
- **AI** stays off and isn't mentioned (ADR 0062).

**Get Started folds into the setup:** the Welcome plugin's Get Started group (choose a theme, a keyboard scheme, the importers, Fonts and Colors, Done) is gone from the Start page; Help → Get Started opens the setup. Tips stay. `welcome.onboarded` stays registered (unused, described as such), so a settings file that has it isn't reported; `welcome.finishOnboarding` is gone. This closes M38's Get Started gap ([m38](m38.md)).

**The importers** (`ImportVsCodeSettingsAsync`, `ImportVsSettingsAsync`, `ImportSettingsAsync`) return what they told the user, for the setup; their commands and notifications are unchanged.

**Smoke test:** step `shell.setup` (M46, before `shell.startWindow`): it checks that the setup didn't open by itself, then opens it as at a first start at 1280 × 800; Harbor Light's appearance step is `setup-appearance.png`, the website's `setup.png`; Ember Dark previews in the setup window and the IDE (`setup-appearance-ember-dark.png`) and Next saves it; VS Code's keys; a stand-in of VS Code's user folder imported (`setup-settings.png`); the tools checked, the SDK found (`setup-tools.png`); Done opens the start window with the theme applied. The settings it changed are put back.

**Docs and site:** the user guide's [first-run setup](../user-guide/getting-started.md#the-first-run-setup) (the steps, the keys, when it doesn't show, `--skip-setup`) and the command line table, the themes section of [settings](../user-guide/settings.md#themes); [environment-variables.md](../environment-variables.md); the design doc's status; the website's Features page (a "First start" screenshot in the tour, a "Make it yours" line), Home's "Familiar" card and the README; `CHANGELOG.md`; the roadmap's status row and change log.

## Tests

- **`FirstRunSetupTests`** (6, new):
  - unit: the decision for every case (a new folder, completed, synced, used before, the switch and its variable, the smoke test, benchmarks, screenshots, and each way the command line opens something), `--skip-setup` in the parser and the help; a folder counts as used with a setting or a saved window, not with an empty or comments-only settings file;
  - headless, on an empty user data folder (`ShellFixture.Create(firstRun: true)`): the setup shows at the first start and the start window waits for it; the defaults (Harbor, Match system, Default keys); a card previews without saving; Skip setup keeps the defaults, records the setup, opens the start window, and the folder's next start doesn't show it;
  - each step writes its setting: Graphite Dark on Next, VS Code's keys, Back showing what's saved; VS Code's settings, a `.vssettings` file and an export imported from the setup; the Tools step's check (the SDK and git found here), and a missing SDK (a stand-in) whose Install… shows the exact command and runs nothing until the yes, then runs the stand-in runner once; Done records the setup and opens the start window with the theme, the keys and the imported settings applied;
  - the live preview: Ember Dark in the IDE (`ActualThemeVariant`), in the setup window (its variant, its background, and a pixel of the rendered frame in Ember Dark's window color) and in every card's picture; every button and card has an accessible name; the arrow keys choose the next card, `Alt+Right` saves and goes on, `Alt+Left` goes back, `Esc` skips and ends an unsaved preview; from Help the start window doesn't follow;
  - after a sync: a profile whose settings name a sync target doesn't show the setup; turning sync on in the setup with a folder that has settings takes them (theme and keys) over the ones chosen, and Back shows them.
- **Updated:** `ShellHeadlessTests` (the Start page without Get Started; the keyboard scheme from the plugin's command; Help → Get Started opens the setup); `ShellFixture` skips the setup (`ShellOptions.SkipSetup`) and the start window as before, and `firstRun: true` starts on an empty folder with both allowed; `ThemeFamilyTests`' Options cards draw through the shared picture.
- With `CODALUS_UI_SNAPSHOTS` set, the tests save each step's frame (`first-run-setup-*.png`).

## Gaps

- **The other platforms:** the setup window over Windows' and macOS's main window (owned, centered, its own title bar), the file and folder pickers from it, and the smoke step's pictures there need their run (CI, or the Mac session). The exit criterion (a new user data folder through the setup to the start window with the theme, keys and imported settings applied, on Windows, Linux and macOS) is met on Linux only. `TODO(issue)`
- **Settings sync's sign-in:** a Git repository that needs credentials uses git's own prompts (askpass), as Settings Sync: Turn On does; the setup doesn't sign in for it. `TODO(issue)` if a hosting sign-in should be offered there.
- **Profiles:** the setup sets up the active profile (Default at a first start); it doesn't offer to create or import a profile.
- **What's New** is still on the Start page, not in the start window (M38's other gap).
