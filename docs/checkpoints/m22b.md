# M22b checkpoint: the plugin developer experience

Date: 2026-10-13. Decision: [ADR 0059](../adr/0059-plugin-developer-experience.md). Follows M22a ([m22a](m22a.md)); M22c (distribution) remains.

## Built

- **`Codalus.Plugins.Testing`** (`src/Codalus.Plugins.Testing`): `TestPluginContext` and `PluginTestHost.ActivateAsync<TPlugin>()`, in memory.
  - Commands run through JSON, as over the protocol. `OnShellCommand` answers the IDE's commands.
  - Responders answer notifications, quick picks and input boxes.
  - Output channels, status bar items, trees (expand, click, refreshes), Markdown and declarative views (`GetView`, `FindElement`, `ClickAsync`, `ChangeAsync`), custom editors (`OpenCustomEditorAsync`, `GetCustomEditorText`) and tasks with progress (`Cancel()`).
  - The file system, authentication and source control providers the plugin registers. Settings and secrets are in memory.
  - Disposing deactivates the plugin and its subscriptions.
- **The template** `dotnet new codalus-plugin` (`src/Codalus.Templates`, package `Codalus.Templates`): a `.slnx` with the plugin and a test project. Options are `--publisher`, `--codalusVersion` and `--skipTests`.
- **Run and Debug Plugin in Development Instance** (Debug menu, when the startup project has `codalus-plugin.json`; `ShellHost.PluginDevelopment.cs`):
  - It builds the project and starts a second IDE on its output, with user data in `.codalus/plugin-dev`.
  - Debugging adds `--debug-plugin-host <file>`: the plugin runs in a `debug` host group, activated at once (`PluginManager.ActivateDebuggedPluginsAsync`). The host writes its process id and waits for the debugger before activating. The first IDE attaches, and activation has no time limit.
- **The API reference**: `docs/user-guide/plugin-api.md`, generated from the assembly and its XML docs by `ApiReferenceTests` (`CODALUS_UPDATE_API_REFERENCE=1`), which also fails on an undocumented public member. The 64 record parameters that had no docs got them. The site's guide lists it.
- **SVG icons in icon themes**: `eng/icons/CompileIcons.cs` is also built into `codalus-pluginhost --compile-icons <output> <list>`. `IconThemeCompiler` (workbench `Plugins/`) runs it once per theme, cached in `<cache>/icon-themes/`. The shell registers each icon as `vec:<path>` (`IconSet.RegisterVector`, replayed by `CompiledIcons.Build`) and applies the theme again.
- **The API package's version** is 1.0.0 (it still said 0.2.0).

## Tests

- **`Codalus.Plugins.Testing.Tests`** (new): HelloWorld and TodoBoard tested in memory. It covers commands and JSON, notifications and output, the status bar, trees and refreshes, a cancelled task, the three providers, a custom editor's view and text, deactivation, and services the test doesn't supply.
- **Plugins**:
  - `PluginTemplateTests`: the template packed, installed in a private hive, instantiated, built, its tests passing, and the plugin running in the real host.
  - `PluginDevelopmentHostTests`: the debug host group, the process id file, activation after the wait, and the usual host without the option.
  - `ApiReferenceTests`: the page and the documentation check.
- **Headless UI**:
  - `PluginDevelopmentTests`: the option, and the development instance's arguments.
  - `IconThemeTests`: SVG icons listed, then mapped to vectors once converted, with the real conversion through the plugin host.

**Validation**: Windows green on the affected classes; the site's tests and export pass with the reference page. The full suite and the other OSes come with the push (CI runs all three).
