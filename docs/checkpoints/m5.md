# M5 checkpoint: debugging

Date: 2026-10-09. Plan and decisions: [ADR 0007](../adr/0007-debugging.md).

## Built
- **Adapter**: netcoredbg 3.2.0-1092 (Samsung, MIT), fetched and SHA-256-checked by `eng/get-netcoredbg.sh` into `.work/netcoredbg` (CI caches it). Found through `DAEDALUS_NETCOREDBG`, `debugger/` next to the shell, or the source checkout.
- **`DaedalusStudio.Debugging`**: an AOT-safe DAP client (`DapConnection`, framing shared with `DaedalusStudio.Rpc`, source-generated contracts) and `DebugAdapter` (process plus typed requests).
- **`DebugService`** (workbench):
  - launch (from M4's launch plan) and attach; stop terminates or detaches
  - breakpoints per file that follow edits and persist per solution
  - conditions in the adapter; hit counts (`n`, `>= n`, `% n`) and logpoints (`{expr}`, `$FUNCTION`, `$TID`) emulated in the client, since netcoredbg has neither
  - exception filters (user-unhandled by default, or all)
  - threads, frames, scopes, variables, evaluation, setVariable
- **Shell**:
  - F5, Shift+F5, Ctrl+Shift+F5, F10, F11, Shift+F11, Ctrl+Alt+Break, F9, Ctrl+F9, Ctrl+Shift+F9, Ctrl+Alt+P, and a Debug menu.
  - **Editor**: a breakpoint margin (click to toggle; hollow when disabled or unverified, diamond for logpoints, a dot for conditions); the current statement highlighted with an arrow; data tips while stopped (value, type and the first 25 members).
  - **Tool windows**:
    - Locals and Autos (F2 sets a value)
    - Watch (persisted)
    - Call Stack, with a thread picker; frame selection drives the other windows
    - Breakpoints
    - Debug Console: program output and expression evaluation with history
  - Exception settings; status bar state; Locals and Call Stack open at the first stop; an exception stop reports its type and message.
- **Tests**:
  - The DAP client against netcoredbg.
  - `DebugService` integration: hit counts, logpoints, step in and out, set variable, threads, exceptions, attach and detach, command-line splitting, hit conditions.
  - A headless UI test: F9, F5, the Locals, Call Stack, Watch and Debug Console windows, a data-tip expression, F10, and run to exit.
  - Fixture: `samples/Debugging`. 243 tests in total.

## Deviations and gaps
- **netcoredbg gaps**, as documented in ADR 0007:
  - no Edit and Continue or hot reload
  - no mixed-mode, historical or dump debugging
  - no data breakpoints
  - no set next statement
  - no per-exception-type settings: only all exceptions vs. user-unhandled
  - no console input for the debuggee
- Hit counts and logpoints stop the program briefly on every hit (client-side emulation).
- Data tips are read-only text. They don't expand deeper than one level; expand in Locals or Watch instead. `TODO(issue)`: an interactive data tip tree.
- No breakpoint context menu in the editor. Conditions, hit counts and log messages are set with Debug → Breakpoint Conditions and Actions (on the caret's line). `TODO(issue)`.
- Function breakpoints are supported by the adapter and the client, but there is no UI for them yet. `TODO(issue)`.
- macOS x64 has no netcoredbg build, so debugging is unavailable there.
- Builds don't bundle netcoredbg yet; installers will (M7).
- Pre-existing AOT warnings come from library XAML (Dock's default templates, two XAML closures in library resources). They are unchanged since M4 and none come from our code.
