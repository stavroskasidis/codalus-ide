# M11 checkpoint: language platform

Date: 2026-10-10. Decision: [ADR 0016](../adr/0016-language-platform.md) (languages, grammars and the LSP bridge).

## Built

**Language registry** (`LanguageRegistry`, workbench)
- Languages with ids, aliases, file names, file-name patterns, extensions and first-line patterns.
- Grammars, and language configurations in VS Code's `language-configuration.json` format.
- About forty built-in languages (`BuiltInLanguages.cs`). The status bar shows the language's name.

**Highlighting**
- TextMate grammars through AvaloniaEdit.TextMate and TextMateSharp, for every language except C# (Roslyn's semantic tokens).
- Works under Native AOT. The bundled registry loads lazily, and tokenizing runs on a background thread.
- The Dark+, Light+ and High Contrast themes follow the shell's theme.
- Semantic tokens from other servers are remapped from their legend.

**Language configuration**
- Toggle Line Comment, Comment Selection and Uncomment Selection, with line or block comments.
- Auto-closing pairs and typing over them (`editor.autoClosingBrackets`).
- Folding without a server: XML elements, region markers and indentation.
- Word completion (`Ctrl+Alt+Space`, and while typing) when no server completes. It uses a background word index of the document, so it stays cheap in large files.

**Generic LSP bridge**
- `contributes.languageServers`: a supervised stdio server for one or more languages.
- The client:
  - declares real client capabilities and answers `workspace/configuration` from a settings section;
  - accepts `client/registerCapability`, progress and message requests;
  - sends whole documents to full-sync servers;
  - doesn't re-ask for a word the server had nothing complete for.
- `LspNormalizer` turns VS Code-shaped results into the shell's narrowed types: options objects, location links, marked strings, completion arrays, numeric codes, `changes` maps and bare commands.
- Rename works without `prepareRename`.

**Markup host** (`daedalus-markuphost`, supervised, LSP)
- **JSON:**
  - syntax errors;
  - schema validation (our own subset), completion of names and values, and hover;
  - schemas from `$schema`, six bundled ones, and the SchemaStore catalog (downloaded and cached for a week when `json.schemaDownload` is on).
- **XML and MSBuild:**
  - well-formedness;
  - completion of elements, properties, items, metadata, attributes and values (TFMs, RIDs, choices);
  - warnings for unknown values;
  - hover with the **evaluated value and where it is set**: the host asks the shell (`daedalus/msbuild/property`), and the shell asks the build host.
- **YAML:** syntax errors, schema validation and hover.
- **`.editorconfig`:** keys, values, hover and warnings.

**Markdown**
- Open Preview to the Side (`Ctrl+K V`): a live preview that renders 300 ms after each edit.

**Plugin API 0.2.4** (additive)
- `contributes.languages`, `grammars` and `languageServers`.
- Declarative plugins: `entry` is optional.
- Sample: `samples/plugins/TodoLanguage`, with a grammar, a configuration and a small LSP server.

**Tests**
- Bridge tests against a scripted VS Code-style conformance server (`tests/DaedalusStudio.LspConformance.Server`).
- Markup host integration tests: JSON with schemas, MSBuild with evaluated hover, YAML and `.editorconfig`.
- Headless UI tests:
  - grammars;
  - a declarative plugin with its server;
  - JSON and the Markdown preview;
  - comments, brackets, folding and word completion.
- Smoke test step `languages.grammars` (M11).

**Benchmarks**

- `markuphost_mb` in `binary-size`.

- **Opening** a 100k-line JSON or XML file meets budget 3a with room to spare.

- **Fixed while measuring.** Word completion used to scan the whole document on the UI thread for each letter (p99 120 ms in XML). Now it uses a background index, and a server that had nothing complete for a word isn't asked again while the word grows.

## Not done, and deviations

- **LSP types** are not generated from `metaModel.json`. The narrowed, source-generated types stay, and `LspNormalizer` maps what servers send onto them (ADR 0016).
- **Where markup services run.** The MSBuild service runs in the new markup host, not the build host. The build host only exists for trusted folders, so the markup host asks it for evaluated values through the shell.
- **JSON Schema** is our own subset. JsonSchema.Net is under a non-OSI EULA from version 8, and NJsonSchema would bring in Newtonsoft.Json.
- **Sample plugin.** The PowerShell Editor Services sample was replaced with a small `.todo` language and its own LSP server. It proves the same path without a 50 MB download.
- `TODO(issue)`, not in M11:
  - **LSP features for other languages:** inlay hints, call and type hierarchy, pull diagnostics, selection ranges, linked editing, CodeLens and document symbols.
  - **Bridge:** snippet tab stops (snippets are inserted as plain text); several servers for one language.
  - **XML:** XSD validation (`.runsettings`, `nuget.config`, `.xml`).
  - **The `.resx` editor** and strongly typed resource generation.
  - **YAML:** completion, and GitHub Actions/Azure Pipelines schemas offline (they come from the catalog when downloads are on).
  - **MSBuild:** package id and version completion; Go to Definition across imports.
  - **Markdown preview:** relative links and images.
  - Binary-file detection.
  - Grammar tokenization snapshot tests. The UI tests check colors on real lines instead.
