# M15c checkpoint: scaffolding and service references

Date: 2026-10-11. Decision: [ADR 0041](../adr/0041-scaffolding-and-service-references.md). This completes M15 (M15a and M15b: [ADR 0022](../adr/0022-aspnet-core-loop.md)).

## Built

**Build host** (`SolutionSession.WebTools.cs`, `ProjectManagement/ServiceReferences.cs`; [project-protocol.md](../project-protocol.md#scaffolding-and-service-references))
- `scaffold/status`: is the user's `dotnet aspnet-codegenerator` runnable (`--help` in the project's folder), local or global and its version, the project's `Microsoft.VisualStudio.Web.CodeGeneration.Design`, EF Core providers and `Microsoft.EntityFrameworkCore.Tools`, its .NET version.
- `scaffold/install`: `dotnet tool restore`, or a local tool install (a manifest first), plus the design package and, in an EF Core project, EF Core Tools at the project's EF Core version; versions of the project's .NET major, from the global packages folder first.
- `scaffold/run`: the generator as a child process in the project's folder, trusted solutions only, one at a time, its process tree killed on cancel, its output streamed (`scaffold/output`); created and modified files by comparing the folder; a failure says the generator's own message (it exits with 0 after some errors: an error with nothing written fails).
- `serviceReferences/list|add|update|remove`: `OpenApiReference` and `Protobuf` items as `dotnet-openapi` writes them (`SourceUrl`, `CodeGenerator`, `Namespace`, `ClassName`, `Options`, `GrpcServices`, `Access`), the packages the project lacks (through the existing package edits, so central package management works; generators with `PrivateAssets="all"`), versions from the global packages folder, then the sources, then known ones, or pinned by the caller; a restore after.

**Workbench** (`Web/`)
- `Scaffolders`: the catalog (15 scaffolders in API, MVC, Razor Pages, Blazor, Minimal API and Identity), validation and command lines (positional arguments, options, fixed arguments; Razor Pages CRUD; the controller's default plural name), the empty endpoint group's code.
- `ScaffoldingService`: item templates through `templates/instantiate` (with the folder's namespace), the endpoint group written directly, the code generator through `scaffold/run` with `-dbProvider` from the project's provider; `ScaffoldToolMissingException` when the tool or a package is missing. The Scaffolding output channel.
- `ServiceReferenceService`: copies a document into `OpenAPIs/` or `Protos/`, or downloads it from a URL (16 MB at most, through a temporary file); Refresh; add, update, remove and list through the host.

**Shell** (`ShellHost.WebTools.cs`, `WebToolsViewModels.cs`, `ScaffoldView`, `ServiceReferencesView`)
- **Add New Scaffolded Item** (a document): categories, scaffolders (with what runs each), the form generated from the parameters (text, check boxes, choices; models and contexts offered from `daedalus/ef/contexts`), the code generator's state and **Install**, the result; the first new file opens. From the Solution Explorer's project and folder menus (the folder fills the Folder field) and the Project menu.
- **Service References** (a document per project): the references (kind, generator, class, namespace, services, source), Save, Refresh (URL references), Open Document, Remove; a form to add an OpenAPI or gRPC reference from a file (Browse) or a URL.
- Commands `web.addScaffoldedItem` and `web.serviceReferences` (category ASP.NET Core); a `.proto` language with our own TextMate grammar (`Grammars/proto.tmLanguage.json`).

**Fixture:** `samples/Scaffolding`: `Shop` (ASP.NET Core, EF Core 10.0.12 on SQLite with `ShopContext` and `Product`, the design package and EF Core Tools), `Client` (a console app), `contracts/weather.openapi.json` and `contracts/greet.proto`, and `dotnet-aspnet-codegenerator` 10.0.2 as a local tool.

**Tests**
- Build host integration (`WebToolsIntegrationTests`, 3): the status; an API controller over `ShopContext` (name and provider defaults) and minimal API endpoints (a new file, `Program.cs` changed) through the real code generator; a failing model; an SDK item template with the folder's namespace and the built-in endpoint group; the project then builds. OpenAPI and gRPC references added from files (the project file, the packages, `PrivateAssets`), listed, changed, a file reference refusing Refresh, a URL reference downloaded from a loopback mock server and refreshed, a failing URL, removal. A gRPC client reference that a build turns into `GreetGrpc.cs`.
- Workbench (`ScaffoldersTests`, 5): the catalog's shape, every code generator's command line, item template and built-in plans, validation, plurals and providers.
- Headless UI (`WebToolsShellTests`, 1): the generated form (fields, folder from the selection, the provider from the project), validation before running, an API controller through the code generator (it opens), a Razor Page from the item template, a gRPC reference added and its services changed in the Service References document, the `.proto` language.
- **Smoke step `web.scaffolding`** (M15): the API controller through the code generator and a gRPC reference whose client a build generates, with screenshots `smoke-test-scaffold.png` and `smoke-test-service-references.png`.

**Docs:** ADR 0041, [User guide: Web development](../user-guide/web.md) (Scaffolding; Service references), `docs/project-protocol.md`, the roadmap (status, the M15 split, the parity rows, the change log), CLAUDE.md, THIRD-PARTY-NOTICES.md (the fixture's packages).

## Not done, and deviations

- **`dotnet scaffold`** is not used (ADR 0041 picks `dotnet-aspnet-codegenerator`; `dotnet scaffold` is still preview). `TODO(issue)`: a second engine once it is stable.
- **Kiota** is not offered; OpenAPI clients come from NSwag through `OpenApiReference`. `TODO(issue)`.
- **Areas** have no scaffolder, and Identity's file list is typed (`Account.Login;Account.Register`), not picked from `--listFiles`. `TODO(issue)`.
- **Multi-targeted projects:** no `-tfm` is passed; the generator picks the first framework. `TODO(issue)`.
- **Other connected services** (Azure services, SQL databases, monitoring) are not planned here; the parity table lists them as gaps.
- **The OpenAPI client is generated at build time**, as with `dotnet-openapi`; until the first build the language service doesn't know it. The tests build a gRPC client; NSwag's generation isn't in the tests, which restore only packages the other fixtures use (no network). It was checked by hand: a project with the items and packages the host writes (`Microsoft.Extensions.ApiDescription.Client` 10.0.12, `NSwag.ApiDescription.Client` 14.7.1) built and generated `weather.openapiClient.cs` with `Client.Weather.WeatherClient` from the fixture's document. `TODO(issue)`: an NSwag build in CI, where packages are downloaded.
- **Remove** keeps the document and the packages (the protocol can send the document to the trash; the UI doesn't offer it yet).
