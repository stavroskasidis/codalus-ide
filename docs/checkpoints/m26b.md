# M26b checkpoint: build depth, custom tools and T4

Date: 2026-10-11. Decisions: [ADR 0034](../adr/0034-build-depth.md) (build options, the fast up-to-date check, batch builds, timings, binary logs, build events) and [ADR 0035](../adr/0035-custom-tools-and-text-templates.md) (custom tools and text templates). M26a (the project system) is [its own checkpoint](m26a.md).

## Built

**Build host** ([project-protocol.md](../project-protocol.md#build-depth-options-the-up-to-date-check-batch-builds-timings-build-events-and-binary-logs))
- **Build options:** `build/run` and `build/batch` take `BuildOptions`: the Output window's verbosity (the logger now honors quiet to diagnostic, with project and target lines and command lines from normal), MSBuild's `FileLogger` for a log file, `MaxNodeCount`, the `BinaryLogger` (project imports embedded), extra global properties, and whether the up-to-date check may skip MSBuild. Without options a build is what it was.
- **The fast up-to-date check** (`Building/UpToDateCheck.cs`): after a build with options, each project in scope and everything it references records its inputs (project file, imports, compile/resource/analyzer/editorconfig/XAML/`UpToDateCheckInput` items, hint paths, assets file, icon, manifest, key file, copied items, referenced projects' assemblies) and outputs (assembly, reference assembly, deps and runtime config, each copied file at its destination, `UpToDateCheckBuilt`) with sizes and write times in `obj/…/daedalus.uptodate.json`, keyed by the global properties, target framework and SDK. The state is recorded from a fresh evaluation after the build; an input written while the build ran is recorded as stale. A Build skips MSBuild when every project in scope matches its state (a solution: every project the active configuration builds; a project: it and its references); a failure or a clean forgets the state; `DisableFastUpToDateCheck` opts out. `build/upToDate` gives each project's verdict and reason.
- **Timings** (`Building/TimingLogger.cs`): a logger on every build, registered with a `ConfigurableForwardingLogger` that passes only build, project, target and task start/finish events; the projects' spans and nodes, the 50 slowest targets, tasks summed by name, and the critical path over each project's real build. `build/timings`.
- **Binary logs** (`Building/BinaryLogs.cs`): `binlog/open|children|search|close` with MSBuild.StructuredLogger; ids per node as they are sent; search results with their path from the root.
- **Batch builds** (`SolutionSession.Building.cs`): entries in turn in one exclusive build, one restore per project, the check per entry; the exclusive-build plumbing (one at a time, design-time builds paused and resumed) is shared with `build/run`.
- **Build events** (`ProjectManagement/BuildEvents.cs`): `PreBuild`/`PostBuild` targets with an `Exec`, `RunPostBuildEvent`, written as the classic IDE writes them (`ProjectProperties.SetIn` for the property).

**T4 host** (`daedalus-t4host`, `src/DaedalusStudio.TextTemplating.Host`, protocol `DaedalusStudio.TextTemplating.Protocol`): Mono.TextTemplating with its in-process Roslyn compiler; `t4/transform` takes the template's path, optional unsaved content, a namespace, include and reference folders; returns the text, the extension (`output` directive) and errors with 1-based template positions (the host parses first, because the compiler's positions are 0-based and the parser's aren't). Shipped in `t4host/` next to the shell.

**Workbench**
- `BuildService`: `Options` (from the shell), `BatchBuildAsync`, `LastBatch`; `BuildDepthService`: the check, timings, build events, binary logs.
- `CustomToolService`: runs a `Generator` (ResX, T4, or a plugin's command), writes the output next to the input when it changed, and sets `LastGenOutput` and the output's `DesignTime`/`AutoGen`/`DependentUpon` through `items/set`. `ResXGenerator`: `ResXFileCodeGenerator` and `PublicResXFileCodeGenerator` in StronglyTypedResourceBuilder's shape. `TextTemplatingService`: the supervised T4 host (lazy start, restart on a crash, a two-minute limit).
- `PluginManager.CustomTools`.

**Shell**
- **Settings** (Build and Run): Build Output Verbosity, Build Log File Verbosity, Maximum Parallel Project Builds, Fast Up-to-Date Check, Before Running (`build`, `prompt`, `never`; F5 and Ctrl+F5 go through it), Write a Binary Log for Every Build, Run Code Analysis on Build, Run Custom Tools on Save.
- **Build menu:** Batch Build… (a document: every project × configuration × platform, Build/Rebuild/Clean, a result per entry), Check Whether Projects Are Up to Date, Build Timings (a document: a timeline row per project build, the critical path, the slowest targets and tasks, Open Binary Log), Build Solution with Binary Log, Open Binary Log…, Open Build Log.
- **Binary log viewer** (a document per file): the tree a level at a time with icons and durations, search with results that reveal their node, Open File (Enter, double-click) at the node's line, a summary.
- **Build Events** page in the project properties (pre-build, post-build, when the post-build event runs, the macros).
- **Custom tools:** Run Custom Tool (Solution Explorer context menu on `.resx` and `.tt` files, and a command for any file with a `Generator`), and on save; Output → Custom Tool; the `t4` language (`.tt`, `.ttinclude`, `.t4`) with a TextMate grammar and directive and block snippets.
- **Plugin API 0.2.8** (additive, with M26a's): `contributes.customTools`.

**Tests**
- Build host integration (`BuildDepthIntegrationTests`, 4): the up-to-date check against real MSBuild builds (never built; nothing changed, and an MSBuild build writes nothing; a source edit in a referenced project, with Hello out of date through it, and MSBuild recompiling it; a new file under the glob; the project file; a copied content file, then a deleted copy; Clean forgets and Rebuild records; `DisableFastUpToDateCheck`); timings, the critical path, a log file at detailed verbosity, normal verbosity's project lines, and a binary log opened, browsed and searched; batch builds of two configurations, then both skipped; build events written, run (pre-build output, a post-build file) and removed.
- Custom tools (`CustomToolIntegrationTests`, 3): the ResX class (shape, order, escaping, identifiers, file resources, public, manifest names); the T4 host (the fixture's template with its include, unsaved content and the `output` extension, a compile error at its line and column, a parse error once, a killed host restarted); ResX and T4 run on `samples/ProjectSystem/src/Items` (new resources, a changed include, untrusted refused, a new generator's metadata in the project file) and the project then builds.
- Plugins: `contributes.customTools` parsed and listed.
- Headless UI (`BuildDepthTests`, 3): Batch Build (rows, a run with results), the check skipping a build, Build Solution with Binary Log opening the viewer with search and reveal, Build Timings; the Build Events page saved and run; Run Custom Tool on a `.resx`, and a `.tt` edited in the editor (colored as `t4`) regenerated on save.
- Smoke test: `build.depth` (a build skipped by the check, Build with Binary Log in the viewer with search, Build Timings, Batch Build of Hello|Release, the ResX generator and the shipped T4 host in Greetings, which then builds).

## Deviations and gaps

- **Per-project skipping inside a solution build** with out-of-date projects: MSBuild's incrementality decides there; the check skips a solution build only when every project is up to date. `TODO(issue)`.
- **Undeclared inputs** of custom targets aren't tracked (declare them as `UpToDateCheckInput`, as in the classic IDE). By design; documented.
- **Custom tool errors** go to Output → Custom Tool and a notification, not the Error List. `TODO(issue)`.
- **Binary log viewer:** no timeline or project-graph view; logs are read through the open solution's build host (no solution, no viewer). `TODO(issue)`.
- **T4:** no `TextTemplatingFilePreprocessor` (runtime templates), no template debugging, `hostspecific` limited to Mono.TextTemplating's host (`ResolvePath`, parameters). `TODO(issue)`.
- **Resources** for Visual Basic and F# projects (the generators write C#). `TODO(issue)`.
- The benchmark harness's binary-size target doesn't count `t4host/` (nor M14b's `debughost/`). `TODO(issue)`.
