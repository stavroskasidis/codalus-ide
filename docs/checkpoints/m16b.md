# M16b checkpoint: HTML, CSS and JavaScript/TypeScript

Date: 2026-10-10. Decision: [ADR 0024](../adr/0024-node-runtime-and-web-language-servers.md), which settles D3. M16c (Blazor WebAssembly, browser debugging) follows.

## Built

**Workbench** (`Node/NodeRuntime.cs`, `Node/WebLanguageServers.cs`)
- **`NodeRuntime`:**
  - Node.js 24.21.0 for Windows, Linux and macOS (x64 and arm64), downloaded from nodejs.org;
  - checked against the SHA-256 values pinned from the release's `SHASUMS256.txt`;
  - unpacked into the cache folder (`.zip` on Windows, `.tar.gz` elsewhere);
  - runs npm without the user's npm configuration's notifier, fund or audit.
- **`WebLanguageServers`:** `npm ci --ignore-scripts` from the shipped lockfile, into a folder per lockfile hash, with the entry points of the HTML, CSS and TypeScript servers.
- **`LanguageService.RetryAsync`:** a service that couldn't start (not installed yet) starts later and gets the open documents of its languages.

**Shell** (`ShellHost.WebLanguages.cs`, `WebServers/package.json` and `package-lock.json`, shipped as `web-servers/`)
- **Language services:** `html` (with embedded CSS and JavaScript), `css` (CSS, SCSS, Less) and `typescript` (JavaScript, TypeScript, JSX, TSX), each with its initialization options (the formatters, TypeScript's `tsserver`).
- **Consent:**
  - the first web file opened without the servers shows a notification: Install, Not Now, Never;
  - the setting `web.languageServers` (ask, install, off), and the command Install the Web Language Servers;
  - progress in the status bar and the Language Services output;
  - `DAEDALUS_NODE_CACHE` for a shared download folder.
- **`DocumentUris.ToPath`** understands `file:///c%3A/…`: diagnostics and locations from VS Code's servers reach Windows files.

**Tests**
- **Workbench:** `NodeRuntimeTests`: a download with the wrong checksum is refused and removed (a fake HTTP handler, so offline); the platform layout.
- **Language host:** `DocumentUrisTests`: escaped and lower-case drive letters.
- **Headless UI:** `WebLanguagesTests`. It installs the real runtime and servers (into a shared cache: only the first run downloads), then checks:
  - a TypeScript type error (TS2322) in the Error List data;
  - TypeScript hover and member completion;
  - HTML element completion and CSS property completion.
- **Smoke test:** step `web.languages` (M16): the install, a TypeScript error and HTML completion. `eng/smoke-test.sh` keeps the download in `.work/node-cache`.

**Docs:** ADR 0024, [User guide: Web development](../user-guide/web.md) (HTML, CSS, JavaScript and TypeScript), `THIRD-PARTY-NOTICES.md` (Node.js and every package in the lockfile, with their licenses: MIT, BSD-2-Clause, Apache-2.0, ISC), the roadmap (D3 decided), CLAUDE.md (`DAEDALUS_NODE_CACHE`).
