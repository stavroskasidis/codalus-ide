# M18b checkpoint: allocations, memory, .NET Async, threads, exceptions, file I/O, activities, the events viewer and BenchmarkDotNet

Date: 2026-10-12. Decision: [ADR 0046](../adr/0046-profiler-tools.md) (the profiler's other tools), on [ADR 0044](../adr/0044-diagnostics-host-and-trace-processing.md) and [ADR 0045](../adr/0045-profiler-views.md). M18 was split (roadmap rule 5) into [M18a](m18a.md) and M18b (this); with it, M18 is complete.

## Built

**The diagnostics host** (`src/DaedalusStudio.Diagnostics.Host`, protocol in [docs/diagnostics-protocol.md](../diagnostics-protocol.md)): the same host, protocol version 1 (every change is an addition; M18a's sessions open unchanged).
- **One session, every tool** (`DiagnosticsPort.TraceProviders`): `diag/trace/start` takes `tools` (`cpu`, `allocations`, `async`, `threads`, `exceptions`, `fileio`, `activities`) and extra `providers` (any EventSource or EventPipe provider, with keywords, level and arguments), merged into one EventPipe session with the runtime's method events and rundown; the session folder's trace is now `trace.nettrace`.
- **One pass** (`Cpu/NettraceReader.cs` → `Trace/TraceData.cs`): the `TraceLog` is walked once into four **stack profiles** with **weighted samples** (`CpuSample.Weight`; CPU samples, allocation ticks in KB with the type as a leaf frame, lock contention in microseconds under a "Lock contention" frame, exceptions with their type as the leaf and the runtime's `System.Runtime.EH` frames removed so the throw site shows), the TPL's operations, the thread pool's events, contentions, exceptions, HTTP requests, database commands, spans, and an index of every event. Every M18a view takes `filter.profile`.
- **Views**: `diag/async/tasks` (the longest first; async methods named from their state machines, `Worker.FetchAsync`; the creating stack), `diag/threads` (each thread's states in buckets, the thread pool's adjustments with their reasons, starts and retirements), `diag/exceptions` (by type and throw site with the line), `diag/activities` (HTTP from `System.Net.Http`, database commands from SqlClient's and EF Core's DiagnosticSource events and `db.*` spans, `ActivitySource` spans nested by parent), `diag/fileio`, `diag/events/stats` and `diag/events/list` (provider, name, payload text, time range, threads), `diag/trace/export` (Speedscope; Chromium trace events with the activities on their own tracks), `diag/cpu/compare`.
- **File I/O** (`Trace/IoSampler.cs`): the process's I/O counters four times a second into `trace.io.json`: `GetProcessIoCounters` on Windows, `/proc/<pid>/io` on Linux, `proc_pid_rusage` on macOS (ADR 0046 says what each counts).
- **Memory** (`Memory/`): `HeapSnapshotRecorder` takes a snapshot as dotnet-gcdump does (the `GCHeapSnapshot` keywords, an induced full GC, the session stopped when it ends; the events kept as `heap-N.nettrace` through a tee stream); `HeapGraph` links the bulk node, edge, root and type events, names generic types, and walks from the roots for the paths to roots; types by size, diffs by name, referrer trees (`diag/heap/*`).

**Workbench** (`src/DaedalusStudio.Workbench/Diagnostics`): `DiagnosticsService.StartTraceAsync` with tools and providers, `TakeHeapSnapshotAsync`, `OpenHeapSnapshotAsync` (`HeapSnapshot`, reopened after a host restart like `CpuTrace`); `CpuTrace`'s new views; `ProfilerSession` with `Snapshots` and `Dump`; `ProfilerTools` and their titles; `Benchmarks.cs`: `BenchmarkFinder` (attribute lists naming `Benchmark`, the method after them, nested types and namespaces, comments and strings skipped), `BenchmarkService` (projects referencing BenchmarkDotNet, `dotnet run -c Release … --filter … --exporters json --artifacts …`, the JSON report, `.daedalus/benchmarks/history.json`).

**The shell**:
- **Performance Profiler**: nine tools (CPU Usage, .NET Counters, .NET Object Allocation, Memory Usage, .NET Async, Threads and Contention, Exceptions, File I/O, Activities); while collecting with Memory Usage, **Take Snapshot** (also `profiler.takeSnapshot`) and **Create Full Dump** (the debug companion host writes `full.dmp` into the session); **Compare** a session with a baseline.
- **The report**: **Stacks of** (CPU, allocations, lock contention, exceptions) for the stack views, and the tabs **Allocations**, **Memory** (snapshot and baseline, types by size or growth, paths to roots, Inspect Objects in the Full Dump through M14's dump view), **.NET Async**, **Threads** (`Controls/ProfilingControls.cs`: `StateStrip`, `SpanBar`), **Exceptions** (over time, grouped, Go to the throw site), **File I/O**, **Activities**, **Events** (counts, filtered pages, Export for Speedscope, Export Chromium Trace, Save Trace As).
- **Comparison** (`ProfilingComparisonViewModel`): functions by change of share; heap growth between the sessions' last snapshots.
- **BenchmarkDotNet**: `Editor/BenchmarkMargin.cs` (a stopwatch on each benchmark and its class; click to run), the **Benchmarks** window (View → Other Windows: the solution's benchmarks, Run All, Run Selected, Stop, the job, in process, results with mean, error, deviation, allocations, the history of a benchmark), `benchmarks.runAll`, the `Benchmarks` output; trusted solutions only.

**Fixtures** (`samples/Diagnostics`): `AsyncHeavy` now throws and catches an exception for every eighth item (`// [throw]`) and starves the pool at its start; `Allocations` and `Leaky` run until killed with 0; new `Activities` (HTTP to its own server, EF Core on in-memory SQLite, `ActivitySource` spans, 1 MB of file I/O a round) and `Benchmarks` (BenchmarkDotNet 0.15.8).

## Deviations and gaps

- **gcdump**: snapshots are recorded the way dotnet-gcdump records them but kept as `.nettrace` files of the runtime's heap events; dotnet-gcdump's `.gcdump` files (PerfView's FastSerialization graph, not in the TraceEvent package) can't be opened or written yet. `TODO(issue)`
- **Retained sizes**: types show their objects' own sizes; retained sizes need a dominator tree. `TODO(issue)`
- **File I/O** is the process's I/O counters; per-file reads and writes need kernel tracing (ETW's file I/O with an administrator session and the proprietary KernelTraceControl we don't ship; `perf`, eBPF or DTrace with privileges). `TODO(issue)`
- **Allocations** are the runtime's allocation ticks (about one per 100 KB per thread); .NET 10's randomized `AllocationSampled` events with exact sizes are a refinement. `TODO(issue)`
- **Spans** are recorded when they stop: a span still open when the trace ends isn't shown. HTTP requests show their URL (paths redacted by .NET 9 and later's `System.Net.Http` events) without the method.
- **Thread states** come from the sampler and contention events (running, waiting or native, blocked); EventPipe has no context switches, so "waiting" can't be split into I/O, sleep and synchronization.
- **Benchmark ratios** are against each class's first result in the run, not its `[Benchmark(Baseline = true)]` (the JSON report doesn't mark it). `TODO(issue)`
- **Comparing CPU sessions** matches functions by name; a renamed or inlined function shows as gone and new.
- Programs in containers, WSL or over SSH still can't be profiled (M21, as in M18a).
