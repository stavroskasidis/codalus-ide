# M40b checkpoint: the WPF previewer and the Live Visual Tree for WPF

Date: 2026-10-16. The second and last part of M40 (the Windows desktop phase; D31: Windows-only features, the other OSes decided later), so M40 is done. Decision: [ADR 0072](../adr/0072-wpf-previewer-hosting.md) (WPF previewer hosting). M40a ([m40a](m40a.md), ADR 0071) built the projects, run and debug, and WPF XAML editing.

## Done

**The WPF designer host and live agent** (`src/Codalus.Previewer.Wpf`, `codalus-wpfpreviewer.dll`): WPF code, `net8.0-windows` with `UseWPF`, framework references only, so it loads into any WPF app on .NET 8 or later.
- **Building and shipping:** it's in `Codalus.slnx` and builds on Linux and macOS with `EnableWindowsTargeting` (the WPF code compiles everywhere). The shell references it for build order only and copies it to `wpfpreviewer/` on a Windows build and on a `win-*` publish, so only the Windows package has it (`eng/package.sh` packages the publish output).
- **The designer host** (`Program`, `WpfDesigner`): started by the IDE as Avalonia's is (`dotnet exec` with the app's runtimeconfig and deps.json), it speaks Avalonia's remote protocol through the workbench's own `RemoteProtocol.cs` (linked). It loads the app (its folder searched for references), sets `Application.ResourceAssembly`, creates the app's `App` and calls `InitializeComponent` (App.xaml's resources and merged dictionaries) without running it, and serves the agent's `hit` and `bounds` itself on the agent port.
- **Loading the edited text:** `XamlXmlReader` with WPF's schema context, the file's assembly as `LocalAssembly` (`clr-namespace:` without `assembly=`) and its pack URI as base, through `DesignTimeXamlReader`, which leaves out `x:Class`, `x:Subclass`, `x:ClassModifier`, `x:FieldModifier`, `x:Code`, event members and `EventSetter`s; then `XamlReader.Load`. Errors keep their line and column. A window's or page's content moves into a stand-in border that keeps its background, resources, name scope, data context and text properties; a resource dictionary and App.xaml draw a description.
- **Design time** (`DesignXaml`, WPF-free): the root's `x:Class` (it names the root in selection paths), `d:DesignWidth` and `d:DesignHeight` (else the window's `Width` and `Height`, else the content's size), and `d:DataContext="{d:DesignInstance …}"` in its forms (positional, `Type=`, `{x:Type …}`), an instance created when `IsDesignTimeCreatable=True` (a list with `CreateList`). What it can't use goes to the log.
- **Frames:** a hidden `HwndSource` hosts the elements (loaded as in an app); `RenderTargetBitmap` draws them at `96 × scale` DPI after the update's bindings and layout, and again half a second later if the pixels changed. BGRA, or swapped to the RGBA the IDE asks for. The last good preview stays on an error; the user's code failing later is logged.
- **Selection** (`WpfTree`): logical paths of `Type:ordinal:Name` steps over `LogicalTreeHelper`, as the Avalonia agent's; a hit climbs out of templates and up the visual tree to an element the XAML declares.
- **The live agent** (`StartupHook`, `LiveAgent`, `AgentLink`): the Avalonia agent's protocol over WPF: `windows`, `tree` (logical or visual, templated flag), `props` (dependency properties and attached ones set, values and `DependencyPropertyHelper.GetValueSource`), `set` (the property's converter, as a local value; read-only refused), `highlight` (an adorner), `pick` (a class handler on windows' `PreviewMouseDown`), `path`. It waits for `Application.Current` before touching the app's dispatcher, and every command has a 10-second limit on the UI thread.

**The IDE's side** (workbench and shell):
- **`PreviewService` routes by dialect** (`DialectOf`): `.axaml` files and Avalonia projects to Avalonia's designer host, a WPF project's `.xaml` to the WPF previewer (`PreviewTarget.Dialect`), MAUI's XAML to a message. A WPF target: Windows only ("The WPF previewer runs on Windows only…", before trust, build or start), trusted folders, the file's project or a WPF app referencing it (the startup project first), .NET 8 or later (`WpfFrameworkProblem`), the shipped host (`CODALUS_WPF_PREVIEWER`). `LaunchFor` starts it with `PreviewerLaunch.AgentInHost` (the agent's port and token, no startup hook; `PreviewerSession.ApplyAgentEnvironment`). Theme variants are Avalonia's only.
- **The XAML Previewer** follows `.xaml` editors as well as `.axaml` ones (Shift+F7 and the editor's context menu in both), rebuilds on saves of `.xaml` too, hides the theme picker for WPF (`XamlPreviewViewModel.SupportsThemes`), and asks the logical tree of the editor's language.
- **The live tools:** `RunService.ProgramPlan` adds the WPF agent to a WPF app on Windows on .NET 8 or later (`ShellHost.LiveAgentFor`), and `LiveSession` serves it unchanged; Go to XAML searches `.xaml` files for the window's `x:Class`. Off Windows the Live Visual Tree says that a WPF app's tree is Windows only. The setting is now "Live Visual Tree for Avalonia and WPF apps".
- **The C# host's logical tree** leaves out WPF's non-logical property elements (`ToolTip`, `Style`, `Triggers`, `LayoutTransform`, `InputBindings`, `CommandBindings`, `ItemContainerStyle`, `FocusVisualStyle`).

**Docs:** the user guide's [WPF and Windows Forms](../user-guide/windows-desktop.md) page (the previewer and the live tree), the Avalonia page's links, the website's Features page, `CODALUS_WPF_PREVIEWER` in [environment variables](../environment-variables.md), the changelog, and ADRs 0048, 0052 and 0071 linked to 0072.

## Tests

- **Workbench, every OS** `WpfPreviewerRoutingTests` (7): the dialect of `.xaml` and `.axaml` files in WPF, mixed and Avalonia projects; .NET 8 or later (`net48`, `net6.0-windows`, multi-targeting, `netcoreapp3.1`); the WPF launch serving the agent in the host and Avalonia's with the startup hook chained (and nothing without an agent file); the fixture's window, user control, App.xaml and resource dictionary read by `DesignXaml` (class, design size, design instance); `d:DesignInstance`'s forms and what it can't use; `clr-namespace:` parsing; the WPF host's messages (errors with positions, BGRA frames) through the codec.
- **Workbench, Windows only** `WpfPreviewerTests` (4) on the fixture's build output with the real designer host and `PreviewerSession`: the window at 480×360 with its design-time data (the remaining count has a width, and none without `IsDesignTimeCreatable`), an edit's new frame, an unknown property's error at its line, malformed XAML, recovery to the same pixels; the user control at 120×24, the styles dictionary (its `StaticResource`s from App.xaml) and App.xaml; bounds and hits both ways (the button through its template's text, the named text box, an item of the list in the ListBox, a missing element); scale 2 at 960×720 and back.
- **Workbench, Windows only** `WpfLiveAgentTests` (1): the fixture app run with the agent through `LiveSession`: its window, the logical tree (the button, the named text box, the user control, nothing templated) and the visual tree (the button's `Chrome`, list items); properties and sources (Local for a binding and a margin, Style for the style's padding, attached `DockPanel.Dock`, read-only `IsMouseOver`); values set (`4`, `Red`, Width's `Auto`) and refused (read-only, a bad thickness); highlight and pick; the paths of an element and of a template part; the disconnect when the app ends.
- **Headless UI** `WpfPreviewerShellTests` (2): off Windows (skipped on Windows), Shift+F7's command on the fixture's `MainWindow.xaml` says Windows only, builds and starts nothing, again after an edit, and no live agent joins a WPF app; on Windows (skipped elsewhere), the previewer builds and renders the window at its design size without the theme picker, follows an edit, selects the button's tag on a click, outlines the text box at the caret, shows the loader's error with its line and recovers, renders at scale 2; then the app runs with the live agent: the tree, the visual tree, a margin set in the Live Property Explorer, and Go to XAML on the text box.
- **Smoke** `wpf.preview` (Windows; skipped elsewhere, after `windows.desktop`): the WPF fixture's `MainWindow.xaml` in the XAML Previewer at its design size with its design-time data, an edit's frame, a click selecting the button, `wpf-previewer.png`.

## Gaps

- **Pointer hover** isn't shown in the WPF preview: WPF's hover state follows the real mouse, which the hidden window never has. Clicks select, as in the Avalonia previewer; keyboard input isn't forwarded. `TODO(issue)`
- **Design-time data** on the root only (not nested elements), and `d:DesignData` sample files aren't supported; Visual Studio's `d:` design-time properties (`d:Text`) aren't applied. `TODO(issue)`
- **Internal types** the XAML creates by reflection (loose XAML's access rules) fail to load in the preview. `TODO(issue)`
- **The code-behind doesn't run** in the preview (the edited XAML, not the compiled class), and a code-behind change shows after a save and a rebuild, as for Avalonia.
- **XAML Hot Reload** (a candidate, as for Avalonia): Live Property Explorer edits stay in the running app.
- **Linux and macOS:** the previewer and live tools through a Windows machine (the remote target, decided later under D31); WPF on .NET Framework (M43).
- **The website's screenshot** of the WPF previewer: `wpf-previewer.png` comes from the smoke step on Windows (CI), not taken here.
