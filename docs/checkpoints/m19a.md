# M19a checkpoint: Avalonia XAML editing and the live previewer

Date: 2026-10-12. Decisions: [ADR 0047](../adr/0047-xaml-language-service.md) (the XAML language service) and [ADR 0048](../adr/0048-avalonia-previewer-hosting.md) (Avalonia previewer hosting). M19 is split (roadmap rule 5) into M19a (this) and M19b (below).

## Built

**XAML editing in the C# host** (`src/DaedalusStudio.LanguageServices.Host/Xaml`): `.axaml` files are the language `axaml` ("Avalonia XAML", TextMate's XML grammar), routed to `daedalus-lshost` like Razor files. They are additional files of their projects (Avalonia's targets add every `AvaloniaXaml` item), so the editor's text drives Avalonia's name generator.
- `XamlSyntax`: a tolerant parser (elements, property elements, attributes and values with offsets; unclosed tags, unterminated values, mismatched end tags as errors; never throws).
- `XamlTypeSystem` on the project's Roslyn compilation: XML namespaces through `[XmlnsDefinition]`, `using:` and `clr-namespace:`; types (Avalonia's from metadata, the app's and its libraries' from source); CLR properties, Avalonia properties (`XxxProperty`), attached properties, events, content properties, pseudo-classes (`[PseudoClasses]`), values (enums, booleans, named colors, static instances), bindable members.
- **Completion**: elements (default and prefixed namespaces, property elements), attributes (settable properties, events, attached properties, directives, minus those set; `Name="$0"` snippets), values, markup extensions, `StaticResource`/`DynamicResource` keys (the project's and its references' XAML), **compiled binding paths** from the `x:DataType` in scope (through indexers, `#Name`, `$parent[Type]`), binding arguments and modes, `ElementName`, `x:Static` members, `TemplateBinding`, setters' properties and values from the target type, selectors (types, classes, pseudo-classes, names, `/template/`), `x:Class`, `x:DataType`, `xmlns`, style classes, event handlers from the code-behind. The editor triggers it also on `{`, `=`, `/` and `|` in XAML.
- **Diagnostics** 250 ms after an edit (600 ms after other files' edits): `XAML0001` syntax, `XAML0002` undeclared prefix, `XAML0003` unknown type, `XAML0004` unknown member, `XAML0005` invalid enum value, `XAML0006` a compiled binding's unknown path member (compiled per `x:CompileBindings`, `CompiledBinding` or the project's `AvaloniaUseCompiledBindingsByDefault` from the analyzer config). The **XAML compiler's errors** (`AVLN…`) of the last build are squiggles in their files (`XamlBuildDiagnostics`, source `axaml.build`) until the file changes or the next build.
- **Hover**, **Go to Definition** (types and members in source or decompiled, resource keys, style classes to their styles, binding path members, `x:Class`, named elements), **`x:Name` rename** (the name, `#Name`, `ElementName`, and the code-behind's uses of the generated field through `SymbolFinder`), **formatting** (document and range; whitespace only), folding ranges, document symbols, and **`daedalus/xaml/logicalTree`** for the previewer.

**The previewer** (`src/DaedalusStudio.Workbench/Previewer`):
- `RemoteProtocol`: Avalonia's remote protocol (length, message GUID, BSON) in our own AOT-safe codec for the messages the previewer uses; the tests check it against `Avalonia.Remote.Protocol`'s transport both ways.
- `PreviewerSession`: Avalonia's designer host from the app's own package (`AvaloniaPreviewerNetCoreToolPath`), `dotnet exec` with the app's runtimeconfig and deps.json, over loopback TCP with a session id; frames acknowledged; updates one at a time, the frame after the answer counted as the update's; every wait bounded.
- `PreviewService`: the file's project and host app (itself, or an app referencing the library, the startup project first), trusted folders only, a build when the outputs are older than the projects' items (the previewed file aside), the session stopped before every build (Windows locks the app's assemblies), the render scale and theme kept across sessions.
- The **agent** `DaedalusStudio.Previewer.Agent` (netstandard2.0 startup hook, shipped in `debughost/`): `hit`, `bounds`, `theme` over a second loopback connection with a token, reaching Avalonia by reflection on its UI thread.
- `PreviewSelection`: XAML paths (type and index among same-type siblings) against the preview's logical paths, both ways.

**The shell** (`ShellHost.Xaml.cs`, `BuiltIns.Xaml.cs`, `XamlPreviewViewModel`, `XamlPreviewView`): the **XAML Previewer** tool window (docked right; Shift+F7 in an `.axaml` editor, View → Other Windows, the editor's context menu) follows the active `.axaml` editor, renders its text 150 ms after the last edit, shows the loader's error with its line above the last frame, fits the frame to the pane by default (never above 100%; Fit returns to it), zoom (25–400%, the zoom button is 100%), render scale (100–200%) and theme variant (Default, Light, Dark); a click selects the element's start tag in the XAML, the caret's element is outlined in the preview; a saved C# or XAML file of the preview's projects rebuilds and restarts it. Its log is the "XAML Previewer" output channel.

**Fixture** `samples/Avalonia` (`Avalonia.slnx`): `AvaloniaApp` (MVVM without a library; `MainWindow.axaml` with compiled bindings, `d:DataContext` from `DesignData`, `d:DesignWidth`/`d:DesignHeight`, named elements used in the code-behind, a `StaticResource`, the library's control, a typed `DataTemplate`; `TodoItemView.axaml` with `Design.DataContext`; `Styles/AppStyles.axaml` with classes, a template selector and `Design.PreviewWith`; `App.axaml` with resources and the library's merged dictionary; the Inter font so previews look the same everywhere) and `AvaloniaControls` (`RatingControl`, a templated control, and its `ControlTheme`).

## Tests

- **Workbench, unit** `PreviewProtocolTests` (Avalonia's transport's messages decode with our codec and ours decode in Avalonia's: session, update, result with exception details, frames with data, viewport, pixel formats, render info, frame acknowledgements, pointer input; round trips; the agent's replies); `PreviewSelectionTests` (caret to path, hits aligned at the XAML's root through a wrapping window, item containers, unrelated paths; AVLN errors to diagnostics, duplicates once, C# errors left out).
- **Workbench, host integration** `XamlPreviewerTests` (the real designer host on the built fixture with the agent): a window at its design size, 12 edits each answered by a changed frame (edit to frame p95 asserted off CI), errors with their line and column (an unknown property, malformed XAML) and recovery; a user control with `Design.DataContext` at its design size, the library's resource dictionary through the app with the library's assembly, styles with `Design.PreviewWith`; hit testing (the button through its XAML path and back), bounds, Dark and Light themes changing the pixels, scale 2 doubling the frame.
- **Language host integration** `XamlLanguageTests` (samples/Avalonia in the real build and C# hosts): no false alarms on any of the fixture's five XAML files (each with one planted error, the only one reported); elements, attributes, values, `x:DataType`, the library control's properties; markup extensions, resources from the app and the library, binding paths with documentation and through indexers, modes, the data template's type; selectors, classes, pseudo-classes, setters; live errors of each kind at their positions, no errors for untyped data templates or `xml:`, recovery; hover and definition (types, members, attached properties, resources, styles, the code-behind, Avalonia's types); `x:Name` rename into the code-behind; formatting (and its idempotence); the logical tree.
- **Headless UI** `XamlShellTests`: completion in an `.axaml` editor; the previewer builds the app and renders at the design size, follows an edit, zoom, a click selects the button's start tag, the caret outlines the greeting, the loader's error with its line and recovery, the Dark theme, scale 200%; a saved view model change rebuilds the preview and shows it; a build's AVLN error lands in its `.axaml` file at its line.
- **Smoke** `xaml.preview`: binding path completion in the published app, the previewer's first frame (build included), an edit's frame, a click selecting the button, `smoke-test-xaml-preview.png`; every wait bounded with a message.

## Deviations and gaps

- The edit debounce (150 ms) is on top of the measured edit-to-frame time in the IDE; the budget's measurement (`XamlPreviewerTests`) is the designer's own (update sent to frame shown). With the debounce, an edit shows in about 200 ms.
- Resources from compiled themes (Fluent's `SystemAccentColor`…) aren't completed and unknown `StaticResource` keys aren't reported: themes exist only as compiled XAML. `TODO(issue)`: read their keys from the assemblies' `!AvaloniaResources`.
- XAML formatting re-indents but doesn't wrap or sort attributes. `TODO(issue)`
- The agent finds the previewed window through the designer host's private `s_currentWindow`; selection and themes would stop (not the preview) if Avalonia renames it. `TODO(issue)`: an element query in Avalonia's remote protocol.
- Code-behind changes show after a save and a rebuild, not as typed (no Hot Reload into the designer).
- Pointer moves are forwarded (hover styles); clicks select instead of reaching the preview, and keyboard input isn't forwarded.
- **M19b** (planned): the Live Visual Tree and Live Property Explorer for running Avalonia apps (a startup-hook diagnostics agent like the previewer's, the element tree with adorners, property values with their sources, editable, element to XAML line, a screen-reader tree of the preview's elements), the Avalonia templates through `dotnet new`, and runtime XAML hot reload as a candidate.
