# M23a checkpoint: personalization

Date: 2026-10-13. M23 is split in two:
- **M23a** (this checkpoint) covers how the IDE looks, which keys it takes, what users bring from other tools, and the first run.
- **M23b** covers profiles, settings sync, localization, and customizing menus and toolbars.

No new ADR: everything here stays inside existing decisions. Settings stay VS Code-shaped (ADR 0002's settings model), key bindings use the M29 `keyboardScheme` key, and onboarding is in the Welcome plugin on the public API (ADR 0003).

## Done

**Fonts and Colors** (Tools → Fonts and Colors; `FontsAndColorsViewModel`, `ShellHost.Colors.cs`, `Theming/ColorCustomizations.cs`). Users override colors over the theme with VS Code's two settings, which are now registered (`SettingType.Object`, multi-line JSON in Options):
- `editor.tokenColorCustomizations`: the shorthands (comments, strings, keywords, numbers, types, functions, variables) and `semanticTokenColors` by token type.
- `workbench.colorCustomizations`: the editor's elements by VS Code's ids (selection, current line, read and write highlights, bracket match, the four squiggles, find matches), and window colors by `Shell.*` resource key.
- Either can be scoped as `"[Dark]"` to one theme.
- Colors are `#RRGGBB` or `#RRGGBBAA` (alpha last).
- `EditorTheme.WithOverrides` gives the editor its colors. Window colors are set in `Application.Resources` and follow theme changes.
- The page lists every item with the theme's color and the override. A color is typed as hex, for the current theme or every theme, and Reset clears both scopes.

**Keyboard schemes** (`keyboard.scheme`): ReSharper and Emacs join Default and VS Code (`BuiltIns.Keymaps.cs`).
- Both build on the default scheme. Only the active scheme's own bindings are among the defaults (`ParseDefaultKeybindings(platform, scheme)`), so menus, tooltips and the shortcuts editor show its keys.
- Emacs needed caret commands the editor didn't have (`CodeEditorController.Caret.cs`, on AvaloniaEdit's editing commands):
  - `cursorLeft`…`cursorBottom`;
  - the mark (`editor.action.setSelectionAnchor`: moves extend the selection until `Ctrl+G`);
  - kill to the line's end, and cut and copy that end the mark;
  - `deleteRight`;
  - its `Ctrl+X` chords and `Alt+X`.

**Importers**:
- **VS Code** (Tools → Import Settings from VS Code; `VsCodeImport`). It reads the user folder of VS Code, Insiders or VSCodium.
  - Settings that are also ours come over with valid values, including the color customizations. Built-in themes map to ours.
  - Key bindings whose commands exist here come over.
- **`.vssettings`** (Tools → Import a .vssettings File; `VsSettingsImport`):
  - the text editor's font and size (points as pixels);
  - its syntax and element colors, converted from `0x00BBGGRR`, with "automatic" left to the theme and added to the user's colors;
  - tab size, tabs, word wrap and line numbers;
  - the user's shortcuts (chords, removals, the Text Editor scope as `editorTextFocus`) for 67 mapped commands.
- Both importers ask first and log every skipped item with why.

**Export and Import Settings** (Tools; `ShellHost.SettingsTransfer.cs`): one JSON file (`"daedalusSettings": 1`) with settings, keyboard shortcuts and saved layouts.
- Importing asks which of the three parts to take.
- Settings are validated one by one; unknown ones are skipped and logged. Shortcuts replace the user's, and layouts are added.

**Window layouts** (Window; `ShellHost.Layouts.cs`):
- Named layouts are saved, applied and deleted in the state folder's `layouts.json`, with Default being the reset layout.
- Full Screen (`Shift+Alt+Enter`, `⌃⌘F`; `IShellWindow.IsFullScreen`).
- Distraction-Free Mode: no tool windows, toolbar or status bar, full screen. The same command restores all of it, and the `distractionFree` context key is set while it is on.

**Onboarding** (the Welcome plugin):
- Until the user chooses Done (`welcome.onboarded`), the Start page begins with **Get Started**:
  - the color theme and keyboard scheme, each with its current value (the scheme from a quick pick);
  - the VS Code and file importers;
  - Fonts and Colors.
- Help → Get Started brings it back.
- A **tip** of the day runs what it describes; Next Tip moves on.

**Tests**: `ColorCustomizationTests`, `VsCodeImportTests`, `VsSettingsImportTests`, `SettingsTransferTests`, `WindowLayoutTests`, `KeyboardSchemeTests` (Emacs keys typed into a real editor), and the Start page's test, which now drives Get Started.
