# M61 checkpoint: debugging runtime-async code (.NET 11)

Date: 2026-11-13. The roadmap's [M61](../roadmap.md#m61--debugging-runtime-async-code-net-11), D53 ([ADR 0100](../adr/0100-debugging-runtime-async-code.md)): a spike of the Codalus debugger on async code compiled for runtime async and on the same code as state machines, the gaps it found fixed in the debugger, and the rest recorded as limits. One pull request.

## Done

**The fixture.** `samples/Debugging/Async.slnx`, its own solution so the other debugger classes don't build it:
- `AsyncDebuggee`, async code as state machines, and `AsyncDebuggee.RuntimeAsync`, the same files with `<Features>$(Features);runtime-async=on</Features>` (no `AsyncStateMachineAttribute`, no `<Method>d__N`; the methods are marked `MethodImplAttributes.Async`, and the PDB has no async stepping information);
- `AsyncLib` and `AsyncLib.RuntimeAsync`, one library built both ways: each program references the one built the other way, so the two kinds await each other in both directions;
- its scenarios, chosen by the program's argument (`steps`, `chain`, `throw`, `mixed`): locals before and after `Task.Delay` and `Task.Yield`, an awaited call of the user's that returns a value, a chain of three awaits, an exception thrown after an await, a library awaiting the program's callback. Lines by `// [marker]`.

**The spike** (`RuntimeAsyncDebuggingTests`, ten scenarios, each on both builds): before this milestone the Codalus debugger had nothing async-specific. Breakpoints and Run to Cursor after an await, the resumed method's parameters, locals and `this`, exception stops after an await, the call stack's folding and Set Next Statement already worked on both kinds. Every step across a suspending `await` ran the program on to its end, on both kinds; Step Into a state machine's method missed its body. The ADR's table has each scenario and build.

**Step Over an `await`** stops on the method's next line once it resumes, on whichever thread, for both kinds:
- `ClrModuleInfo.AsyncKind` tells a runtime-async method (`MethodImplAttributes.Async`) and a state machine's `MoveNext` (a type implementing `IAsyncStateMachine`) from metadata;
- before a step from such a method starts, a temporary breakpoint goes on each of its lines but the one it starts from; the first hit by the same call (a state machine's object, or a runtime-async method's `this`, held by strong handles), on any thread, ends the step;
- a stepper that ends in another method while the call is suspended (a state machine's state, or for runtime async a return into code that isn't the user's or right after the call, from IL without a `ret`) is ignored, and any other stop removes the breakpoints.

**Step Into** a state machine's method stops on its opening brace: its kickoff and its state machine's constructor are made the runtime's non-user code (`ICorDebugFunction2::SetJMCStatus`, `IClrProcess.SetUserCode` for a method) and the step goes through them to `MoveNext`.

**Step Out of a resumed async method**, and a step over its closing brace, go back to the method awaiting it once that resumes:
- a state machine's task names its awaiting state machine (its continuation, or a state machine on another thread's stack holding an awaiter of the task, before it has set the continuation): its lines get the temporary breakpoints, and the value the method returned (the task's result) is first in Locals and `$ReturnValue`;
- otherwise (runtime async), a Just My Code step through the dispatcher to the first of the user's code that runs, and out of a method the resumed awaiting call calls (the limits below).

**Stale step completions.** `CorDebugTarget` drops the completion of a stepper it cancelled: a breakpoint that stopped the program during a step (the user's, or one of the new ones) could have that step's completion delivered after the next request, which stopped at once on another thread.

**The user guide.** Debugging's new section, [Async code and runtime async (.NET 11)](../user-guide/debugging.md#async-code-and-runtime-async-net-11), says what works and the limits, and the Codalus debugger's limits list them.
