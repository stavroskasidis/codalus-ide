# M41a checkpoint: the Windows Forms designer for common forms

Date: 2026-10-16. The first part of M41 (the Windows desktop phase; D31: Windows-only features, the other OSes decided later). Decision: [ADR 0073](../adr/0073-windows-forms-designer.md) (Windows Forms designer). M41b follows, and M41 is one milestone with one stable (the maintainer's order).

## Done

**Reading and writing `InitializeComponent`** (C# host, `src/Codalus.LanguageServices.Host/WinForms`; [protocol](../protocol.md)):
- **`codalus/winforms/read`** (`DesignerReader`, `WinFormsFeature`): a form's or user control's model from its code or designer file: the class, its base type, its components (fields created with `new`, locals, the root) and the statements in order (creations; assignments to property paths; calls such as `Controls.Add` with a `TableLayoutPanel` cell or into a `SplitContainer` panel, `Items.AddRange`, `ColumnStyles.Add`, extender calls; `SuspendLayout`, `ResumeLayout`, `PerformLayout`, `BeginInit`, `EndInit`; event hookups as method groups or `new EventHandler(this.M)`; `resources.ApplyResources` and `GetObject`; Visual Studio's section comments), values as expression trees. Types through the compilation (`DockStyle.Fill` an enum member, `Color.Red` a static property, `Controls.CounterControl` the app's control), with a syntactic fallback. The file's style: `this.`, full type names, section comment rule, indentation, line endings.
- **Code it can't read** (`if`, loops, lambdas, the class's own methods, names that aren't components, property reads, object initializers, string interpolation…) fails with the reason and its line. A class that isn't a control isn't designable (the component designer is M41b).
- **`codalus/winforms/edit`** (`DesignerWriter`, `DesignerCodeGenerator`, `LineDiff`): `setProperty`, `addComponent`, `removeComponent`, `renameComponent`, `setParent`, `addEvent`, `removeEvent`, each the smallest edit, placed as Visual Studio's designer places it (alphabetical within the section, events after, new fields and creations after the last, new sections before the next component's, new controls first in their parent's `Controls.Add`, the parent's layout calls with its first child, `components` and `ISupportInitialize` handled), written in the file's style (Visual Studio for .NET or for .NET Framework: CodeDOM's casts, line-broken flags and arrays, `((byte)(0))`, `FromArgb`'s casts). Removals cascade to the controls inside and every mention; renames reach the class's other files through Roslyn; event handlers go to the code file with the event's own parameters (`object? sender` when the file has nullable annotations); an existing handler is shown. The edit is a line diff, with the model after it.
- **`codalus/winforms/toolbox`**: the project's and its referenced projects' components and controls.

**The designer host** (`src/Codalus.WinForms.Designer`, `codalus-winformsdesigner.dll`, `net8.0-windows`, `UseWindowsForms`, framework references only; [protocol](../winforms-designer-protocol.md)):
- Built on every OS (`EnableWindowsTargeting`), in `Codalus.slnx`; the shell copies it to `winformsdesigner/` on a Windows build and a `win-*` publish only. `CODALUS_WINFORMS_DESIGNER` overrides it ([environment variables](../environment-variables.md)).
- Started on the app's runtime (`dotnet exec` with the app's runtimeconfig and deps.json; a library alone on the host's own, rolled forward), supervised (JSON-RPC on stdio, the `Codalus.Rpc` connection linked), trusted folders only, after a build when the output is older than the sources.
- Windows Forms' `DesignSurface` with the root (the base type, named as the class) and the components created through `IDesignerHost` (designers attached, design mode), the statements run in order (property descriptors, reflection for calls, the compiled resources), failures listed with their lines; a hidden off-screen window, DPI unaware; frames as PNG with every control's bounds and client origin, `SplitContainer` panels as parts, non-visual components.
- Create (the designer's `InitializeNewComponent`, the front of the parent, a table cell, the next tab index), set properties (type converters, values, reset), reparent, delete (with the controls inside), each answered with the code it changes: every component's serializable properties compared before and after, serialized as CodeDOM does (literals, enum members, colors, components, `InstanceDescriptor`s). The Properties window's descriptors (merged, editors, standard values, `ShouldSerializeValue`) and events (delegate types, parameters, the default event).

**The IDE's side** (workbench and shell):
- **`WinFormsDesignerService`** (`src/Codalus.Workbench/WinForms`): which files open in the designer (a Windows Forms project's `.cs` with a `.Designer.cs` that has `InitializeComponent`), the target (the project, the app that hosts it, the designer host), Windows only (D31: "The Windows Forms designer runs on Windows only…" before anything else), the build, the host process (`WinFormsDesignerProcess`, behind `IWinFormsDesignerHost`).
- **The designer document** (`WinFormsDesignerDocument`, `WinFormsDesignerView`, `ShellHost.WinFormsDesigner.cs`): "OrderForm.cs [Design]"; reads the model, starts the host, loads and draws the form; the frame with the shell's own adorners (selection rectangles, grab handles, the rubber band, the drawn rectangle); select (Ctrl or Shift to add, rubber band, `Esc` to the parent, `Ctrl+A`), move (into another container), resize, nudge (`Shift` to resize), delete, cut, copy, paste, duplicate, a double-click's default event handler, the non-visual components under the surface. Each change: the host, then the C# host's edit applied to the designer file's text model (held while the designer is open, shared with its editor) as one undoable edit; undo and redo are that model's, and any change of the code not made by the designer loads the form again. Code it can't read: the designer closes and the code opens at the line with the reason. Save writes the designer file.
- **Opening**: forms open in the designer on Windows (`windowsForms.openInDesigner`), View Code (`F7`), View Designer (`Shift+F7`, the editor's and Solution Explorer's context menus, the View menu), the form icon in Solution Explorer (classic icon `form`). Off Windows a form opens as code, the status bar says once why, and View Designer says the designer is Windows only.
- **The Toolbox** (`ToolboxViewModel`, `ToolboxView`, `Ctrl+Alt+X`, on the View menu): Visual Studio's categories, the project's own components first, a search box, a click to arm (a click or a drag on the surface creates), drag and drop, the Pointer; names as Visual Studio's (`button1`).
- **The Properties window** (M26a's) over the designer's selection (`IDesignerPropertySource`, `ShellHost.PropertySource`): categorized or alphabetical, properties or events, values the code sets in bold, choices, flags toggles (`Anchor`), a color swatch, `(Name)` renames; the Events view hooks a typed handler or creates and shows one.

**Docs:** the user guide's [Windows Forms designer](../user-guide/windows-desktop.md#the-windows-forms-designer) section, the website's Features page, the changelog, ADR 0073, [the designer host's protocol](../winforms-designer-protocol.md), the C# host's requests in [protocol.md](../protocol.md), `CODALUS_WINFORMS_DESIGNER`, the fixture's README.

**Fixture** (`samples/WindowsDesktop/WinFormsApp`): `OrderForm` as Visual Studio for .NET writes it (common controls, `GroupBox`, `Panel`, `TableLayoutPanel` with styles and cells, `SplitContainer` panels, a `ToolTip` in `components`, `NumericUpDown` with `BeginInit`, events, an image through `resources.GetObject`, the app's user control, `AcceptButton`, a root event), `AboutForm` as Visual Studio for .NET Framework writes it (localizable, `resources.ApplyResources`, `this.`, full names, CodeDOM's casts and line breaks), `UnreadableForm` (a lambda in InitializeComponent, the SDK's `WFO3010` turned off around it), `WinFormsApp.slnx`. The fixture builds on Linux (its `.resx` images through the Windows Desktop SDK).

## Gaps

- **Localizable forms** load from their resources, but their localizable properties aren't changed (the designer says so): M41b writes them to the `.resx`, per culture. Images in resources show and aren't changed (M41b: images into resources).
- **M41b**: snap lines, tab order mode, docking and anchoring visuals, the component tray's arrangement (M41a lists the non-visual components under the surface), smart tags (designer actions), menu and tool strip editing on the surface, data binding, the component designer, and the optional WPF design surface.
- **Extender properties** (`ToolTip on toolTip1`) aren't in the Properties window (their calls are kept and run). `TODO(issue)`
- **Collections** (`Items`, `ColumnStyles`, a `TabControl`'s pages) are edited as code; their collection editors are M41b. `TODO(issue)`
- **Z-order** (Bring to Front, Send to Back) and alignment commands aren't there yet. `TODO(issue)`
- **Paste** copies a component's properties and the controls inside, not its event hookups. `TODO(issue)`
- **An undo reloads the form** from the code (a few hundred milliseconds for a common form).
- **Linux and macOS:** the designer through a Windows machine (the remote target, decided later under D31); Windows Forms on .NET Framework (M43).
- **The website's screenshot** of the designer: `winforms-designer.png` comes from the smoke step on Windows (CI), not taken here.
