# M9a checkpoint: NuGet package management

Date: 2026-10-09. Decisions: [ADR 0012](../adr/0012-package-management.md). First half of M9 ([roadmap](../roadmap.md#m9--packages-and-project-management)); project properties and solution management are M9b.

## Built
- **Build host: NuGet from the user's SDK.** The host references `NuGet.Protocol` and `NuGet.Credentials` 6.11.2 for compilation only and runs on the NuGet assemblies in the SDK it loaded MSBuild from (7.9 on SDK 10.0.4xx), the same NuGet `dotnet restore` uses. Nothing NuGet ships with Daedalus. A NuGet API missing in an older SDK becomes a readable error, not a crash.
- **`packages/*` protocol** ([project-protocol.md](../project-protocol.md#packages-and-net-tools)):
  - **search** across enabled sources (or one), merged by id, paged per source; a failing source is reported and the others still answer
  - **details**: versions, licence, dependencies per framework, deprecation with the alternative, vulnerabilities, README (global packages folder, the feed's `ReadmeUriTemplate`, or the `.nupkg` of a local source)
  - **installed**: top-level packages per target framework (`direct`, `global`, `implicit`, `VersionOverride`, central version, defining file) and transitive packages from `project.assets.json`
  - **why**: every dependency chain to a package
  - **status**: latest versions and badges for Installed, Updates and Consolidate
  - **install/uninstall** through MSBuild's construction model with the calls `dotnet add/remove package` make; golden tests compare our files with the CLI's. CPM: version-less references plus `PackageVersion` in `Directory.Packages.props`, `VersionOverride`, the central version kept on uninstall, as the CLI does. A restore of the edited projects follows.
  - **sources/setSources**: the effective sources, mappings and config files; saving writes each change into the file that defines it and new items into the solution folder's `nuget.config`, never the user-wide or machine-wide files
  - `build/run` gained the **`pack`** target; **`tools/*`** for local and global .NET tools
  - offline mode (local sources and the global packages folder only); NuGet's credential-provider plugins, non-interactive
- **Shell**:
  - **NuGet Package Manager** document for a project or the solution: Browse, Installed (top-level and transitive, with "why"), Updates (multi-select Update), Consolidate; source picker, prerelease toggle, search on typing or Enter, Load more; the details pane with the version picker (installed, latest, deprecated and vulnerable marked), Install/Update/Uninstall, project choices at solution level, licence, links, dependencies, deprecation and vulnerability notices, and the README rendered as Markdown; restore progress and errors at the top
  - **licence acceptance** before installing packages that require it
  - **CPM**: changing a central version lists the affected projects and offers Override in This Project
  - **Package Sources** document: add, remove, rename, enable, reorder; package source mapping patterns; config files and the global packages folder
  - **.NET Tools** document: local tools from the manifest and global tools; install (`id@version`), update, uninstall, restore, create the manifest, open it
  - **Pack** (project context menu, Build → Pack Project) with a notification that opens the package's folder
  - commands `packages.manage`, `packages.manageSolution`, `packages.sources`, `packages.tools`, `project.pack`; Project menu and Solution Explorer context menus; setting `nuget.offline`
- **Fixture** `samples/Packages`: a plain project, a multi-targeted one, a CPM folder with two projects, `nuget.config` with a local feed and package source mapping, and `feed/` (generated by `FixtureGen packages`): a package with three versions (one prerelease), a README and a dependency, its dependency, and a package that requires licence acceptance.
- **Tests**: 12 build-host integration tests (search, prerelease, source filter, offline; details and README; deprecation, vulnerabilities and README from an in-process HTTP feed; an unreachable source; installed, transitive and why; edits compared with the CLI; CPM; sources and mappings including a solution without `nuget.config`, with the user-wide `NuGet.Config` checked unchanged; tools; pack; trust); 3 headless UI tests (project manager end to end with licence acceptance; solution manager with project choices and the central-version prompt; Package Sources). Two smoke-test steps for the shipped app: `packages.manage` (browse the local feed, update, restore, transitive package) and `packages.pack`.
- **Benchmarks**: scenario `packages` (`--bench packages`) with `package_search_frame_ms` (host response → rendered page) and `package_install_overhead_ms` (Update → new compiler inputs, minus restore). Proposed budgets: max ≤ 200 ms and p50 ≤ 2 s.
- **Docs**: [user guide: NuGet packages and .NET tools](../user-guide/packages.md), [project-protocol.md](../project-protocol.md), ADR 0012, `THIRD-PARTY-NOTICES.md`.

## Not done, and deviations
- **Package icons** are not shown (an initial letter instead): loading icons means network access from the shell, and the roadmap keeps all of it in the build host. `TODO(issue)`: fetch icons through the host and cache them.
- **Licence acceptance for dependencies** that require it (Visual Studio lists them too): only the package being installed is checked. `TODO(issue)`.
- **Interactive credential prompts** (device-code sign-in) inside the IDE: providers run non-interactively; `dotnet restore --interactive` in a terminal signs in. `TODO(issue)`, with M13's sign-in surface.
- **Search of plain-HTTP feeds**: the SDK's NuGet (7.x) skips their search endpoint even with `allowInsecureConnections` (`dotnet package search` behaves the same); metadata and restore work.
- **Preview of changes** before install/uninstall (Visual Studio's preview dialog) is not shown; uninstall asks for confirmation.
- **Rider comparison** for the proposed budgets was not taken. `TODO(issue)`.
- `Directory.Packages.props` edits keep the file's final line break, which `dotnet add package` drops; everything else matches the CLI.

- **Windows 11** (development machine, 2026-10-10): `dotnet test --solution DaedalusStudio.slnx`: 387 passed, 1 skipped (symbolic links need extra privileges). Native AOT publish without warnings, and `eng/smoke-test.sh` on it passed every step (`packages.manage`, `packages.pack`).
- **Linux** (WSL 2, Ubuntu 24.04, `eng/wsl-test.sh --smoke`, 2026-10-10): 388 of 388 tests passed. Native AOT publish and smoke test (WSLg) passed every step.
  - Failures found and fixed on the way: a race between the installed-package reload and the project's re-evaluation after an update (now reloaded on re-evaluation); `MSB0001` when saving project files; orphaned `dotnet restore` processes; the NuGet UI test hung once in an earlier run and hasn't since.
