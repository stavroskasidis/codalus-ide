# M27b checkpoint: the database explorer, queries, the SQL language service and SQL projects (M27 complete)

Date: 2026-10-11. Decisions: [ADR 0037](../adr/0037-data-host-and-providers.md) (the data host and its providers) and [ADR 0038](../adr/0038-sql-language-service-and-database-projects.md) (the SQL language service and SQL database projects). With M27a ([checkpoint](m27a.md), ADR 0036) this completes M27.

## Built

**The data host** (`src/DaedalusStudio.Data.Host`, `daedalus-datahost`, protocol in `docs/data-protocol.md`)
- A new supervised host, started on the first database action (never at startup), shipped in `datahost/` next to the shell (`HelperProcess`, so `eng/package.sh`'s packages carry it); `DAEDALUS_DATAHOST` overrides it.
- **Providers:** SQL Server (Microsoft.Data.SqlClient 7.1.1 with managed networking on every OS: its native SNI is proprietary, excluded with `ExcludeAssets="all"` and never shipped), PostgreSQL (Npgsql 10.0.3), MySQL and MariaDB (MySqlConnector 2.6.2), SQLite (Microsoft.Data.Sqlite 10.0.12).
- **Requests:** connect, disconnect, test, databases, schema (tables, views, procedures, functions, columns with types, nullability and identity, primary, foreign and unique keys with what they reference, indexes; from each engine's catalogs), read a page, count, commit (one transaction, rows found by their key as read, a conflict rolls everything back), execute (batches split on `GO` for SQL Server, sessions per query editor, messages from `PRINT`/notices/errors, rows affected, a row limit), estimated and actual plans as one tree shape (SQL Server showplan XML, PostgreSQL and MySQL `EXPLAIN`, MariaDB `ANALYZE`, SQLite `EXPLAIN QUERY PLAN`), export and import (CSV, JSON).
- Every request runs on the thread pool and is cancellable in the database (SQLite through `sqlite3_interrupt`); a crash restarts the host and the connections are registered again.

**The workbench** (`Data/DataService.cs`): the host's supervision, the connection list (`data-connections.json` in the state folder without passwords; a password goes to the OS credential store when the user saves it, otherwise it is asked once per session), the solution's connections (appsettings, user secrets, Aspire AppHost resources with fixed ports), the schema cache, the query history (200, `query-history.json`).

**The shell** (`ShellHost.Data.cs`, `DataViewModels.cs`, `DataGridView`, the views)
- **Database Explorer** (tool window): your connections and "From the solution"; databases, Tables/Views/Procedures/Functions, columns, keys, indexes; double-click a table for its data, a routine for a query calling it; a context menu from the menu registry (`dataExplorer/context`, `dataNodeKind`): View Data, New Query, Reverse Engineer with EF Core (fills M27a's form with the connection and the tables), Refresh, Disconnect, Edit and Remove Connection.
- **Add Connection** (a document): engine, server, port, database or file, Windows authentication (SQL Server), user, password, save the password, options, or a raw connection string; Test Connection.
- **Table data** (a document): pages (`data.pageSize`), the row count, a `WHERE` filter, cells edited in place (Ctrl+0 for NULL), Add Row, Delete Row, Commit, Revert (the tab shows unsaved changes and asks before closing), Export and Import; views and keyless tables are read-only.
- **Query editor:** New Query opens a `.sql` editor on the connection; a status bar item shows (and changes) the editor's connection; Execute (`Ctrl+Shift+E`), Execute Current Statement (`Ctrl+Shift+Enter`), Cancel (`Alt+Break`), Estimated Plan (`Ctrl+Shift+L`), Actual Plan (`Ctrl+Shift+M`).
- **Query Results** (tool window): a grid per result set (`data.maxRows`, marked when cut), Messages, the plan tree (each operator's cost share, estimated and actual rows) with Open Plan, the History (double-click reopens a query), the time and row count.
- **SQL language service:** `daedalus-datahost --lsp` registered for `sql` through the M11 bridge; the shell sends each SQL document's dialect and schema (`daedalus/sql/context`). Completion of keywords per dialect, objects, schemas and columns (aliases resolved); hover; T-SQL parse errors and formatting through ScriptDom (180.117.0, MIT).
- **SQL database projects:** SDK-style `.sqlproj` (Microsoft.Build.Sql) evaluate with their scripts (`Build`, `PreDeploy`, `PostDeploy` items visible), get no design-time build, are watched, and build into a `.dacpac`.

**Fixtures**: `samples/Data/InventoryDb` (an SDK-style SQL project) and `samples/Data/Database.slnx`; M27a's `Inventory/inventory.db` for the explorer.

Skipped with the reason where no container runtime runs them (failed in CI); each container is removed afterwards.
- `SqlProjectTests` (build host, 1): the `.sqlproj` loads its scripts, gets no design-time build, and builds a `.dacpac`.
- `DataShellTests` (headless UI, 2): the connection form, the tree, table data edited and committed, the query editor's completion, results, plan, errors and history; the solution's connection strings.
- **Smoke step `data.explorer`** (M27): the same in the published app, with `smoke-test-data-table.png`, `smoke-test-data-query.png` and `smoke-test-data-plan.png`.

## Budgets (proposed)

- **Opening a table with 1M rows, first page:** ≤ 500 ms round trip from the shell's service to the host and back. Measured on SQLite (Windows 11): see Validation. `DataHostTests.The_first_page_of_a_million_rows_is_fast` enforces it. (Microsoft.Data.Sqlite's key information reads the whole table, about 1 s per million rows, so SQLite's keys come from `pragma_table_info`.)
- **Completion from a cached schema:** ≤ 100 ms, the median of 20 completions through the LSP bridge. `SqlLanguageServerTests` enforces it.

## Not done, and deviations

- **D15, DacFx:** the `Microsoft.SqlServer.DacFx` package is under Microsoft's proprietary license terms (checked 2026-10-11 on 170.5.96), so **schema compare and publish are a gap**. `TODO(issue)`: **needs the maintainer** — whether running the user's own SqlPackage (installed by the user, like dotnet-ef) is acceptable.
- **SQL Tools Service** wasn't integrated (ADR 0038): a ~100 MB download per platform and its own connection protocol for what ScriptDom and the data host's schema give. `TODO(issue)`: an opt-in integration for its refactorings and object navigation.
- **Other dialects** (PostgreSQL, MySQL, SQLite) get highlighting and schema completion, but no diagnostics or formatting (no open parser good enough). `TODO(issue)`.
- **The grid pages** rather than scrolling through the whole table virtually; Previous/Next and the page size move through it. `TODO(issue)`: continuous scrolling with on-demand pages.
- **Aspire:** only resources with a fixed host port are listed; dynamic ports exist only while the AppHost runs. `TODO(issue)`, with M17.
- **Database connection providers as plugins** (the plugin API track's M27 entry): not built; the four engines are built in. `TODO(issue)`, with the plugin platform (M22). The plugin API is unchanged.
- **Windows:** SQL Server's shared memory and some named-pipe setups need the proprietary native SNI; TCP is used.
- `TODO(issue)`: editing a routine's definition (open `CREATE PROCEDURE` scripts from the explorer), and a graphical plan diagram (the plan is a tree).
