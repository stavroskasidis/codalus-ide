# Changelog

Hand-written notes for each release. The release pages add the list of changes, grouped by milestone, from the commits.

## 0.4.0

- **External agents in AI Chat** (M48, [user guide](docs/user-guide/ai.md#external-agents-acp)): AI Chat can run coding agents that are programs of their own, such as pi, Claude, Codex, Gemini CLI, GitHub Copilot, OpenCode or Goose, over the Agent Client Protocol, next to the built-in assistant. Set one up in one step with **Add agent…** in AI Chat's agent picker (a known agent's entry, pinned to the ACP registry's version, goes to your user settings after it shows the exact command), or add it to your user settings yourself (`ai.agents`; a workspace can't), then turn on AI assistance, open a trusted folder and pick it in AI Chat's toolbar. Their answers, thinking, plans and steps show in the chat (a step's files open at the line; a command's output shows live), with their modes and slash commands. What they ask of the IDE goes through its checks: files read from the editor, only inside the folder and never the excluded ones, redacted; every write through the preview into the editor; every permission and command with Reject the default; each request in the AI log. Each agent gets the IDE's tools through `codalus mcp`. An external agent uses its own provider and data policy, and AI Chat says so whenever one is chosen ([ADR 0079](docs/adr/0079-external-agents-over-the-agent-client-protocol.md)).
- **One look for every button, field and dialog, and redesigned views** (M34h): buttons, toggles, check boxes, combo boxes, text boxes, tabs and toolbars follow one design in all sixteen themes, with a visible focus ring and each family's own corners. Dialogs have a header with an icon, the title and what they're about, and their buttons in your OS's order (the main one last on macOS); `Enter` and `Escape` answer them. More than 40 tool windows and views trade their rows of text buttons for icon toolbars, every icon with a tooltip and a name for screen readers.
  - **Find Results** ([user guide](docs/user-guide/editing.md#find-and-replace-in-files)): each line in the editor's colors for its language, with the match highlighted; what was searched above the results and the counts below; **Tree** or **List**, grouped by folder and file with their counts; `F8` and `Shift+F8` step through the matches; **Clear All** and **Stop Searching** on the toolbar.
  - **HTTP Response** ([user guide](docs/user-guide/web.md)): the status as a chip in its class's color with the time and size, the request linked to its line in the `.http` file, **Body** (Pretty or Raw, with word wrap), **Headers** and **Request** tabs, and Send Again, Copy, Save… and Open in Editor.
  - **The WCF Test Client** ([user guide](docs/user-guide/wcf.md)): one address bar with **Running Services**, the operations with their signatures, and a request grid with each field's type, a red `*` where a value is expected, enums as drop-downs, a list as one row with add and remove, and Nil as a check box. `F5` invokes while the test client has the focus, and a fault shows its code and reason.
  - **AI Chat** ([user guide](docs/user-guide/ai.md)): your questions as bubbles with chips for what went with them (and what didn't, with the reason), answers with their steps (their files open at the line) and code blocks in the editor's colors with Copy, Insert at Cursor and Apply…, and one box to type in with the context chips. Send becomes Stop only while this chat's answer runs (it did for any AI request, inline suggestions included), and a long conversation stays fast.
  - **Options**: colored category icons with counts, a header on each page with how many of its settings are modified, **User | Workspace** as a switch, and modified settings marked. **Containers, Exception Settings, Benchmarks, Counters, Configuration Manager, Service References and Git Worktrees** have the new toolbars. In **Counters**, the process id and the process list are one box: type an id or a name, or pick a process. Configuration Manager's combo boxes show their choice after loading.
  - **Manage NuGet Packages** shows each package with colored initials and its versions as badges (installed, an update, prerelease), and the name and author no longer overlap. **Add New Item**'s templates are one line each, and its preview is in the editor's colors. A preview of changes takes three quarters of the window, each changed line marked. The Windows Forms designer's selection is a sharp one-pixel frame with seven-pixel handles. **Keyboard Shortcuts** highlights the command under the pointer and the selected one.
  - **Colored output**: the Output window and the Debug Console color what their lines report: errors (`error CS1002:`, *Build failed*, exceptions and their stack traces) in red, warnings in amber, a build that succeeded in green, in each theme's colors; a program's standard error is red, and its ANSI colors show as colors, readable on the theme's background, instead of escape codes. Solution Explorer's toolbar icons each take their family's color (and Refresh is green everywhere, Git Changes' Fetch, Pull, Push and Sync the Git color), every Windows Forms Toolbox control and component has an icon of its own, and the theme cards in the first-run setup and Options show the IDE itself in miniature, in that theme's real colors and shapes, instead of a drawing.
- **Classic is the default theme again, and comes first** ([user guide](docs/user-guide/settings.md#themes)): without a theme setting, Codalus IDE uses Classic following your system (Classic Light, Dark, or High Contrast when your system's high-contrast setting is on) instead of Harbor. Classic is the first card in the first-run setup, where it's now offered and preselected (its modes are Light, Dark, High contrast and Match system; Blue is in Options), and the first in Tools → Options → Environment → Appearance and Tools → Color Theme. **If you used 0.3.0 without choosing a theme, you'll see Classic**: choose Harbor once to keep it. A theme you chose stays as it is. The setup now saves the theme you leave chosen, the preselected one too.
- **Key bindings that changed** ([user guide](docs/user-guide/keyboard.md)), so that each key does one thing on each OS:
  - **Git → Toggle Blame** is `Ctrl+Shift+Alt+B` on Windows and Linux (`⌘⌥B` on macOS, as before): its `Ctrl+Alt+B` took the Breakpoints window's key in the editor of every Git repository.
  - On **macOS**, Start Without Debugging is `⌃F5`, as in VS Code (`⌘F5` turns VoiceOver on or off), and Break All is `⌘⌥P` (Mac keyboards have no Break key).
  - On **Linux**, the ReSharper scheme's Find Usages is `Shift+Alt+F12`, because GNOME takes `Alt+F7`.
  - `Ctrl+\` splits the editor only in the **VS Code** scheme. In the Default, ReSharper and Emacs schemes, `Ctrl+\`, `Ctrl+E` opens the Error List, which couldn't be typed in a text file before.
  - Fixed: the **Emacs** scheme's `Ctrl+X Ctrl+F` failed (it's Go To File now), and the **ReSharper** scheme's `Shift+Alt+L` opened the system's file manager instead of locating the file in Solution Explorer.
- **A missing .NET runtime is named, and offered** (M49, [user guide](docs/user-guide/troubleshooting.md#common-problems), [ADR 0080](docs/adr/0080-the-hosts-dotnet-runtime.md)): Codalus IDE checks the .NET runtime each helper process needs (the build host, the language services, the plugin host and the others) before starting it, in the .NET folder it would use, and prefers a folder that has it. When it's missing, or only an earlier release candidate is installed, one notification says which runtime is needed and what was found, instead of "The connection was lost", with **Install .NET 11.0** (into `~/.dotnet` on Linux and macOS, through winget on Windows) and **Check Environment**, which has a row for it. Once it's installed, the plugins, the language services and the solution that couldn't open start again without a restart. **Updates check it first**: an update whose runtime isn't installed isn't downloaded, and the IDE offers to install the runtime, or Update Anyway. (0.3.0 doesn't know this check, so the update to 0.4.0 installs without it; 0.4.0 then offers the runtime when it starts.) A helper process that exits while it starts now says why, with its exit code and the first lines it wrote (all of them in its Output channel), and isn't started again, since it would stop the same way; one that's killed (by you, or by the system when memory runs out) is still started again. `CODALUS_SKIP_RUNTIME_CHECK=1` turns the check off.
- **Every command checked from its menu, its key and the command palette**, on Windows, Linux and macOS, and what that found:
  - Clicking a C# CodeLens's reference count ran a command that didn't exist; it runs Find All References.
  - `Ctrl+S` and File → Save didn't save in the `.resx`, `.editorconfig`, Windows Forms designer and plugins' custom editors.
  - Solution Explorer's Git → View History, and Git LFS Lock and Unlock, acted on the active editor's file instead of the item you right-clicked.
  - In an opened folder (not a solution), Publish to a Git host ran `git init` in the folder's parent.
  - Save As Solution Filter said "Saved" when the save failed.
  - `Escape` in a quick pick hid the notifications instead of closing the quick pick.
  - Reattach attached to an unrelated `dotnet` process. Over SSH, in a container or in WSL it now finds the same program by its id and command line; on this machine it asks which `dotnet` process to attach to.
  - Attach to a Process in a Container always used Docker: `debug.containerTool` defaulted to `docker`. It now uses the Containers window's engine (`containers.tool`, else Docker or Podman, whichever is installed), and `debug.containerTool` overrides it when you set it. When no container engine answers (the tool is missing, or Docker is installed but its daemon isn't running), it says so and how to start or install one, as the Containers window does, instead of showing `docker ps`'s message as an error.
  - Create Dump in a session over SSH, in a container, in WSL or in a remote window dumped a local process with the same id. It now says it dumps programs on this machine only.
  - On Windows, copying and pasting while another program held the clipboard failed with an error. It tries again briefly, then says so on the status bar.
  - Options and Settings open without a pause of about a second.
  - Manage NuGet Packages lost every result of a local package folder that had one broken package. Folders are searched package by package, and the broken ones named.
  - With `podman-docker` installed, Check Environment's Docker row showed two lines, cut off.
  - Turning a plugin off copied the workspace's turned-off plugins into your user settings, and turning it on didn't take it out of the workspace's list. Each settings layer keeps its own `plugins.disabled`.
  - View → Other Windows listed the Ports window twice, and the palette said "Markdown: Markdown: Open Preview to the Side".
  - For plugins: the `onSolutionOpened` activation event fires (a plugin that waited for it never started), the `documentTab/context` menu location is accepted, and a `when` clause or enablement that doesn't parse is a warning instead of silently always true ([changelog](docs/plugins.md#changelog)).
- **The Linux repositories serve their packages from the GitHub releases** ([Download](https://stavroskasidis.com/codalus-ide/download/#apt)): the website keeps only the signed repository metadata, and the `.rpm` packages are signed themselves. **If you added the apt repository before 0.4.0, run the Download page's second apt command again**: the sources line is now `mirror+…/apt/mirrors.txt`, which needs apt 1.6 or later. **With zypper, remove the repository** (`sudo zypper removerepo codalus-stable`, or `codalus-nightly`) **and add it again.** dnf's `.repo` files keep working.
- **A trusted folder stays trusted through a symbolic link** ([user guide](docs/user-guide/getting-started.md)): trust was matched by the folder's spelling, but solutions open under their real path, so the trust prompt asked again for a folder trusted through a link (on macOS, any folder under `/var/folders`, which opens as `/private/var/folders`). Folders are now saved and matched by their real path; folders trusted before through a link still count.
- **AI Chat sends nothing while an answer is written** ([user guide](docs/user-guide/ai.md)): `Enter` or **Send** during an agent's turn, while one of its tools ran, started a second question, and **Stop** could no longer end the first. Now the next question waits in the box until the turn ends, and clicking **Send** leaves the focus in the box instead of on the hidden button.
- **Attach to Process lists processes faster on Windows**: it reads each process's modules in one pass and every window title at once, and never waits on a window that doesn't answer.
- **.NET Framework projects' messages name what's missing**: the reason an old-style project can't build, and Convert to SDK-Style's notes, say it imports proprietary MSBuild targets that aren't part of the .NET SDK, and an unsupported project's error offers converting it to an SDK-style project.
- **Releases**: the website's screenshots show 0.4.0, and the tests and the release's tools got fixes of their own.
- **Fixed:** in Find and Replace, hovering the Find what box drew a border around its arrow only, or around its text only, and the text and placeholders of Find what, Look in and File types sat at the top of their boxes. Every editable combo box now draws one border around its text and arrow, under the pointer and with the focus, and every combo box centers its text.
- **Fixed:** the lines sticky scroll pins at the top of the editor drew over the branch picker and other quick picks, the command palette, Find and Replace, dialogs and the editor's find widget. They now stay under them.
- **Fixed:** after you saved a document, Codalus IDE could warn that it had "changed on disk, and you have unsaved changes": on a busy machine, the file watcher could check the file before the save had recorded it. A document's own save is no longer reported; a change made elsewhere still is.
- **Fixed:** after you closed a solution or folder and opened another, a design-time build of the closed one that finished late could bring its projects back into the new solution's C# language service. Results from a closed solution are now dropped.

## 0.3.0

- **Code Search** (M47, [user guide](docs/user-guide/editing.md#code-search)): Go To All (`Ctrl+T`, `Ctrl+,`) is now Visual Studio's Code Search window, floating over the editor under the title row. It finds files, types, members and text (and with **External items**, the types of your packages and the framework), with chips and prefixes to filter (`f:`, `t:`, `m:`, `x:`, and `:42` for a line), two-line results that say where each one is ("in Circle (project Lib)"), and a preview of the selected result below them: the document itself, which you can edit and save (`Ctrl+S`) without leaving the window. `Enter` opens the result, `Ctrl+Enter` keeps the window open. Choose the scope (the solution, the current project or document), pin it, hide the preview, or dock it as a tool window; it remembers its size and place. While projects load it says the results are incomplete and refreshes them when they're done, and the index is kept with the solution, so after a restart types and members are found at once. **Feature Search**, its other tab, is the search box (`Ctrl+Q`): commands with their shortcuts, settings and Options pages. Go To File, Type, Member and Text are `Ctrl+1` then `F`, `T`, `M` or `X`.
- **A first-run setup** (M46, [user guide](docs/user-guide/getting-started.md#the-first-run-setup)): the first time Codalus IDE starts for a user data folder, **Set up Codalus IDE** opens before the start window. **Appearance**: the four theme families as cards with a picture of each and a mode (Light, Dark, High contrast or Match system); the setup and the IDE behind it change as you choose. **Keyboard**: the Default, VS Code, ReSharper or Emacs keys. **Your settings**: import from VS Code, a `.vssettings` file or an export, or turn on settings sync with a folder or a Git repository. **Tools**: the .NET SDK and git checked, with exactly what an install runs and nothing installed without your yes. Skip setup keeps the defaults (Harbor following the system); Help → Set Up Codalus IDE runs it again. It doesn't show when the command line opens something, with `--skip-setup` (or `CODALUS_SKIP_SETUP=1`), when settings sync is on, or for a user data folder from an earlier version, so upgrading doesn't ask. The Start page's Get Started steps moved into it: Help → Get Started opens the setup.
- **Four theme families** (M45, [user guide](docs/user-guide/settings.md#themes)): **Harbor**, **Graphite**, **Daylight** and **Ember**, each in Light, Dark and High contrast, with their own colors and some of their own shapes: Harbor's navy title bar and gutters between tool windows, Graphite's hairlines and teal dot on the focused tool window, Daylight's rounded tabs and violet Start button, Ember's rounded cards and a status bar with a dot for the state. The editor's syntax colors, current line and breakpoint lines and the terminal follow the family. Choose one in Tools → Options → Environment → Appearance, from cards with a picture of each, with a mode (Follow System, Light, Dark, High Contrast), or from Tools → Color Theme, which shows each one as you move through the list. Following the system includes its high-contrast setting. New installs use Harbor following the system; **a theme you chose before keeps its look**: Blue, Light, Dark and High Contrast stay, as the Classic family. In `settings.json`, `workbench.colorTheme` is now `"harbor"` or `"harbor.dark"` (`"dark"` still means Classic Dark). Plugins see the family as the `themeFamily` context key.
- **Codalus runs on .NET 11** (M30b, on .NET 11's second release candidate until its release in November): install the [.NET 11 SDK](https://dotnet.microsoft.com/download/dotnet/11.0), which its helper processes now need; SDKs of older versions still build your solutions next to it. The C# editor has .NET 11's compiler, so C# 15 (unions, collection expression arguments, labeled `break` and `continue`) shows no false errors, and Razor files use the .NET 11 SDK's Razor generator. Plugins built for .NET 10 keep working.
- **WPF and Windows Forms** (M40a, [user guide](docs/user-guide/windows-desktop.md)): their projects open, edit and build on Windows, Linux and macOS, and run, debug, test and use Hot Reload on Windows; on Linux and macOS, Start says they run only on Windows. WPF XAML gets completion, live errors and warnings (binding paths from `d:DataContext`, resources through `App.xaml` and merged dictionaries), the markup compiler's errors in their files, Go to Definition, `x:Name` rename and formatting. New Project names the WPF and Windows Forms templates, and Add New Item makes windows, pages, user controls, resource dictionaries and forms with their code-behind, nested under them.
- **A WPF XAML Previewer and the Live Visual Tree for WPF apps** (M40b, on Windows, [user guide](docs/user-guide/windows-desktop.md#the-wpf-xaml-previewer)): the XAML Previewer (`Shift+F7`) draws a WPF window, page or user control on your app's own WPF as you type, with App.xaml's resources, design-time data from `d:DesignInstance`, the design size, zoom and render scale; a click selects the element's tag, and the caret's element is outlined. Running or debugging a WPF app fills the Live Visual Tree and Live Property Explorer: its logical and visual trees, dependency properties with where each value comes from, values set in the running app, highlight, Select Element in the App and Go to XAML. On Linux and macOS both say they're Windows only.
- **The Windows Forms designer** (M41a, on Windows, [user guide](docs/user-guide/windows-desktop.md#the-windows-forms-designer)): a form's or user control's code file opens in the designer, drawn on your app's own Windows Forms. Select (Ctrl or Shift to add, a rubber band), move (into another container), resize with grab handles, nudge with the arrow keys, delete, copy, paste and duplicate controls; add them from the new **Toolbox** (`Ctrl+Alt+X`), with Windows Forms' common controls by category and your project's own; set their properties in the **Properties** window, by category or alphabetically, and their events in its Events view, which writes the handlers. Every change is written into `InitializeComponent` as Visual Studio's designer writes it, as the smallest edit of the `.Designer.cs` file, so undo (`Ctrl+Z`), local history and source control see only what changed. View Code (`F7`) and View Designer (`Shift+F7`) switch. Code the designer can't read opens as code with the reason. On Linux and macOS forms open as code, and View Designer says the designer is Windows only.
- **The Windows Forms designer, complete** (M41b, on Windows, [user guide](docs/user-guide/windows-desktop.md#the-format-menu-and-tab-order)): snap lines while moving and resizing (edges, text baselines, margins and the form's padding; `Alt` to move freely); a **Format** menu that aligns, makes the same size, spaces and centers the selected controls, and brings them to the front or sends them to the back; View → **Tab Order** to click the tab order; Dock and Anchor pickers in the Properties window and their adorners on the surface. **Smart tags** list a control's tasks (Edit Items…, Add Tab, Dock in Parent Container…) and run them. Menus and tool strips are edited on the form with **Type Here** (separators, item types, reordering). The **component tray** selects, renames, deletes and arranges the form's components. **Collection editors** for list items, list view columns and items, tab pages, tool strip items, grid columns and table layout styles. **Localizable forms** are designed per language (**Language** in the Properties window), into each culture's `.resx`, with renames reaching every culture's keys; images import into the form's `.resx` or the project's resources. Extender properties (**ToolTip on toolTip1**) and **(DataBindings)** to a `BindingSource`'s members are in the Properties window. Paste keeps a control's items, tool tips and bindings, and its event handlers within the same form. As before, every change is the smallest edit of the code and of the `.resx` files, and undo takes them back together.
- **MAUI on Windows and WinUI 3** (M44, on Windows, [user guide](docs/user-guide/windows-desktop.md#winui-3)): MAUI apps run on **Windows Machine** from the device picker, and WinUI 3 apps build, run, debug (netcoredbg) and use Hot Reload. Packaged (MSIX) apps are registered from their build and started by Windows, then followed or attached to; when Developer Mode is off, the IDE explains it and opens its Settings page. WinUI XAML edits on every OS: `x:Bind` paths checked against the page's class as errors, `x:Load` and `x:DefaultBindMode`, `ThemeResource` and resources through `App.xaml`'s merged dictionaries, and WinUI's compiler errors in their files; Add New Item has WinUI's window, page, user control and resource dictionary. Check Environment lists Developer Mode and the Windows App SDK runtime. On Linux and macOS, WinUI projects say they build and run only on Windows.
- **.NET Framework** (M43a, [user guide](docs/user-guide/net-framework.md)): `net48`, `net472` and the other .NET Framework projects open, restore and build on Windows, Linux and macOS, SDK-style or not, with no targeting pack to install (the reference assemblies come from NuGet) and C# 7.3 in the editor. Old-style projects get their `packages.config` packages restored and a Dependencies node of their references and packages; projects that need Visual Studio's own targets (ASP.NET web applications) open with IntelliSense and say why they can't build. **Convert to SDK-Style** on an old-style project's context menu rewrites it as an SDK-style project, `packages.config` as package references, after showing the changes. On Windows, Start Without Debugging runs the app on the .NET Framework; on Linux and macOS, starting it says Windows only. New Project has a .NET Framework Console App and Class Library, and Check Environment shows the installed .NET Framework.
- **Debugging and testing .NET Framework apps** (M43b, on Windows, [user guide](docs/user-guide/net-framework.md#debugging-on-windows)): F5 debugs a .NET Framework app with Codalus IDE's own .NET Framework debugger, on the debugging API that comes with the .NET Framework (nothing to install): breakpoints with conditions and function breakpoints, stepping with Just My Code, the call stack, threads, locals (async methods' too) and Watch with C# expressions and method calls, exceptions with the Exception Settings, and changing numbers in Locals. Attach to Process lists and attaches to .NET Framework processes, and several startup projects debug them together with .NET ones. The Test Explorer discovers, runs and debugs xUnit, NUnit and MSTest tests on .NET Framework, old-style test projects included. Old-style projects now build portable PDBs, which the debugger reads. 32-bit apps aren't debugged yet (set `Prefer32Bit` to false).
- **Git Changes looks like a classic IDE's**: a branch picker with Fetch, Pull, Push and Sync, the outgoing and incoming counts, and Publish branch at the top; a commit button that commits the staged changes or all of them, and can also push or sync; collapsible Related Items, Merge Conflicts, Staged Changes, Changes and Stashes sections; files as a tree or a sortable list with a filter; stashes applied, popped or dropped in the window.
- **A solution's state lives next to it**, like Visual Studio's `.vs`: `.codalus/state/<solution file name>/` keeps the open documents, breakpoints, Watch, startup projects, bookmarks and unloaded projects, and now also the configuration and platform, the Solution Explorer's expansion, the Error List's filters and the Test Explorer's grouping. The folder ignores itself in Git. Sessions, bookmarks and unloaded projects from earlier versions move there the first time you open the solution. A folder that can't be written keeps the state in your user data instead.
- **A polish pass over the newer windows** (M34g): the WPF and Windows Forms tools, the WCF Test Client, the theme pickers, the first-run setup, Code Search and the .NET Framework tooling, checked in every theme at their smallest sizes. Among the fixes: a project that can't build shows its whole reason in a tooltip, Convert to SDK-Style's notes wrap above its changes, the Call Stack shows the .NET Framework debugger's internal frames as labels and dims code outside Just My Code, the Modules window scrolls sideways in a narrow pane, and the details and search matches on a selected row stay readable in every theme.
  - Error and warning messages are readable in every theme: in Classic Light, Dark and Blue and in Harbor and Graphite Light, error text was paler than the WCAG minimum. Error values in Watch, Locals, QuickWatch and data tips are in the error color, as was always meant.
  - In the High contrast families, the selected row of a tree (Options' categories, the Live Visual Tree) is readable, and so are checked toggle buttons. A selected row's second line (a Code Search result's location) takes the selection's color in every theme.
  - The WCF Test Client's form keeps room for its values in a narrow document, its rows line up, and a fault's reason is no longer cut off; before you choose an operation, it says what to do.
  - The Windows Forms designer says why it couldn't open a form where the form would be, and its selection handles follow the theme. The Toolbox says when a search matches nothing. The Properties window's buttons for a designer's selection fit a narrow window. The Live Property Explorer's values have room at the window's narrowest.
  - Code Search says what to try when nothing matches.
  - The messages of the Live Visual Tree, the XAML Previewer, the WCF Test Client and the color theme cards are translatable.
- **Releases**: one pipeline builds, tests and releases every branch. Every push to `develop` that passes it is published as a nightly, and the website deploys only once a stable release has passed every check.
- **Documentation**: the user guide, the website's Features page and the README cover everything up to 0.2.1.
- **Fixed:** after dragging the bottom tool windows into a group of their own, tool windows such as the Plugin Gallery, Coverage Results and Code Metrics Results opened in a new group stacked above them. A tool window now opens as a tab where it was last closed, or in the group of its usual place.
- **Fixed:** a tool window dragged among the documents showed its whole content in its tab. It now has a document tab with its title and icon.
- **Fixed:** Apply Code Changes (`Alt+F10`) pressed while Hot Reload was still starting saved the files before `dotnet watch` watched them, so the running app never got the change, even when it already answered. It now saves once `dotnet watch` watches.
- **Fixed:** the toolbar's Hot Reload button and its arrow were a gray block; they're flat like the buttons beside them.
- **Fixed:** the lines sticky scroll pins at the top of the editor were plain text in one color. They're drawn as in the editor, with its colors, indentation and line numbers.
- **Fixed:** opening the first tool window on the left (such as the Start page) could leave the documents area under a third of the window, with the right pane taking over half.
- **Fixed:** Razor files were colored by their grammar alone: components in the color of an invalid tag, like HTML elements, and namespaces in `@using` like types. They're now colored as in Visual Studio's themes, in every theme: components teal and their parameters light blue, HTML elements blue, delimiters gray, `@` and directives in Razor's directive color, Razor comments green, and the C# in the markup as in a `.cs` file. Each kind has its own entry in Fonts and Colors.
- **Fixed:** on a Mac whose home folder is on another disk than the app, **Restart to update** started the old version again and offered the same update. The update is now prepared on the app's own disk. A 0.2.1 install on such a Mac can't update past the bug itself: install this release's `.pkg` once.
- **Fixed:** a large C# file took longer to show its colors than in 0.2.1 (a 100k-line file about a third longer). The editor asked the language service for them again each time CodeLens, inlay hints or document symbols arrived, and started over; it now waits for its first answer, and asks for those after it.
- **Fixed:** opening a large file took far more memory than the file: a 100k-line C# file left about 120 MB of copies in the IDE's main process after it opened, and every keystroke in it built another copy of the whole text. Sending it to the language service, reading its outline back and a hidden placeholder in the editor each made copies; they don't any more.

## 0.2.1

A maintenance release: two fixes in the app, and 0.2.0 released again by the new release process.
- **Fixed:** floating a tool window or a document made it disappear until the app restarted. It now opens in a window of its own; closing that window closes it, and showing it again puts it back in the main window.
- **Security:** the data host's `System.Security.Cryptography.Pkcs` (from the SQL Server client) is 10.0.13, past two known vulnerabilities in 9.0.18 (GHSA-846f-f764-76mx, GHSA-2fmv-rv2c-59x7).
- **Releases are atomic.** A stable release now publishes nothing until every check has passed: the tests and the smoke tests on every OS, the benchmarks, the installers installed and smoke-tested, and the apt, dnf and zypper repositories built and installed from. Then it publishes the release page, the website with the Linux repositories, and the AUR package, in that order. For 0.2.0 the website and the Linux repositories didn't update.

## 0.2.0

**Daedalus Studio is now Codalus IDE** ([ADR 0056](docs/adr/0056-rename-to-codalus.md)): the CLI is `codalus`, the packages are `codalus` (and `codalus-bin` on the AUR), and the repository is `stavroskasidis/codalus-ide`. It's a clean break, made while there are no users to move:
- settings, state and plugins live in new folders (`Codalus`, `codalus`); nothing is carried over from `Daedalus Studio`;
- environment variables are `CODALUS_*`, and per-solution files are under `.codalus/`;
- 0.1.0 doesn't update to 0.2.0: uninstall it and install Codalus IDE.

New since 0.1.0:
- **Remote development** (M21): open a folder on an SSH machine, in a WSL distribution, in a running container or in a Dev Container (File → Open → Remote Window). The build, the C# language service, terminals and the debugger run there; forwarded ports, the Ports window, and reconnecting after a network drop. Tests can run in WSL, Docker or over SSH (`testenvironments.json`).
- **Plugin API 1.0** (M22a, [ADR 0058](docs/adr/0058-plugin-api-1-0.md)): the API is stable, and minor releases only add to it. New for plugins: color and file icon themes in VS Code's formats, debug adapters, declarative views and custom editors, file system, sign-in and source control providers, and tasks with progress. Plugins built for 0.x ask for `^1.0.0` ([changelog](docs/plugins.md#changelog)).
- **Running tasks in the status bar**: loading projects (*Loading project 29 of 96: …*), restoring packages and builds show their progress where "Ready" is, with a progress bar and cancel.
- **Personalization** (M23): Fonts and Colors over any theme, the ReSharper and Emacs keyboard schemes, importing VS Code settings and `.vssettings`, Export and Import Settings, saved window layouts, full screen and distraction-free mode, profiles, settings sync with a folder or a Git repository, Tools → Customize for menus and toolbars, and the interface's text ready for translation.
- **A start window** (M38) with recent solutions, projects and folders, and **Help → Check Environment** (M37), which finds and offers to install a missing .NET SDK, git and the optional tools.
- **Avalonia**: the Live Visual Tree and Live Property Explorer for running apps (M19b), and the Avalonia templates in New Project.
- **Fixed:** opening a project in an app started from the macOS Finder or a Linux desktop failed with "Path to dotnet executable is not set": the IDE now takes the login shell's PATH and finds the .NET SDK where its installers put it.
- Document tabs that fit their group, with pinned and selected tabs always in view, and more polish (M34e); and the new mark.

## 0.1.0

The first preview release of Daedalus Studio, an open-source (MIT), cross-platform IDE for .NET. It covers the editor, the project system, NuGet, build and run, debugging, testing, Git, the terminal and C# Interactive, profiling, data tools, containers and Aspire, web and Blazor, and Avalonia XAML: see the [features](https://github.com/stavroskasidis/daedalus-studio#features) and the [user guide](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/user-guide/README.md). It's a 0.x release: expect rough edges, and please report what you find in the [issues](https://github.com/stavroskasidis/daedalus-studio/issues).

**Before you install**: you need the .NET SDK 10.0 or newer and git 2.30 or newer ([installing and first start](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/user-guide/getting-started.md)).

**The installers aren't code-signed yet**, so each OS asks once:
- **Windows** ("Windows protected your PC"): choose **More info**, then **Run anyway**.
- **macOS** ("Apple could not verify…"): close the message, open System Settings → Privacy & Security, and choose **Open Anyway** next to Daedalus Studio (or the installer); then open it again.
- **Linux**: the `.deb` and `.rpm` packages and our apt and dnf repositories are signed with the [project's key](https://github.com/stavroskasidis/daedalus-studio/blob/master/eng/packaging/linux/daedalus-studio-packages.asc).

Installed builds update themselves from signed feeds (the Velopack installers and the AppImage), and `SHA256SUMS.txt` lists every file's checksum.

**Platforms**: Windows 11 x64, macOS 15 or newer on Apple silicon, and Linux x64 and arm64. Windows on Arm and Intel Macs aren't built yet.

**Not in this release yet**: remote development (SSH, WSL, containers), Hot Reload while debugging, .NET MAUI, Visual Basic and F#; see the [roadmap](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/roadmap.md).
