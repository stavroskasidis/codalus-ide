# Changelog

Hand-written notes for each release. The release pages add the list of changes, grouped by milestone, from the commits.

## 0.9.0

- **Fixed:** **Stop** while an external agent waited for your approval could tell the agent you had rejected it, instead of that the turn was cancelled.
- **Fixed:** the branch drop-down could show the branches as they were before an **Update** or a change made outside the IDE (a branch still current after a switch, a worktree without its chip) until it was opened again.
- **Fixed:** in Locals, Autos, Watch and QuickWatch, keys (Delete, F2, the arrows) did nothing after the values were evaluated again (a step, an edit) until you clicked a row: the focused row lost the keyboard focus.
- **Fixed:** completion and Quick Info could stop working for the rest of the session when they were asked while a project the file's project references was still waiting for its restore.
- **Fixed:** Test Explorer could find no tests in a project, until it was built again, after VSTest started slowly on a busy machine; a test application slow to connect was reported as a cancelled run instead of its error.
- **Fixed:** staging or committing could fail with git's "index.lock: File exists" while a diff was open: showing a diff took git's index lock.
- **Fixed:** in the Properties window, **OK** in the invalid-value message could put the old value back in the cell instead of the text you typed, to correct it.

## 0.8.0

- **External agents keep their place, and you choose their model** ([user guide](docs/user-guide/ai.md#what-you-see)): after connecting an agent and restarting, AI Chat showed the Connect buttons again, as if nothing were connected. It now opens with the agent you chose last (`ai.chat.agent`). When an agent offers choices for its session over the Agent Client Protocol (its model, its modes, its effort or thinking level, or choices of its own), each has a picker in AI Chat's toolbar; a pick goes to the agent at once and is kept for its next sessions.
- **More AI where you already work** ([user guide](docs/user-guide/ai.md#ai-actions)), each only when you choose it and only while AI is on: **Fix with AI**, **Explain with AI** and **Generate Tests with AI** at the end of the quick actions (`Ctrl+.`); a menu on the Error List's rows with **Go To**, **Copy**, **Fix with AI** and **Explain with AI**; and **Ask AI About the Value** on a value in Locals, Autos, Watch, QuickWatch and data tips while debugging.
- **Help → Report a Problem and Suggest a Feature** ([user guide](docs/user-guide/troubleshooting.md#reporting-a-problem-or-suggesting-a-feature)): a dialog shows exactly what a new GitHub issue would carry (the version, the OS, the .NET runtime and SDK and, for a problem, the IDE's recent log with secrets and your home folder taken out), then opens the issue in your browser, filled in, for you to read and submit. Codalus sends nothing itself; a log too long for the link is saved to a file to attach.
- **Open folders and solutions from your file manager** ([user guide](docs/user-guide/settings.md#system-integration)), on Windows, macOS and Linux, off until you choose it: **Tools → Options → Environment → System Integration** (or the first-run setup) adds **Open with Codalus IDE** to a folder's right-click menu (Explorer, a Finder Quick Action, GNOME Files, Dolphin, Nemo and Thunar), and makes `.sln`, `.slnx`, `.slnf` and project files open in Codalus IDE. Turning it off removes exactly what it added. A folder or solution opened this way, or with `codalus <path>`, goes to the running window when that window has nothing open.
- **Fixed:** some drop-down menus opened as an empty strip: AI Chat's agent picker (so Built-in couldn't be picked again after choosing an agent), the folded groups of the toolbar in a narrow window, and a path box's recent locations (Alt+Down).
- **Fixed:** opening a solution with a `global.json` ran every tool's version check (git, Docker, Podman) just to compare the .NET SDK, seconds of CPU at each open; now only `dotnet` runs.
- **Fixed:** with git 2.51, **Update Branch** on a branch that had diverged from its remote compared it with a stale remote-tracking branch.
- **Fixed:** on Linux without the DejaVu fonts (WSL's Ubuntu, newer Fedora), the code editor used a proportional font: its font list now ends with Noto Sans Mono, Ubuntu Mono, Liberation Mono and Noto Mono before `monospace`. Menu rows stay 24 pixels with a taller system font.
- **Fixed:** saving a file on Linux or macOS made it lose its permissions: an executable script stopped being executable, and git showed a mode change. Saves keep the file's mode.
- **Fixed:** in the Output window, bold and bright colors looked like the plain ones in light themes (Harbor Light's bold green): they now need more contrast than the plain colors, so they stand out.
- **Fixed:** a solution pinned to a .NET SDK 2.1 didn't build in the IDE (the build host used an MSBuild 16 call that SDK 2.1's MSBuild hasn't), and the message about an SDK the IDE can't use named a preview SDK without its preview part.
- **The website**: the home page shows each kind of .NET app Codalus IDE builds (console apps and libraries, Blazor, ASP.NET Core, .NET MAUI, WPF, Windows Forms, WinUI 3, Avalonia, Aspire, WCF and .NET Framework), each with its screenshot, what you get and where it runs, in place of the general screenshots, which stay on the Features page.

## 0.7.0

- **.NET 11 RC 3**: Codalus IDE is built on .NET 11's third release candidate, and its helper processes ask for that runtime (or a later one). With only RC 2 installed, the IDE says so once and offers **Install .NET 11.0**, and an update isn't downloaded until it's installed ([user guide](docs/user-guide/getting-started.md#prerequisites)).
- **Navigate Backward and Forward work after ordinary navigation** ([user guide](docs/user-guide/editing.md#navigation)): they only went back through Go to Definition and the like, so after switching documents they did nothing. The document you left for another and the caret's place before a move of more than ten lines are steps too, as in the classic IDE, and **the mouse's back and forward buttons** run them anywhere in the window.
- **Track Active Item** in Solution Explorer ([user guide](docs/user-guide/solutions.md#solution-explorer)): a toggle on its toolbar (`solutionExplorer.trackActiveItem`, off by default) selects the active document's file each time you switch documents.
  - **Fixed:** Sync with Active Document didn't scroll to a file that was already selected but scrolled out of view, and could be slow in a large solution: it rebuilt the whole tree when nothing had to be expanded.
- **Blazor component parameters in their own color** ([user guide](docs/user-guide/web.md#razor-and-blazor)): `Sources` in `<SourcesDemo Sources="@sources">` had an HTML attribute's color in every theme. Classic gives it the classic IDE's Razor Component Attribute color, bold; the other families their own color. HTML attributes are unchanged.
- **Fixed:** a tool window dragged to the window's other side could land with no width at all, an invisible column. It now keeps the width it had, or takes a quarter of the window, never less than 200 pixels ([user guide](docs/user-guide/settings.md#the-window)).
- **Fixed:** the pin and X in a tool window's header were much larger than a document tab's. They're the tab's size now, with the tab's thin X and pin, in every theme.
- **Fixed:** the Output window's bold text was hard to read: bold shows in the bright color at the regular weight.
- **Help → Get Started is gone**: it opened the same setup as **Help → Set Up Codalus IDE**, which stays.
- **The website**: each page has its own preview image for social sites, the docs have breadcrumbs for search engines, and every page scores 95 or more in Lighthouse (checked on each change).

- **Fixed:** on Windows, **Restart to update** could start the old version again and offer the same update ([user guide](docs/user-guide/troubleshooting.md#common-problems)). The IDE ran in its install folder, so the programs it started did too, and one that keeps running after the IDE exits held the folder the update replaces: adb's server, started when the IDE lists Android devices. The IDE now moves to your home folder when it starts in its own (a terminal opened without a solution starts there too). An earlier install still starts adb in its folder: run `adb kill-server` (or restart Windows), then **Restart to update**.
- **Fixed:** a tool window that shows itself without taking the focus (Output when a build starts, Notifications, the Error List) took the active frame's accent from the document group you were working in, though the keyboard stayed in the editor.

## 0.6.0

- **The Windows Forms designer's Properties window works as the classic IDE's** ([user guide](docs/user-guide/windows-desktop.md#properties-and-events)):
  - **Categories collapse**, and stay so as you select other components; a **component list** above the grid selects the form or any of its components by name.
  - **Font, Location, Size, Padding, Margin and FlatAppearance open into their parts**, each edited alone and written as one assignment of the whole value (`button1.Font = new Font("Segoe UI", 9F, FontStyle.Bold, GraphicsUnit.Point, 0);`).
  - **Editors under the value**: colors in Custom, Web and System tabs (with Define Color), `TextAlign`'s nine positions, multi-line text, a menu item's shortcut keys, flags, Dock and Anchor, and dates. **AcceptButton**, **CancelButton**, **ContextMenuStrip**, **Cursor** (with each cursor's picture) and the font's name offer their choices; a tool tip with line breaks opens the multi-line editor.
  - **Editors behind "…"** as panels over the form: **Font** (one undo step), the **String Collection Editor** for a text box's `Lines`, **Select Resource** for images (the form's resources or the project's `Properties/Resources.resx`, with a preview) and the collection editor, whose items' properties use the same grid.
  - **An invalid value** (`abc` for a location's X) says why: **OK** goes back to what you typed, **Cancel** puts the old value back.
  - **Reset** and **Description** on a row's right-click menu, a double-click cycles a value, set values are bold in the value cell, and `F4` or `Alt+Down` opens the selected row's drop-down ([keys](docs/user-guide/keyboard.md#the-properties-window)).
  - A text box's or combo box's `AutoCompleteCustomSource` is edited as a collection.
  - Read-only values can be selected and copied (`Ctrl+C` copies a row's value), and several edits sent together (the font editor's OK) apply all or none.
- **The Properties window for Solution Explorer's selection** ([user guide](docs/user-guide/solutions.md#the-properties-window)) has the same grid: **Categorized** and **Alphabetical**, collapsible categories, a resizable description, **Reset** on the right-click menu, and **Property Pages**, which opens a project's properties or, for the solution, the Configuration Manager.
- **The Windows Forms designer's context menu is the classic IDE's** ([user guide](docs/user-guide/windows-desktop.md#the-context-menu-and-locked-controls)): right-click a control (or press `Shift+F10`) for its designer's own commands first (a tab control's **Add Tab** and **Remove Tab**, a list box's **Edit Items...**) with **Show Smart Tag**, then **View Code**, **Bring to Front**, **Send to Back**, **Align to Grid**, **Lock Controls**, **Select '_parent_'**, **Cut**, **Copy**, **Paste**, **Delete** and **Properties**. Entries that don't apply are grayed, as in the classic IDE: nothing to cut, copy, delete or align with the form selected, nothing to paste until you copy. **Align**, **Make Same Size** and **Tab Order** moved off this menu: they're in Format and View, as there. A component in the tray has its own commands first too (an image list's **Choose images** opens its Images editor), then View Code, the clipboard, Rename, Line Up Icons and Properties, and the tray's background Paste and Line Up Icons. A command's underlined letter (**Insert Standard Items** on a menu strip) works as in any menu, instead of showing as an `&`.
  - **Edit → Undo, Redo, Cut, Copy, Paste and Select All work in the designer.**
  - **Select All** (`Ctrl+A`) takes every component of the form, the controls inside containers and the tray's components included (moved, a control inside a selected container moves only with it), and **Paste** goes into the selected control's container (a group box, a panel, a split container's panel), not always the form.
  - **The Format menu is grayed when the selection doesn't suit a command**, as in the classic IDE: Align Lefts to Bottoms and Make Same Size need two controls or more, spacing two or more in one container, and a tray component in the selection grays what is for controls.
- **Lock Controls** in the Windows Forms designer ([user guide](docs/user-guide/windows-desktop.md#the-context-menu-and-locked-controls)), in the context menu and at the bottom of Format: locked controls show a lock and no grab handles, and a drag, the arrow keys or the handles can't move or resize them; Format aligns others to a locked control and leaves it in place. It's checked while any control of the form is locked, and choosing it then unlocks them all; a control's **Locked** property locks one control. Locks are kept in the form's `.resx` as the classic IDE keeps them, never in the code, and undo takes them back.
- **The data tip, laid out like the classic IDE's** ([user guide](docs/user-guide/debugging.md#data-tips)): hovering a variable or a member access while the program is stopped shows a header right over it, its name on the code's, with its icon, a **View** drop-down where a visualizer applies (the magnifier opens the likely one, the arrow lists them all) and its value in a box. Expanding it (the pointer resting on its chevron, a click, or `Right`) opens its members in a tip of their own, below and to the right, and each member expands the same way, a tip per level. Rows are compact, a long value stops at 400 px with the whole value in its tooltip, a tip shows 15 rows before it scrolls, and the type is in the name's tooltip instead of after each value. Near the editor's bottom edge the tips open upwards, and near its right edge they move left. The header passes the code's gestures on: a double-click on its name selects the word, `Ctrl+Click` goes to the definition and the wheel scrolls the editor. Holding `Ctrl` fades the tips and lets the pointer through, so the code under them can be read and `Ctrl+Click`ed.
  - **Members as the classic IDE groups them**: each row has its kind's icon (the completion list's blue wrench for a property, a field's brick, a constant, an event). The private, protected and internal members your own code declares are listed with the others, in name order, with a lock on their icon; a library type's go under **Non-Public members**, and **Static members** come last. A property whose getter threw reads "threw InvalidOperationException: …" in the error color, and still expands to the exception; a value the debugger couldn't evaluate reads "Couldn't evaluate", with **Re-evaluate** beside it. Locals, Autos, Watch and QuickWatch group members the same way. In a remote session, where the program's assemblies aren't on this machine, nothing is grouped and the icons are guessed from the names.
  - **Collections as their elements**: a `List<T>`, `Dictionary<TKey, TValue>`, `HashSet<T>`, `Queue<T>` or `Stack<T>` expands to its elements (a dictionary's entries named by their keys, each expanding to Key and Value; a queue from its head, a stack from its top), then **Raw View** with the collection's own members. The debugger can't build their debugger views, so Codalus IDE reads the elements from the collections' fields, on every .NET version from 6 to 11, .NET Framework and Mono. Dictionaries and hash sets get the **Grid Visualizer** too. In a long list, the `[DebuggerDisplay]` text of the elements past the first 60 is filled in as they scroll into view.
  - **Editing in place**: click a value in the header or a row (or press `F2` or `Enter`), type, and press `Enter` to set it, `Escape` to put it back. When the debugger refuses the value, the box stays open with its message under it, so the fix is a keystroke away. A value that can't be changed (a property without a setter, a constant, a read-only field, any value in a Mono program) opens no box, and its tooltip says why.
  - **Changed values are red**: a value that differs from the one it had when the program last stopped is drawn in red, in the data tip as in pinned tips.
  - **Pin any row**: the pin at the end of the row under the pointer pins that member (`app.Properties`) to the line, not only the hovered expression. **Pinned tips look like the header**, with a strip to unpin them on their left and their comment under them; while the program is paused they expand into the same tips, and while it runs their last values are muted. Several on one line stack.
  - **Errors and warnings** at the hovered name show in a strip right above the header, with the code's link, the message, **Fix** and **Other Fixes**, as in Quick Info; when the tips open upwards near the editor's bottom, the strip moves under the header.
  - **Locals, Autos, Watch and QuickWatch use the data tip's rows**: one flat list under a Name | Value | Type header, each level's indent inside the name cell, so values and types stay in their columns however deep you go (drag the header's edges to resize the columns). They have the data tip's icons, groups, collection views, **View** button and in-place editing (`F2`, `Enter` or a double-click on a value), changed values in red, and `Right`/`Left` expand and collapse. What you expanded stays expanded when you step, matched by expression. A watch that doesn't evaluate shows the error icon and its message in the error color. The "Set" dialog is gone.
- **NuGet's verified owners** ([user guide](docs/user-guide/packages.md#verified-owners), #78): a blue badge with a check after a package's ID, in Browse and in the details' heading, says nuget.org reserved the ID's prefix for one of the package's owners; its tooltip adds that the authors shown are not verified, and screen readers read "verified owner". It shows only for packages from `https://api.nuget.org` that can be nobody else's copy: nuget.org chosen in the source box (or your only source), or package source mapping sending the ID to nuget.org alone. A mirror or a feed with nuget.org as its upstream never shows it. Installed, Updates and Consolidate show it in the details, from one nuget.org search beside them; offline, none ([D39](docs/roadmap.md#decision-register)).
  - **Fixed:** with package source mapping, the package manager offered copies restore refuses: in *All sources*, a local feed's newer build of a package mapped to nuget.org was listed (and in the Version box), and installing it failed restore. Search and the details now leave out sources an ID isn't mapped to.
- **Diffs in the editor's colors** ([user guide](docs/user-guide/git.md#diffs), #86): a file's diff colored nothing, so Git compare was plain text. Each side is now colored by its language's grammar, in the editor's colors, and the side whose text is the open document's (usually the working tree) takes the language service's colors too, so interfaces, parameters and the like look as they do in the editor. The colors come from each file's own text, so a removed line that opens a comment never colors the added lines after it. The merge editor's three panes are in the editor's colors too. A changed line's changed words are marked on both sides (`AddSingleton` → `AddScoped`), with a deeper fill and a thin border, removed and added lines have fills of each theme's own (borders only in High Contrast), and a filler row, where the other side has lines, is hatched.
- **The diff document is laid out like the classic IDE's** ([user guide](docs/user-guide/git.md#diffs), #86): a compact toolbar with Next Change and Previous Change (`F8`, `Shift+F8` while the diff has the focus), the count ("Change 3 of 4": a change is a run of changed lines) and the lines removed and added; a gear menu with **Side by Side** and **Inline** (remembered in `git.diff.layout`), Refresh and Open the file. Each side has a header naming its file and what it is ("Startup.cs (Index)", "(Working tree)", "(HEAD)", a renamed file's old name), line numbers that count its own file's lines (filler rows no longer shift them), its own caret and current line, and its own status bar with the caret's line and character, the indentation, the line endings and the encoding, the left one with the zoom box (`Ctrl+wheel` too). The side that is the open document has the navigation bar, the other an empty row so the lines stay aligned. The splitter between the sides still resizes them (double-click: half and half), and the diff keeps its caret, scroll position and splitter when you switch tabs. A revision comparison's tab reads "Startup.cs (3f2a1c9 → 8b7e4d2)".
- **Staging in the diff, change by change** ([user guide](docs/user-guide/git.md#diffs), #86): the code's context menu has **Stage Change**, **Stage Selected Lines**, **Discard Change…** and **Discard Selected Lines…** (in a staged diff, **Unstage Change** and **Unstage Selected Lines**), also in the Command Palette, and the toolbar has **Stage All** and **Discard All…** ("Undo All" in the classic IDE; **Unstage All** in a staged diff). **Show Staging Controls** (`git.diff.showStagingControls`, off by default) adds a column between the line numbers and the signs with each change's Stage and Discard (or Unstage) buttons; hovering one outlines the lines it acts on. A change is what the diff draws, so two edits that git puts in one hunk stage separately, and what is staged is exactly what is drawn. The working-tree side shows the file's open buffer, unsaved edits included, and each action saves the file first, then checks the saved text is the text drawn (format on save can change it; then nothing is applied and you're told). Discard Change… and Discard Selected Lines… now ask first, naming the lines (they didn't before), with Cancel the default, and say when unsaved edits are saved first; Discard All… says when they'll be lost. The diff refreshes by itself after edits, saves and changes to the index, keeping its caret and scroll position.
- **Summary, large and binary files, and what "No changes" means** ([user guide](docs/user-guide/git.md#diffs), #86): **Summary** (on the diff's toolbar and in its gear menu, off by default) folds every unchanged run to three lines of context, on both sides in step; a click or `Enter` on a folded run opens it. A file over 10 MB or 100,000 lines waits for **Compare Anyway** instead of keeping Codalus busy, and a binary file shows each side's size; Stage All and Discard All… still work on both. When there are no lines to compare, the diff says why: no changes at all, the working tree matching the index while the file has staged changes (with **Open Staged Changes**), or only the line endings, the encoding, the file mode or the last newline differing ("Only the line endings differ: CRLF in the index, LF in the working tree.").
- **Fixed: a narrow window.** As the window got narrower, the menu ran under the minimize, maximize and close buttons on Windows, and the standard toolbar wrapped onto a second line. Now, as in the classic IDE, the solution's name shortens first, then the search box shrinks to its magnifier, then the menu wraps onto a second row with the search box at its end, while the window's buttons keep their place at the top right with room to drag the window beside them. The toolbar stays on one row: its groups fold from the right into **…** buttons that list their commands ([user guide](docs/user-guide/settings.md#the-window)). The same happens on macOS and Linux, where the system draws the title bar (on macOS the menu stays in the system's menu bar).

A tab's view now appears at once, as in the classic IDE, without the docking library's fade.
- **Fixed:** Quick Info, the completion list's description and parameter info showed only the declaration of a method or type from a referenced assembly, such as a NuGet package's or .NET's own (`app.UseWebAssemblyDebugging()`, `Console.WriteLine`), without its summary ([user guide](docs/user-guide/editing.md#intellisense)). - **The Git Changes window's folder menu and branch drop-down** ([user guide](docs/user-guide/git.md#the-branch-drop-down)), as the classic IDE has them. Right-click a folder for **Stage**, **Unstage**, **Discard Changes…**, **Stash Changes…**, **Add to .gitignore**, **View History**, **Reveal in File Explorer** (Finder, File Manager), **Open in Terminal**, **Copy Path**, **Copy Relative Path**, **Expand All** and **Collapse All**; a folder's commands act on the files the window shows, and with a filter on the folder says "2 of 5 files" and the section "Changes (2 of 10)". Files, conflicts and the repository node get the same menu, and a folder's hover buttons now include **Discard**. Entries that don't apply are hidden, and the drop-down says why (a merge in progress, a detached HEAD, a branch checked out in another worktree). - **Update a branch without checking it out** ([user guide](docs/user-guide/git.md#branches-and-remotes)): **Git → Branches → Update Branch…** (also in the Git Changes window's ⋯ menu) lists the local branches that have an upstream, the current one first, and brings the one you pick up to date from its remote, so you no longer check it out and pull. It fetches only that branch and moves it only by a fast-forward, so your current branch, your files and any uncommitted changes stay as they are; picking the current branch fast-forwards it, with its files, and never makes a merge commit. The status bar shows it running, with a cancel button, then how many commits came. When both the branch and its upstream have commits the other doesn't, nothing changes and a notification says how many on each side and offers **Checkout**, to merge or rebase there; a branch with only commits of its own has nothing to update (Push sends them). A branch checked out in another worktree, or being rebased there, is left alone, and the notification says where, with **Open in New Window**. Each branch's own menu in the Git Changes window's branch drop-down has it too, as **Update from 'origin/…'**.

## 0.1.0

The first preview release of Daedalus Studio, an open-source (MIT), cross-platform IDE for .NET. It covers the editor, the project system, NuGet, build and run, debugging, testing, Git, the terminal and C# Interactive, profiling, data tools, containers and Aspire, web and Blazor, and Avalonia XAML: see the [features](https://github.com/stavroskasidis/daedalus-studio#features) and the [user guide](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/user-guide/README.md). It's a 0.x release: expect rough edges, and please report what you find in the [issues](https://github.com/stavroskasidis/daedalus-studio/issues).

**Before you install**: you need the .NET SDK 10.0 or newer and git 2.30 or newer ([installing and first start](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/user-guide/getting-started.md)).

**The installers aren't code-signed yet**, so each OS asks once:
- **Windows** ("Windows protected your PC"): choose **More info**, then **Run anyway**.
- **macOS** ("Apple could not verify…"): close the message, open System Settings → Privacy & Security, and choose **Open Anyway** next to Daedalus Studio (or the installer); then open it again.
- **Linux**: the `.deb` and `.rpm` packages and our apt and dnf repositories are signed with the [project's key](https://github.com/stavroskasidis/daedalus-studio/blob/master/eng/packaging/linux/daedalus-studio-packages.asc).

Installed builds update themselves from signed feeds (the Velopack installers and the AppImage), and `SHA256SUMS.txt` lists every file's checksum.

**Platforms**: Windows 11 x64, macOS 15 or newer on Apple silicon, and Linux x64 and arm64. Windows on Arm and Intel Macs aren't built yet.

**Not in this release yet**: remote development (SSH, WSL, containers), Hot Reload while debugging, .NET MAUI, Visual Basic and F#; see the [roadmap](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/roadmap.md).
