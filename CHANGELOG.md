# Changelog

Hand-written notes for each release. The release pages add the list of changes, grouped by milestone, from the commits.

## 0.6.0

- **Fixed: a narrow window.** As the window got narrower, the menu ran under the minimize, maximize and close buttons on Windows, and the standard toolbar wrapped onto a second line. Now, as in the classic IDE, the solution's name shortens first, then the search box shrinks to its magnifier, then the menu wraps onto a second row with the search box at its end, while the window's buttons keep their place at the top right with room to drag the window beside them. The toolbar stays on one row: its groups fold from the right into **…** buttons that list their commands ([user guide](docs/user-guide/settings.md#the-window)). The same happens on macOS and Linux, where the system draws the title bar (on macOS the menu stays in the system's menu bar).
- **Fixed: dimmed editor colors.** After switching documents or tool windows, the editor and the compare view were often drawn at 85% opacity, so every color, the Classic themes' most visibly, looked muted next to the classic IDE's. A tab's view now appears at once, as in the classic IDE, without the docking library's fade.
- **Fixed:** Quick Info, the completion list's description and parameter info showed only the declaration of a method or type from a referenced assembly, such as a NuGet package's or .NET's own (`app.UseWebAssemblyDebugging()`, `Console.WriteLine`), without its summary ([user guide](docs/user-guide/editing.md#intellisense)). They now show its documentation from the XML file next to the assembly, as the classic IDE does, or from a localized one for your OS's language beside it (in a `de`, `pt-br` or `zh-hans` folder) when one is installed. XAML and Razor completion show these summaries too (Avalonia's and WPF's controls, Blazor's components), read when you select an item so the list doesn't wait for a large documentation file. Files outside a project, and the files of a folder you don't trust, get .NET's documentation too: they now compile against .NET's reference assemblies, as a project does.
- **Fixed: building while a form is open in the Windows Forms designer** ([user guide](docs/user-guide/windows-desktop.md#the-windows-forms-designer)): the designer kept your app's assembly open, so the next build failed with MSB3027 ("Could not copy … The process cannot access the file") until you closed it. It now runs on a copy of your build output, as the classic IDE does, and after a build that changes your app it loads the form again on the new build, so your own controls show their changes (a designer in another tab does it when you switch to it). While it loads again, the form takes no clicks, and changes you make in the Properties window apply once it's back. A designer you open while a build runs waits for the build instead of failing with "A build is already running.", and one that couldn't start (your project didn't build yet) starts after your next successful build.
- **Fixed: dragging from the Toolbox onto a form** ([user guide](docs/user-guide/windows-desktop.md#the-toolbox)) didn't start a drag. **Double-click** a Toolbox item, or press **Enter** on it, to add it at once, as in the classic IDE: into the selected container, at its top-left corner or a step below and to the right of the selected control, with the designer focused so the arrow keys move it (`Space` and a click still arm an item). The armed item is highlighted in the list instead of a hint above it, which pushed the items down; the hint is the designer's status line. A component (a Timer) can be dropped on the component tray, and nothing is dropped in tab order mode or beside the form. Items are created through their Toolbox item and container, as in the classic IDE, so the code a Toolbox item writes changes: a Label sizes itself to its text (`AutoSize = true`), a split container fills an empty container, the first menu strip becomes the form's main menu, and a control added to a tab control goes to its selected page.
- **Fixed:** a list box, combo box, domain up-down or list view selected in the Windows Forms designer showed a menu's **Type Here** box over it ([user guide](docs/user-guide/windows-desktop.md#menus-and-tool-strips)), which took the clicks meant for the control, and typing in it replaced the list's items with the typed text. Only menu, tool, status and context menu strips (and strips derived from them) have Type Here now; a list's items are edited in its **Items** collection editor.
- **Fixed:** opening a form in the Windows Forms designer while its project was still loading, with the form's code closed (from Solution Explorer, or as the session reopened it), closed the designer and opened the code, saying the form "isn't a form, a user control or another control" ([user guide](docs/user-guide/windows-desktop.md#the-windows-forms-designer)). It now opens in the designer. Renaming a control while the project loads also renames its uses in the form's code, new code keeps the file's short type names, and the designer reads the form again once the project has loaded.
- **Fixed:** in the Windows Forms designer, a control dropped on another, or moved over it, was drawn behind it although it was in front, and **Send to Back** seemed to bring a control to the front ([user guide](docs/user-guide/windows-desktop.md#the-format-menu-and-tab-order)): Windows Forms' `DrawToBitmap`, which draws the form, draws a container's controls in reverse order. Overlapping controls are now drawn in their real order, on the form and inside group boxes, panels, tab pages and split containers.
- **Fixed:** on Windows, starting a program in the integrated terminal under the debugger now and then failed with "The process cannot access the file … because it is being used by another process.": another program, such as an antivirus scanner, had the file the program reports its process id through open for a moment. Codalus IDE now reads it again a moment later.

## 0.5.0

- **IntelliSense like a classic IDE's** ([user guide](docs/user-guide/editing.md#intellisense)): in C# and Visual Basic, the completion list, parameter info and Quick Info show code in the editor's own colors, and generic types as you use them (`LayoutBuilderBase<PageModel, PageBuilder<PageModel>>.AddTab(…)`, not `LayoutBuilderBase<TModel, TBuilder>`). Other languages get the same popups, in plain text.
  - **The completion list** opens below the line. Each item has an icon for its kind, and the characters you typed are bold. The selected item's declaration, overload count and summary show beside it. Filters at the bottom show only some kinds: `Alt+C` classes, `Alt+M` methods, `Alt+X` extension methods and so on. With the Emacs keyboard scheme, `Alt+F`, `Alt+V` and `Alt+X` keep their Emacs meaning.
  - **Commit characters**: typing `(`, `.`, `;`, Space or other punctuation inserts the selected item first (`Con` then `.` gives `Console.`). Before you type anything, and where you're naming something new (a lambda's parameter), the selection is soft (an outline) and nothing is committed. **Text Editor → Completion: Commit on Space** turns Space off. In Visual Basic, Enter also starts a new line after inserting.
  - **Target type matches** (C#): the items of the type expected at the caret (an argument, an assignment, a return value) are preselected, and `Alt+J` (the target icon in the filter bar) shows only them.
  - **Parameter info** sits above the line, so the two no longer overlap. It has `˄ 1 of 2 ˅` chevrons (or `↑` `↓`), the parameter you're typing in bold, the summary and that parameter's description.
  - **Quick Info** is one tooltip: the symbol's icon and declaration, wrapped instead of cut off, and "Returns:" once. Under it, each error's code links to its documentation, with **Fix** (`Alt+.`, the top fix), **Other Fixes** (`Alt+Enter`) and, with AI on, **Add to Chat**. It no longer opens over the completion list or parameter info. `Alt+.` (**Apply Top Fix**) also works without Quick Info: it applies the top fix for the error or warning at the caret, or on its line.
  - The C# Interactive window has the same completion list and parameter info.
- **Hot Reload while debugging a Blazor WebAssembly app** ([user guide](docs/user-guide/web.md#hot-reload)): Start Debugging runs the app's dev server under `dotnet watch`, so saving a file (or Apply Code Changes: `Alt+F10`, `Shift+Alt+F10` on Linux, `⌥F10` on macOS) applies the edit to the app in the browser while the debugger stays attached, and breakpoints stop in the changed code. Before, Hot Reload worked only without the debugger. The **Hot Reload while debugging** setting (`debug.hotReload`, on by default) turns it off. Programs the debugger runs itself, such as a Blazor Server app, still restart to show an edit: the .NET runtime refuses updates to them ([ADR 0040](docs/adr/0040-hot-reload-while-debugging.md)).
- **The merge editor looks and works like Visual Studio's** ([user guide](docs/user-guide/git.md#resolving-conflicts)): the incoming and current versions side by side, named by their branches ("Incoming: master", "Current: develop"), with a check box beside each conflict: check one side to take its block, both to take both, neither to undo it. A box in each header takes every conflict from that side. The result below no longer shows git's `<<<<<<<` markers: each unresolved conflict shows the merge base's text, highlighted in muted red, and you can still edit it. A compact toolbar has the previous and next conflict (`Shift+F8`, `F8`), the count ("1 Conflict (1 Remaining)") and Accept Merge; its gear menu switches to three columns, puts your version on the left if you prefer, and takes all incoming or all current. The three panes scroll together, and a status bar shows the zoom, the caret, the indentation, the line endings and the encoding, which Accept Merge now keeps. The tab is the file's name, with `*` once you've changed something. The gear menu also has Reset All Conflicts, and the layout and the side on the left are remembered (`git.mergeEditor.layout`, `git.mergeEditor.incomingOnLeft`). The Command Palette has Next Conflict, Previous Conflict, Take Incoming, Take Current and Take Both (for the conflict at the result's caret), Take All Incoming, Take All Current and Accept Merge.
- **One look for every menu**, as in Visual Studio: context menus and drop-down menus have 24 px rows, an icon column on every entry so text lines up in every menu (a check mark takes the icon's place), the shortcut on the right in muted text, separators that start under the text and a small submenu chevron. The menus that windows make themselves have icons now, like the main menus: Git Changes (files, stashes, the Git menu, Commit's choices and the view options), Git History, the Start window's recent list, Service References, Breakpoints, Test Explorer and a test's CodeLens, Locals and Watch, pinned data tips, the inheritance margin, Endpoints Explorer, Task Runner Explorer, the Windows Forms designer's tray, the merge editor's gear menu, Counters' export and the Hot Reload menu.
- **The editor works more like Visual Studio's**:
  - **CodeLens sits above each declaration** ([user guide](docs/user-guide/editing.md#inline-information)), on a small row of its own lined up with the code, instead of at the end of its line. A declaration on the first line, or right after a folded block, keeps it at the end of its line.
  - **Holding `Ctrl` (`⌘` on macOS) over a symbol shows Go to Definition's link** ([user guide](docs/user-guide/editing.md#navigation)): the symbol is underlined and the pointer is a hand when the language service knows its definition, which `Ctrl+Click` goes to as before.
  - **The breakpoint margin comes before the line numbers** ([user guide](docs/user-guide/debugging.md#breakpoints)), and with the pointer over it a faint circle shows the line a click adds a breakpoint to.
  - **Document tabs have a pin beside a thin close button** ([user guide](docs/user-guide/solutions.md#solution-explorer)): the selected or hovered tab shows the pin to pin it (to the left of its group), and a pinned tab keeps it, upright, to unpin it.
- **Codalus IDE comes to the front when the program stops** ([user guide](docs/user-guide/debugging.md#while-stopped)) at a breakpoint, an exception or a step, even when the program's window or the browser had the focus, so `F10` and `F11` go to the debugger. Before, the program or the browser kept the focus, and in a Blazor WebAssembly app on Windows and Linux `F11` toggled the browser's full screen instead of stepping into the method.
- **Solution Explorer sorts like Visual Studio** ([user guide](docs/user-guide/solutions.md#solution-explorer)): a project's `Properties` (`My Project`) and `wwwroot` folders come first, and names with `_` sort before letters.
- **Browse for any path** ([user guide](docs/user-guide/solutions.md#new-projects-and-solutions)): New Project's and New Solution's location, and every other field where you type a path on your computer, have a folder button beside them (**Browse…**) that opens your OS's folder or file picker where the typed path is: EF Core's compiled model folder and Scaffold's output folder, Publish's folder, a SQLite connection's file, a launch profile's executable and working directory, an external tool's command and initial directory, and in Options the Android SDK and JDK locations and the settings sync folder. A folder inside the project stays relative to it. Plugins get the same button with plugin API 1.1's `InputBoxOptions.Browse` ([plugins.md](docs/plugins.md#changelog)).
- **Fixed:** debugging a Blazor WebAssembly app on a busy machine sometimes never stopped at a breakpoint in its components: the page ran, but the browser had opened it before the dev server's debugging proxy was ready for it, so the proxy never saw the app's .NET runtime start. The page now opens once the proxy has attached to it ([ADR 0026](docs/adr/0026-browser-debugging.md#amendment-2026-10-21-the-page-opens-after-the-proxys-handshake)).
- **Fixed:** the Live Visual Tree could stay empty after Start Without Debugging (`Ctrl+F5`) or Start Debugging (`F5`) of an Avalonia app, or a WPF app on Windows: the app's output said its live agent's connection was refused, in a line starting "Codalus previewer agent:" for an Avalonia app or "Codalus WPF live agent:" for a WPF app. The check for the HTTPS development certificate, made as the app starts, also prepared a live session, and when it finished after the start it replaced the app's session and closed the port the app connects to. Only the app that starts gets a session now.
- **Fixed:** a solution's requests to its build host, such as reading the installed packages, now and then failed with "Handle is not initialized." when they evaluated projects just as a design-time build ended. The end of a build clears MSBuild's string cache, which isn't safe while the same process evaluates; the two no longer overlap. An unexpected error in the build host now also logs its full stack.
- **Fixed:** a change Codalus IDE made to a project file, such as Exclude From Project or Include In Project, now and then showed an error such as "The node is not parented by this object.": after the change, the build host read the project file again while its file watcher was reading it too, or a build was using it. They now take turns.
- **Fixed:** the Windows Forms designer's Toolbox could miss your project's own controls and components when you opened a form while the project was still loading or restoring, until you reopened the designer. It now asks again once the project has loaded, and when you come back to the designer.
- **Fixed:** on Linux, Codalus IDE could crash (a segmentation fault) the first time it drew text in a bold or italic its font has no face for, such as an italic of a font that has only an oblique: it made that face from a copy of the font file, whose memory could be freed while it was copied. The copy is now made safely. Also, when an italic or a bold was the first style of a font drawn, the regular text after it could come out slanted or bold.
- **Fixed:** attaching the debugger to a program on this machine that is slow to attach to, such as a packaged WinUI app starting on a busy Windows machine, failed with "Could not start …: Command execution timed out." once netcoredbg had taken 15 seconds, although netcoredbg was still attaching. The session now waits for the program's runtime, as it already did after netcoredbg's 5-second startup wait. Break All pressed before the debugger had attached failed with "Failed command 'threads' : 0x80004005"; it now waits until the debugger is attached, up to a minute, then stops the program. In a session of several programs, Break All leaves a later program that is still starting running.
- **Fixed:** while Quick Info was open, the editor didn't get the pointer: moving away didn't close Quick Info, and the first click in the editor only closed it, so a `Ctrl+Click` on the symbol under it didn't go to its definition. Quick Info now lets the pointer through to the code: moving the pointer away closes it (it stays open while the pointer is on the symbol or on its way to Quick Info), scrolling or zooming the code closes it, and a click in the code acts where you click.

## 0.4.0

- **External agents in AI Chat** (M48, [user guide](docs/user-guide/ai.md#external-agents-acp)): AI Chat can run coding agents that are programs of their own, such as pi, Claude, Codex, Gemini CLI, GitHub Copilot, OpenCode or Goose, over the Agent Client Protocol, next to the built-in assistant. Set one up in one step with **Add agent…** in AI Chat's agent picker (a known agent's entry, pinned to the ACP registry's version, goes to your user settings after it shows the exact command), or add it to your user settings yourself (`ai.agents`; a workspace can't), then turn on AI assistance, open a trusted folder and pick it in AI Chat's toolbar. Their answers, thinking, plans and steps show in the chat (a step's files open at the line; a command's output shows live), with their modes and slash commands. What they ask of the IDE goes through its checks: files read from the editor, only inside the folder and never the excluded ones, redacted; every write through the preview into the editor; every permission and command with Reject the default; each request in the AI log. Each agent gets the IDE's tools through `codalus mcp`. An external agent uses its own provider and data policy, and AI Chat says so whenever one is chosen ([ADR 0079](docs/adr/0079-external-agents-over-the-agent-client-protocol.md)).
- **One look for every button, field and dialog, and redesigned views** (M34h): buttons, toggles, check boxes, combo boxes, text boxes, tabs and toolbars follow one design in all sixteen themes, with a visible focus ring and each family's own corners. Dialogs have a header with an icon, the title and what they're about, and their buttons in your OS's order (the main one last on macOS); `Enter` and `Escape` answer them. More than 40 tool windows and views trade their rows of text buttons for icon toolbars, every icon with a tooltip and a name for screen readers.
  - **Find Results** ([user guide](docs/user-guide/editing.md#find-and-replace-in-files)): each line in the editor's colors for its language, with the match highlighted; what was searched above the results and the counts below; **Tree** or **List**, grouped by folder and file with their counts; `F8` and `Shift+F8` step through the matches; **Clear All** and **Stop Searching** on the toolbar.
  - **HTTP Response** ([user guide](docs/user-guide/web.md)): the status as a chip in its class's color with the time and size, the request linked to its line in the `.http` file, **Body** (Pretty or Raw, with word wrap), **Headers** and **Request** tabs, and Send Again, Copy, Save… and Open in Editor.
  - **The WCF Test Client** ([user guide](docs/user-guide/wcf.md)): one address bar with **Running Services**, the operations with their signatures, and a request grid with each field's type, a red `*` where a value is expected, enums as drop-downs, a list as one row with add and remove, and Nil as a check box. `F5` invokes while the test client has the focus, and a fault shows its code and reason.
  - **AI Chat** ([user guide](docs/user-guide/ai.md)): your questions as bubbles with chips for what went with them (and what didn't, with the reason), answers with their steps (their files open at the line) and code blocks in the editor's colors with Copy, Insert at Cursor and Apply…, and one box to type in with the context chips. Send becomes Stop only while this chat's answer runs (it did for any AI request, inline suggestions included), and a long conversation stays fast.
  - **Options**: colored category icons with counts, a header on each page with how many of its settings are modified, **User | Workspace** as a switch, and modified settings marked. **Containers, Exception Settings, Benchmarks, Counters, Configuration Manager, Service References and Git Worktrees** have the new toolbars. In **Counters**, the process id and the process list are one box: type an id or a name, or pick a process. Configuration Manager's combo boxes show their choice after loading.
  - **Manage NuGet Packages** shows each package with colored initials and its versions as badges (installed, an update, prerelease), and the name and author no longer overlap. **Add New Item**'s templates are one line each, and its preview is in the editor's colors. A preview of changes takes three quarters of the window, each changed line marked. The Windows Forms designer's selection is a sharp one-pixel frame with seven-pixel handles. **Keyboard Shortcuts** highlights the command under the pointer and the selected one.
  - **Colored output**: the Output window and the Debug Console color what their lines report: errors (`error CS1002:`, *Build failed*, exceptions and their stack traces) in red, warnings in amber, a build that succeeded in green, in each theme's colors; a program's standard error is red, and its ANSI colors show as colors, readable on the theme's background, instead of escape codes. Solution Explorer's toolbar icons each take their family's color (and Refresh is green everywhere, Git Changes' Fetch, Pull, Push and Sync the Git color), every Windows Forms Toolbox control and component has an icon of its own, and the theme cards in the first-run setup and Options show the IDE itself in miniature, in that theme's real colors and shapes, instead of a drawing.
- **Classic is the default theme again, and comes first** ([user guide](docs/user-guide/settings.md#themes)): without a theme setting, Codalus IDE uses Classic following your system (Classic Light, Dark, or High Contrast when your system's high-contrast setting is on) instead of Harbor. Classic is the first card in the first-run setup, where it's now offered and preselected (its modes are Light, Dark, High contrast and Match system; Blue is in Options), and the first in Tools → Options → Environment → Appearance and Tools → Color Theme. **If you used 0.3.0 without choosing a theme, you'll see Classic**: choose Harbor once to keep it. A theme you chose stays as it is. The setup now saves the theme you leave chosen, the preselected one too.
- **Key bindings that changed** ([user guide](docs/user-guide/keyboard.md)), so that each key does one thing on each OS:
  - **Git → Toggle Blame** is `Ctrl+Shift+Alt+B` on Windows and Linux (`⌘⌥B` on macOS, as before): its `Ctrl+Alt+B` took the Breakpoints window's key in the editor of every Git repository.
  - On **macOS**, Start Without Debugging is `⌃F5`, as in VS Code (`⌘F5` turns VoiceOver on or off), and Break All is `⌘⌥P` (Mac keyboards have no Break key).
  - On **Linux**, the ReSharper scheme's Find Usages is `Shift+Alt+F12`, because GNOME takes `Alt+F7`.
  - `Ctrl+\` splits the editor only in the **VS Code** scheme. In the Default, ReSharper and Emacs schemes, `Ctrl+\`, `Ctrl+E` opens the Error List, which couldn't be typed in a text file before.
  - Fixed: the **Emacs** scheme's `Ctrl+X Ctrl+F` failed (it's Go To File now), and the **ReSharper** scheme's `Shift+Alt+L` opened the system's file manager instead of locating the file in Solution Explorer.
- **A missing .NET runtime is named, and offered** (M49, [user guide](docs/user-guide/troubleshooting.md#common-problems), [ADR 0080](docs/adr/0080-the-hosts-dotnet-runtime.md)): Codalus IDE checks the .NET runtime each helper process needs (the build host, the language services, the plugin host and the others) before starting it, in the .NET folder it would use, and prefers a folder that has it. When it's missing, or only an earlier release candidate is installed, one notification says which runtime is needed and what was found, instead of "The connection was lost", with **Install .NET 11.0** (into `~/.dotnet` on Linux and macOS, through winget on Windows) and **Check Environment**, which has a row for it. Once it's installed, the plugins, the language services and the solution that couldn't open start again without a restart. **Updates check it first**: an update whose runtime isn't installed isn't downloaded, and the IDE offers to install the runtime, or Update Anyway. (0.3.0 doesn't know this check, so the update to 0.4.0 installs without it; 0.4.0 then offers the runtime when it starts.) A helper process that exits while it starts now says why, with its exit code and the first lines it wrote (all of them in its Output channel), and isn't started again, since it would stop the same way; one that's killed (by you, or by the system when memory runs out) is still started again. `CODALUS_SKIP_RUNTIME_CHECK=1` turns the check off.
- **Every command checked from its menu, its key and the command palette**, on Windows, Linux and macOS, and what that found:
  - Clicking a C# CodeLens's reference count ran a command that didn't exist; it runs Find All References.
  - `Ctrl+S` and File → Save didn't save in the `.resx`, `.editorconfig`, Windows Forms designer and plugins' custom editors.
  - Solution Explorer's Git → View History, and Git LFS Lock and Unlock, acted on the active editor's file instead of the item you right-clicked.
  - In an opened folder (not a solution), Publish to a Git host ran `git init` in the folder's parent.
  - Save As Solution Filter said "Saved" when the save failed.
  - `Escape` in a quick pick hid the notifications instead of closing the quick pick.
  - Reattach attached to an unrelated `dotnet` process. Over SSH, in a container or in WSL it now finds the same program by its id and command line; on this machine it asks which `dotnet` process to attach to.
  - Attach to a Process in a Container always used Docker: `debug.containerTool` defaulted to `docker`. It now uses the Containers window's engine (`containers.tool`, else Docker or Podman, whichever is installed), and `debug.containerTool` overrides it when you set it. When no container engine answers (the tool is missing, or Docker is installed but its daemon isn't running), it says so and how to start or install one, as the Containers window does, instead of showing `docker ps`'s message as an error.
  - Create Dump in a session over SSH, in a container, in WSL or in a remote window dumped a local process with the same id. It now says it dumps programs on this machine only.
  - On Windows, copying and pasting while another program held the clipboard failed with an error. It tries again briefly, then says so on the status bar.
  - Options and Settings open without a pause of about a second.
  - Manage NuGet Packages lost every result of a local package folder that had one broken package. Folders are searched package by package, and the broken ones named.
  - With `podman-docker` installed, Check Environment's Docker row showed two lines, cut off.
  - Turning a plugin off copied the workspace's turned-off plugins into your user settings, and turning it on didn't take it out of the workspace's list. Each settings layer keeps its own `plugins.disabled`.
  - View → Other Windows listed the Ports window twice, and the palette said "Markdown: Markdown: Open Preview to the Side".
  - For plugins: the `onSolutionOpened` activation event fires (a plugin that waited for it never started), the `documentTab/context` menu location is accepted, and a `when` clause or enablement that doesn't parse is a warning instead of silently always true ([changelog](docs/plugins.md#changelog)).
- **The Linux repositories serve their packages from the GitHub releases** ([Download](https://stavroskasidis.com/codalus-ide/download/#apt)): the website keeps only the signed repository metadata, and the `.rpm` packages are signed themselves. **If you added the apt repository before 0.4.0, run the Download page's second apt command again**: the sources line is now `mirror+…/apt/mirrors.txt`, which needs apt 1.6 or later. **With zypper, remove the repository** (`sudo zypper removerepo codalus-stable`, or `codalus-nightly`) **and add it again.** dnf's `.repo` files keep working.
- **A trusted folder stays trusted through a symbolic link** ([user guide](docs/user-guide/getting-started.md)): trust was matched by the folder's spelling, but solutions open under their real path, so the trust prompt asked again for a folder trusted through a link (on macOS, any folder under `/var/folders`, which opens as `/private/var/folders`). Folders are now saved and matched by their real path; folders trusted before through a link still count.
- **AI Chat sends nothing while an answer is written** ([user guide](docs/user-guide/ai.md)): `Enter` or **Send** during an agent's turn, while one of its tools ran, started a second question, and **Stop** could no longer end the first. Now the next question waits in the box until the turn ends, and clicking **Send** leaves the focus in the box instead of on the hidden button.
- **Attach to Process lists processes faster on Windows**: it reads each process's modules in one pass and every window title at once, and never waits on a window that doesn't answer.
- **.NET Framework projects' messages name what's missing**: the reason an old-style project can't build, and Convert to SDK-Style's notes, say it imports proprietary MSBuild targets that aren't part of the .NET SDK, and an unsupported project's error offers converting it to an SDK-style project.
- **Releases**: the website's screenshots show 0.4.0, and the tests and the release's tools got fixes of their own.
- **Fixed:** in Find and Replace, hovering the Find what box drew a border around its arrow only, or around its text only, and the text and placeholders of Find what, Look in and File types sat at the top of their boxes. Every editable combo box now draws one border around its text and arrow, under the pointer and with the focus, and every combo box centers its text.
- **Fixed:** the lines sticky scroll pins at the top of the editor drew over the branch picker and other quick picks, the command palette, Find and Replace, dialogs and the editor's find widget. They now stay under them.
- **Fixed:** after you saved a document, Codalus IDE could warn that it had "changed on disk, and you have unsaved changes": on a busy machine, the file watcher could check the file before the save had recorded it. A document's own save is no longer reported; a change made elsewhere still is.
- **Fixed:** after you closed a solution or folder and opened another, a design-time build of the closed one that finished late could bring its projects back into the new solution's C# language service. Results from a closed solution are now dropped.
- **Fixed:** in the Classic Dark theme, code looked gray next to Visual Studio's Dark theme: namespaces and labels were `#C8C8C8`, and punctuation, and the C# and JavaScript inside Razor files, `#D4D4D4`. They're now Visual Studio's plain text color, `#DCDCDC`. In Classic Light and Blue, plain text is black as in Visual Studio, locals and parameters are Visual Studio's dark blue, and the text of a `///` documentation comment is green, no longer gray like its tags.

- **Fixed:** the Benchmarks window could leave a run out of the selected benchmark's history: when a run measured exactly the same as the one before (a Dry job's single iteration can, on Windows), the history wasn't refreshed. It now always shows the run.

A read older than the one shown is now dropped.
- **Fixed:** on Windows, starting the Performance Profiler with Memory Usage alone could fail after a minute with "Profiling … could not start: A task was canceled.", leaving the program held before it started. Without CPU Usage or another tool, resuming the program is the first connection to its .NET diagnostics port, made as the program starts; connecting just as the runtime creates that port gives a connection the runtime never answers. - **Fixed:** the XAML previewer could wait a minute and then say "The previewer didn't answer within 60 s." after an edit that didn't load (a typo, an unknown property), instead of showing the error: Avalonia's designer can hold an answer back until it next sends something, and after an error it sends nothing else. ## 0.1.0

The first preview release of Daedalus Studio, an open-source (MIT), cross-platform IDE for .NET. It covers the editor, the project system, NuGet, build and run, debugging, testing, Git, the terminal and C# Interactive, profiling, data tools, containers and Aspire, web and Blazor, and Avalonia XAML: see the [features](https://github.com/stavroskasidis/daedalus-studio#features) and the [user guide](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/user-guide/README.md). It's a 0.x release: expect rough edges, and please report what you find in the [issues](https://github.com/stavroskasidis/daedalus-studio/issues).

**Before you install**: you need the .NET SDK 10.0 or newer and git 2.30 or newer ([installing and first start](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/user-guide/getting-started.md)).

**The installers aren't code-signed yet**, so each OS asks once:
- **Windows** ("Windows protected your PC"): choose **More info**, then **Run anyway**.
- **macOS** ("Apple could not verify…"): close the message, open System Settings → Privacy & Security, and choose **Open Anyway** next to Daedalus Studio (or the installer); then open it again.
- **Linux**: the `.deb` and `.rpm` packages and our apt and dnf repositories are signed with the [project's key](https://github.com/stavroskasidis/daedalus-studio/blob/master/eng/packaging/linux/daedalus-studio-packages.asc).

Installed builds update themselves from signed feeds (the Velopack installers and the AppImage), and `SHA256SUMS.txt` lists every file's checksum.

**Platforms**: Windows 11 x64, macOS 15 or newer on Apple silicon, and Linux x64 and arm64. Windows on Arm and Intel Macs aren't built yet.

**Not in this release yet**: remote development (SSH, WSL, containers), Hot Reload while debugging, .NET MAUI, Visual Basic and F#; see the [roadmap](https://github.com/stavroskasidis/daedalus-studio/blob/master/docs/roadmap.md).
